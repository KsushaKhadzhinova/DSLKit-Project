## 1. Что такое DSLKit

Веб-IDE для создания диаграмм через код (diagram-as-code). Пользователь пишет текст на DSL, справа сразу видит диаграмму, а встроенный валидатор проверяет, что код соответствует правилам выбранной нотации.

| Параметр | Значение |
|---|---|
| Название | **DSLKit** (выбрано пользователем: «идеальное название»; домены и товарный знак не проверены) |
| Нотации | IDEF0, ERD, BPMN, сети Петри, UML, DFD |
| Стек (по планам) | React 19 + TypeScript + Vite (PWA), Monaco Editor, elkjs (раскладка), C++ → WASM (разбор и проверка DSL, раскладка, SVG) |
| Цель | Дипломный проект БГУИР, затем выход на рынок (enterprise-уровень, нужны нормальные документы и авторские права) |
| Защита | июнь 2027 (решение D6) |
| Монетизация (D9) | Free + Pro, платный API, лицензии для вузов и команд |
| Интеграции (D8) | Публичный API и SDK, iframe-виджет, плагины (Confluence, Notion, VS Code, GitHub), импорт/экспорт |
| Целевая аудитория | Технические специалисты: разработчики, архитекторы, DevOps, data science, преподаватели и студенты. Для нетехнических ролей (бизнес-аналитики, HR) нужен отдельный «простой режим» либо они не целевые |

### Дополнительные функции, которые просила пользователь
- Загрузка кода или репозитория: приложение само рисует нужный тип диаграммы.
- Image → DSL (ограниченная функция). Идея конвейера: предобработка → детекция → граф → классификация нотации → формализация → промежуточное представление → DSL (основа: статья «Автоматизация преобразования изображений», `E:\Статьи\`).
- Лимиты: в beta до 5 диаграмм в день; позже только в Pro; обычная подписка 1 диаграмма в неделю; без подписки 1 в месяц.
- PWA, адаптив: на телефоне ограниченный набор функций, на планшете слегка урезанный.
- Онбординг-тур при первом запуске, его можно пропустить.
- Интерфейс «с воздухом», максимум полезной информации без перегруза. Пожелание «чтобы приложение подсаживало на себя» нужно реализовывать через пользу и удобство, без тёмных паттернов (её собственные материалы по UX их запрещают).

## 4. Требования (результаты квиза на 105 вопросов, отвечено 97)

### Продукт и навигация
- Старт: дашборд «Мои проекты» (карточки с SVG-превью, как Figma Home). Полноценный лендинг на `/` (Hero с живой демо, список нотаций, «Как это работает», отзывы студентов, FAQ).
- Первое действие: онбординг-тур из 5 шагов (редактор, холст, Run, Problems, AI), можно пропустить.
- Документация: всплывает в боковой панели по иконке.
- Вход встроен в Welcome Screen: Email+пароль, гость, Google, GitHub, GitLab, Microsoft/Azure AD. Гость: 1 файл, без экспорта. После входа сразу в последний файл.

### Раскладка и тулбар
- Режимы Editor-only / Canvas-only / Split; расположение зависит от экрана; допустимы полноэкранные редактор и холст.
- Нижняя панель: Problems, AI Assistant, Terminal/CLI, Output, Versions.
- Status Bar: нотация, Ln/Col, статус сохранения, число ошибок, ветка Git, статус Auto ON/OFF.
- Breadcrumb (A-0 › A0 › A1.2); вкладки, не более 5.
- Тулбар обязательно: Run, Сохранить, Экспорт, селектор нотации (выпадающий, с иконками и поиском), Тема, Поделиться (view/edit). Run всегда сверху.
- Хоткеи: Ctrl+Enter Run, Ctrl+S, Ctrl+Shift+E, Ctrl+\` тема, Ctrl+\\ холст, Ctrl+B сайдбар, Ctrl+Z/Y.

### Редактор
- Автодополнение; ошибки: волна, иконка в gutter, фон строки, tooltip, счётчик в статус-баре.
- Нет minimap и мультикурсоров; есть folding, Format Document, водяной знак нотации, поиск/замена (Ctrl+H), автозакрытие скобок, ruler 80/100, undo на 20 операций.
- Шаблоны из панели Template в сайдбаре. Контекстное меню строки: Go to Definition, Добавить в шаблоны, Rename, Find References, Fix with AI.

### Холст
- Плавающие Zoom/Fit (позицию можно менять); мини-карты в MVP нет; сетка кнопкой.
- Клик по элементу: подсветка строки, панель свойств, рамка, tooltip. Drag-and-drop с записью `pos` в код — обязательно. Мультивыбор, Auto-Layout кнопкой, snap to grid нет, double-click = inline rename, линейка включается в настройках.
- Pan: средняя кнопка мыши; Ctrl+scroll — zoom, обычный scroll — pan.
- Контекстное меню: Переименовать, Удалить, Копировать как DSL, Зафиксировать позицию, Открыть в коде, Копировать стиль, Экспортировать элемент.

### Run, сохранение, экспорт
- Авторендер: выбор при первом запуске; тонкий прогресс-бар сверху; при ошибке частичный рендер.
- Автосохранение через 1 с; индикатор ● на вкладке.
- Экспорт: модальное окно с выбором формата. Форматы MVP: SVG, PNG ×2, PlantUML, Mermaid, BPMN XML, XMI (UML), SQL DDL (ERD), draw.io XML, D2, исходный `.dsl`. После экспорта toast справа внизу.
- Импорт PlantUML/Mermaid с автоконвертацией в синтаксис DSLKit.

### AI
- Панель справа (как Copilot Chat); результат показывается в чате, пользователь копирует сам; «Fix with AI» рядом с ошибкой в Problems; поток с анимацией набора; режимы: написать по описанию, исправить ошибки, объяснить правила, оптимизировать.

### Совместная работа, офлайн, интеграции
- Realtime-совместная работа в Pro; полный Git (commit, branch, diff).
- PWA и офлайн — да, но не главная фича; восстановление после сбоя.
- Источники: скачать `.dsl`, база аккаунта, GitHub, Google Drive, Image→DSL; embed-виджет позже.

### Мобильная версия
- Полноценная, с переключением код/холст.

### Стиль (из квиза и переписки)
- Акцент синий `#0078d4` (позже уточнён токенами, см. `DESIGN-TOKENS.md`), тема Monaco Tokyo Night для кода.
- Уведомления: тосты справа внизу, одновременно до 2; скелетоны при загрузке.

## 5. Правила и ограничения от пользователя

### Процесс и право
- **Без AI-атрибуции**: никаких упоминаний, что проект сделан с помощью ИИ; никаких коммитов «от чужого имени» и соавторов. Коммиты только от имени владельца.
- Чистый код и чистая архитектура; минимальные, точечные изменения; без спекулятивных абстракций.
- После каждой крупной задачи — независимая экспертная проверка другим исполнителем (ошибки, уязвимости, слабые места).
- Найти и оформить источники (литература и интернет) по всем частям продукта: сборка, управление, требования, проектирование интерфейсов, веб-дизайн, SDLC, архитектура ПО и др.
- Подготовить документы и авторские права к выходу на рынок.

### Дизайн
- **Светлая тема проектируется первой**, тёмная вторая.
- Золотое сечение (φ = 1.618) — обязательно, плюс правила хорошего UX. Источники вдохновения: draw.io и VS Code, но **нельзя копировать их напрямую**: нужны собственный шрифт и стили.
- Максимальный минимализм, мало скругления, гармоничные приглушённые цвета в интерфейсе (код может быть ярким), «воздух».
- Не нравятся: Glassmorphism, Tokyo Night как UI-гамма, Neo-Brutalism, Material Design 3, Nord Polar. Ориентир позже: Microsoft Fluent + Apple iOS (Liquid Glass как возможный акцент).
- Иконки минималистичные, не выделяющиеся; сетка тонкая с переключением на точки; как в VS Code/draw.io подсвечивать отступы и выравнивание.
- Макеты именно макеты, не скриншоты: в Figma всё вручную нативными объектами.
- Литература, которую дала сама: Ян Агеенко «Как стать дизайнером с нуля»; девять блоков справочных правил по UX (эвристики Нильсена, законы UX, WCAG 2.2, дизайн-токены, Core Web Vitals, PWA, этика, Human-AI Interaction и др.).

## 6. Дизайн-система (итоговое состояние)

Полные таблицы: `DESIGN-TOKENS.md`. Кратко:

- **Светлая тема**: `--bg #f8f9fc`, `--sf #fff`, `--br #dde1e9`, `--tx #1c1f2e`, `--tx2 #4a5068`, `--tx3 #6b7285`, акцент `#2563eb`, success `#16a34a`.
- **Тёмная тема** (класс `.t-dark`, палитра в духе Catppuccin): `--bg #1e1e2e`, `--sf #181825`, `--tx #cdd6f4`, `--tx3 #7f849c` (исправлено ради контраста 4.6:1).
- **Layout по φ**: Activity bar 40 px, Sidebar 180 px, редактор ≈ 38.2 %, холст ≈ 61.8 %, Status bar 22 px. Рекомендованная раскладка: вариант A (код слева) + режим Zen (23.6/76.4).
- **Правило 60-30-10**: фон / поверхности / акцент.
- **Типографика**: UI — Inter; код — Geist Mono / JetBrains Mono (шрифты Geist предложены, пользователь окончательно не подтвердила; собственные шрифты проекта ещё не созданы).
- **Иконки**: Tabler outline, stroke 1.25 px, 17 px.
- **Решения по компонентам**: Autosave — переключатель (как смена темы), включено = зелёный, выключено = жёлтая кнопка Save; несохранённые правки — точка ● на вкладке; закрытие вкладки — кнопка × 20 px; Run — зелёная заливка, Validate — ghost; Undo/Redo всегда видны; панель ошибок снизу, закрываемая; метка нотации «Diagram: IDEF0» в тулбаре; пустой экран — выбор шаблона нотации.

- A/B тесты: batch 1–5 (около 49 вопросов), принятые решения перечислены в `UX-RESEARCH-RESULTS.md`. Подробные ответы пользователя по первым батчам в чате не сохранились; по квизу на 105 вопросов — сохранились (раздел 4).

DSLKit-Project/
