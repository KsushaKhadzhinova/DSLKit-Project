## Лист 1. Проект в одной минуте

**DSLKit** – веб-приложение для хранения диаграмм, записанных текстом (UML, BPMN, ERD, DFD, IDEF0, Petri).

**Роли:** гость (регистрация, вход) → пользователь (свои диаграммы, профиль) → администратор (всё + чужие диаграммы, пользователи, смена роли, удаление пользователя без диаграмм).

**Три модуля:** аутентификация · диаграммы · администрирование.

**Стек:** React 19 + Vite · Express 5 · Sequelize 6 · PostgreSQL 16 · bcrypt + JWT · Docker Compose + Nginx · Vitest, `node --test`.

**Как показать за 2 минуты:**
1. `docker compose up --build` (папка `part-2/lab-08-docker`, `.env` из `.env.example`).
2. Открыть `http://localhost:8080`, зарегистрироваться, войти.
3. Создать диаграмму, найти по названию, изменить, удалить.
4. Показать `docker ps`: три контейнера healthy.
5. Показать `npm test`: 136 и 100.

**Честно о слабых местах:** 3 сущности (рекомендовано 4–6) · нет React Router в курсовом · нет публичного адреса · нет экрана администратора в клиенте.

## Лист 2. Архитектура и API

```
Браузер ──► Nginx :8080 ──► /      статика React
                       └──► /api/  ──► Express :3000 ──► PostgreSQL :5432
                                         (внутренняя сеть, порт наружу не открыт)
```

**Единая точка входа** → один источник для браузера → CORS в контейнерах не нужен. В разработке: клиент :5178 → сервер :3000, CORS с одним адресом.

| Метод | URL | Кто | Коды |
| --- | --- | --- | --- |
| POST | /auth/register | все | 201, 400, 409 |
| POST | /auth/login | все | 200, 400, 401, 429 |
| GET | /profile | токен | 200, 401 |
| GET | /diagrams | токен | 200 + `X-Total-Count` |
| POST | /diagrams | токен | 201 + `Location` |
| PUT/DELETE | /diagrams/:id | владелец, admin | 200/204, 403, 404 |
| GET | /users | admin | 200, 403 |
| PATCH | /users/:id/role | admin | 200, 400, 404 |
| DELETE | /users/:id | admin | 204, 400, 404, 409 |
| GET | /health | все | 200 или 503 |

Список: `search`, `limit` 1–100, `offset`, `sort` (белый список), `order`.
Ошибка: `{"error": "...", "details": [...]}`; 500 → только «Internal server error».

## Лист 3. База данных и авторизация

**Таблицы:** `Users` (id, email нижним регистром, хеш, роль) · `Diagrams` (id, title ≤ 80, notation, sourceCode ≤ 10000, priority, userId) · журнал запросов.

**Целостность в самой базе:** допустимая нотация, непустое название, лимит длины.

**Миграции** применяются при старте; **сид** создаёт администратора из `ADMIN_EMAIL`, `ADMIN_PASSWORD` (пароль от 10 символов).

**База:** PostgreSQL по `DATABASE_URL`; SQLite только для тестов (`SQLITE_STORAGE`).

**JWT-цепочка:**
1. POST /auth/login → сверка пароля с bcrypt.
2. Токен HS256, издатель `dslkit`, срок 1 час (максимум 24).
3. Клиент: `Authorization: Bearer <токен>`.
4. Сервер: подпись → издатель → срок → **пользователь из базы** (роль берётся из базы, а не из токена).

**RBAC:** user и admin. Владелец или admin меняет/удаляет диаграмму. Роль при регистрации всегда `user`.

## Лист 4. Безопасность (таблица угроз)

| Угроза | Мера |
| --- | --- |
| Кража паролей | bcrypt 10 раундов, пароль 8…72 байта |
| Узнать, есть ли почта | одинаковые ответ и время (запасной хеш) |
| Подбор пароля | 20 входов / 15 мин с адреса (429, `Retry-After`), блок почты на 15 мин после 5 неудач |
| Массовая регистрация | 10 в час с адреса |
| Подделка токена | только HS256, проверка издателя, секрет ≥ 32 символов, без секрета сервер не стартует |
| SQL-инъекция | параметры Sequelize, белый список сортировки |
| Чужой источник | CORS с одним адресом, `*` запрещён, `Vary: Origin` |
| Утечка ошибок | общий обработчик, 500 без трассировки |
| Огромные тела | лимит 100 КБ, проверка длины полей |
| Заголовки | нет `x-powered-by`, CSP, запрет фрейма, `nosniff`, запрет кэша (вручную, `src/middleware/http.js`, без helmet) |

**Docker-безопасность:** непривилегированный пользователь · `read_only` · `cap_drop: ALL` · `no-new-privileges` · лимиты памяти и процессов · база во внутренней сети · секреты в `.env`, не в репозитории.

## Лист 5. Клиент, тесты, числа, ответы на каверзные вопросы

**Клиент:** одна страница, содержимое по состоянию (нет токена → форма, есть → рабочая область). axios с перехватчиками: токен подставляется сам, 401 сбрасывает сессию, повтор при сетевой ошибке 3 раза с паузой 300 мс. Оптимистичное добавление с откатом. Общий `limits.json`.

**Тесты:** сервер 136/136 (строки 100%, ветви 98%) · клиент 100/100 · Docker 11 проверок файлов. Контрольные примеры: раздел 3.2.

**Числа:** тело ≤ 100 КБ · `limit` ≤ 100 · токен 1 ч · порт 8080 · название ≤ 80 · код ≤ 10000.

**Каверзные вопросы:**
- *Почему 3 таблицы?* Предметная область из трёх понятий; четвёртая («Комментарий») спроектирована в `diagrams/er-planned.mmd`, реализована в ЛР6 на MongoDB, добавляется таблицей `Comments`.
- *Где маршруты?* Клиент одностраничный; React Router сделан в ПЗ3 (версии 6.30 и 7.18), перенос возможен.
- *Где деплой?* Основной запуск – Docker Compose; публичный адрес не заведён, подойдут Render, Supabase, Neon.
- *Почему роль из базы?* Чтобы смена роли и удаление пользователя действовали сразу.
- *Почему без helmet?* Заголовки записаны вручную и покрыты тестами; поведение то же.
- *Что улучшить?* Комментарии, React Router, облако, экран администратора, GitHub Actions.
