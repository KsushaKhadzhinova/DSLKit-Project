# Сервер редактора DSLKit: аккаунты, роли, проекты

English version: [README.en.md](README.en.md). Матрица прав «роль × действие»: [ROLES.md](ROLES.md).

Express 5 + Sequelize + JWT. Серверное хранение проектов диаграмм. Редактор без сервера работает как раньше (роль «Гость», локальное хранилище).

## Запуск

```powershell
cd server
npm install
copy .env.example .env   # заполните JWT_SECRET (минимум 32 символа), при желании ADMIN_EMAIL и ADMIN_PASSWORD
npm start
npm test                 # тесты и пороги покрытия
npm run lint
```

Тесты на PostgreSQL: задайте `TEST_PG_URL` (строка подключения администратора, например контейнер `postgres:16`), на каждый тестовый сервер создаётся и удаляется отдельная база.

```powershell
$env:TEST_PG_URL = "postgres://postgres:<пароль>@127.0.0.1:55432/postgres"; npm test
```

`.env` в репозиторий не попадает. Все настройки: `.env.example`. Пределы (длины, лимиты, время жизни токенов): `limits.json`.

## База данных

`DB_DIALECT=sqlite` (разработка и тесты, файл `DB_STORAGE`) или `postgres` (боевой режим, `DATABASE_URL`). Таблицы: `users` (роль в поле `role`), `projects`, `project_members`, `refresh_tokens` (только хэши), `request_logs` (журнал запросов: метод, путь без query, статус, пользователь, IP, время).

Создание схемы: вне production создаются через `sequelize.sync()` (`DB_SYNC` по умолчанию `true`), в production `DB_SYNC` по умолчанию `false`, схему создаёт миграция: `npm run migrate` (применяет `migrations/*.js` по порядку, журнал в таблице `schema_migrations`, повторный запуск ничего не делает). Тест сверяет, что миграция даёт ту же схему, что и модели (SQLite и PostgreSQL).

Поиск идёт по предвычисленному полю `searchText` (нижний регистр, NFC и «ё = е» считаются в коде, значение обрезается до размера колонки), поэтому кириллица и регистр работают одинаково в SQLite и PostgreSQL.

## API (префикс `/api`, ошибки: `{"error":{"code","message","details?"}}`)

| Метод и путь                               | Доступ                  | Что делает                                                             |
| ------------------------------------------ | ----------------------- | ---------------------------------------------------------------------- |
| `GET /health`                              | все                     | проверка живости                                                       |
| `POST /auth/register`                      | все                     | регистрация (всегда роль `user`)                                       |
| `POST /auth/login`                         | все                     | вход, выдаёт access (10 мин) и refresh (7 дней) токены                 |
| `POST /auth/refresh`                       | все                     | обновление с ротацией refresh-токена                                   |
| `POST /auth/logout`                        | все                     | отзыв refresh-токена                                                   |
| `GET /me`                                  | вошедший                | свой профиль                                                           |
| `GET /projects`                            | вошедший                | список: `page`, `pageSize`, `q`, `sort`, `order`, `mine`, `visibility` |
| `POST /projects`                           | вошедший                | создать                                                                |
| `GET/PATCH/DELETE /projects/:id`           | по матрице              | читать, править, удалить                                               |
| `GET /projects/:id/members`                | владелец, администратор | участники                                                              |
| `PUT/DELETE /projects/:id/members/:userId` | владелец, администратор | выдать (`read`/`write`) или отозвать доступ                            |
| `GET /users`                               | администратор           | пользователи с email, страницы и поиск                                 |
| `PATCH /users/:id`                         | администратор           | сменить роль (не свою)                                                 |
| `POST /users/:id/unlock`                   | администратор           | снять блокировку входа                                                 |
| `GET /logs`                                | администратор           | журнал запросов                                                        |

## Безопасность

- Пароли: bcrypt (стоимость из `BCRYPT_ROUNDS`, в продакшене не ниже 10), 8 символов минимум, буква и цифра, не больше 72 байт.
- Токены: access JWT (HS256, `iss`, `aud`, 10 минут), refresh непрозрачный, в базе только SHA-256; ротация, повтор старого токена отзывает все сессии пользователя; не больше 10 сессий.
- Вход: 5 неверных паролей блокируют аккаунт на 15 минут. Счётчик атомарный (параллельные запросы не обходят блокировку). Заблокированный аккаунт отвечает так же, как неверный пароль (401), чтобы блокировка не раскрывала существование аккаунта; администратор снимает блокировку. Остаётся риск: чужой email можно заблокировать подбором, смягчают лимиты по IP. Лимиты по IP: общие запросы, вход, регистрация, обновление.
- Ввод проверяется строго на границе (схема в `src/schema.js`): типы, длины, неизвестные поля запрещены (нет массового присваивания роли и владельца), поиск экранирует `%` и `_`, SQL только через параметры Sequelize.
- Права проверяются на сервере при каждом запросе по роли из базы (смена роли действует сразу). Чужой закрытый проект, несуществующий и с неверным id дают один и тот же 404.
- Email виден только владельцу и администратору. В журнале нет тел запросов, паролей и токенов.
- CORS только по списку `CORS_ORIGINS` (без `*`); токены в заголовке `Authorization`, не в cookie, поэтому CSRF не применим. Заголовки: `nosniff`, `X-Frame-Options`, `no-store`, строгий CSP.
- Известные компромиссы: повторная регистрация возвращает 409 (раскрывает, что email занят); лимиты в памяти одного процесса; за обратным прокси задайте `TRUST_PROXY` (число прокси), иначе лимит считается по адресу прокси.
- HTTPS: сервер сам TLS не терминирует, держите его за обратным прокси с TLS; в production шлётся `Strict-Transport-Security`.
- Хранение: журнал запросов хранится `logRetentionDays` (30) дней, просроченные refresh-токены удаляются раз в час.
- Тексты `title` и `description` хранятся как есть, включая `<` и `>`: клиент обязан выводить их через `textContent`, не через `innerHTML`.

После срабатывания блокировки счётчик сбрасывается в 0; при залпе параллельных неверных паролей в этот момент в счётчике может остаться небольшой остаток (до числа запросов залпа). Блокировка при этом уже стоит, остаток только приближает следующую.

Поиск находит только то, что попало в `searchText`: хвост очень длинного названия (дольше колонки: 1000 символов у проектов, 300 у пользователей) в поиске не участвует.
