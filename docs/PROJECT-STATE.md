# Состояние проекта и порядок продолжения работы

Английская версия: [`PROJECT-STATE.en.md`](PROJECT-STATE.en.md). Документ написан для любого, кто продолжает работу над проектом: сам владелец, коллега или помощник. Здесь собрано всё, что нужно знать, чтобы начать без вопросов: цель, правила, карта веток, статус каждой работы, команды, ловушки среды, принятые решения, открытые вопросы и план. Подробные разборы по каждой работе для защиты лежат в [`study/`](study/).

Дата среза: 23 октября 2026.

## 1 Цель и контекст

- Студентка БГУИР, дисциплина «Интернет-технологии и веб-программирование» (ИТиВП), **вариант 26 (чётный)**. Все работы выполняются на одной теме, DSLKit: веб-редактор диаграмм «как код» (IDEF0, DFD, ERD, BPMN, UML, сети Петри и другие, всего 27 нотаций).
- Часть 1: восемь лабораторных (сеть, окружение, семантический HTML, адаптивный CSS, JavaScript и DOM, API и хранилища, React-компоненты, тесты). Результат: сайт в `site/`.
- Часть 2: восемь лабораторных (Node.js, Sequelize, аутентификация, состояние React, React и сервер, MongoDB, WebSocket, Docker), четыре практических занятия (middleware и EJS, проектирование REST API, маршрутизация, Context и reducer) и курсовой проект.
- Преподаватель на защите задаёт вопросы по коду и просит дописать код. Поэтому для каждой работы есть разбор в [`study/`](study/): что делает работа, как устроена, вероятные вопросы, упражнения «допиши при мне».
- Условия работ лежат в [`../materials`](../materials/README.md) (текстовые копии рядом с PDF).

## 2 Правила владельца (обязательны)

1. Коммиты только от имени владельца, сообщения на английском, **без посторонних подписей и отметок об инструментах** (ни в тексте коммита, ни в подписях, ни в именах веток и файлов, ни в документах).
2. Ничего не вливается в `main` без решения владельца. Порядок, который владелец утвердила: сначала каждая ветка работы публикуется отдельно, затем ветки сливаются в `main`.
3. Секреты (пароли, ключи, строки подключения) только в `.env` на машине владельца, не в чате и не в репозитории. В репозитории лежат только `.env.example`.
4. Отчёты и README только в Markdown, **русская и английская версии одновременно**.
5. Дизайн Части 2 идентичен Части 1 (один пакет CSS, одни токены `site/css/variables.css`). Новые варианты стиля владелец отвергла.
6. Каждая работа покрыта тестами. Для Части 1 порог 100% строк, ветвей и функций проверяет `npm test`. Для Части 2 у каждой работы свой `npm test` вместе с проверкой отчётов.
7. Отчёты проверяет строгий линтер `tools/lint-report.js`: заголовки, подписи «Рисунок N – …» и «Таблица N – …», запрет точки с запятой, слов-паразитов и блоков кода вне приложений. После правки кода отчёт нужно пересобрать, иначе тест отчёта падает.
8. Объяснять вопросы владельцу простым языком, с примером. Ответы приходят номерами.

## 4 Что сделано в каждой работе

Подробности в разборах [`study/10`–`study/21`](study/), обзоры в [`study/30`](study/30-PART1-ITIVP-OVERVIEW.md) (Часть 1), [`study/31`](study/31-PART2-ITIVP-OVERVIEW.md) (Часть 2) и [`study/32`](study/32-COURSE-PROJECT.md) (курсовой).

- **Часть 1.** 27 нотаций, 4 движка отрисовки (Graphviz, Mermaid, PlantUML через сервис Kroki и собственный движок в браузере), светлая и тёмная темы, русский и английский, офлайн-кэш. При ошибке сервиса старая картинка скрывается. Поле диаграммы размывается, пока идёт отрисовка. Три крупных функции отрисовки разбиты на мелкие. Безопасность: строгая CSP, очистка чужого SVG, вывод через `textContent`.
- **ЛР1–ЛР3.** REST API диаграмм на Express: слои, проверка ввода на границах, единый формат ошибок, `PATCH`, поле `createdAt`, фильтр `?notation=` и поиск `?q=`, страницы и сортировка, плавная остановка, ESLint. ЛР2 добавляет базу, миграции, связь один-ко-многим и 409. ЛР3 добавляет bcrypt, JWT, роли, блокировку входа (пределы в `limits.json`). В отчётах абзац об архитектуре.
- **ЛР4.** `useState`, `useEffect`, `localStorage`: повреждённая запись удаляется отдельно, фильтр по нотации, `memo`, `maxLength`.
- **ЛР5.** Клиент на axios: оптимистичные обновления с откатом, отмена устаревших запросов, поиск с задержкой, «Загрузить ещё», правка нотации, автоповтор чтения списка. `App.jsx` разбит на хук `useSession`, экран и мелкие компоненты.
- **ЛР6.** Mongoose: вложенные документы, индексы, агрегации, `PATCH`, сортировка, счётчик, текстовый поиск, журнал в коллекцию. Копии ЛР1 и ЛР2 в ветке заменены актуальными.
- **ЛР7.** Socket.IO: комнаты, присутствие, чат, личные сообщения, токен входа, проверка `Origin`, история в памяти или MongoDB.
- **ЛР8.** Три контейнера (Nginx с React, Express, PostgreSQL), healthcheck, закрытая внутренняя сеть, лимиты памяти и процессов, ротация журналов, необязательные pgAdmin и Redis через профили Compose.
- **ПЗ1.** Express и EJS: порядок middleware, CSRF, журнал запросов в таблицу SQLite, проверка формы, страницы 404 и 500, `/health`, кнопки правки, удаления и очистки журнала.
- **ПЗ2.** Три связанных ресурса, схема как единственный источник правил, фильтры, поиск, сортировка, страницы, вложенные маршруты, пределы в `limits.json`, email скрыт в общем списке, описание OpenAPI по адресу `/api/openapi.json`.
- **ПЗ3.** React Router 7: защищённые маршруты и роли, фильтр каталога в адресе, ленивая загрузка, хлебные крошки, `basename` и режим `HashRouter` при сборке.
- **ПЗ4.** Context и `useReducer`: два контекста (данные и `dispatch`), количество в избранном, отмена и возврат действий, блок «prop drilling» с проблемой и решением.
- **Курсовой.** Записка и диаграммы в ветке `course-project`, числа тестов и проверки в тексте приведены в соответствие с кодом.

## 5 Принятые решения

- Холст при ошибке сервиса отрисовки скрывает старую картинку, остаются сообщение и кнопка повтора.
- ЛР4: если в сохранённом списке испорчена одна запись, удаляется только она.
- ПЗ2: email в общем списке пользователей скрыт, по нему нельзя фильтровать и искать.
- ПЗ1: управляющие символы в названии отклоняются, а другие методы на адрес записи дают 405.
- Макеты (51 МБ) хранятся в Git.
- Для чётного варианта журнал запросов пишется в таблицу или коллекцию БД (ЛР2, ЛР3, ЛР6, ПЗ1).
- В ЛР7 не включено `connectionStateRecovery`: восстановленный сокет вернулся бы в комнаты, а состояние сервера (кто в какой комнате, кто в сети) хранится отдельно и разошлось бы с ним. Для включения нужно переписать состояние сервера. Ответ на вопрос о восстановлении связи подготовлен в разборе ЛР7.

## 6 Как работать

```bash
npm install
npm test                         # Часть 1: все тесты с порогом покрытия 100%
npm run lab3:report              # пересобрать отчёт лабораторной N Части 1
node tools/build.js part-2/lab-05-react-api   # пересобрать отчёт работы Части 2
cd part-2/lab-03-auth && npm install && npm test
cd part-2/lab-08-docker && docker compose up --build
```

Для работы с несколькими ветками одновременно удобны отдельные рабочие папки: `git worktree add ../dslkit-lab25 25`. У каждой работы Части 2 свои зависимости, `npm install` нужен в её папке.

## 7 Ловушки среды

- Windows 11, Git Bash и PowerShell. Большие heredoc с кириллицей, обратными слэшами и апострофами в Bash ломаются: файлы с такими строками создавать редактором, а не командой оболочки.
- В правках через оболочку и некоторые редакторы последовательности вида `​` превращаются в настоящие символы. Для таких строк собирать обратный слэш программно.
- Python в Windows пишет файлы с CRLF. В проекте `.gitattributes` задаёт LF.
- Отчёт с вставленным кодом падает в тесте, пока не пересобран (`node tools/build.js …`).
- Тесты клиентов (Vitest) могут падать по таймауту, пока компьютер загружен (например, запускается Docker Desktop). Повторить запуск.
- Сервис Kroki иногда отвечает ошибками и таймаутами. Кадры Mermaid снимаются заново командой `node docs/design-contest/shoot-mockups.mjs docs/design-contest/mockups "" mermaid`, затем `node docs/design-contest/contact-sheets.mjs` (нужны `puppeteer-core` из папки ЛР7 и Chrome).
- Docker Desktop на этом компьютере запускается долго (до нескольких минут), `docker desktop stop` может зависать.

Скрипты съёмки используют `puppeteer-core` из `part-2/lab-07-websocket` и Chrome по стандартному пути. Путь к `puppeteer-core` задаётся переменной `LAB7_DIR`, по умолчанию `part-2/lab-07-websocket` рядом с репозиторием. Сайт для съёмки поднимается командой `node tools/serve.js site 5173`.
