Оценка: по WCAG 2.5.8 (минимум 24x24) всё проходит, но по рекомендации 44x44 (Apple HIG / WCAG 2.5.5 AAA) не проходят все иконки IDE и CTA шапки. Крестик вкладки 16x16 это худший случай: маленький, скрыт до hover, соседствует с областью вкладки; на тач-устройстве недоступен без предварительного касания. Положительное: Run стоит у правого края тулбара (`margin-left:auto`), то есть цель на границе (бесконечная глубина по Фиттсу); hero-кнопки 48 px высотой.

Исправления:

1. `.tab-close`: hit-area 24x24 через `::before`/padding, всегда видим на активной вкладке (уже так), на `@media (pointer:coarse)` всегда видим на всех вкладках.
2. `.btn-icon` довести до 32x32 на десктопе и 44x44 при `pointer:coarse`; кнопку "новый файл" 20x20 -> 28x28.
3. CTA шапки: min-height 40 px (было ~32), `min-width` 96 px; зазор между последним пунктом навигации и CTA не менее 24 px (на 768 px скрывать пункты в бургер, а не сжимать: сейчас 7 px).
4. Для текущей разметки задать `.nav__link, .theme__button, .header__lang, .faq__question, .card__link, .footer__link { min-height:44px; display:inline-flex; align-items:center }`.
5. Ссылки "Получить шаблон ..." в карточках: растянуть кликабельную область на всю карточку (`a::after{content:"";position:absolute;inset:0}`), цель вырастет с ~170x20 до ~430x180 px.

- Hero: 2 действия (основное и вторичное), хорошо.

- Форма: 6 полей (имя, email, нотация, размер команды, комментарий, согласие), 2 fieldset (2 + 3) + 1 чекбокс.
- Тарифы: 2 плана, по 3 пункта. Без кнопок выбора: решение принять негде.
- IDE (экран редактора): screen-nav 3, Activity Bar 5, кнопка нового файла 1, дерево ~9 строк, селект нотации (8 вариантов), вкладки файлов 3 (+3 крестика), тулбар 6 кнопок, тулбар холста 3 + бейджи, вкладки панели 4, режимы AI 4, поле AI и отправка 2. Итого **около 44** интерактивных элементов одновременно.

Исправления:

1. Шапка: убрать из основной линии "Для кого" (в навигации лендинга есть, в подвале нет) и перенести "English" и переключатель темы в один компактный блок-иконки (глобус, луна) с `aria-label`. Цель: 5 ссылок + CTA = 6.
2. Карточки нотаций: оставить одну ссылку на карточку (весь блок кликабелен) и добавить предвыбор: `href="#waitlist" data-notation="idef0"` + 5 строк JS, ставящих `select#notation`. Тогда обещание "Получить шаблон IDEF0" честно: форма открывается уже с IDEF0.
3. Планы: добавить кнопку "Начать бесплатно" в Free и "В список ожидания Pro" в Pro. Сейчас в точке принятия решения действия нет.
4. IDE: селект нотации в сайдбаре (8 пунктов) заменить автоопределением по расширению/первой строке `notation idef0` (она уже есть в коде, строка 3). Дерево папок уже кодирует нотацию (idef0, idef3), то есть выбор дублируется.
5. Прогрессивное раскрытие: режимы AI "Написать / Исправить / Объяснить / Docs" оставить, но Docs убрать в меню "...", остаётся 3.

### 2.3 Закон Миллера (рабочая память 7±2, чанкинг)

Измерения:

- Форма: 2 fieldset по 2 и 3 поля, затем 1 чекбокс. Чанки 2-3, отлично.
- Нотации: сетка 3x2, тарифы 2x3, шаги 3, FAQ 4: все ≤ 6.
- Дашборд IDE: 6 крупных блоков (обзор, недавние проекты, активность, импорт, баннер Pro, шапка) и в них 4 плитки, 3 карточки, 5 событий, 3 вкладки импорта, 3 чипа лимитов. На экран попадает ~25 информационных единиц. Для эксперта нормально, но все подписи 11-12 px.
- Три разные системы лимитов на одном экране: "5 из 5 лимит Free" (проекты), "12 из 20 лимит Free" (файлы), "До 20 версий на файл", "Beta: 5/день (Free) / Pro: 1/нед / Без подп: 1/мес". Пользователю нужно держать в голове 7 чисел.

Исправления:

1. Свести лимиты в один блок "Ваш тариф Free" с полосками (проекты 3/5, файлы 12/20, версии 18/20) и одной ссылкой "Что даёт Pro".
2. Чипы лимитов импорта: показывать только действующий для пользователя (Free: 5/день), остальные в тултипе.
3. Размер шрифта подписей: поднять `--f-xs` с 11 до 12 px.

### 2.4 Закон Якоба (привычные паттерны)

Плюсы:

- IDE: Activity Bar 48 px -> сайдбар 240 px -> вкладки -> тулбар -> разделённый редактор/холст -> нижняя панель -> статус-бар 22 px, то есть раскладка VS Code. Разработчики и студенты узнают её сразу. Значок шестерёнки внизу, дерево файлов с ▾/▸, подчёркивание волнистой линией ошибок.
- Лендинг: шапка с лого слева и CTA справа, hero, карточки, тарифы Free/Pro, FAQ на `<details>`, форма с fieldset. Пропуск навигации `skip-link`. Язык отображается эндонимом "English", это правильно.

Минусы:

1. `Run (⌘↵)` показан безусловно; аудитория БГУИР в основном на Windows (`Ctrl+Enter`). Определять платформу (`navigator.userAgentData?.platform`) и показывать нужную подсказку.
2. Подвал лендинга содержит ссылку "Пример страницы ошибки 500" в основной навигации. Пользователь не ждёт там служебных страниц; убрать из видимого списка (оставить в sitemap/в тестах).
3. Переключатель темы подписан статично "Тёмная тема" (checkbox + label), пользователи ждут иконку-переключатель с состоянием. Сделать `aria-pressed` + динамическая подпись.
4. Единая точка входа: на лендинге CTA "Записаться в бету" / "В бету"; в прототипе "Попробовать бесплатно" / "Попробовать"; в IDE баннер "Попробовать Pro". Один глагол на одно действие.
5. Межпродуктовая согласованность: палитра лендинга (primary #2563eb, dark bg #1e1e2e, text #cdd6f4) и IDE (Tokyo Night: #7aa2f7, bg #1a1b26, text #c0caf5) отличаются, в IDE светлой темы нет. Переход лендинг -> IDE это визуальный скачок и разная семантика цветов (зелёный #16a34a против #9ece6a).

### 2.5 Закон Постела (будь либеральным к вводу)

Измерения/находки:

1. Поле "Имя": `pattern="[A-Za-zА-Яа-яЁё' \-]{2,60}"`. Диапазон А-я это U+0410-U+044F. **Белорусские буквы Ў (U+040E), ў (U+045E), І (U+0406), і (U+0456) в него не входят**. Для проекта БГУИР (Минск) это реальная ошибка: имена "Ксения" проходят, а "Юлія", "Ілья", "Ўладзімір" отклоняются. Не проходят также типографский апостроф ’, умлауты и диакритика (Zoë, Łukasz), составные имена с точкой.
2. Сообщение об ошибке при этом говорит "содержит цифры и знаки", то есть неверно описывает причину для белорусской буквы.
3. Email: `type=email` + maxlength, хорошо. Нет обрезки пробелов и приведения регистра.
4. Размер команды: `type=number` с `value=0`, `min=0`, `max=500`, `step=1`. Дробь "2,5" будет молча отвергнута; допустим 0 по умолчанию (поле предзаполнено, пользователь может отправить, не прочитав).
5. Форма `method="get" action="#waitlist"`: данные уйдут в URL (имя, email, комментарий в query string, попадут в историю, логи, Referer). Это нарушение правил приватности и отсутствие явной обработки.

Исправления:

- `pattern="[\p{L}\p{M}' ’.\-]{2,60}"` с атрибутом `pattern` в режиме Unicode (`v` флаг поддерживается современными браузерами) либо убрать pattern и оставить `minlength=2`, а проверку делать на сервере. Сообщение: "Введите имя (от 2 символов)".
- Форма `method="post"`, на клиенте `fetch` + состояние успеха на месте формы.
- Обрезать пробелы (`value.trim()`), принимать запятую в числах, для команды использовать `select` с вариантами "Один / 2-5 / 6-20 / 21+" (меньше ошибок ввода).

### 2.6 Закон Теслера (сохранение сложности)

Что сделано хорошо: сложность нотаций забирают валидатор, шаблоны ("Получить шаблон ..."), подсказки и AI-режимы "Написать / Исправить". Сообщения об ошибках формы объясняют, что не так, и дают пример ("например «Ксения»"). В коде макета ошибка E003 содержит причину.

Что перекладывается на пользователя:

1. В DSL-примере IDEF0 дублируется информация: `version "A-0"` + `box A0 { node_number: "A-0" }` + заголовок. Номер узла должен вычисляться из `box A0`.
2. Нотацию пользователь выбирает три раза: в селекте сайдбара, в первой строке кода `notation idef0`, в имени папки. Источник истины один, остальное вывод.
3. Для не-программистов обещан "режим редактирования кликами", но это "планируется" (FAQ). Лендинг ведёт студентов-аналитиков в продукт, который сейчас требует писать код. Это честно написано, но стоит вынести ожидаемую дату или вариант "начните с шаблона".
4. Ошибка E003 в макете показана как комментарий в конце строки. Нет быстрого исправления (кнопка "Добавить role").

Исправления: вывод нотации из `notation`; автогенерация `node_number`; `quick fix` для частых ошибок (E003: "Добавить role: ..." по клику).

### 2.7 Эффект фон Ресторф (выделяется отличающееся)

Измерения:

- Синий акцент (#7aa2f7 в IDE, #2563eb на лендинге) выполняет 7 ролей: основная кнопка, активная вкладка импорта, активный режим AI, подчёркивание активной вкладки, логотип (градиент), аватар, **сплошная полоса статус-бара 22 px на всю ширину**. Статус-бар самый широкий насыщенный блок на экране, что противоречит его вторичной роли.
- Два "основных" синих CTA на дашборде: "Сгенерировать" и "Попробовать Pro" плюс активная вкладка "GitHub" той же заливки.
- "Новый проект" (самое частое действие дашборда) нарисован пунктиром цветом `--tx-3` (#3b4261), контраст около 1.7:1 с фоном, то есть он наименее заметен из трёх карточек.
- Run (зелёный, единственный зелёный CTA) по умолчанию disabled (`--border-hi`), то есть выделяющий элемент на старте экрана не работает.
- Лендинг: Free/Pro плашки одинаковы, рекомендуемый план не выделен.

Исправления:

1. Статус-бар: фон `--surface`, синий только для индикатора ошибок/подключения.
2. Один основной CTA на экран дашборда: "Новый проект" сделать заполненной карточкой/кнопкой в шапке с подписью; "Сгенерировать" перевести в outline; баннер Pro в ghost/outline либо вторичный.
3. Run: в состоянии disabled оставлять зелёную рамку и подпись "2 ошибки", чтобы кнопка читалась как "почти готово", а не как мёртвая.
4. Тарифы: Pro выделить рамкой primary и бейджем "Скоро", Free оставить нейтральным.

### 2.8 Aesthetic-Usability (красивое воспринимается как удобное)

Плюсы: токены дисциплинированы: сетка 8 px (8/16/24/48), шкала H1 48/56 - H3 20/28, 16/24 основной, Inter + JetBrains Mono, радиусы по правилу концентричности (18 - 4 = 14), единые тени, тёмная и светлая палитры с токенами `link` и `muted`. Макет IDE выглядит цельно и профессионально.

Минусы (влияют на воспринимаемую удобность):

1. Контраст `--tx-3` #3b4261 на фоне #1a1b26 = **1.74:1** (расчёт по WCAG), используется для номеров строк, меток разделов, времени активности, плейсхолдера поиска, "Новый проект". `--tx-2` #7982a9 на карточке #24283b = **3.87:1** при размере 11-12 px (норма 4.5:1). Светлая тема: `muted` #6b7285 на #f8f9fc около 4.5:1 (на пределе); зелёный #16a34a с белым текстом около 3.3:1 (не подходит для текста кнопки).
2. 11-px шрифт в 20+ местах (`--f-xs`), включая вкладки, дерево, диагностику, статус-бар.
3. Текущий лендинг без CSS: визуальный слой, который должен привлекать, отсутствует.
4. Прототип ссылается на Google Fonts (в `<head>` макета); без сети шрифт откатится на `system-ui`, метрики поедут.

Исправления: `--tx-3` довести до >= #6a7299 (>= 3:1 для декоративного, а для информативного использовать `--tx-2`); `--tx-2` осветлить до #8f98c0 (>= 4.5:1 на `--card`); `--f-xs` 12 px; для зелёного фона кнопки брать тёмный текст (#0b1a0f).

### 2.9 Закон Доэрти (отклик менее 400 мс)

Измерения:

- Переходы в макете 150-200 мс (`transition: all .15s`, `toastIn .2s`, `slideUp .15s`): в пределах нормы.
- Автозакрытие тоста 2 с (JS строка 1433).
- Run блокируется при ошибках; причина только в `title` (строки 1394-1398), то есть невидима на тач-устройствах и при навигации с клавиатуры без hover.
- Лендинг заявляет "Холст обновляется сразу" (шаг 2), а в IDE есть кнопка Run (⌘↵). Если нужен ручной запуск, обещание нарушено; если перерисовка живая, Run лишний или должен называться "Экспорт/Проверить".
- Форма waitlist: `action="#waitlist" method="get"`, JS пока 62 байта: нажатие "Отправить" перезагрузит страницу к тому же якорю без подтверждения. Нет состояния загрузки и успеха, а значит нет обратной связи вообще.
- Нет скелетонов/индикатора для генерации из GitHub-репозитория (Beta импорт кода), хотя операция заведомо долгая.

Исправления: показывать причину блокировки Run текстом рядом ("2 ошибки: E003, E001", клик переходит к первой); живая перерисовка с debounce 250 мс и индикатор "Проверка..." после 400 мс; форма с `aria-live` статусом "Отправляем..." -> "Готово, письмо придёт на ...".

### 2.10 Близость (Proximity)

Хорошо: fieldset с legend группируют контакты и проект; hint закреплён под полем (`aria-describedby`); в карточках иконка-заголовок-текст-ссылка вертикальным стеком; тулбар IDE разделён `tool-sep` на группы (история/экспорт; сетка/Run).

Плохо:

1. Шапка (прототип): зазоры между пунктами 28/28/44/22 px (495 -> 539 между "Как это работает" и "Тарифы" больше остальных), а на планшете FAQ и CTA разделены 7 px, то есть CTA читается как пункт меню.
2. Лендинг: язык, тема и CTA находятся в одном блоке `header__tools` рядом друг с другом, хотя это действия разной важности (настройка vs. конверсия).
3. IDE: тулбар холста смешивает масштаб, подпись "Бидир. подсветка: Вкл" и бейджи нотации в одну линию 5 px/6 px зазора; тост ("a0-context.dsl успешно сохранено") в screenshot перекрывает чип "Pro: 1/нед".
4. В карточках дашборда "изменён 2 ч. назад" и "4 файла" имеют одинаковый стиль, без разделителей.

Исправления: единая шкала зазоров 8/16/24; блок настроек (язык, тема) отделить от CTA 24+ px или перенести в подвал; тост поднять выше нижней панели (bottom: 40px -> 64 px) и не перекрывать чипы.

### 2.11 Сходство (Similarity)

- Бейджи (blue/green/purple/yellow/red/cyan) назначены по нотации и по статусу одновременно: IDEF0 синий, ERD зелёный (нотации), Free зелёный (тариф), Beta фиолетовый (статус), "Вкл" зелёный (состояние). Зелёный означает три разных вещи.
- `stat-delta` у "5 из 5 лимит Free" окрашен зелёным со стрелкой вверх (положительное), хотя лимит исчерпан. Должен быть жёлтым/красным. Рядом "3 Активных проекта" с лимитом "5 из 5" это ещё и противоречие данных (3 != 5).
- Хорошо: `.btn-primary/-outline/-ghost` единообразны, радиусы по токенам, иконки одного стиля (fill currentColor).
- Несогласованность названий: "Пример страницы ошибки 500" / "FAQ" vs "Вопросы и ответы" (шапка использует FAQ, заголовок и подвал "Вопросы и ответы").

Исправления: закрепить палитру: нотация = нейтральный бейдж с иконкой; статус = семантические цвета; лимит полный = warning.

### 2.12 Общая область (Common Region)

Сильная сторона: каждая смысловая группа в своём контейнере (карточка, fieldset, плашка плана, bento-блок, модальное окно), границы 1 px + радиус. Модалка закрытия вкладки сделана корректно (`--r-xl`, заголовок, текст, правая группа кнопок). Единственное замечание: блок-"Активность" и "Импорт кода" в одной bento-строке имеют разную высоту содержимого, нижний край карточки импорта обрезается (home screenshot, тост перекрывает), стоит задать `align-items:stretch` и `max-height` с прокруткой.

### 2.13 Позиция в списке (Serial Position)

Шапка лендинга: первое "Нотации", последнее (справа) CTA "В бету": сильные позиции заняты правильно. "Тарифы" и "FAQ" на 4-5 месте (середина/конец) нормально. Минус: "Для кого" в середине списка без самостоятельного значения. Подвал: первые пункты хороши, последний пункт "English version" (важный для i18n) стоит после технической ссылки "Пример страницы ошибки 500". В IDE последняя вкладка нижней панели "Результат" это важнейшая информация, а стоит в конце; поставить "Диагностика" первой (уже так) и "Результат" второй.

### 2.14 Пик-финал (Peak-End)

Пик: hero-блок "код -> схема" (показывает ценность сразу). Финал лендинга: длинная форма (6 полей), после неё подвал с ссылкой на страницу ошибки 500. Нет финального состояния "Вы в списке", благодарности, ожидаемого срока. Финал в IDE: тост "успешно сохранено" хороший, но Run disabled с ошибкой в верхней точке пути (первые секунды работы пользователь видит красную ошибку и серую кнопку).

Исправления: экран успеха после отправки с обещанием ("Письмо придёт в течение 7 дней, пока откройте шаблон IDEF0"); пример первой диаграммы в IDE без ошибок (E003 убрать из стартового шаблона, оставить как обучающий сценарий).

### 2.15 Эффект цели-градиента и Зейгарник

Форма: нет индикатора "Шаг 1 из 2", но она короткая. Для IDE: лимиты показаны (5 из 5, 12 из 20), но нет следующего шага (как расширить). Для лендинга нет примера "первая диаграмма за 60 секунд" как цели. Предложение: добавить в Hero счётчик "~2 минуты до первой схемы" и в дашборд чек-лист онбординга (создать проект -> написать код -> экспорт) с 3 шагами.

### 2.16 Закон Парето

80% ценности (текст -> диаграмма -> экспорт) показано в hero и в 3 шагах: хорошо. Но экранов в макете три, из них "UI Styles" (стили интерфейса) и дашборд с 4 плитками статистики не поддерживают основной сценарий. Для MVP дашборд можно сократить до списка проектов и кнопки "Новый проект", статистику и активность убрать за сворачиваемый блок.
