# Чеклист оформления курсовой и структура пояснительной записки (уровень В, справочный материал)

Источник: правила, которые передала владелец (чат, 2026-11-27). Нормативная база: СТП 01–2024 (разделы 2–3 распространяются на курсовые) и ГОСТ 2.105–95, 2.106–96, 2.004–88, 7.1–2003, 7.9–95.

Этот документ хранится целиком для будущей курсовой. К отчётам по ПЗ и ЛР применяется только то, что отмечено уровнем А или Б в `docs/notes/20-report-rules-stp-2024.md`. Расхождения чеклиста с текстом СТП перечислены там же, при расхождении приоритет у СТП (а для ПЗ и ЛР у требований преподавателя).

## Чеклист

### A. Общие

- Оформление по СТП 01–2024 (разд. 2–3) и ГОСТ.
- Поля, заголовки, номер страницы по приложению Л; формулы по приложению М; иллюстрация между абзацами по приложению Н; приложение по приложению П; единицы приложение С, соотношения Т, алфавиты У.
- Записка подшита в скоросшиватель.

### B. Объём и структура (курсовая)

- 20–30 страниц без приложений (допуск до 33).
- Порядок: титул, задание, содержание, перечень сокращений, введение, главы 1–3, заключение, список источников, приложения.
- Содержание автоматическое по стилям «Заголовок 1/2/3».
- Каждая часть с новой страницы; есть план-проспект.

### C. Титул и задание

- Титул по образцу кафедры; кафедра и факультет без сокращений; тема прописными буквами точно как в задании.
- Подписи студента, руководителя, заведующего кафедрой, даты.
- Номер страницы на титуле не ставится, но лист входит в счёт.
- Шифр ПЗ курсовой: `БГУИР КР 6-05-0612-03 XX ПЗ`.
- Задание по шаблону кафедры, п. 5 «Графическая часть не предусмотрена»; реферат не требуется.
- Тема: одно предложение, без знаков препинания, без слов «разработка» и «проектирование», без названий языков, СУБД и фреймворков.

### D. Текст (п. 2.3 СТП)

- Times New Roman 14 пт, интервал 1,15, абзацный отступ 1,25 см, выравнивание по ширине.
- Заголовки частей («Содержание», «Введение», «Заключение», «Список использованных источников», «Приложение»): по центру, ПРОПИСНЫМИ, 16 пт, интервал 12 пт сверху и снизу, без номера.
- Заголовки разделов: ПРОПИСНЫМИ 16 пт, с отступом 1,25 см по левому краю, без переносов, каждый раздел с новой страницы.
- Заголовки подразделов: с прописной буквы, 14 пт (сверху 12 пт, снизу 6 пт). Заголовки пунктов: 14 пт (сверху 6 пт, снизу 0).
- Все заголовки полужирные, без точки в конце; многострочные с одинарным интервалом; заголовок не оставлять в конце страницы.
- Номер страницы справа внизу на 17 мм от нижнего края; титул и задание без номера, нумерация с содержания.
- Неразрывный пробел перед единицами и знаком «%»; тире «—»; кавычки «ёлочки»; десятичная запятая; диапазоны «20–30».
- Сокращения расшифровывать при первом упоминании.

### E. Рисунки и таблицы

- Нумерация по разделам («Рисунок 1.1»), в приложениях «А.1».
- Подпись под рисунком по центру без отступа: «Рисунок 2.3 – Название»; интервал сверху 6 пт, снизу 12 пт; рисунок отделяют пустой строкой.
- Ссылка в тексте идёт до объекта.
- Таблицы по п. 2.6: название над таблицей по левому краю «Таблица 2.1 – Название»; интервал сверху 12 пт, снизу 6 пт; таблица не разрывается (при необходимости «Продолжение таблицы 2.1»); единицы в шапке; шрифт 12 пт, одинарный интервал; пустые ячейки «—».
- Скриншоты: 3–4 в тексте, полные в приложении В; единый стиль (один браузер, окно 1280×720, русский интерфейс); читаемость в чёрно-белом виде.

### F. Формулы и листинги

- Формулы по центру, номер справа в скобках, отступ 6 пт; нумерация по разделам (2.1); пояснение символов после слова «где» без отступа.
- Листинги текстом: Courier New 12 пт, одинарный интервал, с номером и заголовком «Листинг 2.1 – …» и ссылкой в тексте.
- Рисунком оформляют только скриншоты IDE и консоли.
- Без подсветки синтаксиса, длинные строки не переносить, комментарии на русском, без нумерации строк, пропуск обозначать «…».
- Фрагмент в тексте не более одной страницы, полные листинги в приложении А.

### G. Источники

- 15–20 источников; книги не старше 5 лет, статьи 2022–2026.
- Алфавитный порядок (нормативные документы первыми); оформление по п. 2.8 СТП и ГОСТ 7.1–2003.
- СТП: «Стандарт предприятия. Дипломные проекты (работы). Общие требования : СТП 01–2024. – Минск : БГУИР, 2024.»
- Электронные ресурсы с URL и датой обращения.
- Не включать Википедию, help-системы, поисковики, конспекты лекций.
- Ссылки в тексте «[12]»; все источники имеют ссылки в тексте и наоборот.

### H. Приложения

- А листинги, Б исходные данные для тестирования, В полные скриншоты, Г бесплатные сервисы.
- Буквенная нумерация без букв Ё, З, Й, О, Ч, Ъ, Ы, Ь.
- Заголовок из трёх строк: «ПРИЛОЖЕНИЕ А» / «(обязательное)» / название; по центру, с новой страницы.
- На каждое приложение есть ссылка в тексте.
- Приложение Б: тестовые учётные записи, примеры JSON-запросов, seed-данные, граничные и некорректные данные.
- Приложение Г: хостинг Netlify и GitHub Pages, Render и Supabase, Coolify; БД Supabase, Neon, Render, MongoDB Atlas; CI/CD GitHub Actions; мониторинг GlitchTip; аналитика Яндекс.Метрика, Rybbit, Plausible, с бесплатными лимитами и санкционными ограничениями.

### I. Веб-специфика (курсовая)

- Графическая часть на А1 не требуется.
- Use Case, ER и архитектура рисунками в главе 1; UML и ER в draw.io, PNG 300 dpi; UML 2.5 для Use Case, нотация Crow's Foot для ER.
- «3 основных модуля» = 3 CRUD-сущности плюс аутентификация.
- Защита: демонстрация 5–7 минут; критерии: работоспособность 50 %, оформление 20 %, защита 30 %.
- Презентация 8–10 слайдов, шрифт не менее 20 пт, без анимации; резервное видео демонстрации 2–3 минуты.

### J. Процедура

- Срок сдачи за 2 недели до зачётной недели; контрольные точки 30 %, 60 %, 90 %, 100 %.
- Самопроверка по разделу K обязательна.
- ИИ-инструменты допускаются при понимании кода; в ПЗ указать, какие и для чего.
- Оригинальность текста не ниже 50 %.
- Электронная версия: PDF плюс ссылка на репозиторий; презентация PDF или PPTX; видео MP4.

### K. Финальная проверка

- Оглавление обновлено (F9); стили «Заголовок 1/2/3».
- Титул и задание без номера, нумерация с содержания.
- Перекрёстные ссылки через «Вставка → Перекрёстная ссылка».
- Нет случайных шрифтов Calibri и Arial.
- Проверены невидимые символы: лишние пробелы, пустые абзацы, разрывы строк.
- PDF: рисунки не обрезаны, таблицы не разъехались, номера страниц на месте, приложения с новой страницы.

## Структура пояснительной записки курсовой «Разработка веб-приложения»

Объём 20–30 страниц без приложений.

1. Титульный лист.
2. Задание.
3. Содержание (автоматическое).
4. Перечень условных обозначений (необязательно): API, SPA, JSX, REST, JWT, ORM, CI/CD, деплой.
5. Введение, 1–1,5 страницы: актуальность, цель, задачи (1–5), объект и предмет, практическая значимость, структура работы.
6. Глава 1 «Анализ и проектирование системы», 7–8 страниц:
   - 1.1 Анализ и требования FR/NFR, 2 страницы.
   - 1.2 Архитектура, 3 страницы: Use Case, схема «Клиент – Сервер – БД» или C4 уровня 1, таблица эндпоинтов REST.
   - 1.3 ER-диаграмма на 4–6 сущностей, 2 страницы.
7. Глава 2 «Реализация веб-приложения», 12–13 страниц:
   - 2.1 Стек и обоснование, 1,5 страницы.
   - 2.2 Backend, 4 страницы: структура, модели Sequelize или Mongoose, REST API CRUD с валидацией, JWT, ошибки и безопасность (helmet, cors, bcrypt).
   - 2.3 Frontend, 4 страницы: структура, React Router, компоненты и состояние, взаимодействие с сервером, адаптивный интерфейс.
   - 2.4 Интеграция, Docker, деплой, тестирование, 2,5 страницы.
8. Глава 3 «Руководство пользователя и тестирование», 4–5 страниц:
   - 3.1 Руководство пользователя, 2,5 страницы.
   - 3.2 Контрольные примеры таблицей, 1,5 страницы.
9. Заключение, 1 страница.
10. Список источников, 1 страница (15–20 источников).
11. Приложения (не входят в объём): А листинги; Б исходные данные для тестирования; В полные скриншоты; Г рекомендации по бесплатным сервисам (хостинг Netlify и GitHub Pages, Render и Supabase, Coolify; БД Supabase, Neon, Render, MongoDB Atlas; CI/CD GitHub Actions; мониторинг GlitchTip; аналитика Яндекс.Метрика, Rybbit, Plausible).
