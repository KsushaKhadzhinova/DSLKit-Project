# Допы преподавателя: поломки «вживую», потоки и понятные ошибки

Дата: 24 октября 2026. Основа: новый доп, который передал Вадим («удаляет файл лога и хочет, чтобы ошибка была пользовательская», «работу с файлом делать через поток»), прежние рассказы группы (огромные числа, остановка базы, страница 500 реальным сбоем) и `notes/07-possible-teacher-extras.md`. Это прогноз по его стилю, не его слова.

## 1 Что за стиль

Преподаватель на защите **ломает работающую программу руками** и смотрит, что увидит человек:

1. удаляет или портит файл, таблицу, базу, `.env`;
2. останавливает базу, сервер, сеть;
3. вводит огромные числа, пустые и странные строки;
4. просит объяснить код и дописать мелочь при нём.

Ему нужны три вещи: программа **не падает**, человек видит **понятную страницу** (что случилось, почему, что делать), в коде использованы **нужные приёмы** (потоки, `async`, обработка событий `error`).

## 2 Новый доп: журнал в файл, поток, удалённый файл

В условии для нечётных вариантов журнал пишется в файл, у нас (вариант 26, чётный) в таблицу. Доп сделан для нашего варианта в ПЗ1 (ветка `pz21`):

| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |

| Удалил файл лога: ошибка понятная | Страница «The log file was not found»: что это, почему, как исправить (нажать «Export the log to a file»), без путей и без текста исключений. Код 404                                     | `src/errors.js`, `views/500.ejs`                            |

| Обрыв посреди передачи            | Соединение закрывается, причина пишется в консоль сервера, сервер живёт                                                                                                                   | `sendLogFile`, тест «failure in the middle of the transfer» |

| Удалил базу журнала               | Страница «Server error» с тремя частями, сервер при следующем обращении создаёт файл заново                                                                                               | `src/data/requestLog.js`                                    |

Проверка: `test/log-file.test.js`, 13 тестов. Показ вживую: на странице `/log?auth=1` нажать «Export the log to a file», удалить файл `data/request-log.txt`, нажать «Download the file».

Что сказать, если спросят «почему поток»: файл может быть большим, поток читает и отдаёт кусками и не держит всё в памяти; `pipeline` сам закрывает потоки при ошибке и передаёт её в `catch`, поэтому нет «висящих» дескрипторов; ответ браузеру нельзя заменить страницей, когда он уже начался, поэтому проверка наличия файла идёт до заголовков.

## 4 Заготовки на потоки (Node.js)

Все примеры можно показать за минуту и объяснить словами «поток читает кусками, `pipeline` закрывает всё при ошибке».

```js
import { createReadStream, createWriteStream } from 'node:fs';
import { createInterface } from 'node:readline';
import { Transform } from 'node:stream';
import { pipeline } from 'node:stream/promises';
import { createGzip } from 'node:zlib';

// 1. Копирование файла потоком.
await pipeline(createReadStream('in.log'), createWriteStream('out.log'));

// 2. Чтение большого файла построчно, не загружая его целиком.
const lines = createInterface({ input: createReadStream('request-log.txt'), crlfDelay: Infinity });
for await (const line of lines) console.log(line);

// 3. Преобразование на лету: только строки с ошибками, в верхнем регистре.
const onlyErrors = new Transform({
  transform(chunk, encoding, done) {
    const kept = chunk
      .toString()
      .split('\n')
      .filter((line) => /\t(4|5)\d\d\t/.test(line));
    done(null, kept.map((line) => `${line.toUpperCase()}\n`).join(''));
  },
});
await pipeline(createReadStream('request-log.txt'), onlyErrors, createWriteStream('errors.txt'));

// 4. Сжатие потоком.
await pipeline(createReadStream('request-log.txt'), createGzip(), createWriteStream('request-log.txt.gz'));

// 5. Ответ браузеру файлом, с понятной ошибкой, если файла нет (как в logFile.js).
app.get('/download', (req, res) => {
  const input = createReadStream(file);
  input.once('error', () => res.status(404).send('Файл не найден. Создайте его кнопкой «Экспорт».'));
  input.once('open', () => {
    res.set('Content-Disposition', 'attachment; filename="log.txt"');
    pipeline(input, res).catch(() => res.destroy());
  });
});

// 6. Добавление в конец файла (журнал), поток открыт один раз.
const out = createWriteStream('app.log', { flags: 'a' });
out.on('error', (error) => console.error('журнал недоступен:', error.code));
out.write(`${new Date().toISOString()} запрос\n`);
```

Типичные вопросы: чем поток лучше `readFile` (память); что такое `highWaterMark` (размер порции, по умолчанию 64 КБ для файлов); зачем событие `error` (без обработчика ошибка потока роняет процесс); чем `pipeline` лучше `.pipe()` (закрывает потоки и передаёт ошибку); что такое обратное давление (`write` возвращает `false`, пишущий ждёт `drain`).

## 5 Как закрывать новые допы

1. Сначала спросить, **что именно сломали** и **что человек должен увидеть**.
2. Ответ на сбой всегда из трёх частей: что случилось, почему, что сделать. Нового текста не придумывать: добавить запись в каталог ошибок (`src/errors.js` в ПЗ1, `errorCatalog.js` в клиентах).
3. Исключение не показывать и пути не раскрывать: причина идёт в консоль сервера.
4. Каждый разбор сопровождать тестом: сломать так же, как преподаватель, и проверить страницу.
