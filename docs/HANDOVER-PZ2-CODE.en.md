# Handover: practical 2 code (REST API), variant 26

Folder `part-2/pz-02-rest-api`, work branch `pz22`, published to `wip/t37-pz2-code`. The report was not written or changed by this task, except that `report.md` and `report.en.md` were rebuilt from their templates because they embed source listings.

## Done

- Request journal in a database table (`request_log`, SQLite): written before the request runs; if the write fails the answer is 500 `journal_unavailable` and the action is not carried out (checked for POST, PUT, PATCH, DELETE and under parallel load).
- Request ID: every answer carries an `X-Request-Id` header (always generated by the server); the same value is in the error body, in the journal table (`request_id`) and in the server log line. An old journal file without that column is upgraded automatically.
- Detailed errors: JSON `{ error: { code, message, title, description, requestId, details? } }`; for a browser (the `Accept` header prefers HTML) a styled page with "What happened", "Likely cause", "What to do" and the Request ID. Texts: `src/error-catalog.js`, page: `src/error-page.js`. Statuses 400, 403, 404, 405, 406, 409, 412, 413, 415, 429, 500. No route answers 403 (the API has no authorization); the 403 page is described and covered by a test.
- PATCH and DELETE: conditional requests with `If-Match` (412), 404 for an already deleted record, 409 for a record with dependants; walk-through in `docs/study/36-PZ2-PATCH-DELETE.en.md`.
- Races: "create a child while the administrator deletes the parent" gives 201/409/404 and never a 5xx or an orphan (`test/consistency.test.js`, `test/break.test.js`).
- Input validation and limits in `limits.json`; tests for huge values, whitespace, invisible characters, SQL and HTML injection, extra keys, out-of-range numbers.
- OpenAPI and `API.generated.*.md` now match the code (409 for a missing parent, 412).

## How to reproduce the journal failure (for the page-500 screenshot)

1. `$env:JOURNAL_FILE = "demo.sqlite"; $env:PORT = 4210; node src/server.js`
2. In another window: `node tools/break-journal.mjs demo.sqlite` (drops the journal table under the running server).
3. Open `http://localhost:4210/api/users` in a browser: the 500 page "Request journal unavailable" with a Request ID; no row is written, the action is not carried out.
4. Restore: `node tools/break-journal.mjs demo.sqlite --restore`.
