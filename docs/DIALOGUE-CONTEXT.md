# Контекст диалога с владельцем (для продолжающего работу)

Сжатая хронология требований и решений владельца за все сессии. Формулировки владельца переданы по смыслу, ключевые фразы дословно.

## Цель

Закончить все 8 лабораторных Части 1 «ИТиВП» (потом Часть 2 из `E:\ИТиВП\Часть 2`), строго проверить по условиям и теории, всё закоммитить и выложить на GitHub, чтобы новый ИИ мог продолжить с полным контекстом. Работу должны проверять независимые помощники («максимально дотошно и внимательно»), с оценками и мнениями по UX, юзабилити, адаптивности, удобству, доступности; три отдельных тестировщика (ручные и автотесты).

## Решения и запреты владельца

- Коммиты только от её имени, без соавторства ИИ и меток об ИИ («коммиты я запрещаю тебе делать от твоего имени и также добавлять свое соавторство или метки что это было агенерированно ии или есть авторство ии»). Английские сообщения коммитов.
- Каждая часть, задание и лабораторная сначала в отдельную ветку, потом в `main`.
- Тема проекта: SaaS, «диаграммы как код»; **преподаватель тему одобрил**. Домен купит позже: «куплю потом работай пока с тем что есть».
- Сайт: главная показывает сильные стороны продукта без сравнения с конкурентами; порядок нотаций UML, BPMN, ERD, DFD, IDEF0, сети Петри; акцент синий `#2563eb`; светлая тема первой; русский первым, затем английский; золотое сечение; mobile-first; БЭМ; «ВСЕ ЭЛЕМЕНТЫ ДОЛЖНЫ БЫТЬ СТИЛИ» (у абсолютно всех элементов есть CSS).
- Главная: нужна большая кнопка «Создать диаграмму» на первом экране. **Не нравятся**: упрощение дизайна главной и «иишный сине-фиолетовый градиент» на этой кнопке (градиент убран). A/B-тест первого экрана: выбран вариант **B** (основная синяя кнопка без панели, точечная сетка на фоне, плотный заголовок) для десктопа и телефона.
- Выбор движка генерации диаграмм делается **в настройках сайта**, а не во время разбора диаграммы.
- Отчёты: пока только Markdown (RU и EN), без PDF и титульного листа. **Ответы на контрольные вопросы в отчётах не нужны.** README и шаблоны отчётов к каждой работе всегда.
- Скриншоты и инструменты делать самой системой: «сделай сам», включая DevTools, HAR в настоящем Chrome, React Developer Tools. Ключи и данные брать по условиям её проекта и задания.
- Макеты: мультиязычные (RU первым, EN), мокапы и вайрфреймы по модулям и устройствам (мобильный, планшет, десктоп), отдельные элементы (кнопки, шрифты, цвета) с подписями, hex-кодами и метриками; мудборд со списком сайтов и приложений, послуживших вдохновением (Claude/Anthropic, Innowise, Mermaid, draw.io, diagrams.net, attio, framer, lovable, minimal.gallery, onepagelove, dribbble, wisepops, webflow); логотип проекта должен быть в Figma. Всё добавить в Figma (её браузер открыт ею, она вошла).
- Выкладывать код на сайты проверки из условий лабораторных (W3C HTML, CSS, Schema.org, Rich Results).
- Лимиты: на 80 процентов недельного лимита дойти до логической точки, закоммитить, обновить документы передачи и остановиться.
- Просьба 2026-10-15: показать подробные статусы в процентах по каждой работе и написать отчёт для нового ИИ (см. `PROGRESS-AND-HANDOVER.md`).
