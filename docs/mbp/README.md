## Оформление отчётов

Отчёты собираются в строгом режиме report-gen (`layout: strict` в `meta.yaml`):

- «Минск 2026» в последней строке титульного листа, «Выполнил» и «Проверил» по центру;
- названия разделов по левому краю, «ВЫВОДЫ» по центру;
- пробельная строка перед подписью таблицы, перед рисунком, перед подпунктом и после таблицы и рисунка; пробельная строка не бывает первой на странице (отступ абзаца, а не пустой абзац);
- после каждой таблицы и каждого рисунка стоит абзац текста;
- подпись и таблица, рисунок и подпись не разрываются; большая таблица делится на части с подписью «Продолжение таблицы N»;
- широкие диаграммы стоят на отдельной странице, повёрнутые на -90°, подпись справа читается снизу вверх;
- диаграммы не режутся на части.

PDF проверен визуально. DOCX собирается тем же режимом, но на этом компьютере нет Word, поэтому его вёрстка визуально не проверялась.

## Как проверено

Каждая диаграмма строится из одной модели и проверяется программой (`src`):

- IDEF0: один блок в A-0, от 3 до 6 блоков в A0, управление и выход у каждого блока, ступенька блоков, стороны подхода стрелок, совпадение 14 граничных стрелок A0 с A-0 по кодам ICOM;
- BPMN: правила методички для диаграмм «для людей» (типы задач, шлюзы XOR и AND, подписи выходов, потоки сообщений не у шлюзов, старт без входа, конец без выхода);
- EPC: 11 правил методички (чередование, операторы, число функций, связи);
- ССП: не более 25 целей, 1–3 показателя на цель, около 80 % нефинансовых, направление причинно-следственных связей, сила влияния из набора методички;
- вёрстка: наложение подписей, выход текста за фигуру, пересечение подписи со стрелкой, наклонные отрезки.

Файлы `.drawio` открыты в просмотрщике draw.io для проверки отображения нативных фигур BPMN и EPC. Линтер report-gen: 0 ошибок и 0 предупреждений для всех четырёх отчётов.
