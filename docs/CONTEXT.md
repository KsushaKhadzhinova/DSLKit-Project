## 3. Как работать с пользователем

- Делать по очереди: после каждой работы показать результат в браузере, задать вопросы и ждать «принято» или правки. Слияние в `main` только после принятия.
- Задавать много вопросов, но коротко и с вариантами. Если вопросы закрыты без ответа, действовать по рекомендованному варианту и сообщить об этом.
- Комментарии в коде не писать, лишнего кода не писать, подход ponytail (минимум кода, платформа и стандартная библиотека вперёд).
- Все работы покрыты тестами: порог 100 процентов строк, ветвей и функций в `npm test` для JavaScript, для HTML и CSS тест на каждый критерий оценки из условия.
- Учитывать все случаи: страницы ошибок с подробными пояснениями (400, 403, 404, 405, 500), проверка значений форм, обработка сбоев. Цель: преподаватель не должен найти, что добавить или поменять.
- Для визуальных проверок просить независимых помощников посмотреть скриншоты: искать наложения, обрезанный текст, пустые блоки. Такая проверка уже нашла реальные дефекты прототипов.
- К каждой ветке: README из 7 разделов (как запускать, архитектура, условие, термины, теория, рисунки и диаграммы, что делать пользователю), сиды данных, отчёты Markdown на русском и английском. Handover обновлять параллельно с работой, коммитить часто и пушить.

## 4. Требования преподавателя к отчётам

Они зашиты в `tools/lint-report.js` и проверяются тестами. Основные: заголовок «1 Цель работы» и раздел «Заключение», подписи «Рисунок N – Описание» и «Таблица N – Описание» с заглавной буквы, описание словами перед рисунком без скобок «(см. рис. 1)», код только в приложениях, рисунки не в приложениях, без слов «также» и «были», кавычки «ёлочки», ответы только на вопросы n−1, n, n+1 варианта (вариант 26: для списка из N вопросов индексы берутся по кругу, `tools/variant.js`). Для практических: чётный вариант логирует запросы в таблицу БД (нечётный в файл), страница 500 вместо текста на чёрном фоне, проверка полей формы (непустое, число не меньше 0, уникальное поле времени создания).

## 6. Среда и ловушки

- Windows 11, Git Bash и PowerShell, Node 24, Python 3.11, Chromium для Playwright 1.64.0 в `C:\Users\zheny\AppData\Local\ms-playwright`, расширения VS Code из ЛР2 уже стоят.
- Команда `cd` в Bash меняет рабочую папку сессии: каждую команду начинать с `cd "E:/DSLKit-Project"`.
- Python в Windows пишет файлы с CRLF в текстовом режиме: для файлов с шаблонами открывать с `newline=""`. В проекте `.gitattributes` задаёт LF.
- Обратные слеши в heredoc и аргументах инструментов правки могут превращаться в переводы строк: проверять результат, для таких правок использовать Edit.
- Кириллица в PDF: `pdftotext` теряет буквы, использовать PyMuPDF (`import pymupdf`).
- В Git Bash путь `/tmp` недоступен для Python Windows, временные файлы класть в папку scratchpad сессии.
- Figma: встроенный браузер открывает файл гостем, писать в него нельзя, вход за пользователя недопустим.
