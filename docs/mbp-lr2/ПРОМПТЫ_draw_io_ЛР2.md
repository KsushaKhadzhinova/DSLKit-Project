# ЛР2 МБП – промпты для BPMN-диаграмм (процесс «Написание и проверка DSL-кода», DSLKit)

Общий префикс: «Нарисуй диаграмму в нотации BPMN 2.0 (draw.io или Lucidchart): пулы и дорожки, события, задачи, шлюзы, объекты данных. Внешние участники показаны свёрнутыми пулами, взаимодействие между пулами только потоками сообщений (пунктир), задачи названы «глагол + существительное», события названы прошедшим временем, выходы из XOR подписаны «Да» и «Нет».»

## 1. Основная диаграмма
Пулы: «Пользователь» (свёрнутый, сверху), «DSLKit: написание и проверка DSL-кода» (открытый, две дорожки: «Веб-редактор», «Модуль проверки»), «Сервис рендеринга Kroki» (свёрнутый, снизу).
Дорожка «Веб-редактор»: старт с сообщением «Пользователь открыл редактор» → задача отправки «Показать нотации и шаблоны» → промежуточное событие с сообщением «Выбрана нотация» → «Создать заготовку кода» (создаёт объект «Заготовка кода») → задача получения «Принять код пользователя» (граничное событие-таймер «Прошло 30 минут» → «Сохранить черновик» → конец «Черновик сохранён») → XOR «Лимит тарифа превышен?»: «Да» → задача отправки «Предложить тариф Pro» → конец «Ввод отклонён»; «Нет» → «Отправить код на проверку».
Дорожка «Модуль проверки»: свёрнутый подпроцесс «Проверить код» → XOR «Код допустим?»: «Да» → «Сохранить проверенный код в проекте» (изменяет хранилище «База проектов») → конец с сообщением «Код передан на построение» (поток сообщений в пул Kroki); «Нет» → «Сформировать список ошибок» (создаёт объект «Список ошибок») → задача отправки «Показать ошибки и подсказки» (дорожка «Веб-редактор») → возврат к задаче «Принять код пользователя».
Потоки сообщений: от пользователя к событию старта, к промежуточному событию «Выбрана нотация» и к задаче «Принять код пользователя»; от задач «Показать нотации и шаблоны», «Предложить тариф Pro» и «Показать ошибки и подсказки» к пользователю.

## 2. Подпроцесс «Проверить код»
Один пул «Проверка кода» с дорожкой «Модуль проверки»: старт «Получен код на проверку» → параллельный шлюз AND (разделение) → задачи «Проверить синтаксис» и «Проверить правила нотации» → параллельный шлюз AND (слияние) → XOR «Ошибки найдены?»: «Да» → «Сформировать список ошибок» (создаёт объект «Список ошибок») → конец «Код отклонён»; «Нет» → конец «Код принят».
