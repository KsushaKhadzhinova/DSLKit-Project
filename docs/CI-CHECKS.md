# Проверки качества и CI

Английская версия: [`CI-CHECKS.en.md`](CI-CHECKS.en.md).

Ветвление: GitHub Flow и trunk-based. `main` всегда зелёный, каждое изменение идёт короткой веткой от `origin/main` через pull request.

## Что проверяется на каждый push и pull request

| Проверка                          | Где                                              | Что ломает сборку                                                                                                                                                                                           |
| --------------------------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ESLint (`npm run lint`)           | job `test`                                       | неопределённые и неиспользуемые имена, `var`, нестрогое сравнение, пустые блоки, ошибки регулярных выражений                                                                                                |
| Prettier (`npm run format:check`) | job `test`                                       | любое расхождение с форматом                                                                                                                                                                                |
| Тесты сайта (`npm test`)          | job `test`                                       | падение теста или покрытие ниже 100% строк, ветвей и функций; в покрытие явно входят все файлы `site/js` и `tools`, даже те, что тесты не загрузили                                                         |
| `npm audit --omit=dev`            | job `test`                                       | уязвимость уровня high в библиотеках, которые доходят до пользователя                                                                                                                                       |
| Папки работ (`part-2/*`)          | job `work-folders`, 12 папок параллельно         | тесты каждой лабораторной и практической, отчёты, `npm audit`                                                                                                                                               |
| Сборка сайта                      | job `build`                                      | ошибка сборки                                                                                                                                                                                               |
| React-приложение                  | job `react`                                      | тесты и сборка                                                                                                                                                                                              |
| e2e в браузере (Playwright)       | job `e2e`                                        | любой сценарий не в состоянии Passed или грязное дерево после прогона                                                                                                                                       |
| CodeQL (`security-and-quality`)   | `security.yml`, также раз в неделю               | находки статического анализа безопасности                                                                                                                                                                   |
| Dependency review                 | `security.yml`, только pull request              | новая зависимость с уязвимостью high                                                                                                                                                                        |
| Утечки памяти                     | `leaks.yml`, pull request, раз в неделю, вручную | куча сервера после 2000 запросов или 500 сокетов выросла выше предела, после `close()` остался открытый дескриптор, редактор или список проектов оставили узлы DOM, слушатели или документы после 50 циклов |

Локально всё сразу: `npm run verify` (lint, format, тесты).

## Проверки утечек памяти

Отдельно от `npm test`: они медленные и требуют `node --expose-gc`. Workflow `.github/workflows/leaks.yml` запускает их на pull request, каждый понедельник и вручную.

- Node: `npm run test:leaks` в `part-2/lab-01-node-server`, `lab-02-sequelize`, `lab-03-auth`, `lab-06-mongodb`, `lab-07-websocket`, `pz-01-middleware-ejs`, `pz-02-rest-api` (матрица из 7 заданий). Каждый тест поднимает настоящее приложение в своём процессе и шлёт 2000 запросов (чтения, создание и удаление, отклонённое тело, 404); в работе 7 ещё 500 клиентов-сокетов подключаются, пишут и отключаются. Помощник `tools/leaks/heap-growth.js` (покрыт тестами на 100%) принудительно запускает сборку мусора, читает `heapUsed` после прогрева и ещё в 5 точках и сравнивает последнее значение с первым. После `server.close()` тест сравнивает `process.getActiveResourcesInfo()` со списком до запуска: не должно остаться ни сокета, ни сервера, ни таймера. В работе 7 ещё проверяется, что на сервере не остались клиенты, сокеты, комнаты и лишние слушатели.
- Браузер: `python testing-course/full/leaks-e2e.py` (Chromium или Edge, один браузер) 50 раз открывает и закрывает пять панелей редактора, переключает все нотации, перерисовывает диаграмму и открывает и отменяет диалоги переименования и удаления в списке проектов. До и после собирается мусор, а у протокола DevTools запрашиваются `Memory.getDOMCounters` (узлы, слушатели, документы) и `Runtime.getHeapUsage`.
- `LEAK_ITERATIONS`, `LEAK_WARMUP`, `LEAK_SOCKETS` и `LEAK_CYCLES` меняют размеры для быстрой пробы на своей машине.

Пределы: удвоенный наибольший рост из трёх запусков (Windows, Node 24, Edge), но не ниже уровня шума:

| Проверка                       | Измерено (наибольшее из 3 запусков)                        | Предел                                        |
| ------------------------------ | ---------------------------------------------------------- | --------------------------------------------- |
| работа 1, 2000 запросов        | 202 КБ                                                     | 500 КБ                                        |
| работы 2 и 3, практическая 1   | ниже 0 (куча после прогона меньше)                         | 500 КБ                                        |
| работа 6                       | 232 КБ                                                     | 500 КБ                                        |
| работа 7, 2000 HTTP-запросов   | 390 КБ                                                     | 800 КБ                                        |
| работа 7, 500 клиентов-сокетов | 280 КБ (история хранит 50 сообщений на комнату)            | 600 КБ                                        |
| практическая 2                 | 238 КБ                                                     | 500 КБ                                        |
| редактор и список (браузер)    | 32 узла DOM (один раз), 0 слушателей, 0 документов, 195 КБ | 100 узлов, 20 слушателей, 0 документов, 1 МиБ |

Рост, который не повторяется, не утечка: работа 7 на 500 сокетах оставляет около 270 КБ, а на 2000 сокетах 440 КБ, потому что история чата ограничена и заполняется первой. Настоящих утечек найдено: нет. Нарочно добавленная утечка (1 КБ на запрос, слушатель за цикл) роняет тесты, то есть проверки реагируют.

## Что не проверяется автоматически

Живые Atlas и Gemini (нужны секреты), реальные Postman, Docker Desktop и устройства. Они остаются ручными и записаны в `docs/STATUS-CHECKLIST.md`.
