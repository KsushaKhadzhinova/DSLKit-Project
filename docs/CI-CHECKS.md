# Проверки качества и CI

Английская версия: [`CI-CHECKS.en.md`](CI-CHECKS.en.md).

Ветвление: GitHub Flow и trunk-based. `main` всегда зелёный, каждое изменение идёт короткой веткой от `origin/main` через pull request.

## Что проверяется на каждый push и pull request

| Проверка                          | Где                                      | Что ломает сборку                                                                                                                                   |
| --------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| ESLint (`npm run lint`)           | job `test`                               | неопределённые и неиспользуемые имена, `var`, нестрогое сравнение, пустые блоки, ошибки регулярных выражений                                        |
| Prettier (`npm run format:check`) | job `test`                               | любое расхождение с форматом                                                                                                                        |
| Тесты сайта (`npm test`)          | job `test`                               | падение теста или покрытие ниже 100% строк, ветвей и функций; в покрытие явно входят все файлы `site/js` и `tools`, даже те, что тесты не загрузили |
| `npm audit --omit=dev`            | job `test`                               | уязвимость уровня high в библиотеках, которые доходят до пользователя                                                                               |
| Папки работ (`part-2/*`)          | job `work-folders`, 12 папок параллельно | тесты каждой лабораторной и практической, отчёты, `npm audit`                                                                                       |
| Сборка сайта                      | job `build`                              | ошибка сборки                                                                                                                                       |
| React-приложение                  | job `react`                              | тесты и сборка                                                                                                                                      |
| e2e в браузере (Playwright)       | job `e2e`                                | любой сценарий не в состоянии Passed или грязное дерево после прогона                                                                               |
| CodeQL (`security-and-quality`)   | `security.yml`, также раз в неделю       | находки статического анализа безопасности                                                                                                           |
| Dependency review                 | `security.yml`, только pull request      | новая зависимость с уязвимостью high                                                                                                                |

Страж репозитория (`guard.yml`, `npm run guard`): запрещённые файлы (`.env`, личные файлы, `node_modules`, ключи), похожие на секреты строки (ключи API, строки подключения с паролем), файлы больше 5 МБ (кроме замеров ЛР1) и подписи инструментов или ИИ в сообщениях коммитов. Также проверяется, что у каждого workflow задан `permissions` и нет `curl | sh`. Локально то же делает хук перед push (`npm run hooks:install`).

Автослияние (`auto-merge.yml`): когда CI на рабочей ветке зелёный, workflow открывает pull request и включает автослияние (squash); GitHub вливает его в `main`, только когда пройдены все обязательные проверки правила защиты ветки. Ветки `wip/*` и `dependabot/*` пропускаются.

## Дополнительные проверки качества (`quality.yml`)

Отдельный workflow, запускается на каждый push и pull request.

| Проверка                  | Job                                                     | Что ломает сборку                                                                                                                                                                                                                       | Локально                                                                                                                                                 |
| ------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ESLint каждой папки работ | `lint-work-folders`, 12 папок                           | любая ошибка ESLint в `part-2/<папка>` (свой конфиг у каждой; у React-папок рекомендованные правила, плагина React в зависимостях нет)                                                                                                  | `cd part-2/<папка> && npm run lint`                                                                                                                      |
| Пороги покрытия           | `npm test` каждой папки (job `work-folders` в `ci.yml`) | покрытие ниже измеренного уровня, заданного в скрипте `test` (Node) или `vite.config.js` (Vitest)                                                                                                                                       | `cd part-2/<папка> && npm test`                                                                                                                          |
| Типы `site/js`            | `typecheck`                                             | ошибка `tsc --checkJs` (`tsconfig.check.json`, мягкий режим: `strict` и `noImplicitAny` выключены)                                                                                                                                      | `npm run typecheck` (входит в `npm run verify`)                                                                                                          |
| Workflow                  | `actionlint`                                            | любая находка actionlint в `.github/workflows`                                                                                                                                                                                          | скачать actionlint, запустить `actionlint`                                                                                                               |
| Доступность               | `accessibility`                                         | серьёзное или критическое нарушение axe-core на главной, в редакторе, кабинете и входе, светлая и тёмная темы; Lighthouse CI ниже: доступность 0,95, лучшие практики 0,9, производительность 0,8 (профиль desktop, `lighthouserc.json`) | `python testing-course/full/axe-e2e.py` при сайте на :5173; `npm run build`, раздать `dist` на :5174, `npx @lhci/cli autorun --config=lighthouserc.json` |
| Бюджет размера            | `size-budget`                                           | `dist` больше чем на 15% выше `size-budget.json` (всего, gzip, JS, CSS)                                                                                                                                                                 | `npm run build && node ci/size-budget.mjs dist`; `--update` переписывает бюджет                                                                          |
| Нестабильные тесты        | `flaky`                                                 | `npm test`, запущенный дважды (второй раз с файлами тестов в перемешанном порядке), даёт разные результаты                                                                                                                              | `node ci/flaky.mjs`                                                                                                                                      |
| Ссылки в Markdown         | `markdown-links`                                        | битая относительная ссылка или якорь в `docs/**/*.md` и README (внешняя сеть не используется)                                                                                                                                           | `node ci/check-links.mjs`                                                                                                                                |

Долг по типам: файлы, на которых проверка падает из-за вывода типов, начинаются с `// @ts-nocheck -- type-check debt`. Строку убирают, когда файл проходит `npm run typecheck`; новые файлы проверяются с первой строки.

Локально всё сразу: `npm run verify` (lint, format, тесты).

## Что не проверяется автоматически

Живые Atlas и Gemini (нужны секреты), реальные Postman, Docker Desktop и устройства. Они остаются ручными и записаны в `docs/STATUS-CHECKLIST.md`.
