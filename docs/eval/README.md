# Стенд оценки точности автоматизации

English: [README.en.md](README.en.md)

Стенд измеряет три модуля: автопостроение по описанию (`site/js/automation/`), выбор нотации экспертной системой (`site/js/expert/`) и проверку диаграмм (`site/js/utils/diagram-review.js`, `diagram-questions.js`), а также импорт Mermaid, PlantUML и DOT. Он работает без сети и без ключа ИИ, детерминирован и не меняет продукт: код продукта вызывается только из `tools/eval/adapters.js`. ИИ-режим не измеряется.

## Команды

| Команда                 | Что делает                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------- |
| `npm run eval`          | прогоняет набор и печатает числа, ничего не пишет                                                        |
| `npm run eval:baseline` | то же и записывает `baseline.json`, `BASELINE.md`, `BASELINE.en.md` (запускать, когда улучшение принято) |
| `npm run eval:check`    | сравнивает прогон с `baseline.json` по допускам из `ratchet.json`; код выхода 1, если что-то хуже        |

В CI шаг `accuracy-eval` не блокирует слияние (`continue-on-error`) и не входит в обязательные проверки.

## Состав набора

- `descriptions.ru.json`, `descriptions.en.json`: по 150 описаний (30 на каждую нотацию из `BUILDABLE`: bpmn, gost, erd, uml-sequence, dfd). Поля: `text`, ожидаемая `notation`, `el` (элементы), `rel` (связи), `level` (easy, medium, hard), `tags` (cond, loop, parallel, roles, negation, list, numbered, coref, store), `contested` (эталон спорный).
- `check.json`: 102 диаграммы DSLKit с одной засеянной ошибкой (категории: syntax, dangling, unreachable, deadend, notation-rule, level-balance) и 116 чистых. Ошибка и её строка известны из способа изготовления, а не из ответа проверки.
- `import.json`: 45 кодов (Mermaid 29, PlantUML 10, DOT 6) с ожидаемыми элементами и связями.
- `ratchet.json`: допуски храповика. `baseline.json`: опубликованные числа. `src/`: скрипты, из которых набор собран (`make-*.mjs`, `desc-*.mjs`); запускаются вручную.

Формат эталона: элемент `"Подпись"` (шаг), `"d:…"` (решение), `"a:…"` (участник, сущность, внешний объект), `"s:…"` (хранилище); связи `"0-1-2 1-3"` (цепочки индексов элементов). Начало и конец диаграммы не учитываются. В ERD направление связи не важно.

## Правила эталона (честность)

1. Ожидаемое задаётся по смыслу текста, а не по тому, что выдаёт код. Нельзя править эталон, чтобы метрика выросла; править можно только явную ошибку эталона, отдельным коммитом с объяснением.
2. Спорные случаи помечаются `contested: true` и остаются в наборе.
3. Сравнение подписей написано отдельно от продукта (`tools/eval/text.js`: основа слова и доля общих основ не меньше 0,5).

## Как добавить пример

Добавьте запись в нужный `docs/eval/src/desc-*.mjs` (или в `make-import.mjs`, `make-check.mjs`), выполните `node docs/eval/src/make-descriptions.mjs` (и остальные `make-*.mjs`), затем `npm run eval:baseline`. Объём набора изменился, поэтому `eval:check` попросит обновить базовую линию. Тест `tools/eval/gold.test.js` не даёт набору стать меньше минимума.

## Как читать метрики

- **top-1, top-3**: доля описаний, у которых верная нотация первая или среди трёх лучших (из пяти строящихся). **macro-F1**: среднее F1 по классам.
- **ECE**: ожидаемая ошибка калибровки по 10 корзинам уверенности (чем меньше, тем лучше).
- **F1 элементов и связей**: сопоставление построенного с эталоном по подписям и типам; режим «автоопределение» берёт нотацию продукта, «нотация задана» измеряет сам построитель.
- **Без ошибок валидатора**: доля результатов, прошедших `parseDiagram` без ошибок.
- **Повтор «построить, экспортировать в Mermaid, импортировать»**: доля результатов, чей граф после круга не изменился.
- **Полнота проверки**: доля засеянных ошибок, найденных правилом нужной категории (`CATEGORY_RULES` в `tools/eval/config.js`); отдельно с совпадением строки. **Ложные срабатывания**: доля чистых диаграмм с ошибкой или предупреждением.
- **Вопросы**: доля засеянных ошибок, по которым `buildQuestions` задал вопрос, и число чистых диаграмм с вопросом.
- **Стабильность**: доля одинаковых ответов двух прогонов. Время печатается, но в базу и сравнение не входит.

## Ограничения

Описания и чистые диаграммы короткие и однотипные; ложные срабатывания на сложных настоящих диаграммах стенд пока не оценивает. Уровни IDEF0 проверяются в пределах одной диаграммы (межуровневого баланса в продукте нет). ИИ-режим не измеряется. Эталон написан одним автором.
