# ХОД РАБОТЫ

## Определение предметной области и границ проекта

DSLKit – облачный редактор диаграмм как кода. Пользователь пишет текстовое описание диаграммы, сервис проверяет синтаксис, строит изображение через сервис рендеринга Kroki и хранит проекты в личном кабинете. Поддерживаются формальные нотации: UML, IDEF0, ERD, DFD, BPMN и сети Петри. Целевая аудитория: студенты, бизнес-аналитики и разработчики. Сервис распространяется по модели freemium: бесплатный тариф Free с ограничением числа проектов, файлов и ежедневных импортов и платный тариф Pro без этих ограничений.

На предметную область влияют законодательство о персональных данных, условия тарифов, правила и синтаксис нотаций, а также поведение конкурентных инструментов. Обратное влияние выражается в данных об использовании сервиса, по которым корректируются квоты и тарифы.

## Анализ осуществимости и бизнес-задача

Сервис соответствует целям проекта: он закрывает потребность в быстром построении формальных диаграмм без перетаскивания блоков и даёт воспроизводимый текстовый источник, который можно хранить в системе контроля версий. Технически задача выполнима известными средствами: клиент на React, сервер на Node.js, база данных и внешний сервис рендеринга Kroki. Нужна интеграция с сервисом рендеринга, базой данных и системой развёртывания в контейнерах. Вывод: разработку следует продолжать, первая версия включает регистрацию, редактор с проверкой, построение и экспорт, хранение проектов и администрирование.

Бизнес-задача сформулирована ответами на четыре вопроса. Задача возникла из-за неудобства существующих инструментов: одни требуют ручного рисования, другие не проверяют диаграмму по правилам нотации. Назначение сервиса состоит в быстром получении корректной диаграммы из текста. Сервис даёт проверку по правилам нотации, хранение проектов и экспорт. Он решает проблемы ручной отрисовки, ошибок в диаграммах и потери исходных описаний.

## Бизнес-моделирование

Основные понятия предметной области сведены в глоссарий, он показан в таблице 1.3.

Таблица: Глоссарий

| Термин | Определение |
|---|---|
| DSL | Предметно-ориентированный язык для описания диаграммы текстом |
| Нотация | Формальный набор правил и обозначений диаграммы: UML, IDEF0, ERD, DFD, BPMN |
| Диаграмма | Запись с названием, нотацией и исходным кодом на DSL |
| Проект | Набор диаграмм одного пользователя |
| Рендеринг | Построение изображения диаграммы по исходному коду |
| Тариф | Набор квот пользователя: Free или Pro |
| Квота | Предельное число проектов, файлов и ежедневных импортов |

Работа сервиса регулируется законодательством о защите персональных данных, условиями тарифов и правилами нотаций. Внутренние правила включают политику безопасности и хранения данных и параметры рендеринга.

Процессы выстроены в такой последовательности. Гость регистрируется и получает роль и квоты тарифа. Пользователь выбирает нотацию и шаблон, вводит код, сервис проверяет его и показывает ошибки. После проверки сервис строит диаграмму и предлагает экспорт. Проект сохраняется, администратор следит за работой сервиса по журналу запросов. Данные об использовании возвращаются в управление доступом как основа для квот.

## Требования

Бизнес-требования: давать пользователю корректную диаграмму по текстовому описанию, сохранять проекты и поддерживать две модели тарифов.

Пользовательские требования записаны в виде пользовательских историй:

- гость хочет зарегистрироваться, чтобы сохранять свои проекты;
- пользователь хочет видеть ошибки в коде сразу, чтобы быстро их исправить;
- пользователь хочет экспортировать диаграмму, чтобы вставить её в документ;
- пользователь хочет вернуться к сохранённому проекту, чтобы продолжить работу;
- администратор хочет видеть журнал запросов, чтобы разбираться со сбоями.

Системные требования и ограничения. Сервис единичный, одновременно работает до нескольких сотен пользователей. Исходные тексты диаграмм критичны, потеря недопустима, поэтому настроено резервное копирование. Пароли хранятся только в виде хеша, доступ защищён токеном. Число пользователей и проектов может вырасти в несколько раз без смены архитектуры.
