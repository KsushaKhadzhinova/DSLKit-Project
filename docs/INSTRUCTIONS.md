# Рабочие инструкции по проекту

Обновлено: 2026-10-13. Прочитайте этот файл первым, затем [`CONTEXT.md`](CONTEXT.md), [`HANDOVER-LABS.md`](HANDOVER-LABS.md), [`SESSION-LOG.md`](SESSION-LOG.md) и [`design-brief.md`](design-brief.md). Состояние проверяйте по `git log` и `npm test`, а не только по документам.

## Правила владельца проекта (обязательны)

1. **Коммиты.** Делайте коммиты только от имени владельца (git-идентичность из `git config`). Никакого соавторства ИИ, `Co-Authored-By`, меток «сгенерировано ИИ» и упоминаний ИИ в сообщениях коммитов, коде и документах результата.
2. **Регулярные коммиты и push** после каждого законченного шага, чтобы при обрыве интернета или лимитов ничего не потерялось. Сообщения на английском в стиле истории (`feat(site): ...`, `docs(ux): ...`).
3. **Вопросы.** Задавайте владельцу вопросы, когда решение не следует из репозитория (акцентный цвет, формулировки обязательств, домен). Результаты показывайте в браузере и получайте валидацию до слияния в `main`.
4. **Теория перед лабораторной.** Сначала читайте лекции и условие (`materials/text/part-1`, лекции лежат у владельца в `E:\ИТиВП`), только потом делайте работу. Следуйте критериям оценки из условия.
5. **Чистый код и чистая архитектура.** Понятные имена, маленькие функции, разделение ответственности, без дублирования. По Code guide курса: отступ 2 пробела, двойные кавычки в HTML и CSS, одинарные в JS, классы в kebab-case на английском (БЭМ), без транслита, порядок свойств CSS по группам.
6. **README и шаблоны отчётов** добавляются к каждой работе всегда. Отчёты Markdown на русском и английском, правила в `tools/lint-report.js`.
7. **UX-метрики и тестирование.** Для каждого значимого результата считайте метрики (контраст, размеры целей, сетка, типографика), прогоняйте тесты (`npm test`, порог 100 процентов) и независимых оценщиков. Оценки независимых оценщиков всегда называйте симуляцией, а не данными пользователей.
8. **Помощники.** Рабочую (механическую) вёрстку поручайте лёгким помощникам по очереди, одному за раз, с точным заданием. Результат каждого проверяйте сами (валидатор, ссылки). Для финальных проверок собирайте консилиум независимых проверяющих с разными ракурсами (критерии лабораторной, доступность, чистый код, паритет RU и EN). Агентам запрещайте git, коммиты делаете вы.
9. **Язык.** Интерфейс и документы сначала на русском, английская версия после. Заголовок и текст честные: продукт в разработке, без выдуманных отзывов, пользователей и цен.
10. **Порядок работ.** Сначала HTML и разметка, затем стили (CSS), затем JS. Стили делаются по `docs/design-brief.md`.

## Золотое сечение (обязательное требование владельца)

Сайт должен полностью соответствовать правилам золотого сечения. Реализовано в `site/css/variables.css`: `--phi` 1.618, шкала шрифтов с шагом √φ (1.272) и φ, отступы по Фибоначчи на 8 px, колонки `1fr 1.618fr`, hero и холст в пропорции φ. Тест `labs/04-responsive-css/styles.test.js` не даёт отклониться. Новые стили пишите только через токены.

## Решения по дизайну

- Нотации в порядке популярности: UML, BPMN, ERD, DFD, IDEF0, сети Петри. ERD, DFD и IDEF0 помечены «в бете».
- Главная показывает возможности и сильные стороны, без сравнения с конкурентами; нужны визуальные примеры и живая демо-диаграмма.
- Ориентиры стиля: спокойные продуктовые сайты, Innowise, Mermaid, draw.io. Принципы, не копирование брендов.
- Домен сайта: `dslkit.io` (пока не куплен). Светлая тема первой, тёмная второй, шапка закреплена, мобильная и десктопная версии обязательны.
- Открыто: акцентный цвет (синий `#2563eb` или тёплый), тексты политики конфиденциальности, доступ к Figma.

## Ловушки среды

- Windows 11, Git Bash и PowerShell; Node 24; в `node_modules` нет Playwright, для скриншотов подходит локальный Chrome в режиме `--headless=new --screenshot`.
- Для кириллических PDF используйте PyMuPDF (`pdftotext` теряет буквы).
- Сервер `tools/server.js` отдаёт страницы ошибок по произвольным адресам, поэтому на страницах ошибок только корневые пути (`/css/style.css`).
- Форма сайта работает методом GET с якорем `#waitlist`, пока нет JavaScript (ЛР5) и сервера. Это известный недостаток, он отмечен в метриках.
- Figma без подключённого коннектора или расширения Chrome недоступна. В файл нужно положить: макеты (desktop, tablet, mobile, светлая и тёмная темы), мокапы, вайрфреймы, мудборд, шрифты, цвета, логотипы, примеры-вдохновения, компоненты с вариантами (кнопки и др.), страницы по модулям и устройствам. SVG лежат в `site/design/figma` и `docs/project/figma-svg`.
