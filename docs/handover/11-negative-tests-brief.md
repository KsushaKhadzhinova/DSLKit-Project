# Бриф: тесты неправильного поведения пользователя

Цель: для работы добавить автотесты, которые отражают **неправильные действия пользователя и отклонения от нормального сценария**. Преподаватель ломает работы так: огромные числа и строки, пробельные значения, повторная отправка, остановка БД, подделка полей, чужие или просроченные токены, странные адреса. Тесты должны показывать, что приложение отвечает понятной ошибкой и не падает.

## Правила
1. Работай только в указанной папке работы (git worktree) и только в ней. Git не использовать (ни commit, ни checkout, ни stash).
2. Новые тесты складывай в НОВЫЙ файл рядом с существующими тестами (`tests/negative.test.js`, `test/negative.test.js` или `src/negative.test.jsx`, смотри как устроены текущие тесты и какой раннер: `node --test` или `vitest`). Старые тесты не менять и не удалять.
3. Каждый тест имеет понятное английское имя в стиле существующих («…answers 400 for …»). Один сценарий на тест, без лишней логики. Повторяй стиль, хелперы и harness существующих тестов.
4. Если тест обнаружил РЕАЛЬНЫЙ дефект в коде (приложение падает, отвечает 500 на неверный ввод, пропускает запрещённое), исправь код минимально и опиши в `NEGATIVE-TESTS.md` (таблица: сценарий, что было, что стало). Если дефект крупный, не чини, а запиши в `NEGATIVE-TESTS.md`.
5. Тесты не должны зависеть от интернета, реальных баз и времени суток. Не оставляй сон дольше 200 мс. Покрытие и порог покрытия в `npm test` не ухудшать, отчётные тесты (`report.test.mjs`) не трогать.
6. В конце запусти `npm test` в папке работы и пришли итог: число тестов до и после, список найденных дефектов (если были), путь к файлу `NEGATIVE-TESTS.md` в папке работы (создай: таблица «Сценарий | Ожидаемый ответ | Тест»).
7. Секреты не писать, `.env` не создавать.

## Каталог сценариев (выбери применимые, не меньше 20 на API-работу, 12 на интерфейсную)

API (Express, Sequelize, Mongoose):
- Тело: пустое, не JSON, обрезанный JSON, массив вместо объекта, `null`, строка, вложенность глубиной 50, поле неверного типа (число вместо строки, объект вместо строки), лишние поля (`id`, `owner`, `role`, `createdAt`), повтор ключей.
- Значения: пустая строка, только пробелы и табуляции, `\u0000`, эмодзи, RTL-символы, строка длиннее лимита на 1 символ и на 1 мегабайт, число `-1`, `0`, `1.5`, `NaN`, `1e309`, `2147483648`, `Number.MAX_SAFE_INTEGER + 1`, булево вместо числа, SQL и NoSQL внедрение (`' OR 1=1 --`, `{"$ne":null}`, `{"$gt":""}`).
- Адреса: id `abc`, `-1`, `0`, `1.5`, `1e3`, `0x1`, `%`, `%00`, `99999999999999999999`, пробел, очень длинный путь; неизвестный маршрут; неподдерживаемый метод (405 с Allow); неверный `Content-Type` (415); слишком большое тело (413).
- Поведение: двойной POST создаёт две записи, двойной PUT идемпотентен, DELETE дважды (204, затем 404), PUT без обязательных полей, обновление чужой записи (403), параллельные запросы к одному ресурсу, запрос после удаления.
- Авторизация: нет заголовка, неверная схема (`Basic`), пустой токен, мусорный токен, подделанная подпись, токен с `alg: none`, просроченный токен, токен удалённого пользователя, обычный пользователь в админ-маршруте, понижение роли старым токеном, неверный пароль и неизвестная почта (одинаковый ответ), дубликат регистрации в другом регистре, пароль из пробелов, слишком длинный пароль.
- Отказы окружения: база недоступна или закрыта (понятная 500/503 без внутренних деталей), нет прав на файл, пустые переменные окружения (сервер не стартует с понятной ошибкой), занятый порт.

Интерфейс (EJS и React, Vitest + Testing Library):
- Отправка пустой формы, формы из пробелов, слишком длинных значений (вставка 100 000 символов), отрицательных и нечисловых значений в числовом поле.
- Двойной клик и двойной Enter по отправке и удалению (один запрос), быстрая смена поиска (старый ответ не перезаписывает новый), отмена правки клавишей Escape.
- Сервер недоступен, отвечает 500, 401 посреди сессии (возврат на вход), 403, 404, HTML вместо JSON, пустой ответ, очень медленный ответ.
- Разметка в данных (`<img onerror>`, `<script>`) выводится текстом, не выполняется.
- Повреждённый или заблокированный `localStorage` (невалидный JSON, массив вместо объекта, исключение при чтении), неизвестный маршрут, возврат назад, обновление страницы, неизвестный `id` в адресе.
- CSRF-токен отсутствует или неверный (EJS), повторяющиеся ключи формы, тело больше лимита.

WebSocket (Socket.IO):
- Событие без данных, с числом вместо объекта, огромный пакет, имя из пробелов или слишком длинное, комната из пробелов, сообщение пустое или из пробелов, сообщение самому себе, сообщение несуществующему адресату, спам больше лимита частоты, повторный вход без выхода, отключение посреди набора текста, чужой Origin.
