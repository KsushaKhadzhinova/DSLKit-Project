# Дизайн и UI

## Правило согласования (решение владельца 2026-10-16)

Все интерфейсы и макеты согласуются с владельцем **буквально по каждой детали** до внедрения в `site/css` и `site/*.html`. Порядок: показать вариант (прототип или скриншот) → собрать замечания по деталям (цвета, шрифты, отступы, шапка, кнопки, карточки, тексты, состояния) → получить «да» → только тогда внедрять отдельной веткой. Без «да» в реальный сайт ничего не переносится.

## Уже принято

- Основная ветка `main`. UI строится по вариантам, полученным после проверки конкурентов.
- Светлая тема первой, mobile-first, точки 576/768/1024, БЭМ, золотое сечение.
- Sticky-шапка и тулбар (макет `docs/project/mockups/dslkit-mockup-v2.html`).
- Домен не куплен: плейсхолдер `dslkit.example`.

## Итоги 100 A/B тестов (65 раз A, 35 раз B)

Источник: `docs/project/ab-results/ab-results.md`, страница `docs/project/mockups/dslkit-100-ab-tests.html`, исходники `mockups/ab-src/` (пересборка `python mockups/ab-src/build.py`).

- Тулбар: Run синий, при ошибках красный и нажимаемый (открывает список ошибок); диалог «Сохранить перед запуском?»; спиннер внутри Run; Save с меню.
- Редактор: код 13 px, номера строк, без minimap и переноса, автодополнение, парные скобки, подсказка AI по Tab, поиск панелью справа вверху.
- Холст: вертикальный split (код слева), инспектор по клику, drag пишет `pos` в код, точечная сетка, плавающий Zoom, мини-карта.
- Вкладки: жёлтая точка несохранённых, модал при закрытии, × при наведении и на активной.
- Ошибки: панель снизу, группировка, Fix with AI, схлопывается при успехе.
- Статус-бар 22 px; мобильная версия только просмотр с нижней навигацией.

**Три конфликта со старыми решениями, ждут подтверждения владельца:** (1) Run был зелёным и отключался при ошибках; (2) Share был в тулбаре, теперь в File; (3) × вкладки был всегда виден, теперь по наведению и на активной.

## Варианты UI

- Прототипы: ветка `design/ui-prototype-variants` (галерея `docs/project/ui-prototypes/r2-pages.html`): лендинг bento, «средний» тёмный и светлый, страницы приложения. Фраза «средний между текущим и вариантом 2 тёмным» понята как «между текущим и вариантом 1»; не подтверждено.
- Конкуренты: `docs/COMPETITOR-ANALYSIS.md`. Проверены Mermaid, D2, Kroki, Eraser, PlantUML, Structurizr, Excalidraw. Не закончено: SaaS/IaaS/PaaS и стартапы (Linear, Vercel, Stripe, Supabase, Notion, Figma, Resend), ссылки с выводами по стилю и вёрстке.
- Паттерны из ресерча: продукт в первом экране, плотный трекинг заголовков, тёмная тема с одним акцентом, bento-сетки, код в hero, вкладки SDK-сниппетов.

## Следующие шаги

1. Дособрать ресерч конкурентов со ссылками.
2. Подготовить 2–3 финальных варианта лендинга и страниц приложения.

4. Внедрить согласованное отдельной веткой от `main`, прогнать тесты, W3C, кросс-браузер.
5. Английские версии `site/app/*.html`, аудит золотого сечения, загрузка макетов в Figma (файл `bsuir-diploma`).
