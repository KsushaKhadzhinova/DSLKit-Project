# Проверка кода по книгам: чистый код и чистая архитектура

Дата: 2026-10-22. Эталоны: «Чистый код» и «Чистая архитектура» (Мартин), Refactoring (Фаулер), A Philosophy of Software Design (Усте́рхаут), Code Complete (Макконнелл), Get Your Hands Dirty on Clean Architecture (Хомбергс), Patterns of Enterprise Application Architecture (Фаулер). Проверка механическая и выборочная: размер файлов и функций, глубина вложенности, слои, повторения. Метрики собраны грубым скриптом по первой и последней строке функции, поэтому цифры приблизительные. Чтение всего кода построчно по каждому правилу книг не проводилось.

## 1 Метрики до правок

Порог для «длинной» функции взят 40 строк (у Мартина функция должна быть заметно короче, у Макконнелла предел около 50–100). Порог файла 300 строк.

Серверные работы ЛР1–ЛР3 уже в хорошей форме: маленькие функции, слои «маршрут, проверка, контроллер, модель, обработчик ошибок».

| Нарушение | Книга и правило | Что сделано | Проверка |

## 3 Что оставлено и почему

| Место | Замечание | Решение |
| --- | --- | --- |
| `site/js/notations/graph.js`, `defineGraph` (89 строк) | Фабрика: данные описывают нотацию, внутри короткие функции `parse`, `toDot`, `toMermaid`, `toPlantUml`, `render` | Оставлено: это паттерн «поведение задаётся данными», каждая вложенная функция короткая; Усте́рхаут одобряет глубокий модуль с узким интерфейсом |
| `idef0-render.js` (75), `class.js` (65), `er.js` (59), `graphs.js`, `svg.js` | Отрисовка SVG длинными последовательностями вызовов | Кандидаты на следующий круг (Extract Function), поведение покрыто тестами |
| `tools/design-gen.js` (110 строк) | Генератор макетов, не часть продукта | Не трогаю, это одноразовый инструмент |
| `App.jsx` в ЛР5 (77 строк, вложенность 7) | Компонент собирает страницу | Кандидат на разделение по компонентам |
| Серверные ЛР1–ЛР3: контроллеры работают с моделью напрямую | В «Чистой архитектуре» между контроллером и БД стоят варианты использования и порты | Сознательный компромисс: для CRUD-лабораторной дополнительные слои дают больше кода, чем пользы. Слои «маршрут → проверка → контроллер → модель → обработчик ошибок» уже отделяют HTTP от данных. В отчётах это можно назвать упрощённой слоистой архитектурой по Фаулеру (PoEAA: Service Layer не выделен) |

## 4 Соответствие остальным правилам книг (по выборке)

| Правило | Состояние |
| --- | --- |
| Имена выражают намерение (Мартин, Макконнелл) | В целом да: `createHandshake`, `usePagedList`, `isTemporary`; сокращённые имена `n`, `i` только в коротких циклах |
| Комментарии объясняют «почему» (Мартин) | Да: комментарии над функциями описывают причину, а не повторяют код |
| Обработка ошибок без «проглатывания» (Мартин) | Да: ошибки превращаются в понятные ответы, внутренние детали не выходят наружу |
| Зависимости направлены внутрь (Мартин, Хомбергс) | В ЛР7 история внедряется через параметр `history` (порт), в ЛР6 подключение к MongoDB изолировано в `db.js`; в ЛР1–ЛР3 слой моделей зависит от ORM, что допустимо для работы такого размера |
| Тесты рядом с кодом, один сценарий на тест (Бек, Фримен и Прайс) | Да: тесты на каждую работу, негативные сценарии в отдельных файлах |
| Конфигурация вне кода (Двенадцатифакторное приложение, Pragmatic Programmer) | Да: секреты и адреса из `.env`, лимиты из `limits.json` |
