## ЛР4. Управление состоянием в React (ветка 24)

**Цель.** Освоить `useState` и `useEffect` на списке в предметной области проекта (у нас «Мои диаграммы»).

**Что требует задание:**

1. React-приложение на Vite.
2. Компонент управления списком: добавление, удаление, редактирование.
3. `useState` для массива, поля ввода и фильтра или сортировки.
4. `useEffect` с `[items]` сохраняет в `localStorage` (`JSON.stringify`). `useEffect` с пустым массивом загружает данные при старте.
5. Фильтрация или сортировка.
6. Дополнительные эффекты по выбору: таймер автосохранения, `document.title` по числу элементов и т.п.

**Теория:**

- `useState` хранит данные, от которых зависит экран. Состояние не изменяют напрямую: `map`, `filter` и `{...d}` создают новые данные.
- `useEffect` срабатывает после отрисовки, пустой массив зависимостей значит «один раз», функция очистки сбрасывает таймеры.
- `localStorage` хранит только строки.
- Отфильтрованный список считают при отрисовке, а не хранят в состоянии.

**Сделано:**

- Хук `useLocalStorage` с проверкой формы данных (сломанный JSON не роняет приложение).
- Добавление, переименование (Enter сохраняет, Esc отменяет), удаление, публикация.
- Поиск, фильтр, сортировка, статистика.
- Автосохранение: индикатор через 500 мс.
- Валидация названия, предел 200 записей.
- Мобильный вид и тёмная тема.
- Пункта «имитация загрузки 1 с» не было (он по выбору), добавляется отдельно.

**Скриншоты** (15 штук, `part-2/lab-04-react-state/figures` в ветке 24): список на десктопе, ошибка валидации, после добавления, фильтр, после перезагрузки (данные на месте), мобильный список и меню, тёмная тема, автосохранение, сортировка, поиск, правка и ошибка правки, после удаления, пустой список.

## ЛР5. React и сервер (ветка 25)

**Цель.** Подключить клиент ЛР4 к своему API из ЛР1–3 (Express, PostgreSQL, JWT).

**Что требует задание:**

1. Получение списка (GET) с индикаторами загрузки и ошибки.
2. Добавление (POST) с оптимистичным обновлением.
3. Удаление (DELETE).
4. Редактирование (PUT или PATCH).
5. Одно улучшение: пагинация, поиск, debounce, повтор запросов или отмена запроса.
6. `axios` (или `fetch`), `.env` с `VITE_API_URL`, файл `src/api.js` с токеном и обработкой ошибок.

**Теория:**

- `axios` даёт перехватчики: токен в заголовок, на 401 выход из аккаунта. Он бросает ошибку на 4xx и 5xx, есть таймаут.
- Оптимистичное обновление: экран меняется сразу, при ошибке откатывается.
- Debounce: запрос уходит после паузы в наборе.
- `AbortController` отменяет устаревший запрос.
- CORS: сервер разрешает адрес клиента.
- Токен в `localStorage` удобен, но доступен скриптам (риск XSS).

**Сделано:**

- Вход и регистрация, токен в перехватчике.
- Список постранично («Загрузить ещё» по заголовку `X-Total-Count`).
- Поиск на сервере с debounce 400 мс и отменой запросов.
- Оптимистичные добавление и удаление с откатом.
- Правка.
- Автоповтор чтения до трёх раз (запись не повторяется).
- Сообщения об ошибках 401, 403, 404, 500 и сети.
- Сервер для ЛР5 нужен из ветки 25: в ветке 23 нет CORS.

**Скриншоты** (10 штук, `part-2/lab-05-react-api/figures` в ветке 25): вход, загрузка, список, добавление (до, оптимистично, после), удаление, поиск, ошибка, «загрузить ещё».

## ЛР6. MongoDB и Mongoose (ветка 26)

**Цель.** Освоить NoSQL: подключение, схемы, CRUD и документную модель (вложенные структуры вместо нескольких таблиц).

**Что требует задание:**

1. Бесплатный кластер MongoDB Atlas (M0) или локальная установка.
2. Подключение Mongoose к Node.js-приложению.
3. Схема и модель коллекции предметной области.
4. CRUD через маршруты Express.
5. Вложенные документы или массивы (теги, комментарии).
6. Показать отличие от реляционной модели.
7. Строка подключения в `.env` (в задании `MONGO_URI`, у нас `MONGODB_URI` с синонимом `MONGO_URI`).

**Теория:**

- Документы (BSON) лежат в коллекциях, идентификатор это `ObjectId`.
- Mongoose задаёт схему, валидацию и методы.
- Вложенный массив комментариев вместо JOIN: один запрос возвращает диаграмму вместе с комментариями.
- NoSQL-инъекции в теле и запросе (операторы вида `$ne`) надо отсекать.
- Строка Atlas имеет вид `mongodb+srv://…`.

**Сделано:**

- CRUD диаграмм: GET список и одна запись, POST 201, PUT, PATCH, DELETE.
- Комментарии и теги внутри документа, фильтр по тегу.
- Поиск, сортировка, пагинация, статистика.
- Валидация, лимиты, защита от инъекций, ответы 404, 400 и 503.
- Скрипт `npm run seed`.
- Не сделано: запуск на Atlas (нужна строка подключения в `.env`).

**Скриншоты** (25 штук, `part-2/lab-06-mongodb/figures` в ветке 26): запросы с `01` по `20` (список, одна запись, создание, замена, удаление, комментарии, тег, документ в Mongo, ошибки, лимиты, инъекции в теле и запросе, patch, сортировка, поиск, статистика, пагинация) и страницы в браузере (список, 404, 400, 503, health 503). Снимков Atlas и Compass нет.

## ЛР7. WebSocket и Socket.IO (ветка 27)

**Цель.** Двусторонняя связь в реальном времени (чат, уведомления) под нужды курсового проекта.

**Что требует задание:**

1. Сервер на Node.js, Express и Socket.IO.
2. Клиент (React или HTML/JS).
3. Отправка и получение сообщений в реальном времени.
4. Уведомления о подключении и отключении пользователей.
5. Дополнительная функция по логике проекта: комнаты, история в MongoDB, приватные сообщения, голосование и т.п.

**Теория:**

- HTTP односторонний (клиент спрашивает, сервер отвечает). WebSocket после handshake держит постоянное соединение в обе стороны.
- Socket.IO добавляет события, комнаты, широковещание (`io.emit`, `socket.to(room)`) и переподключение.
- События: `connection`, `disconnect`, `join`, `leave`.
- Комнаты изолируют каналы: сообщение комнаты одной диаграммы не доходит в другую.

**Сделано:**

- Комната на каждую диаграмму: вход, чат, уведомления о входе, уходе и отключении.
- «Кто сейчас редактирует».
- Проверка входящих данных.
- Отсутствие утечки сообщений между комнатами.
- Схема потока событий `event-flow.svg`.

**Скриншоты** (10 штук и схема, `part-2/lab-07-websocket/figures` в ветке 27): вход Алисы с уведомлениями, вход Боба, чат Алисы и Боба, комната другой диаграммы (Кэрол), «нет утечки» у Алисы, «кто редактирует», ошибка проверки у Боба, уведомления об уходе и об отключении.

## ЛР8. Docker (ветка 28)

**Цель.** Упаковать курсовой проект в контейнеры.

**Что требует задание:**

1. `Dockerfile` backend (Node.js, Express).
2. `Dockerfile` frontend с многоэтапной сборкой (сборка React, затем nginx).
3. `docker-compose.yml`: backend, frontend, база (PostgreSQL или MongoDB).
4. Сборка и запуск одной командой `docker-compose up --build`.
5. Проверка работы в контейнерах.
6. Минимум одно дополнительное требование по выбору.
7. Для РБ: Docker Hub может быть недоступен, допустимы альтернативные реестры.

**Теория:**

- Образ это «шаблон», контейнер его запущенный экземпляр.
- Инструкции: `FROM`, `WORKDIR`, `COPY`, `RUN`, `EXPOSE`, `CMD`.
- Многоэтапная сборка: на первом этапе собирается приложение, во второй образ копируется только готовая сборка (легче и безопаснее).
- Сети и тома: общая сеть compose, том `pgdata` хранит данные базы.
- Compose описывает сервисы и зависимости (`depends_on`, `healthcheck`).

**Сделано:** compose `dslkit` с базой, backend, frontend и pgAdmin, запуск и проверки пройдены, тесты конфигурации проходят. Не сделано: образы не залиты на Docker Hub.

**Скриншоты** (4 штуки, `part-2/lab-08-docker/figures` в ветке 28): `docker ps`, вход в приложение, список, проверки.
