# Какие данные, логины и ключи нужны от вас и куда их вписывать

Правило: **пароли, ключи и строки подключения никогда не пишите в чат с ассистентом и не коммитьте в Git.** Они лежат только в файлах `.env` на вашем компьютере. Файл `.env` уже исключён из Git (`.gitignore`), а образец без секретов называется `.env.example`.

## 1 Без чего всё работает «из коробки»
Все лабораторные и ПЗ запускаются и проходят тесты **без внешних аккаунтов**: серверные работы используют локальный файл SQLite, ЛР6 в тестах использует базу в памяти, клиенты работают с локальным сервером. Внешние данные нужны только для проверки «как у преподавателя» на настоящих сервисах и для сдачи.

## 2 Что создать самой (по шагам)

### 2.1 Секрет для токенов JWT (ЛР3, ЛР5, ЛР8, курсовой)
1. В терминале выполнить: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`.
2. Скопировать вывод в `.env` работы: `JWT_SECRET=<вывод>`.
3. Файл: `part-2/lab-03-auth/.env` (копия `.env.example`). Секрет не короче 32 символов, срок токена `JWT_EXPIRES_IN=1h` (не больше 24 часов).

### 2.2 Первый администратор (ЛР3)
В том же `.env`: `ADMIN_EMAIL=<ваш адрес>`, `ADMIN_PASSWORD=<пароль от 10 символов>`. Создаётся командой `npm run db:seed`. Если оставить пустыми, администратор не создаётся.

### 2.3 PostgreSQL в облаке (нужно, если преподаватель потребует PostgreSQL; ЛР2, ЛР3, ЛР8)
1. Зайти на https://neon.tech (или https://supabase.com), зарегистрироваться своим аккаунтом (логин и пароль вводите только вы).
2. Создать проект и базу, скопировать строку подключения вида `postgres://user:password@host/dbname`.
3. Вписать в `.env` работы: `DATABASE_URL=<строка>` и для облака `DATABASE_SSL=true`. Сертификат проверяется по умолчанию, отключать проверку (`DATABASE_SSL_REJECT_UNAUTHORIZED=false`) только если провайдер выдаёт самоподписанный.
4. Выполнить `npm run db:migrate` и `npm run db:seed`.
5. Где это читается в коде: `part-2/lab-02-sequelize/config/config.js` и `part-2/lab-03-auth/config/config.js`. Без `DATABASE_URL` используется SQLite (`SQLITE_STORAGE`).
6. **Состояние:** работа на PostgreSQL ни разу не запускалась, поэтому в отчёте это названо «не проверено». После успешного запуска впишите это в отчёт ЛР2 раздел про проверку.

### 2.4 MongoDB (ЛР6)
Вариант 1, локально: установить MongoDB Community Server, запустить службу, `MONGODB_URI=mongodb://127.0.0.1:27017/dslkit`.
Вариант 2, Atlas (облако):
1. https://www.mongodb.com/atlas → Sign up (вы вводите свои данные) → создать бесплатный кластер (M0).
2. Database Access → Add New Database User: имя и пароль только латиницей, без спецсимволов.
3. Network Access → Add IP Address → «Add Current IP Address» (для проверки допустимо «Allow access from anywhere», потом убрать).
4. Connect → Drivers → скопировать строку `mongodb+srv://<user>:<password>@cluster…/dslkit`, подставить пароль.
5. Вписать в `part-2/lab-06-mongodb/.env`: `MONGODB_URI=<строка>` (также принимается имя `MONGO_URI`). Выполнить `npm run seed`, затем `npm start`.
6. Для отчёта преподаватель может потребовать скриншоты Atlas (дашборд кластера, Database Access, Data Explorer с коллекцией `diagrams`). Их снимаете вы после шагов выше.

### 2.5 Docker (ЛР8)
1. Установить Docker Desktop, запустить. Проверка: `docker --version`, `docker compose version`, `docker ps`.
2. Docker Hub в Беларуси может не открываться. В Docker Desktop: Settings → Docker Engine, в JSON добавить `"registry-mirrors": ["https://mirror.gcr.io", "https://dockerhub.timeweb.cloud"]`, нажать Apply & Restart. На Linux это файл `/etc/docker/daemon.json`.
3. В отчёте указать, какое зеркало использовано (условие ЛР8 требует).
4. Пароли базы для контейнеров задаются в `.env` рядом с `docker-compose.yml` (образец `.env.example`), не в самом compose.

### 2.5.1 GitLab Container Registry (если решите публиковать образ, вопрос 14 ЛР8)
Аккаунт GitLab, проект, затем `docker login registry.gitlab.com` (логин и токен вводите вы), `docker tag` и `docker push`. Эту часть ассистент не выполняет.

### 2.6 Адреса клиента и сервера (CORS)
| Что | Где вписать | Значение по умолчанию |
| --- | --- | --- |
| Адрес API для клиента ЛР5 | `part-2/lab-05-react-api/.env`: `VITE_API_URL` | `http://localhost:3000` |
| Какому адресу сервер разрешает запросы | `part-2/lab-03-auth/.env`: `CORS_ORIGIN` | `http://localhost:5178` |
| Разрешённые адреса для WebSocket | `part-2/lab-07-websocket/.env`: `ALLOWED_ORIGINS` | локальные адреса |
| Файл базы журнала ПЗ1 | переменная `DB_FILE` (иначе `data/requests.db`) | `data/requests.db` |
| Порт любого сервера | переменная `PORT` | 3000 |

### 2.7 GitHub (отправка кода)
Вход в GitHub, токен или вход через Git Credential Manager выполняете только вы. Команды: `git push origin 23` (ветка работы), по одной ветке. Слияние в `main` только когда решите; ассистент без вашего явного «да» ничего не отправляет.

## 3 Что менять в коде, если нужно другое
| Хочу | Файл и место |
| --- | --- |
| Другой лимит длины, числа, размера тела | `limits.json` в папке работы (ЛР1–ЛР3, ЛР5 `src/limits.json`, ЛР6, ЛР7, ПЗ1) |
| Другие допустимые нотации и приоритеты | `src/models/diagram.constants.js` (ЛР1–ЛР3) и такой же список в клиенте `src/utils/validation.js` |
| Время жизни токена | `JWT_EXPIRES_IN` в `.env` |
| Сколько неудачных входов до блокировки | `DEFAULTS` в `part-2/lab-03-auth/src/app.js` (`loginMaxAttempts`, `loginLockMs`) |
| Адрес разрешённого клиента | `corsOrigin` в `src/app.js` или `CORS_ORIGIN` |
| Название приложения и тексты интерфейса | компоненты в `src/components` (React) или `views/*.ejs` (ПЗ1) |
| Тема, цвета, размеры | `dslkit.css` скопирован из `site/css`, меняйте токены в `variables.css` сайта и пересоберите: `node docs/design-contest/bundle-css.mjs <файл>` |
