## F. Защита: короткие ответы и «допиши при мне»

Вопросы преподавателя по коду и просьба написать код вживую (см. `docs/notes/06-teacher-requirements.md`, `07-possible-teacher-extras.md`). Каждый ответ опирается на файл в репозитории. ### F1. Импорт файлов диаграмм (`docs/agent-reports/feature-import-recognition.md`)

**Что делает импорт?** Берёт файл (draw.io, BPMN, XMI, GraphML, DOT, CSV, Visio, Mermaid, PlantUML, Markdown с блоком) и превращает его в код DSLKit. Пример: файл `a.drawio` с ромбом и овалом становится блок-схемой ГОСТ.

**Где вход?** `site/js/automation/upload.js`: `uploadKind` смотрит на тип и расширение (`picture`, `bmp`, `zip`, `text`, `unknown`), `importUpload` отклоняет файлы больше 10 МБ (`MAX_FILE_BYTES`), берёт блок диаграммы из Markdown и отдаёт текст нужному читателю. Структурные форматы читает `site/js/utils/diagram-file-import.js`. Результат: `{ ok, notation, code, warnings }` или `{ ok: false, reason }` (`no-structure`, `bad-file`, `unknown`). Код проверяет `parseDiagram`.

**Нужен ли ключ ИИ?** Для структурных файлов нет, всё детерминированно. Для картинок и PDF да: `tools/ai-vision.js` и `tools/ai-api.js`. Честно: распознавание картинок с настоящим API Claude не запускалось, запрос и повтор проверены только на поддельном сервере. Распаковка сжатого draw.io в браузере (`DecompressionStream('deflate-raw')`) в настоящем браузере не запускалась, в Node проверена через `deflateRaw`. Читатели SVG Graphviz и Mermaid писались по известной структуре, на реальных файлах разных версий не проверялись.

**Почему свой читатель XML, а не `DOMParser`?** Чтобы один и тот же код работал и в браузере, и в Node (тесты).

**Допиши при мне: новое расширение.** Например, `.mmdc`. Шаг 1: добавить `'mmdc'` в список `TEXT_EXTENSIONS` в `upload.js` (`ACCEPT` и `uploadKind` подхватят его сами). Шаг 2: проверить в `importUpload`, куда уходит такой текст (как у `mmd`). Шаг 3: тест рядом с тестами `upload.js`.

**Допиши при мне: другой предел размера.** Константа `MAX_FILE_BYTES` (10 МБ) импортируется в `upload.js` из `diagram-file-import.js`; поменять число и тест на ответ `too-big`.

### F2. «Проверить и исправить» (`docs/agent-reports/feature-review-fix.md`)

**Как работает?** `reviewCode(code, { lang })` в `site/js/utils/diagram-review.js` собирает замечания парсера и правил, потом строит варианты: «минимальный» (только ошибки) и «полная чистка». Исправления идут проходами (до четырёх), каждый вариант заново разбирается, и предлагается он, только если проблем стало меньше.

**Откуда замечания?** Из парсера и валидатора каждой нотации, те же, что в панели проблем, плюс правила: нет названия, пустая диаграмма, слишком длинная подпись, у блока IDEF0 нет входа.

**А ИИ?** Необязательный слой `tools/ai-review.js`: ответ модели проверяется тем же валидатором, остаётся не больше двух вариантов. Без ключа сервер отвечает 503, и панель работает только на локальных правилах. С настоящим ключом не пробовалось.

**Можно ли отменить?** Да. Применение пишет код в редактор как обычную правку, «Отменить» возвращает прежний код.

**Чего не умеет?** Не знает смысла диаграммы («данные», «Обработка» надо заменить самому), недостижимый узел со связями чинится вручную. Вид панели на реальном телефоне не проверялся, только разметка и тесты.

**Допиши при мне: новое правило.** В `diagram-review.js` рядом с другими правилами добавить замечание `{ severity, line, rule, message: { ru, en }, fix }`; `fix` это правка строки, её применит `applyEdits`. Пример: «подпись длиннее 60 символов». Сообщение сразу на обоих языках, затем тест.

### F3. Уточняющие вопросы (`docs/agent-reports/feature-clarify-complete.md`)

**Идея.** Если диаграмма неполная, система спрашивает («где конец процесса?») и достраивает её по ответам. Файл: `site/js/utils/diagram-questions.js`.

**Функции.** `buildQuestions(code, notation)` возвращает вопросы по важности; у каждого есть `apply(answer, code)`. `completeFromAnswers(code, answers, notation)` применяет ответы и проверяет результат парсером. Если ошибок стало больше или код не изменился, будет `ok: false`, а код останется исходным: плохой результат молча не возвращается.

**Почему порядок ответов не важен?** Строки ищутся по содержимому, а не по номеру.

**ИИ.** `tools/ai-questions.js`, маршрут `POST /api/ai/clarify`: модель добавляет до трёх вопросов и дорабатывает код. Без ключа или при сбое работает запасной вариант на правилах. В тестах ответ модели поддельный; настоящий ключ и вид диалога в реальном браузере на 375 px не проверялись (проверены разметка и поведение в jsdom). Правил для диаграмм классов и таймингов пока нет.

**Допиши при мне: новый вопрос.** В `diagram-questions.js` добавить правило, которое возвращает `{ id, kind: 'yesno', text: { ru, en }, target, priority, apply }`; `apply` возвращает новый код. Тест: код без нужного элемента даёт вопрос, ответ «да» убирает проблему.

### F4. Два языка (`docs/agent-reports/i18n-audit.md`)

**Как устроены языки?** `site/js/utils/lang.js`: `LANGUAGES = ['ru', 'en']`, первый язык исходный. `normalizeLanguage` для неизвестного кода даёт русский, `pageLanguage` берёт атрибут `lang` страницы, `pick(texts, code, params)` берёт текст из словаря `{ ru, en }` и подставляет `{name}`. ### F5. CI/CD (`.github/workflows`)

**Что запускается?** `ci.yml` на каждый push, pull request и вручную. Задачи: `test` (`npm ci`, `format:check`, `npm test`, `npm audit --omit=dev --audit-level=high`), `build` (`npm run build`, артефакт `dist` на 7 дней), `react` (тесты и сборка `react-app`), `e2e` (сайт на порту 5173, скрипты Playwright на Python, затем `e2e-gate.py` падает, если какой-то результат не Passed; Chromium вместо Edge). `pages.yml` публикует сайт на GitHub Pages при пуше в `main` и в `docs/overview-and-ab-tests` или вручную.

**Честно.** Зелёный запуск на серверах GitHub виден только в Actions; здесь описан файл, а не результат запуска. Секретов в CI нет.

**Допиши при мне: новая задача.** Блок в `jobs:` с `runs-on: ubuntu-latest`, `timeout-minutes`, шагами `actions/checkout@v4`, `actions/setup-node@v4` (`node-version: 24`, `cache: npm`), `npm ci` и командой. Пример: задача `lint` с `npm run format:check`.

### F6. Docker ЛР8: исправление образа backend (`part-2/lab-08-docker`)

**Три проблемы и решения.**

1. **sequelize-cli.** Контейнер на старте запускает миграции и сид (`CMD` в `backend/Dockerfile`), а `sequelize-cli` в ЛР3 это dev-зависимость, и `npm ci --omit=dev` её не ставит. Тогда `npx` пробует скачать пакет, а файловая система только для чтения. Решение: в стадии `deps` после `npm ci --omit=dev` ставится `sequelize-cli@6.6.5` (версия из lockfile) с `--no-save --no-package-lock --ignore-scripts`.
2. **Read-only.** В `docker-compose.yml` у `backend`: `read_only: true`, `tmpfs: [/tmp]`, `cap_drop: [ALL]`, `no-new-privileges`. Писать можно только в `/tmp`, поэтому скачивать на лету нельзя: всё ставится при сборке.
3. **DNS в Nginx** (`frontend/nginx.conf`). Обычный `proxy_pass http://backend:3000` разрешает имя один раз при старте: после пересоздания backend (новый адрес) будет 502 до перезагрузки Nginx. С `resolver 127.0.0.11 valid=10s;` и переменной `set $backend_upstream ...` Nginx спрашивает DNS Docker каждые 10 секунд. С переменной он сам не отрезает `/api/`, поэтому нужен `rewrite ^/api/(.*)$ /$1 break;`.

**Что ещё в образе?** Две стадии, пользователь `node` (не root), `HEALTHCHECK` на `/health`, `depends_on: condition: service_healthy`, БД во внутренней сети (`internal: true`), том `pgdata`, ротация логов, `limit_req_zone` 10 запросов в секунду на адрес, `client_max_body_size 100k`.

**Честно.** Ответ собран по тексту `Dockerfile`, `docker-compose.yml` и `nginx.conf`. Что полный `docker compose up` отработал на вашей машине, здесь не проверялось: подтверждённые запуски смотрите в `docs/study/17-LR8-DOCKER.md` и отчёте ЛР8.

**Допиши при мне.** (а) Поменять порт: в `docker-compose.yml` frontend слушает `'${FRONTEND_PORT:-8080}:8080'`, достаточно `FRONTEND_PORT` в `.env`. (б) Добавить сервис: блок рядом с `redis`, с `profiles`, чтобы он не стартовал по умолчанию. (в) Объяснить, почему запуск падает без `POSTGRES_PASSWORD`: запись `${POSTGRES_PASSWORD:?...}` останавливает его намеренно.

### F7. Ограничитель частоты запросов и журнал ЛР3 (`part-2/lab-03-auth/src/middleware`)

**Ограничитель (`rate-limit.js`).** `createRateLimiter({ windowMs, max, now })`: счётчик с фиксированным окном на адрес клиента (`req.ip`). Пример: `max = 5`, окно одна минута: шестой запрос за минуту получает ошибку 429 `tooManyRequests` с числом секунд ожидания (`src/errors.js`). Состояние в памяти, значит на процесс (так записано в `AUDIT.md`). Время передаётся параметром `now`, поэтому тест не ждёт реальных минут.

**Защита от переполнения.** `makeRoom`: при 10 000 ключей сразу удаляется самая старая десятая часть (`Map` помнит порядок вставки), память не растёт бесконечно.

**Блокировка входа.** `createLoginGuard({ maxAttempts, lockMs })`: `fail(email)` считает неудачи, после `maxAttempts` ключ заблокирован на `lockMs`, даже при верном пароле; `succeed` сбрасывает счётчик; `retryAfter` отдаёт секунды ожидания. Ключ контроллер строит из адреса и email, известного или нет, поэтому ответ не показывает, какие email существуют. Лимиты берутся из `limits.json` (в `app.js`: `loginRateMax`, `loginMaxAttempts`, `loginLockMinutes`, `registerRateMax`).

**Заголовок `Retry-After`.** Уже есть: `src/middleware/error-handler.js` ставит его из `err.retryAfter`.

**Почему `TRUST_PROXY`?** За Nginx адрес клиента иначе всегда один, адрес прокси. В `app.js` `app.set('trust proxy', ...)`, в compose `TRUST_PROXY: '1'`.

**Журнал (`request-log.js`).** Вариант 26 чётный: журнал пишется в таблицу БД `RequestLog`, не в файл. Запись создаётся до маршрута; если не удалась, ошибка идёт в обработчик ошибок и клиент видит страницу 500. Статус дописывается после ответа (`res.on('finish')`), по возможности. `clean` заменяет управляющие символы на `?` (иначе перевод строки подделал бы строку журнала) и режет длину до 200; строку запроса журнал отбрасывает, в ней могут быть токены. Хранение 30 дней: `purgeOldLogs` при старте и раз в час (`startLogRetention`).

**Допиши при мне.** (а) Изменить лимит: поменять число в `limits.json`, код не трогать. (б) Новое поле журнала, например `userAgent` (сейчас его нет): новая миграция по образцу `migrations/20261016000004-create-request-logs.js`, поле в `models/request-log.js`, в `RequestLog.create` передать `clean(req.get('user-agent') ?? '', 200)`.

**Честно.** Здесь код только прочитан и описан, тесты ЛР3 в рамках этой правки документов не запускались.

### F8. Линтеры отчётов (`tools/lint-report.js`, `tools/part2/lint-report.js`)

**Что проверяют?** Markdown-отчёт на правила преподавателя: раздел «1 Цель работы» и «Заключение» (не «Выводы»), нет слов «также» и «были», нет ссылок вида «(см. рис.)», только «ёлочки», код не в основном тексте, рисунок не в приложении, подпись «Рисунок N – Описание» с большой буквы, перед рисунком есть словесная ссылка на него, подпись таблицы. Версия Части 2 в режиме `strict` добавляет: приложение называется «Приложение А (обязательное) Название», хотя бы одно приложение, на каждое есть ссылка в тексте, нет точки с запятой, предложение не начинается со ссылки на рисунок.

**Как устроено?** Объект `L` с правилами и сообщениями для `ru` и `en`, функция `lintReport(text, lang, { strict })` возвращает список сообщений об ошибках; пустой список значит, что замечаний нет.
