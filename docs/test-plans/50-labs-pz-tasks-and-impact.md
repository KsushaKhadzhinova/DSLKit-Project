### 1.5 Прочие связи [док]

- Версия ЛР3 из ветки `25` считается основной: в ней CORS и параметр `?search=`. ЛР5 использует этот сервер.
- ЛР8 включает копии ЛР1–ЛР5, а `docker-compose.yml` ссылается на пути ЛР3 и ЛР5: переименование переменных окружения ЛР3 ломает compose.
- ЛР6 содержит копии ЛР1 и ЛР2, заменённые актуальными (`25` = `26` = `28`).
- ЛР7 использует драйвер `mongodb` и токен входа, а не Mongoose.
- Курсовой: серверная часть выросла из ЛР3, клиентская из ЛР5 (в `course-app` `app.css` совпадает построчно с ЛР5 в нескольких местах); Postman-коллекция курсового (17 запросов) это копия ЛР3.
- Порты: ЛР2 `PORT=3000`, БД 5434; ЛР3 `PORT=3001`, БД 5433; клиент ЛР5 на 5178, ЛР4 на 5175; ЛР8 по умолчанию 8080 и 3000 (условие требует 80 и 5000).
- Файл `limits.json` встречается в ПЗ1, ПЗ2, ЛР3 и курсовом (сервер и клиент).
- Формат ошибок: ЛР1, ЛР2, ЛР3, ЛР6, курсовой отдают `{"error":"текст"}`, ПЗ2 и корневой API отдают `{"error":{"code","message"}}`, ЛР7 и ПЗ1 отдают HTML.
- Страницы ошибок 401/403/404/500/сеть сделаны только в `pz23` (`fe27e69`, `cb934b2`).

## 4. Порядок распространения изменения (процедура)

Для любого изменения из матрицы выполнять по шагам:

1. Определить тип по таблице раздела 2 (M1…M19) и выписать список затронутых работ.
2. Выбрать эталонную ветку (где менять первым). Для Части 2: ЛР1 и ЛР2 — группа `25`; ЛР3 — `25`; ЛР4 — `24`; ЛР5 — `25`; остальное — своя ветка. Для сайта — `testing-course-full`.
3. Внести правку и тест в эталон, прогнать там `npm test` по одному процессу.
4. Для каждой затронутой ветки: перенести коммит (`git cherry-pick <sha>`) в её отдельной рабочей копии (`git worktree add`), не в общем корне; при конфликте разбирать вручную, историю не переписывать.
5. Пересобрать затронутые отчёты (`node tools/build.js <папка>`, RU и EN), прогнать линтер.
6. Прогнать тесты каждой затронутой работы по отдельности и записать число (M18).
7. Обновить документы: README, `PROJECT-STATE.md`, таблицы в `00-project-checklist.md`, карточки защиты.
8. Показать результат владелице, пуш каждой ветки только по её слову.

Ограничения: на 70% недельного лимита остановиться; удаляющие команды Docker только с «да»; секреты не переносить в коммиты.
