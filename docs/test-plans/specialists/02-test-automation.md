Ручные тест-кейсы (TC-001…TC-224), чек-листы (CL-…) и матрица прослеживаемости лежат в `docs/testing-kulikov/` и здесь не повторяются, дальше на них даны ссылки по ID.

## 1. Роль и область

Инженер по автоматизации отвечает за то, чтобы проверки запускались одной командой, давали одинаковый результат на чужой машине и в CI, а их результат можно было положить в отчёт.

В области:

- Юнит-тесты корня на `node:test` и `jsdom` в `labs/**/*.test.js` и `tools/**/*.test.js` (97 файлов, порог покрытия 100 % по строкам, веткам и функциям).
- Тесты серверных и клиентских работ Части 2 в рабочих копиях `.claude/worktrees/` (`node:test`, Vitest) и `react-app/` (Jest).
- Сквозные проверки в `testing-course/full/*.py` и `static-sec-perf.js`, чек-листы `testing-course/lab2` и `lab3`.
- Контрактные проверки API отрисовки и серверных работ, коллекции Postman.
- CI в `.github/workflows/ci.yml`, формат `prettier`, линтер отчётов `tools/lint-report.js`.
- Тестовые данные, сиды, порядок запуска, отчётность прогона.

Вне области: ручные тест-кейсы и исследовательское тестирование (специалист 01), безопасность (03), доступность (04), нагрузка (05), содержание отчётов для преподавателя (08).

## 2. Что проверяет специалист

| Приоритет | Что проверяется                                                                                                                                                                          |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0        | `npm test` в корне зелёный и держит порог 100 %. `ci.yml` зелёный на ветке сдачи. Сквозной путь (регистрация, диаграмма, сохранение, выход, вход) проходит в `tc:full` без ручных правок |
| P1        | Нет нестабильных тестов, которые краснеют от нагрузки машины или заполненного `.env`. `tc:full` собирается целиком. Сценарии S1 и S13 зелёные. Результаты прогона лежат в отчёте         |
| P2        | Тесты серверных ветвей и клиентов Части 2 запускаются по одному и дают то же число тестов, что в аудите. Контракты API закреплены тестами. Кросс-браузерный прогон в Firefox и WebKit    |
| P3        | Мутационная проверка слабых мест (`tools/mutate.cjs`), единый `test:load`, JUnit-отчёт, ускорение прогона                                                                                |

Пороги: любой красный тест из P0 блокирует выпуск и сдачу, P1 закрывается до сдачи или записывается в известные дефекты с причиной, P2 и P3 идут в очередь.

## 3. План

### 3.1 Цели

Любое изменение в `site/`, `tools/`, `labs/` ловится автоматикой до ручной проверки. Красный результат всегда значит дефект продукта или теста, а не «машина занята» и не «в `.env` что-то лежит». Результат каждого прогона сохраняется файлом и попадает в документацию без правки руками.

### 3.3 Объём

Входит: все пункты раздела 1. Автоматизация в первую очередь для TC групп «Вход», «Регистрация», «Панель», «Проекты», «Редактор», «API» (TC-001…TC-196) по критическому пути, остальное по приоритету High из `docs/testing-kulikov/13-test-cases.md`.

Не входит: Kroki как внешний сервис (по `docs/testing-kulikov/10-test-plan.md` проверяется только поведение DSLKit при его недоступности) и нагрузка с тысячами пользователей (план 05).

### 3.4 Подход

- Один уровень отвечает за один риск, дублирование убирается: что покрыто юнит-тестом, в e2e не повторяется.
- Каждый тест независим: свой порт (`listen(0)` как в `static-sec-perf.js` и `lab3/run.js`), своя временная база, чистый профиль браузера.
- Ожидания в e2e строятся на состоянии (`wait_for_url`, видимость, число узлов), а не на `wait_for_timeout`. Сейчас в `scenarios-e2e.py` стоят фиксированные паузы, это кандидат на переделку.
- Красный тест сначала воспроизводится одной командой на одном файле, потом разбирается (причина: продукт, тест, данные, окружение), результат записывается в таблицу известных дефектов.
- Нагрузочные `spike` и тесты, зависящие от машины, живут отдельно от `npm test`.

### 3.6 Критерии входа

- Рабочая копия без чужих правок `site/` (в аудите красный `npm test` вызван правками другого агента в `site/js/script.js`), `npm ci` выполнен, Node не ниже 20.
- Для e2e: сервер сайта запущен, порт свободен, Edge установлен, `pip install playwright` выполнен.
- Для Части 2: свободная машина, Docker запущен, `.env` заполнен тестовыми значениями либо отсутствует (см. 4.9).

### 3.7 Критерии выхода

- `npm run format:check` и `npm test` зелёные, покрытие 100 %.
- `tc:full` завершается кодом 0, дополнительно запущены `critical-path-e2e.py`, `extra-e2e.py`, `palette-e2e.py`, `scenarios-e2e.py`, `click-everything.py`, каждый красный пункт исправлен или записан как известный дефект.
- Тесты Части 2 прогнаны по одному на свободной машине, JSON свежие, `04-full-test-documentation.md` пересобран после них.
