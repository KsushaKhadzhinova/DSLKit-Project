## 1. Роль и область

Ведущий QA отвечает за то, что продукт делает то, что обещано в требованиях, и не теряет данные пользователя. Его область: функциональное тестирование через интерфейс и через собственный API отрисовки, дымовые проверки каждой сборки, критический путь, регрессия после исправлений, исследовательские сессии, приёмочные проверки (UAT) по сценариям владельца, граничные значения и негативные сценарии. Вне роли (есть отдельные специалисты): безопасность, нагрузка, доступность, кросс-браузерная матрица, оформление. Они упомянуты только там, где функция без них не проверяется.

Что уже сделано до этого плана: 224 кейса, 100 % покрытие 102 требований (14-traceability-matrix.md, раздел 5), прогоны 20, 30, 41, 50, 70, 80, e2e-сценарии `testing-course/full/*.py`. Этот план закрывает четыре вида пробелов: функции, появившиеся после матрицы (раздел 3.3), устаревшие ожидания в кейсах, порядок и приоритеты прогона, критерии входа и выхода для релиза.

### 3.4 Подход

- Порядок слоёв: smoke, критический путь, затем P1 по разделам, затем P2/P3, затем исследовательские сессии, затем регрессия 4.K, затем UAT.
- Автоматизация используется там, где она уже есть: `npm test` (модульные), `npm run tc:full` (статический разбор, e2e редактора и входа, сборка отчёта), отдельные `testing-course/full/*-e2e.py`. Новые пункты выполняются вручную и становятся кандидатами на автоматизацию, когда пройдены дважды.
- Каждый найденный дефект оформляется по полям 10-test-plan.md (раздел 11) и получает следующий номер в новом файле отчёта прогона, старые отчёты не правятся.

### 3.5 Окружение и данные

- Сервер: `npm start` (порт 5173, `tools/serve.js site 5173`). В старых документах указан 5190, перед прогоном привести к одному порту и записать его в протокол.
- Браузеры: Chrome и Edge (основные), Firefox, WebKit (выборочно, детали у специалиста по совместимости). Окна: 375, 768, 1366 px. Темы: светлая, тёмная. Языки: ru, en.
- Данные: пустой профиль (`localStorage.clear()`), пользователи A и B из 13-test-cases.md (тестовые значения), набор DSL из 12-test-design.md, учётная запись с ролью admin: данные лежат в локальном файле владельца и не попадают в репозиторий.
- Время: суточная квота и корзина 30 дней проверяются сдвигом полей `created`, `trashedAt` в ключе `projects.<id>`.
- Для автоматического построения нужен ключ в `.env` владельца и команда `npm run start:ai`. Без ключа проверяется только запасной режим «по правилам». Ключ в чат и репозиторий не попадает.

## 5. Как запускать

Все команды из `package.json` корня, если не указано иное. Сервер сайта запускают в отдельном окне терминала.

```bash
npm install                      # один раз
npm start                        # сайт на http://localhost:5173 (tools/serve.js site 5173)
npm run dev                      # то же с перезапуском при правках
npm run start:ai                 # с файлом .env, нужен для автоматического построения (QF-NEW-10)
npm run build && npm run start:prod   # проверка собранной версии из dist/
npm test                         # модульные тесты labs и tools, пороги покрытия 100 %
npm run format:check             # проверка форматирования
npm run react:test               # тесты react-app
npm run tc:lab2                  # кейсы формы заявки (QF-LND-02…05)
npm run tc:lab3                  # дымовой (8) и критического пути (36) чек-листы
npm run tc:full                  # статический разбор, e2e редактора и входа, сборка отчёта
python testing-course/full/critical-path-e2e.py   # критический путь (QF-CRP)
python testing-course/full/editor-e2e.py          # редактор (QF-EDT)
python testing-course/full/auth-e2e.py            # вход и регистрация (QF-AUT)
python testing-course/full/palette-e2e.py         # палитра (QF-EDT-06, 07)
python testing-course/full/scenarios-e2e.py       # сценарии, на последнем известном прогоне часть была красной, проверить
python testing-course/full/extra-e2e.py          # также click-everything.py, node static-sec-perf.js
npm run lab1:report ... npm run lab8:report       # сборка отчётов ЛР1…ЛР8 Части 1
```

Для API: `curl -s http://localhost:5173/api/notations`, `curl -s -X POST -H "Content-Type: application/json" -d "{\"source\":\"diagram idef0\"}" http://localhost:5173/api/render` (пример источника уточнить по `npm run dsl:reference`). Справочник DSL: `npm run dsl:reference`. Лабы Части 2 и курсовой проект: в рабочей копии нужной ветки (`E:\DSLKit-Project\.claude\worktrees\`) `npm install`, затем `npm test` и `npm start` или `npm run dev` в папке лабы. Для e2e нужен Python 3.10+ с Playwright и установленным браузером Edge (требование скриптов `testing-course/full/*.py`).

Порядок прогона: A, затем B, C и D, E, F, G, H, I, J, затем K и L, затем M, затем N, затем O (параллельно с остальным, отдельный тестировщик).
