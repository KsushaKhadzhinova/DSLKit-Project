# 06. Совместимость, адаптивность и локализация: тест-план и чеклист

Проект DSLKit, ветка `testing-course-full`. Сайт `site/` (русский в корне, английский в `site/en/`), страницы приложения `site/app/*` и `site/en/app/*`, сборка `dist/`. Документ не повторяет найденное, а ссылается на него: матрица и баги `docs/testing-kulikov/70`, `71`, аудит вёрстки `95`, проверка глазами пользователей `92`, быстрый прогон Firefox и Edge `docs/metrics/browsers`, скрипт `tools/evidence/cross2.mjs`, снимки `docs/testing-kulikov/screens-devices`.

## 1. Роль и область

Специалист по совместимости, адаптивности и локализации отвечает за то, чтобы одни и те же сценарии давали одинаковый результат в разных браузерах, на разных экранах, в двух языках и двух темах.

В области: браузеры и движки Blink, Gecko, WebKit (десктоп и мобильные), брейкпоинты 576, 768, 1024 px (в CSS только `min-width`), ориентации, масштаб до 400 процентов, плотность пикселей и 4K, светлая и тёмная тема с `prefers-*` и `forced-colors`, поддержка возможностей (`color-mix`, `clamp`, `:has`, `dvh`, логические свойства, File API, Service Worker, WebCrypto, Pointer Events), ввод мышью, касанием и клавиатурой, перетаскивание блока, экспорт и импорт файлов, `localStorage`, PWA и офлайн, печать, локализация RU и EN (полнота, переключение, длина строк, даты и числа, `hreflang`, `canonical`), разметка для поисковиков и валидаторы W3C.

Вне области: производительность (отдельный специалист), безопасность и доступность по WCAG в полном объёме. Пересечения с доступностью даны только там, где они зависят от устройства (цели касания, масштаб, контраст темы).
Уже сделано и не повторяется: прогон Chromium 153, Edge 156, Chrome 156 по устройствам (файл 70), 8 дефектов BUG-CB-01..08 (файл 71), аудит CSS и HTML (95: CSS-01..21, HTML-01..04), Firefox 157 и Edge 155 на 20 проверках (`docs/metrics/browsers`). Не сделано: Playwright Firefox и WebKit, настоящие iOS и Android, 360x640, 768x1024 в проверке персоны, альбомная 812x375, жест масштаба пальцами, экранная клавиатура, печать вне Chromium.

### 3.3 Подход

- Автоматизация: Playwright (Python, как в `testing-course/full`) гоняет цикл «движок × устройство × страница» и собирает ошибки консоли, горизонтальную прокрутку, снимки. Расширяет скрипты файла 70, у которых нет Firefox и WebKit.
- Живые браузеры: `tools/evidence/cross2.mjs` для обычного Firefox и Edge, где Playwright-сборка не стартует.
- Ручной проход по чеклисту раздела 4 на настоящих устройствах Tier 2: касание, экранная клавиатура, установка PWA, печать.
- Каждый дефект получает ссылку на BUG-CB, CSS или HTML из файлов 71 и 95, если он там есть, новые нумеруются BUG-CB-09 и далее в формате файла 71.
- Снимки называются `[dist-]браузер-устройство-экран.png`, как в `screens-devices`, сравниваются глазами. Проверка идёт на `site/` и на `dist/` (сборка `esbuild`), так как баги файла 70 воспроизводились на обеих.

### 3.4 Окружение

- Windows 11, Node 20 и новее, Python 3 с `playwright` 1.63, браузеры Playwright (`chromium`, `firefox`, `webkit`), установленные Chrome, Edge, Firefox.
- Сервер: `npm start` (`site/`, порт 5173) и `npm run start:prod` (`dist/`, порт 5173, по очереди).
- Локали: `ru-RU` и `en-US`, часовые пояса `Europe/Minsk` и `America/New_York` для проверки дат.
- Данные: чистый профиль для каждого прогона и отдельный прогон с заполненным `localStorage` (ключи с префиксом `dslkit.`, например `dslkit.projects.`, `dslkit.accounts`, `dslkit.tour-done`). Учётные записи только тестовые и локальные.
- Мобильные устройства: настоящие iPhone и Android, доступ к `http://<адрес ноутбука>:5173` по локальной сети. Для WebCrypto и Service Worker нужен защищённый контекст, поэтому на телефоне использовать туннель с HTTPS или `chrome://inspect` с пробросом порта.

### 3.5 Критерии входа и выхода

Вход:

- сборка стартует, `npm test` и `npm run format:check` зелёные, известен список изменённых файлов `site/`
- стенд свободен от посторонней нагрузки (в файле 70 нагрузка 100 процентов дала таймауты)
- браузеры Playwright скачаны и запускаются
  Выход:
- все пункты P0 и P1 чеклиста пройдены в Tier 1, у каждого пункта есть снимок или лог
- ноль ошибок консоли, кроме ожидаемой офлайн-ошибки запроса к `kroki.io/health`
- нулевая горизонтальная прокрутка документа на всех страницах и вьюпортах из 3.2
- открытые BUG-CB с приоритетом P0 или P1 отсутствуют, остальные заведены с владельцем
- не проверенное перечислено явно с причиной (как в разделе 7 файла 70)

## 5. Как запускать

Подготовка:

```
cd E:\DSLKit-Project
npm install
python -m pip install playwright
python -m playwright install chromium firefox webkit
npm start
```

Сайт на `http://localhost:5173`. Для `dist/` остановить сервер, затем `npm run build` и `npm run start:prod`.
Цикл «движок × устройство × страница» (Playwright, Python) собирает ошибки консоли и горизонтальную прокрутку:

```python
from playwright.sync_api import sync_playwright
BASE = "http://localhost:5173"
PAGES = ["/", "/en/", "/app/login.html", "/app/editor.html", "/en/app/editor.html"]
DEVICES = {"chromium": ["Pixel 7", "iPad (gen 7)"], "webkit": ["iPhone 13"], "firefox": []}
SIZES = [(320, 568), (375, 667), (768, 1024), (1366, 768), (1920, 1080)]
with sync_playwright() as p:
    for engine, devices in DEVICES.items():
        browser = getattr(p, engine).launch()
        contexts = [(d, browser.new_context(**p.devices[d])) for d in devices]
        contexts += [(f"{w}x{h}", browser.new_context(viewport={"width": w, "height": h})) for w, h in SIZES]
        for name, ctx in contexts:
            page = ctx.new_page()
            errors = []
            page.on("console", lambda m: errors.append(m.text) if m.type == "error" else None)
            for path in PAGES:
                page.goto(BASE + path)
                wide = page.evaluate("document.documentElement.scrollWidth > window.innerWidth")
                print(engine, name, path, "overflow" if wide else "ok", len(errors))
            ctx.close()
        browser.close()
```

Режимы (параметры контекста и страницы Playwright):

- тёмная тема: `new_context(color_scheme="dark")`, уменьшение движения: `reduced_motion="reduce"`, высокая контрастность: `forced_colors="active"`
- язык и пояс: `new_context(locale="en-US", timezone_id="America/New_York")`
- офлайн: `ctx.set_offline(True)` после первой загрузки и повторного захода, чтобы Service Worker успел установиться
- плотность: `device_scale_factor=2` или `3`, масштаб 200 процентов: окно 683x384 при `device_scale_factor=2`
- печать (только Chromium): `page.emulate_media(media="print")` и `page.pdf(path="print-index.pdf", format="A4")`
- касание: `new_context(has_touch=True, is_mobile=True)` (не в Firefox), жесты через CDP `Input.dispatchTouchEvent`, как в BUG-CB-01

Готовые прогоны:

- `python testing-course/full/editor-e2e.py http://localhost:5173` и остальные `*-e2e.py` (Edge), весь набор: `npm run tc:full`
- обычный Firefox и Edge через puppeteer-core: `npm install --no-save puppeteer-core` затем `node tools/evidence/cross2.mjs`, снимки пишутся в `docs/metrics/browsers`
- контраст токенов: `node --test tools/contrast.test.js`
- весь набор проекта: `npm test`, форматирование: `npm run format:check`

SEO и валидаторы:

- `npx html-validate "site/**/*.html"`
- `java -jar vnu.jar --skip-non-html site` (Nu Html Checker скачивается отдельно, в проект не входит)
- CSS: загрузить файлы в W3C CSS Validator (jigsaw.w3.org/css-validator), режим CSS уровня 3
- `hreflang` и `canonical`: `curl -s http://localhost:5173/en/ | grep -E "canonical|hreflang"` по каждой паре страниц, сравнить с `site/sitemap.xml`
- Schema.org: Rich Results Test, вкладка «Код», вставить HTML лендинга, и validator.schema.org
- Lighthouse: `npx lighthouse http://localhost:5173/ --only-categories=seo,accessibility,best-practices --preset=desktop` и то же без `--preset` для мобильного профиля
- русский текст в EN: `grep -rnP "[А-Яа-яЁё]" site/en` и построчный разбор остатка

Ручной проход на устройствах Tier 2: открыть сайт по HTTPS-туннелю и пройти разделы B, F, G, H, I. Установить PWA, отключить сеть, открыть `index` и `editor`. Повернуть устройство, вызвать клавиатуру в поле кода, перетащить блок пальцем. Результат занести с пометкой «реальное устройство» или «эмуляция».
