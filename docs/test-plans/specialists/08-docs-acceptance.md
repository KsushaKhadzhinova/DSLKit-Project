## 1 Роль и область

Роль: специалист по приёмке учебных работ и документации. Проверяет, что результат совпадает с условием преподавателя и с оформлением по Стандарту предприятия (редакция 2024), что отчёты собираются из шаблонов, что числа, ссылки и пути в документах не устарели, что русская и английская версии равны.

В область входят:

- Часть 1: `labs/01-network` ... `labs/08-frontend-testing` (корень, ветка `testing-course-full`), отчёты `report.md`, `report.en.md` из `report.tpl.md`, `report.en.tpl.md`.
- Часть 2: ЛР1-8 в ветках `lab21`, `lab12`, `23`, `24`, `25`, `26`, `27`, `28`, ПЗ1-4 в ветках `pz21`, `pz22`, `pz23`, `pz24`, отчёты PDF для ЛР2-8 и ПЗ1 в `E:\Downloads`.
- Курсовой проект: ветка `course-app` (`course-project/note.md`, `note.en.md`, `defence-cards.md`, `cheat-sheet.md`).
- МБП ЛР1 и ЛР2 (`E:\ИИТ\МБП_ЛР1`, `E:\ИИТ\МБП_ЛР2`), статьи ITS-2026 (`paper-its`, Overleaf).

- Условия: `materials/text/part-1`, `materials/text/part-2`, список файлов `materials/files.tsv`.

Вне области: исправление кода, оформление в Word и PDF (делает владелица), отправка в СЭО, публикация веток, слияние в `main`. Коммиты и пуши этим планом не выполняются.

## 3 План

### 3.1 Цели

1. Для каждой работы получить заполненную таблицу «условие, доказательство, статус» по разделу 4.
2. Подтвердить, что отчёты пересобираются из шаблонов и проходят линтер без ошибок.
3. Сверить числа тестов и покрытия в README, отчётах и записках с фактическим прогоном.
4. Свести открытые вопросы к преподавателю в один список с датой ответа.

### 3.2 Объём

Все работы из раздела 1. Для каждой работы единица проверки: пункт условия из `materials/text`, соответствующий файл отчёта, снимок, команда или ветка.

### 3.3 Подход

- Чтение условия, затем поиск доказательства в отчёте и в файле репозитория (путь от корня или от рабочей копии `.claude/worktrees/<имя>`).
- Автоматическая часть: сборка отчётов, линтер оформления, тесты отчётов, форматирование (команды в разделе 5).
- Ручная часть: титульный лист, оглавление, нумерация страниц, объём в Word, соответствие снимков тексту, приёмка в СЭО.
- Ссылки и пути проверяются поиском по `report.md` и README, затем открытием файла или команды `git branch --list`.
- Статусы: «- [x]» только при найденном доказательстве, рядом записывается путь. Если доказательства нет, пункт остаётся «- [ ]» с пометкой в столбце замечаний отчёта приёмки.

### 3.4 Критерии входа

- Выбрана рабочая копия и ветка, `git status` понятен, чужие правки не затронуты.
- Установлены зависимости (`npm ci` или `npm install`) в проверяемой папке.
- Машина свободна от тяжёлых процессов: аудит 29.10.2026 фиксировал таймауты воркеров при нагрузке, прогоны делать по одному.
- Доступны условия `materials/text` и файл `variant.json` (вариант 26).
- Заполнены локальные `.env` (значения не копировать в отчёты и в чат), либо тесты запускаются в чистом окружении.

### 3.5 Критерии выхода

- Все пункты P0 и P1 закрыты «- [x]» либо внесены в список открытых вопросов с владельцем и сроком.
- `npm test` в корне проходит, отчёты Части 1 и 2 совпадают с шаблонами, линтер без ошибок для ru и en.
- Числа тестов в README и отчётах совпадают с прогоном этого дня.
- Список вопросов преподавателю (раздел 4.14) отправлен владелицей, ответы внесены в `docs/PROJECT-STATE.md`.
- Итоговый отчёт приёмки сохранён вместе с датой и хэшем коммита каждой проверенной ветки.

## 5 Как запускать

Корень репозитория (ветка `testing-course-full`), команды из `package.json`:

```
npm ci
npm test
npm run format:check
npm run lab5:report
npm run react:test
git status --short labs
node --test labs/05-javascript-interactivity/report.test.js
node -e "import('./tools/lint-report.js').then(m=>console.log(JSON.stringify(m.lintReport(require('fs').readFileSync('labs/05-javascript-interactivity/report.md','utf8'),'ru'))))"
```

Сборка остальных отчётов: `npm run lab1:report`, `lab2:report`, `lab3:report`, `lab4:report`, `lab6:report`, `lab7:report`, `lab8:report`. Последние две команды блока проверяют тест отчёта одной работы и печатают результат линтера (пустой массив означает «замечаний нет», язык `ru` или `en`).

Часть 2, в папке `.claude/worktrees/<имя>/part-2/<папка>`, и сборка отчёта из корня рабочей копии:

```
npm ci
npm test
npm run lint
node --test report.test.mjs
node tools/build.js part-2/lab-01-node-server
```

Скрипта `lint` нет в ЛР4-ЛР8, ПЗ3, ПЗ4. В ЛР4, ЛР5, ПЗ3, ПЗ4 `npm test` запускает `vitest run`, затем `node --test report.test.mjs`. В ЛР8 тесты: `node --test docker.test.mjs hardening.test.mjs report.test.mjs`.

Курсовой (рабочая копия ветки `course-app`), поиск расхождений RU и EN, проверка веток:

```
cd course-project/app/server && npm test
cd ../client && npm test
git grep -n "TODO" -- course-project/note.md course-project/note.en.md
git grep -c "^!\[" -- "labs/*/report.tpl.md" "labs/*/report.en.tpl.md"
git branch --list lab21 lab12 23 24 25 26 27 28 pz21 pz22 pz23 pz24 course-app
git ls-remote --heads origin
```

Порядок: корень, затем рабочие копии Части 2 по одной, затем курсовой. Тяжёлые прогоны (PostgreSQL, MongoDB, нагрузочные) запускать отдельно. Значения из `.env` в отчёты не копировать.

Названия веток соответствуют таблице в `docs/HANDOVER-SESSION-2026-10-28.md`: ЛР1 `lab21` (`w-lab21`), ЛР2 `lab12` (`check-lab12`), ЛР3 `23` (`part2-server-labs-87ed8e`), ЛР4 `24` (`lab24-fix`), ЛР5 `25` (`lab25`), ЛР6 `26` (`part2-mongo-work-6cc76b`), ЛР7 `27` (`part2-ws-work-ee9b7b`), ЛР8 `28` (`lab28`), ПЗ1 `pz21` (`w-pz21`), ПЗ2 `pz22` (`check-pz22`), ПЗ3 `pz23` (`check-pz23`), ПЗ4 `pz24` (`w-pz24`), курсовой `course-app` (`angry-goldberg-bca72d`).
