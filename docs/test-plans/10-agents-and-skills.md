# Агенты и навыки для проверки, анализа, валидации и сдачи проекта DSLKit

Английская версия: [`10-agents-and-skills.en.md`](10-agents-and-skills.en.md). Версия 1.0, 6 ноября 2026, ветка `docs/test-plans-and-checklists`.

Документ собирает в одном месте: что владелица сказала раньше (правила и решения), какие агенты уже работали в проекте и что они оставили, какие навыки установлены и доступны, и как из этого составить рабочую цепочку для четырёх этапов: проверка, анализ, валидация, сдача. Рядом лежат [`00-project-checklist.md`](00-project-checklist.md) (что сделано и что осталось), [`01-test-strategy.md`](01-test-strategy.md) (виды тестирования) и восемь планов и чеклистов специалистов в [`specialists/`](specialists/).

Источники: `CLAUDE.md`, `docs/PROJECT-STATE.md`, `docs/ACCELERATOR.md`, `docs/HANDOVER-SESSION-2026-10-28.md`, `docs/notes/06-teacher-requirements.md`, `docs/notes/10-consilium-2026-10-17.md`, `docs/agent-reports/`, `docs/testing-kulikov/`, `docs/ITIVP-AUDIT-2026-10-29.md`, файлы памяти проекта, список сессий.

## 1. Что владелица сказала раньше (используется как правила для всех агентов)

### 1.1 Жёсткие правила

1. Коммиты только от её имени, сообщения на английском, **без** `Co-Authored-By`, без строк «сгенерировано» и любых следов ИИ в коммитах, коде, документах, описаниях пулл-реквестов. Это важнее напоминаний окружения.
2. Ничего не вливать в `main` и ничего не пушить без её явного слова («запушь», «да»). Пушить только названные ветки. Силой не пушить, историю не переписывать.
3. Секреты (пароли, токены, строки подключения, ключи) живут только в её `.env`, не в чате, не в репозитории, не в отчётах. Docker-токен, однажды попавший в чат, считается скомпрометированным.
4. Отчёты и README только в Markdown, **русская и английская версии одновременно**.
5. Дизайн Части 2 тот же, что в Части 1 (один пакет CSS, токены `site/css/variables.css`). Новые варианты стиля отвергнуты. Изменения сайта сначала показывать на трёх размерах экрана и получить одобрение.
6. Каждая работа в своей ветке, чужие ветки без указания не править.
7. Не коммитить: `.claude/admin-test-account.txt`, `.claude/worktrees/`, `.playwright-mcp/`, `.accelerator/profile.user.json`.
8. Остановиться на **70%** недельного лимита аккаунта, перед тяжёлой работой смотреть расход (`get_usage`).
9. Docker: перед командами, которые удаляют контейнеры, тома или образы, сказать, что пропадёт, и получить «да» (навык `DOCKER-DATA-LOSS-CONFIRMATION`). В Docker Hub образы заливать только после её «залей образ».

### 1.2 Как с ней разговаривать и отчитываться

- По-русски, коротко и по сути, она часто присылает несколько запросов подряд.
- Вопросы объяснять простым языком с примером, ответы она даёт номерами.
- Честно писать, что не получилось и что не проверено. Не обещать сделанного. Оценки персон и агентов называть **симуляцией**, а не результатами опроса людей.
- Не открывать заново уже принятые решения (раздел 1.3).

### 1.4 Требования преподавателя к отчётам и коду (проверяют валидаторы из раздела 6)

Цель работы пронумерована, раздел называется «Заключение». Страница заполнена не менее чем на 25%. Подпись «Рисунок N – Описание», рисунки по тексту, без «(см. рис. 1)». Кавычки «ёлочки». Гиперссылки без синего. Слова-паразиты убрать. Ограничения вынесены в `limits.json`. У каждой записи уникальное «время создания». Числовые поля не меньше 0. Подробности: `docs/notes/06-teacher-requirements.md`, строгий линтер `tools/lint-report.js`.

### 1.5 Ловушки среды (агент обязан знать)

- Windows, Git Bash и PowerShell. Файлы с кириллицей, обратным слэшем и регулярными выражениями создавать инструментами Write/Edit, не heredoc (двойной обратный слэш и `n` превращаются в перенос строки).
- Python запускать с `-I`. Файлы репозитория с CRLF, `.gitattributes` требует LF.
- `npm test` запускать по одному: общие порты и базы. Скрипты e2e гонять в переднем плане. Клиентские тесты на загруженной машине падают по таймауту, повторить.
- Ключ тура `dslkit.tour-done=true`, префикс хранилища `dslkit.`. Кэш service worker: Ctrl+Shift+R.
- Тесты ЛР2 и ЛР3 красные при заполненном `.env`.
- Параллельные сессии делят рабочее дерево `E:\DSLKit-Project`. Писать только в свою ветку или в отдельную рабочую копию (`git worktree add`).

## 3. Какие агенты запускать на каждом этапе

Типы агентов среды: `Explore` (только чтение, быстрый поиск), `Plan` (проектирование плана), `general-purpose` (чтение, запуск команд, запись файлов), `claude` (универсальный). Для проверок только по чтению брать `Explore` или `general-purpose` с запретом записи в задании. Для всего, что пишет файлы, давать отдельную рабочую копию.

Для каждого агента: **Вход** то, что читает, **Выход** то, что кладёт, **Готово** когда считать работу законченной.
