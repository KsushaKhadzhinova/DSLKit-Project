## 3 Решения владельца, зависящие от этой работы

**Журнал запросов в таблицу БД.** Требование преподавателя «чётный вариант: middleware логирования пишет запросы в таблицу БД, при сбое записи страница 500» относится к ПЗ1; для ПЗ2 условие прямо требует массив («Для хранения данных используйте временное хранилище в массиве»). Сейчас в API нет журнала запросов вообще (только запись непредвиденных ошибок в консоль).

| Вариант | Что делать | Трудозатраты | Риск |
| --- | --- | --- | --- |
| А. Оставить как есть (рекомендуется) | В отчёте и на защите сказать: ПЗ2 по условию в массиве, журнал в БД сделан в ПЗ1 | 0 | Преподаватель может спросить про журнал |
| Б. Журнал запросов в таблицу SQLite (`node:sqlite`, Node 22+) | Middleware пишет метод, путь, статус, время в таблицу `request_log`; при сбое записи ответ 500; тесты на сбой БД | 3–4 часа, 1 зависимость от версии Node (сейчас `engines >= 20`) | Выход за условие, данные ресурсов остаются в массиве, объяснять смесь; зависит от решения «SQLite или PostgreSQL» |
| В. Журнал в таблицу PostgreSQL | То же через `pg`, нужен сервер БД и Docker | 6–8 часов | Запуск с нуля усложняется, снимки структуры БД только владелец |

Не реализовано, пока владелец не выбрал. Если выберет Б или В, T38 обновит отчёт (раздел про хранение, скриншот таблицы).

## 4 Что нужно только владельцу: скриншоты

Сервер: `npm start` в `part-2/pz-02-rest-api`, затем в Postman импортировать `postman_collection.json` (переменные `root` и `base` уже заданы). В каждом кадре должны быть видны метод, URL, код ответа и тело.

Postman, не менее пяти разных операций (рекомендуется одиннадцать). Существующие рисунки 2 и 9–12 в отчёте записаны скриптом, а не окном Postman, и так подписаны; настоящие снимки владельца кладутся рядом под новыми именами в `part-2/pz-02-rest-api/figures/`, T38 вставит их в отчёт.

Данные в памяти: перед съёмкой перезапустить сервер (Ctrl+C и снова `npm start`), иначе `POST` и `DELETE` дадут другие числа. Один кадр окна Runner со всеми зелёными проверками (`postman-12-runner.png`) усилит отчёт.

Документация API: снимки Swagger UI (рисунки 15 и 16) делает `node shots/swagger-shot.mjs` (нужны сеть для CDN, `puppeteer-core` и Chrome). Владелец может заменить их своими снимками Swagger UI (импорт `http://localhost:3000/api/openapi.json`) под именами `swagger-01-list.png` и `swagger-02-post.png`.

### По одному снимку на каждый тип запроса (замечание преподавателя)

Минимальный набор, по одному кадру на метод API, имена из таблицы выше: GET (`postman-01-list-users.png`), POST (`postman-04-create-user.png`), PUT (`postman-07-put.png`), PATCH (`postman-06-patch.png`), DELETE (`postman-11-delete-204.png`). Остальные методы API: OPTIONS (`postman-13-options.png`, запрос Allowed methods with OPTIONS, 204 и заголовок `Allow`), HEAD (`postman-14-head.png`, 200 без тела). Условный запрос: `postman-15-stale-412.png` (Stale PATCH with If-Match, 412 `precondition_failed`). Чтобы его снять, сначала выполнить One user и убедиться, что заголовок `ETag` есть; в коллекции стоит заведомо устаревший тег.
