## 3 Только владелец

1. Установить Postman, импортировать `part-2/lab-01-node-server/postman_collection.json`, запустить `npm start` в папке работы.
2. `GET http://localhost:3000/diagrams`: снимок с адресом, статусом 200 и телом (две диаграммы).
3. `GET http://localhost:3000/diagrams/1`: статус 200.
4. `POST http://localhost:3000/diagrams`, Body → raw → JSON `{"title":"Login flow","notation":"UML","sourceCode":"user -> server","owner":"carol"}`: статус 201, во вкладке Headers виден `Location`.
5. `POST` с телом `{"title":"   ","notation":"XYZ","sourceCode":"x","owner":"o"}`: статус 400 и список `details`.
6. `PUT http://localhost:3000/diagrams/1` с полным телом: статус 200.
7. `PATCH http://localhost:3000/diagrams/1` с телом `{"priority":"high"}`: статус 200.
8. `GET http://localhost:3000/diagrams/99`: статус 404.
9. `DELETE http://localhost:3000/diagrams/2`: 204, затем повтор: 404.
10. На каждом снимке видны метод, адрес, тело запроса и статус. Заменить рисунки 6–8 в `figures/` и пересобрать отчёт командой `node tools/build.js part-2/lab-01-node-server`.
11. Создать и запушить ветку `lab21` с содержимым папки (имя из условия не менять).
12. Если выбран вариант с БД: снимки структуры таблицы (pgAdmin или DBeaver) и результата запроса `SELECT`.

## 4 Решения владельца: оба варианта

### (а) Данные ЛР1: массив или БД

| | Массив (сейчас) | БД |
| --- | --- | --- |
| Соответствие | условию ЛР1 («данные хранить в массиве»), прежнему решению | требованию преподавателя от 16.10 для чётного варианта |
| Трудозатраты | 0 | SQLite встроенным `node:sqlite` без новых зависимостей: около 0,5–1 дня (новое хранилище с тем же интерфейсом, асинхронный контроллер, тесты на временном файле, правка отчёта, README, разбора). PostgreSQL: около 1,5 дней плюс сервер БД |
| Риски | замечание преподавателя на защите | отчёт перестаёт совпадать с условием («массив»); ЛР2 теряет смысл как первая работа с БД; `node:sqlite` помечен экспериментальным; PostgreSQL усложняет запуск с нуля и скриншоты |
| Готовность кода | нет | `createApp(store)` принимает хранилище, маршруты и проверки не меняются |

Предложение без навязывания: спросить преподавателя, обязательна ли БД в ЛР1, раз условие говорит «массив».

### (б) Страница 500 от реального сбоя

Зависит от (а). Без БД реального сбоя нет, доказательство только тест с подменой хранилища. С БД сбой воспроизводится остановкой БД или запретом записи в файл, обработчик ошибок уже отдаёт 500 без внутреннего текста (около 0,5 дня на тест и описание в отчёте). Оформленная HTML-страница в ЛР1 не нужна: это JSON API, страницы 404 и 500 относятся к ПЗ1.

### (в) SQLite или PostgreSQL

Относится к ЛР2 и ЛР3; для ЛР1 важно только при выборе БД в (а).

### (г) Число контрольных вопросов

Условие даёт 16 вопросов, отчёт отвечает на 9, 10, 11. Если число иное, правится блок `{{answers}}` в обоих шаблонах (около часа).
