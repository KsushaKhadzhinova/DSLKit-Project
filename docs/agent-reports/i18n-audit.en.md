# Multilingual audit (RU / EN)

Scope: pages in `site/` and `site/en/`, error pages, components and modules in `site/js/`, documentation texts, manifest, service worker, sitemap, Open Graph. Terminology follows `docs/DSL-REFERENCE.md`.

## What was checked and how

- Pages: all 30 HTML files were parsed; the Russian and English copies were compared element by element (tags, attribute names, texts, `aria-label`, `title`, `placeholder`, `alt`, `data-tip`), the English pages were scanned for Cyrillic.
- Components and modules: every `{ ru, en }` dictionary (the `TEXTS`, `LABELS`, `MESSAGES`, `TEXT` tables, the notation messages, the knowledge bases, the decision tasks, the palettes) was compared key by key, with the `{placeholders}`; a scan of the sources found texts chosen by hand with `lang === 'en' ? ... : ...`.
- Documentation: `content.ru.js` against `content.en.js` (sections, headings, lists, code blocks, links, inline code, Russian words in the English text).
- Manifest, service worker, sitemap, `hreflang`, Open Graph, titles, descriptions.

## Guards (tests)

`labs/06-async-api-storage/i18n-parity.test.js`:

- every dictionary in the sources of `site/js` (found by scanning the top-level constants) and every `{ ru, en }` value exported by the modules has the same keys, types and `{placeholders}` in every language of `LANGUAGES`; the English text has no Cyrillic;
- the documentation has the same sections, `id`s and structure; the English text has Russian words only in code and in quoted examples;
- the page pairs have the same elements, attribute names and texts to translate; the English pages have no Russian text; every language link leads to the same page of the other language; `lang`, title, description, canonical and Open Graph of the indexed pages; the error pages; the sitemap; the manifests.

Also: `lang-switch.test.js`, `i18n-editor-en.test.js`, additions to `pwa.test.js` and `script.test.js`.

## How to add a third language (for example German, `de`)

1. `site/js/utils/lang.js`: add `'de'` to `LANGUAGES`. Run `npm test`: `i18n-parity.test.js` lists everything that is missing (dictionaries, pages, documentation).
2. Dictionaries: add the `de` key to every `{ ru, en }` object found by the test (components: `TEXTS`, `LABELS`, `MESSAGES`, `TEXT`; modules: `notations/messages.js`, `expert/*`, `decision/*`, `automation/*`, `utils/palette.js`, the notation names in `notations/index.js`). Keep the `{placeholders}`.
3. Texts translated by patterns: add `DE_RULES` to `utils/i18n.js` and register it in `RULES`.
4. Pages: copy `site/en/` to `site/de/`, set `lang="de"`, translate the texts, `aria-label`s and `title`s; add `<link rel="alternate" hreflang="de">` to all indexed pages, a language link `hreflang="de"` to every switcher, `site/de/manifest.webmanifest`, the Open Graph tags (`og:locale` `de_DE`), the entries of `sitemap.xml` and the pages of `sw.js` (`SHELL`). Adjust the `englishPages` helpers of the page tests (they compare each page with the Russian source).
5. Documentation: `site/js/docs/content.de.js` with the same `id`s; connect it where `content.en.js` is imported (`components/docs.js`).
6. The server and the API (`LANGS` in `tools/render-api.js`).
7. `npm test` and `npx prettier --check .` must stay clean.
