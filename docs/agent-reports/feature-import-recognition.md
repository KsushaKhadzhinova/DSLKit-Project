# Функция: импорт файлов диаграмм и распознавание картинок

## Что сделано

- `site/js/utils/diagram-file-import.js`: детерминированный импортёр без ключа. Свой небольшой читатель XML (без `DOMParser`), поэтому работает и в браузере, и в Node. Результат: `{ ok, notation, code, warnings }` или `{ ok: false, reason }` с причиной `no-structure`, `bad-file` или `unknown`.
- `site/js/automation/upload.js`: входная дверь мастера. Определяет формат по содержимому и по расширению, отклоняет файлы больше 10 МБ, берёт блок Mermaid, PlantUML, DOT или DSLKit из Markdown, а текст Mermaid, PlantUML и DSLKit отдаёт существующему импорту (`importDiagram`, он не переписывался). Результат проверяет `parseDiagram`.
- `tools/ai-vision.js`: подсказка для картинок (вид диаграммы, элементы, стрелки, соответствие фигур, `pos=XxY`), PDF как блок `document`, дополнительные проверки ответа (заголовок, хотя бы один элемент) и сообщение для повтора с ошибками парсера. Сам повтор (не больше двух) уже был в `tools/ai-api.js`.
- Мастер принимает все эти файлы на обеих вкладках; картинка, брошенная на вкладку кода, переключает вкладку на «Картинка», и наоборот.

## Форматы

| Формат                                                                      | Нотация                                                      |
| --------------------------------------------------------------------------- | ------------------------------------------------------------ |
| draw.io (.drawio, .dio, сжатый и обычный), SVG (draw.io, Graphviz, Mermaid) | блок-схема ГОСТ, BPMN (по фигурам `mxgraph.bpmn`) или граф   |
| JSON (nodes/edges/links, Cytoscape, Excalidraw, Lucid)                      | граф или блок-схема ГОСТ (поле `notation` учитывается)       |
| BPMN 2.0 XML                                                                | BPMN, `pos` из `BPMNShape`                                   |
| XMI (.xmi, .uml)                                                            | UML, диаграмма классов (имена, атрибуты, операции без типов) |
| GraphML, GEXF, DOT, CSV/TSV                                                 | граф                                                         |
| Visio (.vdx, .vsdx, первая страница)                                        | блок-схема ГОСТ или граф                                     |
| Mermaid, PlantUML, DSLKit, Markdown с блоком диаграммы, текст               | существующий импорт                                          |
| png, jpeg, webp, gif, pdf                                                   | только ИИ с ключом; BMP отклоняется с понятным сообщением    |

Правила выбора: диаграмма draw.io или JSON хотя бы с одной фигурой блок-схемы (ромб, параллелограмм, овал, цилиндр и т. д.) становится блок-схемой ГОСТ с `pos=XxY` (центры блоков, сдвинутые к левому верхнему углу). Если правила блок-схемы не выполнены (нет начала, конца, тупик), диаграмма рисуется как граф с предупреждением; только отсутствие подписи на ветви решения остаётся ошибкой парсера в списке проверки.

## Без ключа

Картинки и PDF требуют ключ на сервере; мастер говорит об этом в строке состояния и на вкладке «Картинка». Все структурные файлы работают без ключа.

## Правки общих файлов

- `tools/ai-api.js`: импорт `ai-vision.js`; в `IMAGE_TYPES` добавлено `...VISION_TYPES`; в `SIGNATURES` добавлено `...VISION_SIGNATURES`; `TASKS.image = VISION_TASK`; в `firstMessage` блок картинки это `visionBlock(mediaType, image)`; в `generate` вызов `visionIssues` после `problemsOf` и `retryMessage(...)` вместо встроенного текста.
- `site/js/components/automation.js`: импорты `upload.js` и `vsdxToXml`; новые тексты (`formats`, `bmp`, `too-big`, `no-structure`, `bad-file`, изменены `codeLabel`, `imageLabel`, `imageNoAi`, `imageType`); в `IMAGE_TYPES` добавлен PDF; `CODE_ACCEPT` заменён на `ACCEPT`; подсказка под полем показывает форматы; `buildFromCode` заменён на `await importUpload(...)`; `takeFile` переписан и выбирает путь по виду файла.
- `tools/dsl-reference.js`: раздел «Импорт файлов и картинок»; `docs/DSL-REFERENCE*.md` пересозданы.

## Не проверено

- Читатели SVG Graphviz и Mermaid написаны по известной структуре этих экспортов, на реальных файлах каждой версии не проверялись.
- Сжатие draw.io проверено через `deflateRaw` Node; в браузере используется `DecompressionStream('deflate-raw')`, в настоящем браузере не запускалось.
- XMI из Enterprise Architect (нестандартные расширения) не поддерживается.
- Распознавание картинок не запускалось с настоящим API Claude (здесь нет ключа); запрос и повтор проверены только на поддельном сервере.
- BMP и SVG как картинка ИИ не отправляются (API не принимает BMP); SVG читается как структурный файл.
