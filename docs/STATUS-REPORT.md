## 2 Цель, контекст, правила

Студентка БГУИР, дисциплина «Интернет-технологии и веб-программирование» (ИТиВП), вариант 26 (чётный). Все работы выполняются на одной теме: DSLKit, веб-редактор диаграмм «как код». Параллельно ведётся дипломный замысел на том же продукте, защита запланирована на июнь 2027.

Правила владельца:

1. Коммиты только от имени владельца, на английском, без меток ИИ и без `Co-Authored-By`.
2. Каждая работа в своей ветке, в `main` ничего не вливается без явного «да». Очистка истории принудительной отправкой тоже только после отдельного «да».
3. Секреты только в `.env` на машине владельца.
4. Отчёты и README только в Markdown, русская и английская версии одновременно.
5. Дизайн Части 2 тот же, что в Части 1 (общие токены `site/css/variables.css`).
6. Каждая работа покрыта тестами. Для Части 1 порог 100% строк, ветвей и функций.
7. Отчёты проверяет строгий линтер `tools/lint-report.js`, после правки кода отчёт пересобирается командой `node tools/build.js <папка>`.
8. Любые действия на GitHub и в Figma только с разрешения владельца.

- Большие heredoc с кириллицей и обратными слэшами в оболочке ломаются: файлы создавать редактором.
- Два прогона `npm test` одновременно мешают друг другу.
- Тур редактора открывается при чистом хранилище, скрипты съёмки сначала записывают `dslkit.tour-done`.
- Kroki иногда отвечает ошибками. Docker Desktop запускается долго, порт 5432 занят PostgreSQL из WSL, в Compose порт берётся из `POSTGRES_PORT`.
- Галереи логотипов держать вне `site/`: проверки считают каждую HTML-страницу в этой папке.
- Среда блокирует `Remove-Item` в каталоге проекта (для удаления файлов использовался `[System.IO.File]::Delete`).

## 11 Чек-лист решений и действий

Нужны решения владельца:

1. Версия роутера в курсовом: 6.30.6 или 7.18.4 (раздел 5).
2. Запушить ветки `docs/mbp-lr1` и `docs/mbp-lr2`.
3. Слияние веток работ в `main`, затем отдельное «да» на очистку истории от следов ИИ принудительной отправкой.
4. Собственные шрифты, финальная палитра.
5. Количество сущностей в курсовом и судьба экрана администратора.
6. Тема и объём диплома с научным руководителем.

Нужны действия владельца:

1. Скриншоты Postman и БД, Atlas, Docker Hub.
2. Firefox, Edge, PWA в Chrome, Rich Results Test.
3. Курсовой в Word: титульный лист, задание, содержание, источники, облачный деплой.
4. Открыть Figma один раз до полной загрузки и разрешить дозагрузку новых кадров.

Можно продолжить без владельца:

1. Дождаться трёх идущих сессий и проверить результат по diff.
2. Закоммитить документы и варианты логотипов.
3. Страницы ошибок по остальным клиентским работам.
