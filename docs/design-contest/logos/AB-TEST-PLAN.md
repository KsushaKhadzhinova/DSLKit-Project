# Логотип DSLKit — протокол A/B-теста

Правила логотипа с учётом протокола A/B-тестирования: логотип выбирается не «что красивее», а по влиянию на измеримую метрику. Выбранные знаки (`final/smile-block.svg` для сайта и фавикона, `final/cursor-drag.svg` для редактора) — это **контроль A**. Любой новый вариант делается как **B, отличающийся одним элементом**.

## Правила при создании вариантов логотипа

1. Между A и B меняется ровно одна вещь (форма, цвет, наличие улыбки, расположение слова). Если меняется силуэт и цвет сразу — непонятно, что дало эффект.
2. Один главный показатель. Побеждает только он; остальные — страховочные (guardrails).
3. Все версии готовятся в одном наборе: светлая, тёмная, одноцветная, 16×16 фавикон. B проверяется на тех же размерах и фонах, что и A.
4. Назначение пользователей случайное и «липкое» (хранится в `localStorage`), чтобы человек всегда видел один и тот же логотип.
5. Результат не смотрим до набора запланированной выборки (без «подглядывания»).

## Шаблон гипотезы

> Если в шапке сайта заменить логотип A («улыбающийся блок») на B (тот же блок без улыбки / с другим акцентным цветом — менять только одно), то CTR кнопки «Open editor» изменится на +10 %, потому что …(обоснование: контраст, узнаваемость, ощущение «личного приложения»).

## Параметры

| Параметр | Значение |
|---|---|
| Главная метрика | CTR кнопки «Open editor» (клик / уникальный посетитель) |
| Страховочные | доля отказов, время на странице, ошибки загрузки логотипа/фавикона |
| Baseline | 8 % |
| MDE | относительно +10 % (8 % → 8,8 %) |
| α / мощность | 0,05 / 0,80 |
| Разделение | 50/50, sticky |
| Длительность | не менее 14 дней или до расчётной выборки |

## Размер выборки

n на группу ≈ (z₁₋α/2 + z₁₋β)² · [p₁(1−p₁) + p₂(1−p₂)] / (p₂−p₁)²
= 7,84 · (0,0736 + 0,0803) / 0,000064 ≈ **18 850 посетителей в каждой группе** (≈ 37 700 всего).

Для учебного сайта такого трафика не будет. Поэтому:

- **Реалистичный вариант:** предпочтительный тест (5 секунд / «какой знак запомнился») на 30–50 респондентах как качественная проверка, а количественный A/B считать расчётным шаблоном.
- **Либо** брать только крупный эффект (MDE ≥ 50 % относительно), тогда n падает до ≈ 800 на группу.

## Решение

- B значимо лучше A и страховочные в норме → заменить логотип.
- B хуже или разницы нет → оставить A (уже выбранный владельцем).
- Результат записать в журнал эксперимента: гипотеза, варианты, даты, выборка, метрики, итог.

## Типичные ошибки (избегать)

Подглядывание за p-value, несколько изменений сразу, слишком короткий срок (меньше недели), нестабильное назначение варианта, игнорирование страховочных метрик, больше двух вариантов без поправки на множественные сравнения.

## Исправление к расчёту выборки

Если в других источниках встречается «≈3 900 на группу» для baseline 8 % и +10 % относительно, это ошибка: при δ = 0,008 знаменатель равен 0,000064, и результат ≈ **18 850** на группу (калькуляторы дают то же). 3 900 примерно соответствует относительному эффекту +20–25 %.

## Порядок проверок (не только A/B)

1. Техническая: 16/32/48 px, ч/б, тёмный фон, печать.
2. 5-second test на 5–8 людях из целевой аудитории (студенты, аналитики): что запомнили, чем занимается продукт, 3 слова.
3. Уникальность: reverse image search, TMview/WIPO, сравнение рядом с 5–10 аналогами из `docs/ANALOGS-AND-INSPIRATION.md`.
4. A/B на трафике — только если трафик достаточен, иначе пункты 1–3.
