# Бриф конкурса дизайна DSLKit

Продукт: DSLKit, веб-редактор диаграмм как кода (UML, BPMN, ERD, DFD, IDEF0, сети Петри). Часть 1 курса уже сделала сайт, но экраны приложения перегружены. Владелец: «интерфейс слишком перегружен, нужен единый стиль и чистота».

## Что проектировать
Два экрана приложения в трёх размерах (десктоп 1280x800, планшет 768x1024, мобильный 375x812), светлая тема основная, тёмная тоже:
1. `editor.html` — редактор: код DSL слева, диаграмма справа, список проблем (ошибки и предупреждения), файлы, запуск, сохранение, undo/redo, поделиться, автосохранение, выбор движка отрисовки (Kroki или локально), автораскладка, зум, история запусков, статус сервиса, квота беты 3 из 5, нижняя строка состояния.
2. `dashboard.html` — «Мои проекты»: поиск, фильтры по нотациям, сортировка, сетка карточек диаграмм, создание новой, меню карточки, боковая навигация (Мои проекты, Шаблоны, Общие, Корзина).
Обязательные данные: пример кода и ошибки смотри в `site/app/editor.html` и `site/app/dashboard.html`.

## От чего отталкиваться (прошлые макеты и интерфейсы)
- Дизайн-система Части 1: `site/css/variables.css` (токены, золотое сечение 1:1,618, шкала шрифтов √φ и φ, отступы Фибоначчи×8, радиусы 8/16/24, акцент синий #2563eb, светлая тема первой), `site/css/editor.css`, `site/css/app.css`.
- Текущие экраны: `site/app/editor.html`, `site/app/dashboard.html`, скриншоты `docs/approval-shots/part1/screens/` и `docs/approval-shots/part1/sheet-app-*.png`.
- Прошлые макеты: `site/design/mockups/` (галерея, `mockups-app`, `components`, `foundations`), `docs/project/ui-prototypes/` (варианты r2-app-dashboard, r2-app-editor, bento и др.), `docs/design-review/*.png`.
- Критика текущего редактора (измерено): 11 интерактивных элементов в шапке, 40 на экране, 13 стилей кнопок, число ошибок показано в 4 местах, три «главные» кнопки в разных стилях, много мелких целей (32 px), мелкий серый текст. Отчёты: `docs/agent-reports/usability-2026-10-16.md`, `design-metrics-2026-10-16.md`.
- Ранее показанные варианты редактора (владелец их отклонила, они слишком отличались от прежнего вида): `docs/approval-shots/editor-variants/`, `canvas-variants/`. Узнаваемость прежнего интерфейса надо сохранить: те же токены, логотип, тёмный блок кода, карточки с сеткой превью, пилюли-чипы.

## Жёсткие правила
- Одна главная кнопка на экран (заливка синим), остальные вторичные или иконки с подписью `aria-label` и подсказкой.
- Не больше 7 видимых управляющих элементов в верхней панели; остальное через прогрессивное раскрытие (меню «⋯», командная палитра, контекст).
- Число ошибок показывается один раз как сводка и один раз в самом коде (подсветка строки), без дублей.
- Цели касания не меньше 44x44 px, текст не меньше 14 px, контраст AA (4,5:1 для текста, 3:1 для элементов), видимое фокус-кольцо, `lang`, заголовки по порядку, не передавать смысл только цветом.
- Золотое сечение: колонки код:диаграмма = 1:1,618, шкала шрифтов и отступы из токенов, без произвольных значений.
- Мобильный: mobile-first, только `min-width` запросы по точкам 576, 768, 1024; один столбец, нижняя навигация или вкладки, без горизонтальной прокрутки.
- Все размеры в rem от плавного корня (`html { font-size: clamp(0.9375rem, 0.875rem + 0.25vw, 1.125rem) }`), цвета только токенами.
- Статичный HTML+CSS (JS минимально, только для меню/переключателей, если нужно), без внешних ресурсов, без шрифтов с внешних хостов.
- Нельзя менять файлы вне своей папки конкурса. Git не использовать.

## Как сдавать
В своей папке `docs/design-contest/<имя>/`: `editor.html`, `dashboard.html`, общий `style.css` (токены скопировать из `site/css/variables.css`), и `NOTES.md` (до 25 строк: идея, что убрано и куда переехало, число видимых элементов в шапке редактора, число стилей кнопок, как закрыты WCAG и золотое сечение). Затем запусти `node E:/DSLKit-Project/docs/design-contest/shoot.mjs <твоя папка>`, открой скриншоты в `shots/` (инструментом чтения изображений), найди и исправь дефекты (наложения, обрезка, горизонтальный скролл, слишком мелкий текст), снова сними. В финальный ответ: не более 10 строк.
