## 3 Аудит «как преподаватель»
Для своих работ найди и ИСПРАВЬ то, к чему мог бы придраться преподаватель по теории и условию. Проверь минимум: (а) безопасность: XSS (экранирование в шаблонах и React, innerHTML), внедрение в SQL и NoSQL-операторы, CSRF для форм, заголовки безопасности (Content-Security-Policy, X-Content-Type-Options, X-Frame-Options, Referrer-Policy; можно вручную middleware без новых пакетов), ограничение размера тела и числа запросов (rate limit на вход), утечки текста ошибок, пароли и хеши в ответах, секреты в репозитории, CORS не `*`, JWT (срок, алгоритм, секрет из окружения), небезопасный разбор JSON из localStorage, log injection (переводы строк в логах); (б) полнота условия: каждая пункт задач и дополнительное требование выполнены, README с запуском и именем ветки, `.env.example`, нет `.env` и секретов, тесты, сиды; (в) качество кода: комментарии, структура, обработка ошибок, согласованные коды ответов, идемпотентность сидов; (г) мелочи: опечатки, битые ссылки в README и отчётах, одинаковые проверки на клиенте и сервере, ответы на страницах 404 и 500 в стиле сайта. Каждую найденную проблему либо исправь с тестом, либо запиши в `AUDIT.md` в папке работы (проблема, риск, что сделано или почему не сделано, не более 1 строки на пункт, таблицей). Не выдумывай проблем: каждая должна быть подтверждена кодом или запуском.

## 4 Рабочие правила
- Работай ТОЛЬКО в указанной рабочей папке (git worktree) и только в папках своих работ. Git не использовать (ни commit, ни stash, ни checkout), коммиты делает владелец.
- Тесты проходят: `npm test` в папке работы. После правок отчётов: `cd <корень worktree> && node tools/build.js part-2/<папка работы>` (пересоберёт report.md и report.en.md из шаблонов), потом тесты проверят строгие правила отчётов (`tools/lint-report.js`). Отчёты и README на русском и английском. Не добавлять упоминаний ИИ в код, коммиты и документы.
- Секреты и ключи не писать нигде, в чат не просить. Базы только локальные (SQLite, in-memory, локальная Mongo, если уже настроена).
- Если меняется внешний вид, обнови README и шаблоны отчётов там, где они описывают интерфейс, а скриншоты в `figures/` пересними скриптом (кроме случаев, когда нужен браузер, которого нет).
- В конце: `NOTES.md` в папке работы (до 20 строк: что изменено, найденные проблемы, что осталось) и итог в ответе не более 12 строк с числами тестов.
