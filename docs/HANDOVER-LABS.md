Обновлено: 2026-10-11. Автор проекта: Ксения Хаджинова. Репозиторий: https://github.com/KsushaKhadzhinova/DSLKit-Project. Язык общения: русский.

## 1. Цель

Выполнить на теме проекта DSLKit (веб-IDE для диаграмм как кода):

- Часть 1 (`E:\ИТиВП\Часть 1`): лабораторные 1–8.
- Часть 2 (`E:\ИТиВП\Часть 2`): лабораторные 1–8 (Node.js, Sequelize, аутентификация, React-состояние, React и сервер, MongoDB, WebSocket, Docker), практические 1–4 (middleware и шаблонизаторы, REST API, маршрутизация React, состояние), курсовой проект.

## 2. Правила пользователя (обязательны)

- Комментарии в коде не писать. Лишнего кода не писать. Использовать подход ponytail (минимум кода, стандартная библиотека и платформа вперёд).
- Все лабы и практические полностью покрыты тестами (порог 100 процентов строк, ветвей и функций в `npm test`).
- Сначала изучать теорию, потом делать работу. Каждую работу валидировать с пользователем по очереди, задавать много вопросов.
- Интерфейс: сначала светлая тема, потом тёмная. Обязательны мобильная и десктопная версии. Закреплённая шапка сайта.
- Работы нельзя сломать, учитывать все случаи: ошибки с подробным пояснением, чтобы преподаватель не смог придраться или дать дополнительное задание.
- Отчёты Markdown на русском и английском, титульный лист для части 1 не нужен. Каждая ветка имеет README из 7 разделов: как запускать, архитектура, условие, термины, теория, рисунки и диаграммы, что делать пользователю. Добавлять сиды данных.
- Без AI-атрибуции в коммитах, коде и документах. Коммиты без соавторских строк. Коммитить часто, пушить на GitHub.
- Периодически открывать результаты в браузере и показывать пользователю.
- Экономить токены: лёгкие агенты и модели для механической работы.

## 3. Требования преподавателя к отчётам (из чатов потока)

Заголовки «1 Цель работы» и «Заключение» (вместо «Выводы»). Рисунки и номера подписей на одной строке, подпись «Рисунок N – Описание» с заглавной буквы и содержательная. Описание словами перед рисунком, без «(см. рис. 1)» и скобок. Без слов-паразитов «также», «были». Кавычки «ёлочки». Код только в приложениях, приложения небольшие и с точными названиями. Рисунки в тексте, не в приложениях. Каждую ошибку и функцию описывать с рисунком. Ответы только на контрольные вопросы n−1, n, n+1 своего варианта (номер варианта пользователь ещё не назвала). Практические: нечётные варианты логируют в файл, чётные в таблицу БД; страница 500; проверки значений формы (непустое, числа не меньше 0, уникальное поле времени создания). Все эти правила проверяет `tools/lint-report.js`.

## 5. Принятые решения

- Отчёты в Markdown, собираются из шаблонов командой `npm run labN:report`; код из приложений подставляется автоматически.
- ЛР3 и ЛР4: лендинг DSLKit в `site/` на русском и английском, светлая тема первой отдельным коммитом, тёмная вторым, переключатель темы без JavaScript (чекбокс и `:has()`).
- Ветки лаб идут от `main`, готовая лаба сливается в `main` после валидации пользователем (fast-forward). Условия ЛР3 и ЛР4 называют ветки `feature/semantic-markup` и `feature/responsive-layout`, ЛР5 `feature/javascript-interactivity`, ЛР6 `feature/async-api-storage`, ЛР7 `feature/react-components`, ЛР8 `feature/frontend-testing`.
- В `main` пустой стартовый коммит; docs-ветка не слита.
- Токены тёмной темы: `muted` изменён на `#8a8fa8`, потому что `#7f849c` давал контраст 4,44 (ниже AA).
- Скриншоты DevTools в ЛР1 не нужны, вместо них таблицы из HAR и графики.

## 6. Открытые вопросы к пользователю

1. Номер варианта (нужен для ответов n−1, n, n+1 и для чётного или нечётного логирования в Части 2).
2. Figma: запись в `bsuir-diploma` автоматически невозможна, встроенный браузер открывает файл гостем, расширение Chrome не отвечает. Нужен ручной вход пользователя и импорт SVG из `site/design/figma`.
3. Сливать ли `lab/02-environment` и `docs/overview-and-ab-tests` в `main`.
4. Файл `dslkit-ab-results.md` в корне рабочей папки не отслеживается (выгрузка пользователя).
5. Условия практических и ЛР Части 2 надо прочитать и задать вопросы перед началом.

## 7. Технические ловушки среды

- Оболочка Windows: команда `cd` в Bash меняет рабочую папку сессии, всегда начинать команду с `cd "E:/DSLKit-Project"`.
- Кириллица в PDF: `pdftotext` теряет буквы, использовать PyMuPDF (`import pymupdf`).
- Обратные слеши в heredoc и инструментах правки могут превращаться в переводы строк; для строк с `\n` использовать Edit и проверять результат.
- Git автоматически меняет переводы строк; в репозитории `.gitattributes` задаёт LF.
- Playwright 1.64.0 с Chromium лежит в `C:\Users\zheny\AppData\Local\ms-playwright`; в проект ставить ту же версию.
- Расширения VS Code из ЛР2 уже установлены у пользователя.
