# 62. Качество отрисовки диаграмм (33 нотации)

Дата проверки: 29.10.2026. Проверялся собственный движок (`site/js/notations/*.js`): для каждой из 33 нотаций взят шаблон из `templates.js`, получен SVG (тот же `renderNotation`, что и у `POST /api/render`), SVG отрисован в Chromium (Playwright) в светлой и тёмной теме и просмотрен глазами. Кроме шаблонов сделаны стресс-проверки с длинными подписями (`screens-render/stress-*.png`).

Файлы кода не менялись. Картинки: `docs/testing-kulikov/screens-render/<нотация>-light.png` и `<нотация>-dark.png` (по одной паре на нотацию), плюс `stress-*` и `editor-dark-arrowheads-missing.png`.

## Сквозные дефекты (затрагивают много нотаций)

### X1. Тёмная тема: чёрные стрелки, маркеры и подписи сливаются с фоном (P1)
Все цвета в SVG зашиты как атрибуты (`INK = #1e293b`, `MUTED = #475569`, `svg.js` строки 3-4). Правила тёмной темы в `site/css/editor.css` (1253-1275) перекрашивают только `fill` равный `ffffff`, `0f172a`, `475569`, `334155` и `stroke` равный `1e293b`/`334155`. Не покрыт `fill="#1e293b"` (256 вхождений в 33 шаблонах):
- наконечники стрел (`m-arrow`, `m-diamond-filled` в `svg.js` 14-30) исчезают, направление связей не читается во всех нотациях со стрелками (см. `editor-dark-arrowheads-missing.png`);
- тексты внутри узлов, написанные цветом INK (члены класса, подписи мест Петри, названия состояний и действий UML, названия в Activity) становятся тёмно-синими на тёмном фоне: `uml-class-dark.png`, `uml-activity-dark.png`, `petri-dark.png`;
- начальные точки UML, токены Петри, закрашенные ромбы композиции.
Правка: в `editor.css` добавить `.canvas__remote[data-engine='local'] svg [fill$='1e293b' i] { fill: var(--color-text-light); }` (и для `marker path`), либо перейти в `svg.js` на `currentColor`/CSS-переменные. Рядом: `--color-diagram-paper` в тёмной теме не переопределён (`variables.css` строка 12), для сквозной надёжности задать значение и в тёмной теме.

### X2. Рёбра рисуются одной квадратичной кривой без обхода узлов (P1)
`svg.js`, `edgeMarkup` (строки 156-205): кривая зависит только от числа «братьев» пары узлов, соседние по рангу и пропускающие ранг рёбра идут прямой через промежуточные узлы. Видно в `dfd` (поток 2 -> Customer идёт через все узлы и хранилище), `dag` (Lint -> Package под узлом Test), `uml-deployment`, `network`.
Правка: в `layout` (122-146) добавить фиктивные вершины для рёбер длиннее одного ранга и огибать их, либо вычислять опорную точку кривой, обходящую промежуточные узлы.

### X3. Подписи рёбер лежат прямо на линии и сталкиваются (P2)
`svg.js` 199-202: подпись ставится в точку кривой (`ly - 5`), размер 11 px, обводка белая 3 px. Подписи разных рёбер с одной серединой накладываются (`dfd`: «valid order» и «receipt» слиты в «valikreceipt»), подпись режется наконечником (`c4`: «writes diagram», «asks to draw», «reads and writes»), в UML-классе кратность склеена с именем: «1 contains 1..*» прорезана линией. В тёмной теме белая обводка подписи заменяется правилом `stroke ffffff -> surface` (строка 1273), это работает.
Правка: смещать подпись по нормали к линии, избегать столкновений с ранее поставленными подписями, отодвигать от маркера на длину маркера; кратности ставить у концов, а не в середине (`class.js`).

### X4. Генерический столбцовый макет вместо канонического направления (P2)
`layout` в `svg.js` всегда ранжирует слева направо. Для ГОСТ-блок-схем, оргструктуры, дерева решений, UML Activity канон: сверху вниз. Это же причина вытянутых по ширине диаграмм (`gost` 1100 px, `epc` 1250 px, `uml-activity` 1200 px).
Правка: параметр направления в `defineGraph` (`graph.js`), для gost/orgchart/activity/decision включить вертикальный поток.

### X5. Размер холста не пересчитывается по тексту (P1 для sequence, P2 для остальных)
`sequence.js` строка 75: `width = 120 + (участников - 1) * COLUMN`, подпись сообщения не измеряется. Длинная подпись выходит за левую границу и закрывает актёра (`stress-sequence-long-light.png`). `gost`/`decision`: текст не влезает в ромб (`stress-gost-long-light.png`), `mindmap`: узел с длинным текстом превращается в круг.
Правка: использовать `textWidth` из `common.js` для расчёта шага колонок и размеров ромба/эллипса (`sizer`/`ratioSize` в `specs.js`).

### X6. Служебное имя вместо пустой подписи (P2)
`graph.js` строка 25: `label = unquote(match[3] ?? match[2])` - если у узла нет подписи, берётся id. Поэтому шлюз BPMN без имени называется «g2», узел слияния Activity и Overview «m», сокет IDEF1X «ki». Правка: для kind-ов без обязательной подписи (merge, join, fork, gateway, junction) не выводить id, `caption(p)` в `svg.js`.

### X7. Нотации монохромные, цветовой семантики нет (P3)
Во всех нотациях только `#ffffff`/`#1e293b` (`strokeOf` в `svg.js` 42). У C4 нет различия Person/System/Container/External (канон: синий, серый), у BPMN нет цвета для событий. Не критично для читаемости, но заметно по сравнению с Kroki/Mermaid.
