# 02. Варианты использования DSLKit

Формат каждого варианта: актёр, цель, предусловия, основной поток, альтернативные потоки (допустимые ответвления), исключения (ошибки и сбои), постусловия, связанные требования. Номера шагов в альтернативах указывают, от какого шага основного потока они отходят. Идентификаторы REQ-xxx даны в `01-requirements.md`, сценарии SC-xx в `03-user-scenarios.md`.

Актёры: **Гость** (не вошёл), **Пользователь** (вошёл), **Внешний клиент API** (скрипт или программа), **Система** (браузер и сайт, действия без участия человека).

## UC-01 Регистрация

- **Актёр:** Гость.
- **Цель:** получить учётную запись, чтобы пользоваться разделом «Мои проекты».
- **Предусловия:** открыта `register.html`; браузер поддерживает Web Crypto (https или localhost); хранилище доступно.
- **Основной поток:**
  1. Гость вводит имя, почту, пароль, подтверждение пароля.
  2. Гость нажимает «Зарегистрироваться» (или Enter в поле).
  3. Система проверяет поля (REQ-002..005).
  4. Система отключает кнопку, вычисляет соль и хеш пароля.
  5. Система проверяет, что почта свободна, записывает учётную запись и сеанс.
  6. Система очищает поля пароля и открывает `welcome.html`.
- **Альтернативные потоки:**
  - 1a. Гость покидает поле с ошибкой: ошибка показывается сразу, при вводе перепроверяется (REQ-014).
  - 2a. Гость нажимает ссылку «Войти» и уходит на `login.html` (UC-02).
  - 6a. Пользователь на `welcome.html` переходит к проектам или в редактор.
- **Исключения:**
  - E1. Неверные поля: показаны ошибки у полей, фокус на первом неверном, сеанс не создан.
  - E2. Почта занята (в том числе зарегистрирована в соседней вкладке за время вычисления): сообщение «Аккаунт с такой почтой уже есть», фокус на почте.
  - E3. Нет Web Crypto: сообщение о https/localhost.
  - E4. Хранилище недоступно или заполнено: сообщение о хранилище, учётная запись не создана.
  - E5. Повторное нажатие во время вычисления игнорируется (REQ-016).
- **Постусловия (успех):** в `dslkit.accounts` одна новая запись без пароля в открытом виде, `dslkit.session` указывает на неё, меню шапки показывает имя.
- **Постусловия (сбой):** учётные записи и сеанс не изменены.

## UC-02 Вход

- **Актёр:** Гость. **Цель:** вернуться в свои данные.
- **Предусловия:** есть учётная запись; открыта `login.html`.
- **Основной поток:**
  1. Гость вводит почту и пароль.
  2. Нажимает «Войти».
  3. Система проверяет формат почты и непустой пароль.
  4. Система вычисляет хеш с солью учётной записи и сравнивает за равное время.
  5. Система записывает сеанс и открывает `dashboard.html`.
- **Альтернативные потоки:**
  - 1a. Почта введена в другом регистре или с пробелами по краям: приводится к виду хранилища, вход успешен.
  - 0a. Пользователь уже вошёл и открыл `login.html`: система сразу переводит его в «Мои проекты» (REQ-011).
- **Исключения:**
  - E1. Неверная почта либо неверный пароль: одно и то же сообщение, пароль очищен, фокус на пароле.
  - E2. Пустые поля: ошибки полей, фокус на первом.
  - E3. Нет Web Crypto или хранилища: сообщение причины.
- **Постусловия:** сеанс создан; при ошибке сеанс не изменился.

## UC-03 Выход

- **Актёр:** Пользователь.
- **Предусловия:** выполнен вход.
- **Основной поток:** 1) Пользователь открывает меню учётной записи. 2) Нажимает «Выйти». 3) Система удаляет сеанс, перерисовывает меню как гостевое. 4) Система открывает главную страницу.
- **Альтернативные потоки:**
  - 3a. В другой вкладке открыт тот же сайт: её меню обновляется по событию `storage` (REQ-013).
  - 4a. После выхода пользователь нажимает «Назад» (см. SC-05).
- **Исключения:** E1. Хранилище недоступно: сеанс может остаться; Система не должна показывать состояние «вышел», если запись не удалена. (Проверить.)
- **Постусловия:** `dslkit.session` отсутствует; проекты и шаблоны пользователя в хранилище сохранены.

## UC-04 Открыть «Мои проекты»

- **Актёр:** Пользователь (основной), Гость (исключение).
- **Предусловия:** открыт `dashboard.html`.
- **Основной поток:**
  1. Система проверяет сеанс (`data-requires-auth`).
  2. Система удаляет проекты, пробывшие в корзине 30 суток и более.
  3. Если список пользователя ни разу не создавался, Система создаёт 6 стартовых диаграмм.
  4. Система показывает карточки в порядке «сначала новые», применяет сохранённые фильтр, поиск, сортировку.
  5. Система показывает счёт квоты и число найденных проектов.
- **Альтернативные потоки:**
  - 4a. Пользователь переходит в «Мои шаблоны», «Общие», «Корзина» (заголовок и список меняются без перезагрузки).
  - 4b. В адресе `?q=текст`: поле поиска и список уже отфильтрованы.
- **Исключения:**
  - E1. Гость: переход на `login.html`, данные не показываются (SC-06).
  - E2. Повреждённое хранилище: пустой список и сообщение «Проектов не найдено», страница не падает.
- **Постусловия:** при первом открытии стартовые проекты записаны, флаг `seeded.<id>` стоит.

## UC-05 Смена пользователя на одном устройстве

- **Актёр:** Пользователь. **Цель:** убедиться, что данные разных людей не смешиваются.
- **Предусловия:** на устройстве две учётные записи А и Б.
- **Основной поток:** 1) А входит, создаёт проект, шаблон, ставит отметку. 2) А выходит. 3) Б входит. 4) Система показывает только данные Б (свои стартовые проекты). 5) Б выходит, А входит снова. 6) Данные А на месте.
- **Альтернативные потоки:** 3a. Б работает как гость в редакторе: проекты гостя лежат под ключом без владельца и не видны ни А, ни Б.
- **Исключения:** E1. Сеанс указывает на несуществующую запись (повреждён): Система считает пользователя гостем.
- **Постусловия:** ключи `projects.<id>`, `templates.<id>`, `likes-<id>`, `seeded.<id>` независимы.

## UC-06 Создать и сохранить проект

- **Актёр:** Пользователь.
- **Предусловия:** открыт `editor.html` без параметров (новая диаграмма) или с `?template=<имя>`.
- **Основной поток:**
  1. Пользователь вводит или меняет код.
  2. Система по таймеру (1 с после последнего изменения) создаёт проект с названием из заголовка диаграммы, если автосохранение включено.
  3. Система записывает идентификатор проекта в адрес (`?p=`), добавляет файл в боковую панель, показывает «Сохранено в «Мои проекты»: …».
  4. Дальнейшие изменения обновляют тот же проект.
- **Альтернативные потоки:**
  - 2a. Пользователь нажимает «Сохранить» или Ctrl+S: сохранение сразу, независимо от переключателя автосохранения.
  - 2b. Автосохранение выключено: проект создаётся только по 2a.
  - 1a. Пользователь открыл шаблон по `?my=<id>`: стартовый код взят из шаблона, сам шаблон не меняется.
  - 1b. Пользователь открыл шаблон по `?tpl=<id>`: сохранение обновляет шаблон, а не проект.
- **Исключения:**
  - E1. В коде нет заголовка: название «Без названия».
  - E2. Хранилище переполнено или недоступно: запись не выполнена, новый проект не появляется (фактическое сообщение для пользователя уточнить).
  - E3. Код с ошибками: проект всё равно сохраняется (код есть код), отрисовка показывает проблемы.
- **Постусловия:** в `projects.<id>` запись с `created`, `updated`; квота +1 на текущий день для новых проектов.

## UC-07 Открыть проект

- **Актёр:** Пользователь.
- **Предусловия:** есть хотя бы один проект вне корзины.
- **Основной поток:** 1) Пользователь нажимает название карточки (или файл в боковой панели редактора). 2) Система открывает `editor.html?p=<id>`. 3) Система показывает код, ставит имя файла в заголовок, запускает отрисовку.
- **Альтернативные потоки:** 1a. Переход по сохранённой ссылке или из закладки. 1b. Открытие карточки «Общего» примера (`?template=`).
- **Исключения:** E1. Идентификатор не найден, проект в корзине или чужой: открыта новая диаграмма и сообщение «Проект не найден». E2. Идентификатор с символами, требующими кодирования: проект всё равно открывается. E3. Карточка в корзине: ссылка отключена.
- **Постусловия:** проект не изменён, пока код не правили.

## UC-08 Переименовать проект

- **Актёр:** Пользователь.
- **Предусловия:** открыт список «Мои проекты».
- **Основной поток:** 1) Нажимает «⋯» у карточки. 2) Выбирает «Переименовать». 3) Вводит новое название в окне. 4) Система обрезает пробелы по краям, сохраняет название, обновляет время изменения, перерисовывает карточку.
- **Альтернативные потоки:** 3a. Название длинное: сохраняется целиком; карточка не ломает вёрстку. 3b. Название содержит разметку: выводится текстом.
- **Исключения:** E1. Отмена окна или пустая строка: ничего не меняется. E2. Проекта уже нет (удалён в другой вкладке): операция не выполняется, список обновляется.
- **Постусловия:** `title` и `updated` проекта обновлены; код проекта не менялся (название в коде диаграммы и название проекта могут разойтись до следующего сохранения из редактора).

## UC-09 Удалить проект, корзина

- **Актёр:** Пользователь; автоудаление выполняет Система.
- **Предусловия:** в списке есть проект.
- **Основной поток (удаление):** 1) «⋯» → «В корзину». 2) Подтверждение. 3) Система ставит отметку времени удаления, карточка уходит из «Мои проекты».
- **Основной поток (восстановление):** 1) Раздел «Корзина». 2) «Восстановить». 3) Проект возвращается в «Мои проекты» на своё место по времени изменения.
- **Альтернативные потоки:**
  - A1. «Удалить навсегда» → подтверждение → запись стёрта.
  - A2. «Очистить корзину» → подтверждение с числом → стёрты все проекты корзины.
  - A3. Автоудаление: при открытии «Мои проекты» Система стирает проекты, у которых прошло 30 суток и больше; на карточках корзины показан остаток дней.
  - 2a. Пользователь отказывается в подтверждении: проект на месте.
- **Исключения:** E1. Корзина пуста: кнопка «Очистить корзину» скрыта, показано «Проектов не найдено». E2. Часы устройства переведены назад или вперёд: срок считается по ним (граница 30 суток: на 29 суток 23 ч проект ещё есть). E3. Проект из корзины открыть нельзя.
- **Постусловия:** удалённый проект продолжает учитываться в квоте за день создания.

## UC-10 Работа с «Моими шаблонами» (создание, чтение, изменение, удаление, список)

- **Актёр:** Пользователь.
- **Предусловия:** раздел «Мои шаблоны» открыт.
- **Основной поток (Create):** 1) «Новый шаблон». 2) Вводит название. 3) Система создаёт шаблон на основе IDEF0 и открывает редактор в режиме изменения шаблона.
- **Поток Create из проекта:** «⋯» у проекта → «Сохранить как шаблон»: копия названия, нотации и кода.
- **Поток Read/List:** карточки шаблонов, счётчик «Найдено шаблонов», сообщение при пустом списке; шаблон открывается ссылкой `?my=<id>` как старт новой диаграммы.
- **Поток Update:** «Переименовать» (окно названия) или «Изменить шаблон» (редактор `?tpl=<id>`, сохранение обновляет шаблон).
- **Поток Delete:** «Удалить шаблон» → подтверждение «нельзя отменить» → стёрт без корзины.
- **Исключения:** E1. Пустое название в «Новый шаблон»/«Переименовать»: действие отменяется. E2. Шаблон не найден по `?tpl=`: новая диаграмма и сообщение. E3. Сохранение шаблона из проекта дважды: появляются два шаблона-копии с одним названием (идентификаторы разные).
- **Постусловия:** шаблоны не входят в квоту, не имеют корзины.

## UC-11 Работа с «Общими» примерами

- **Актёр:** Пользователь.
- **Предусловия:** раздел «Общие» открыт.
- **Основной поток:** 1) Система показывает по одному примеру на каждую нотацию. 2) Пользователь открывает пример (редактор `?template=<ключ>`) или раскрывает «⋯».
- **Альтернативные потоки:**
  - A1. «Сохранить копию в «Мои проекты»» → новый проект с кодом примера.
  - A2. «Добавить в «Мои шаблоны»» → новый шаблон.
  - A3. «Нравится» → отметка (♥, «В избранном») и копия в «Мои проекты»; повторное нажатие снимает отметку, копия остаётся.
- **Исключения:** E1. Повторное копирование того же примера: каждая копия новая запись; Система не предупреждает о дублях. E2. Повреждённый список отметок: считается пустым.
- **Постусловия:** отметки сохранены под `likes-<owner>`; общие примеры не изменяются.

## UC-12 Ввод кода и отрисовка в редакторе

- **Актёр:** Пользователь.
- **Предусловия:** открыт редактор.
- **Основной поток:**
  1. Пользователь вводит код вида `diagram <нотация> "Название"` и элементы.
  2. Нажимает «Запустить» или Ctrl+Enter.
  3. Система разбирает код, проверяет, рисует диаграмму выбранным движком, обновляет список проблем и палитру.
- **Альтернативные потоки:**
  - A1. Tab, Enter, `}` в поле кода выполняют отступы и автозакрытие.
  - A2. «Форматировать», «Сбросить расположение», «Проверить», «Копировать код» — каждое сообщает результат (в том числе «уже отформатировано»).
  - A3. Масштаб ±, «по размеру».
  - A4. Первый визит: показан тур из пяти шагов.
- **Исключения:** E1. Ошибки в коде: диаграмма не рисуется, фокус на первой проблеме. E2. Неизвестная нотация: сообщение о проблеме. E3. Пустой код: сообщение, что рисовать нечего. E4. Внешний движок недоступен: сообщение о таймауте/офлайне, предыдущий результат или кэш (если есть).
- **Постусловия:** код сохранён автосохранением (UC-06); холст показывает последнюю успешную отрисовку.

## UC-13 Добавить элемент из палитры

- **Актёр:** Пользователь.
- **Предусловия:** в коде распознана нотация.
- **Основной поток:** 1) «Элемент» открывает меню. 2) Пользователь нажимает пункт либо перетаскивает его на доску. 3) Система замораживает позиции существующих блоков (если элемент перетащен), добавляет строку в код, проверяет «воротами». 4) Код обновлён, диаграмма перерисована, сообщение «Добавлено: id».
- **Альтернативные потоки:** 2a. Escape или нажатие вне меню закрывает меню. 2b. При смене нотации в коде список пунктов меняется.
- **Исключения:** E1. Ворота отклонили (новая ошибка): код не меняется, сообщение с причиной. E2. Перетаскивание завершено вне доски: элемент не добавляется. E3. Нотация без палитры: меню пусто либо кнопка недоступна (проверить).
- **Постусловия:** новая строка в коде с уникальным id.

## UC-14 Соединить и переместить блоки

- **Актёр:** Пользователь.
- **Предусловия:** на доске минимум два блока.
- **Основной поток (соединение):** 1) Включает режим «Соединить», выбирает тип связи. 2) Нажимает исходный блок (Enter/пробел при управлении клавиатурой). 3) Нажимает целевой блок. 4) Система добавляет связь, проверяет воротами, перерисовывает: «Связь A → B добавлена».
- **Основной поток (перемещение):** перетаскивание блока мышью либо стрелки при выбранном блоке; положение записывается в код.
- **Альтернативные потоки:** 2a. Escape отменяет: «Соединение отменено». 1a. Повторное нажатие на кнопку режима выключает его.
- **Исключения:** E1. Связь недопустима для нотации (например, из блока в самого себя, дубль): ворота отклонили, сообщение с причиной. E2. Нажатие на пустое место доски в режиме соединения: выбор не меняется. E3. Блок перетащен за границу доски: остаётся в допустимой области (проверить).
- **Постусловия:** код содержит новую связь или новые координаты.

## UC-15 Переименовать и удалить элемент

- **Актёр:** Пользователь.
- **Предусловия:** на доске есть блок.
- **Основной поток (переименование):** 1) Двойной щелчок по блоку (или кнопка «Переименовать выбранный»). 2) Появляется поле, пользователь вводит подпись. 3) Enter подтверждает. 4) Система меняет подпись в коде, ворота, перерисовка: «Подпись элемента id изменена».
- **Основной поток (удаление):** 1) Выбрать блок. 2) Delete/Backspace или «Удалить выбранный». 3) Система удаляет элемент и связанные связи: «Удалено: id, связей: n».
- **Альтернативные потоки:** 3a. Escape в поле отменяет переименование.
- **Исключения:** E1. Блок не выбран: «Сначала нажмите на блок на доске». E2. У элемента нет подписи: сообщение, что имя меняется в коде. E3. Ворота отклонили подпись: «Подпись не изменена: причина». E4. Backspace при вводе в поле подписи или в коде не должен удалять блок (проверить).
- **Постусловия:** код согласован с доской; отмена возвращает прежний вид (UC-17).

## UC-16 Квота

- **Актёр:** Пользователь; Система показывает.
- **Предусловия:** любая страница приложения.
- **Основной поток:** Система считает проекты, созданные сегодня (по дате устройства), без стартовых, и пишет «Бета: сегодня создано N из 5» и заполняет полосу.
- **Альтернативные потоки:** A1. N больше 5: «лимит 5 в день превышен», полоса заполнена полностью, создание не блокируется. A2. Удаление проекта счёт не уменьшает. A3. Новый день по часам устройства: счёт начинается с нуля.
- **Исключения:** E1. На странице нет блока квоты: компонент ничего не делает.
- **Постусловия:** данных не меняет.

## UC-17 Отмена и возврат

- **Актёр:** Пользователь.
- **Предусловия:** открыт редактор.
- **Основной поток:** 1) Меняет код любым способом. 2) «Отменить»: Система возвращает предыдущее состояние кода и перерисовывает. 3) «Вернуть»: двигается вперёд.
- **Альтернативные потоки:** 1a. Новое изменение после отмены обрезает ветку «вперёд». 1b. История ограничена 100 состояниями, самые старые теряются.
- **Исключения:** E1. Нечего отменять / возвращать: сообщения «Отменять нечего», «Возвращать нечего». E2. Отмена после перезагрузки страницы: история пуста (она не сохраняется).
- **Постусловия:** код равен выбранному состоянию истории; автосохранение сохранит его.

## UC-18 Поиск, фильтр, сортировка

- **Актёр:** Пользователь.
- **Предусловия:** открыт любой раздел «Мои проекты».
- **Основной поток:** 1) Вводит часть названия в поле поиска (или Ctrl+K для фокуса). 2) Список сразу ограничивается подходящими. 3) Выбирает чип нотации или нотацию из списка. 4) Выбирает сортировку.
- **Альтернативные потоки:** A1. Enter в поле поиска из другой страницы приложения открывает «Мои проекты» с `?q=`. A2. Фильтр «Все» сбрасывает нотацию. A3. Выбор запоминается.
- **Исключения:** E1. Ничего не найдено: сообщение «Проектов не найдено» или «Шаблонов не найдено…». E2. Запрос из пробелов: считается пустым. E3. Спецсимволы регулярных выражений (`.*(`) в запросе ищутся как текст. E4. Поврежденное сохранённое значение фильтра: используются значения по умолчанию.
- **Постусловия:** сохранён объект `dashboard` с фильтром, запросом, сортировкой.

## UC-19 Экспорт

- **Актёр:** Пользователь.
- **Предусловия:** диаграмма нарисована на доске.
- **Основной поток:** 1) Открывает меню «⋯». 2) Выбирает формат (SVG, PNG, JPEG, draw.io, HTML). 3) Система готовит файл и запускает скачивание с именем из названия диаграммы. 4) Статус: «Файл … сохранён».
- **Альтернативные потоки:** 3a. Название содержит пробелы, юникод, эмодзи, символы пути: имя файла очищается до допустимого.
- **Исключения:** E1. Доски нет или не запущена отрисовка: «сначала нажмите Запустить». E2. Растеризация не удалась: «Не удалось подготовить файл». E3. Браузер блокирует скачивание: файл не появляется (проверить на сообщении).
- **Постусловия:** диаграмма и проекты не изменены.

## UC-20 Импорт

- **Актёр:** Пользователь.
- **Предусловия:** открыт редактор.
- **Основной поток:** 1) «Импорт из файла» (выбирает файл) или «Импорт из буфера». 2) Система определяет формат (Mermaid или PlantUML), переводит в код DSLKit. 3) Код заменяет текущий, диаграмма перерисовывается, статус «Импортировано: …» и список непереносимого.
- **Альтернативные потоки:** 2a. Импортирован собственный код DSLKit: вставлен как есть.
- **Исключения:** E1. Пустой текст: «нет диаграммы для импорта». E2. Формат не распознан. E3. Поддерживаемый формат, но неподдерживаемый тип диаграммы: сообщение с названием. E4. Нет доступа к буферу или файл нечитаем: «Не удалось прочитать файл или буфер». E5. Очень большой файл: поведение уточнить (время и память).
- **Постусловия:** прежний код можно вернуть отменой (UC-17).

## UC-21 Настройки: тема, язык, движок

- **Актёр:** Пользователь.
- **Предусловия:** открыта `settings.html` либо кнопка темы в редакторе.
- **Основной поток:** 1) Меняет тему (светлая, тёмная, авто). 2) Меняет язык, нажав ссылку RU/EN. 3) Меняет движок отрисовки. 4) Меняет остальные настройки редактора. 5) Система записывает выбор и применяет его, повторное открытие сохраняет состояние.
- **Альтернативные потоки:** A1. Язык меняют в редакторе: проект или шаблон из адреса остаётся открытым. A2. «Авто» следует системной теме; смена темы ОС меняет страницу.
- **Исключения:** E1. В сохранённых настройках неизвестное значение: берётся значение по умолчанию. E2. Другой компонент записал в `settings` между двумя изменениями (например, автосохранение): значения не теряются.
- **Постусловия:** `theme`, `settings` обновлены.

## UC-22 PWA и работа без сети

- **Актёр:** Система, Пользователь.
- **Предусловия:** сайт открыт хотя бы раз при сети (по https или localhost).
- **Основной поток:** 1) Система регистрирует service worker, кэширует оболочку. 2) Пропадает сеть. 3) Пользователь открывает страницы сайта и приложения. 4) Страницы берутся из кэша; собственный движок рисует в браузере.
- **Альтернативные потоки:** A1. Новая версия сайта: старый кэш удаляется при активации.
- **Исключения:** E1. Нет поддержки service worker: сайт работает как обычно без офлайна. E2. Регистрация не удалась: ошибка в консоль, сайт работает. E3. Внешний движок (Kroki) без сети: сообщение о недоступности. E4. Страница, которой нет в кэше: ошибка браузера «нет сети».
- **Постусловия:** данные пользователя (в `localStorage`) не зависят от кэша.

## UC-23 API отрисовки

- **Актёр:** Внешний клиент API. **Предусловия:** сервер запущен (`http://localhost:5190`).
- **Основной поток:** 1) `GET /api/notations?lang=ru` и `GET /api/grammar` возвращают справочники. 2) `POST /api/validate`, `/api/parse`, `/api/generate` с `{"source": "...", "lang": "ru"}` возвращают результат разбора. 3) `POST /api/render` возвращает JSON с SVG или сам SVG при `Accept: image/svg+xml`.
- **Альтернативные потоки:** A1. Язык `lang` не задан или неизвестен: язык по умолчанию. A2. `format` в `/api/generate` задаёт формат вывода.
- **Исключения:**

| Ситуация                            | Ответ                                   |
| ----------------------------------- | --------------------------------------- |
| Пустой или отсутствующий `source`   | 400, код `source`                       |
| Тело не JSON                        | 400, код `json`                         |
| `source` длиннее 100 000 символов   | 413, код `too-large`                    |
| Неизвестная нотация в `/api/render` | 422, `unknown-notation`, список проблем |
| Неверный метод                      | 405, заголовок `Allow`                  |
| Неизвестный путь `/api/...`         | 404, `not-found`                        |
| Внутренняя ошибка                   | 500, `internal`, без деталей            |

- **Постусловия:** сервер ничего не хранит; повтор запроса даёт тот же ответ.
