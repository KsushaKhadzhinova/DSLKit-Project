# Дефекты, найденные на сценариях сидов

Окружение: Windows 11, Chromium (Playwright), `http://localhost:5190`, RU и EN версии, сборка ветки `testing-course-full` на 29–30.10.2026.
Серьёзность: S1 критическая, S2 значительная, S3 средняя, S4 малая. Срочность: P1 высокая, P2 средняя, P3 низкая.
Данные для воспроизведения: файлы `scenario-N.json` (загрузка описана в `README-scenarios.md`).

## B-01. Страница проектов не запускается, если у проекта в корзине `trashedAt` не число

- Серьёзность S2, срочность P2. Сценарий 4, файл `scenario-4-corrupt-trashedAt.json`.
- Шаги: 1) загрузить файл; 2) открыть `/app/dashboard.html`; 3) нажать «Корзина».
- Ожидается: запись с некорректной датой пропущена или показана с запасным значением, остальные проекты видны.
- Фактически: в консоли `DSLKit: component initDashboard failed RangeError: Invalid time value` (`dashboard.js:124`, функция `time`), список и счётчик пусты (счётчик без текста), навигация по разделам не работает.
- Причина: `new Date(ms).toISOString()` для нечисла; `listTrash` и `expired` проверяют только `!== undefined`.

## B-02. Лимит «5 диаграмм в день» не применяется

- S3, P2. Сценарии 1, 3, 5.
- Шаги: создать шестой проект (или лайкнуть шестой пример).
- Ожидается: отказ или предупреждение до создания, если лимит заявлен как действующий.
- Фактически: создаётся без ограничений (33 лайка дали 33 проекта, всего 68); подпись «Бета: сегодня создано 68, лимит 5 в день превышен», шкала застывает на 5 из 5. Код и комментарий подтверждают «лимит только показывается». Нужно решение владельца: либо сообщать об этом в интерфейсе иначе, либо блокировать.

## B-03. Лайк примера тайно создаёт проект; снятие лайка копию не убирает; повторный лайк плодит копии

- S3, P2. Сценарий 5, раздел «Общие».
- Шаги: лайк примера, затем «Мои проекты»; снять лайк; поставить лайк снова.
- Ожидается: лайк только отмечает пример (или явно сообщает о копии); снятие лайка не оставляет побочных данных.
- Фактически: после лайка появляется проект (+1 к квоте); снятие лайка копию оставляет (33 проекта); новый лайк создаёт вторую копию (34).

## B-04. Повторное копирование без различения: десятки проектов и шаблонов с одинаковыми названиями

- S4, P3. Сценарии 3 и 5.
- Шаги: «Сохранить копию» и «Добавить в шаблоны» по каждому из 33 примеров, затем ещё раз.
- Фактически: 68 проектов при 30 различных названиях, 34 шаблона; нет «(копия)», нет предупреждения о том, что такой проект уже есть. Три проекта «Одинаковое» в сценарии 3 неотличимы в списке. Три примера называются «Checkout» (sequence, communication, timing), поэтому в списке «Общие» их различает только метка нотации.

## B-05. Удаление насовсем и автоочистка корзины уменьшают дневную квоту

- S3, P2. Сценарий 4.
- Шаги: создать 7 проектов за сегодня, удалить в корзину, довести три записи до 30 дней и открыть страницу.
- Ожидается: по комментарию в коде «удалённый всё ещё считается» квота остаётся 7.
- Фактически: после стирания квота «создано 4 из 5». Создание, удаление насовсем и новое создание обходит дневной лимит (если его начнут применять).

## B-06. Английская подпись корзины «erased in 1 days»

- S4, P3. Сценарий 4, EN. Для 29 и 29,9 дня показано «erased in 1 days», нужно «1 day». В русской версии «через 1 дн.» допустимо.

## B-07. Дата удаления в будущем даёт «будет стёрт через 35 дн.»

- S4, P3. Сценарий 4. При `trashedAt` на 5 дней вперёд срок больше 30 дней. Ожидается ограничение 30.

## B-08. Время на карточках в UTC, в редакторе местное

- S4, P3. Карточки показывают `toISOString` без пояса (например «2026-10-30 05:32»), строка статуса редактора — местное время («Сохранено 06:29»). Разница равна смещению пояса, пояс на карточке не указан.

## B-09. Поиск работает только по названию, не по нотации

- S3, P3. Сценарий 5, раздел «Общие»: запрос `uml` даёт «Проектов не найдено», хотя примеров UML двенадцать. Запрос по названию нотации ожидаем, так как на карточке она есть тегом.

## B-10. Незалокализованные названия

- S4, P3. 1) В русском интерфейсе названия общих примеров английские («Order process», «Choose a database»). 2) Проект с названием из пробелов получает «Без названия» при сохранении, и это русское слово видно в EN-интерфейсе (сценарий 3).

## B-11. Переименование в строку из пробелов молча отклоняется

- S4, P3. Сценарий 3: меню «Переименовать», ввод `   `, подтверждение: название не меняется, сообщения нет.

## B-12. Идентификаторы кириллицей отклоняются как ошибки, причина не очевидна

- S3, P2. Сценарий 1 (первый ввод). DFD `entity Клиент`, `flow Клиент -> 0`, ERD `entity Клиент {…}`, sequence `actor Клиент`, usecase `actor Клиент` дали 6, 8, 6, 17, 7 и 5 ошибок в панели проблем; те же диаграммы с латинскими идентификаторами и русскими подписями (`entity Client "Клиент"`) — 0 ошибок. Для студентов ИТиВП естественно писать русские имена; нужны либо поддержка, либо понятное сообщение «идентификатор должен быть латинским» (в справочнике DSL это не сказано явно). Текст самих сообщений в первом прогоне не сохранён, число ошибок зафиксировано по строке статуса.

## B-13. Сохранённое состояние поиска и фильтров остаётся между визитами

- S4, P3. Сценарий 1. Ключ `dslkit.dashboard` хранит запрос и фильтр; после перезагрузки или входа в другой раздел список уже отфильтрован («DFD»), а на новой сессии пользователь видит пустой или короткий список с заполненной строкой поиска. Сам по себе это может быть задумано, но при повторной загрузке сида без сброса список выглядит неполным.

## Наблюдения, требующие проверки (не доказаны)

- N-01. Периодические зависания загрузки страницы: `goto` не дошёл до события `load` за 20 с в редакторе, на `/en/app/dashboard.html`, регистрация не уложилась в 30 с (около пяти раз за 12 запусков, чаще при параллельных запусках). Повторение на пустом сервере не проверялось; возможен вклад параллельной работы над кодом.
- N-02. `fill` поля кода значением 107 КБ дважды завершился тайм-аутом «waiting for element to be visible, enabled and editable» (90 с), тогда как вставка того же текста через событие `input` рисует 1000 узлов за 2–8 с и открытие такого проекта занимает 2,2 с. Причина (замершая вкладка при записи, или артефакт инструмента) не выяснена.

## Что работает корректно

Регистрация и вход, 33 стартовых примера на первом входе (один раз, после удаления не возвращаются), раздельное хранение проектов и шаблонов по пользователям, поиск без учёта регистра и с обрезкой пробелов, фильтры и сортировки, шкала квоты, граница автоудаления (30 дней стираются, 29,9 остаются), восстановление и удаление насовсем, очистка корзины, лайк как переключатель, RU и EN подписи счётчиков, проект на 107 КБ (открытие 2,2 с, 1000 узлов, ошибок нет), отказ кнопки «Соединить» для недопустимой связи (`e → s`, в начальный узел не входят потоки), блокирующий шлюз при добавлении элемента.
