# Найденные дефекты при ручном заполнении сидов

Формат по Куликову: шаги, фактический результат, ожидание, серьёзность. Среда: Chromium (Playwright), `http://localhost:5190`, 1366x900, 29-30.10.2026. Метка «по коду» означает, что поведение выведено из исходников, а в интерфейсе подтверждено не полностью.

## BUG-01. Молчаливая потеря данных при переполнении localStorage

Серьёзность: критическая.
Шаги: 1. Войти пользователем В. 2. Открыть `editor.html?template=bpmn`, вставить диаграмму с двумя подписями по 300 тыс. знаков (около 500 КБ), подождать автосохранение. 3. Повторить для 15 проектов подряд, каждый раз открывая новый редактор.
Факт: проекты 1-9 сохранены (в хранилище около 5,0 млн знаков). С десятого запись не проходит, но строка статуса пишет «Сохранено в «Мои проекты»: Крупный проект 11», а адрес получает `?p=<id>`. В `localStorage` остаётся 10 проектов, «Мои проекты» показывает 10, проекты 10-15 потеряны. Ни ошибки, ни предупреждения нет.
Ожидание: при отказе записи показать явную ошибку («Не удалось сохранить: хранилище браузера заполнено»), не писать «Сохранено», сохранить текст в редакторе, предложить экспорт или очистку корзины.
Причина по коду: `storage.set` возвращает `false`, а `createProjectStore.save/write` результат не проверяют.

## BUG-02. Редактор зависает на больших диаграммах (время растёт быстрее линейного)

Серьёзность: высокая.
Шаги: открыть `editor.html?template=bpmn`, выделить код, вставить BPMN из N задач и N связей.
Факт: время обработки вставки: 10 задач 0,3 с, 25 задач 0,8 с, 50 задач 2,9 с, 100 задач 10 с, 200 задач (404 строки) 37 с; граф на 200 вершин (401 строка) 36 с. Вкладка не отвечает, переходы на другие страницы в это время упираются в таймаут 20-30 с.
Ожидание: диаграмма в 50-200 блоков обрабатывается за секунды, ввод не блокируется (отложенный разбор, ограничение частоты пересчёта).

## BUG-03. Заголовок с вложенными кавычками или обратной косой ломает проект и сбрасывает нотацию на IDEF0

Серьёзность: средняя.
Шаги: 1. Открыть `editor.html?template=erd`. 2. Заменить первую строку на `diagram erd "ERD "Магазин""` (аналогично `diagram uml-package "Пакеты \ backslash \n"`). 3. Подождать автосохранение, открыть «Мои проекты».
Факт: проект сохранён как «Без названия» с нотацией IDEF0, хотя исходник начинается с `diagram erd`. Чип ERD его не находит. В DSL нет способа записать кавычку в названии, подсказки об этом нет.
Ожидание: либо экранирование кавычек, либо понятная ошибка с сохранением нотации по ключевому слову `diagram erd`.

## BUG-04. Пустой или состоящий из пробелов исходник превращается в IDEF0 «Без названия»

Серьёзность: низкая.
Шаги: открыть `editor.html?template=erd` (или uml-class), стереть весь код, подождать автосохранение.
Факт: проект сохранён как «Без названия» с нотацией IDEF0 независимо от выбранной нотации. Три такие записи в сиде Б.
Ожидание: пустой черновик не сохраняется как проект либо сохраняется с исходной нотацией и пометкой «пустая диаграмма».

## BUG-05. «Нравится» создаёт копию в «Мои проекты», снятие лайка копию не убирает

Серьёзность: средняя.
Шаги: 1. «Общие» → меню карточки → «Нравится» (bpmn, erd, mindmap, c4, epc). 2. Открыть «Мои проекты». 3. Снять лайк у epc.
Факт: на каждый лайк добавляется новый проект (пять лайков и три копии дали 65 → 73). Снятие лайка проект не удаляет, повторный лайк делает ещё одну копию. Для копирования есть отдельная команда.
Ожидание: лайк только помечает пример, копия создаётся командой «Сохранить копию».
По коду: ветка `like` в `dashboard.js` вызывает `store.save(copy)` без id.

## BUG-06. Квота «5 диаграмм в день» ничего не ограничивает

Серьёзность: низкая (бета).
Шаги: создать больше пяти проектов за день.
Факт: подпись «Бета: сегодня создано 53, лимит 5 в день превышен», создание продолжается без блокировки и предупреждения.
Ожидание: либо блокировка с объяснением, либо формулировка «лимит пока не применяется».

## BUG-07. В интерфейсе нет публикации проекта

Серьёзность: низкая.
Шаги: искать «Опубликовать» в меню карточки проекта и в редакторе.
Факт: действия нет, бейдж «опубликован» показывается только у части стартовых проектов, управлять им нельзя.
Ожидание: действие публикации и снятия с публикации либо убрать бейдж, пока функции нет.

## BUG-08. Нет страниц и ограничения списка: 86 карточек одним блоком

Серьёзность: низкая.
Шаги: загрузить `user-b.json`, открыть «Мои проекты».
Факт: все 86 карточек подряд, высота страницы 11350 px, загрузка около 1,5 с, постраничного вывода нет. По коду есть тихий предел `LIMIT = 200`: 201-й проект вытесняет самый старый без предупреждения (в интерфейсе не проверялось).
Ожидание: постраничный или ленивый вывод, предупреждение при достижении предела.

## BUG-09. Пустое имя при переименовании отклоняется без сообщения

Серьёзность: низкая.
Шаги: меню карточки → «Переименовать» → ввести пробелы → ОК.
Факт: название не изменилось, сообщения нет.
Ожидание: пояснение «Название не может быть пустым».

## BUG-10. Каждый новый пользователь получает 33 стартовых проекта на английском

Серьёзность: низкая.
Шаги: зарегистрировать пользователя, открыть «Мои проекты».
Факт: сразу 33 проекта («Order process», «Order handling»), в русском интерфейсе названия английские. Пользователь с минимумом данных (В) убрал их 33 отдельными действиями через корзину и «Очистить корзину»; выбрать все разом нельзя.
Ожидание: возможность отказаться от примеров, групповое удаление, названия на языке интерфейса.

## BUG-11. Редактор и настройки открываются гостю, список проектов нет

Серьёзность: низкая (несогласованность).
Шаги: выйти, открыть `/app/dashboard.html`, затем `/app/editor.html` и `/app/settings.html`.
Факт: `dashboard.html` перенаправляет на вход, редактор и настройки открываются.
Ожидание: единое правило для страниц `/app/` либо явный гостевой режим с пометкой.

## BUG-12. Открытие чужого проекта по `?p=<id>` не сообщает, что проекта нет

Серьёзность: низкая.
Шаги: войти пользователем В, открыть `editor.html?p=<id проекта А>`.
Факт: данные А не показаны (изоляция работает), открыта типовая диаграмма IDEF0, в строке статуса «Сохранено 06:46» вместо «Проект не найден, открыта новая диаграмма».
Ожидание: показать сообщение о том, что проект не найден.

## Проверено, дефектов нет

- Изоляция: три аккаунта в одном браузере, у каждого только свои проекты, шаблоны, корзина и лайки.
- Выход и вход А: «Мои проекты» (73), «Мои шаблоны» (9), «Корзина» (4), «Общие» (33) совпадают по счётчику и названиям.
- Юникод (кириллица, CJK, диакритика, эмодзи), одинарные кавычки, «ёлочки», двойные пробелы, `<script>` в названии сохраняются и выводятся без искажений, код не выполняется.
- Поиск без учёта регистра, пробелы по краям обрезаются, символы `% . * [ \` ищутся как текст; фильтры (чипы и список) и сортировка работают вместе с поиском.
