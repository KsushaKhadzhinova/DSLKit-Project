## BUG-01. Редактор зависает на диаграмме из 150 и более блоков

- Серьёзность: высокая. Срочность: в этом выпуске.
- Шаги: 1. Открыть `/app/editor.html?template=dag`. 2. Вставить в поле кода диаграмму `dag` из N задач `task tI "Задача I"` и N-1 связей `tI -> tI+1`. 3. Дождаться отрисовки.
- Фактический результат: 30 блоков 1,5 с; 80 блоков 6,0 с; 150 блоков 20,1 с; 300 блоков вкладка не отвечает дольше 60 секунд (таймаут `fill`), остальные операции в этой вкладке невозможны. Время растёт быстрее, чем линейно.
- Ожидаемый результат: время растёт примерно линейно, диаграмма из 300 блоков отрисовывается за несколько секунд или редактор показывает понятное сообщение о размере, не замораживая страницу.
- Приложение: `screens/PERF-150.png`, `screens/PERF-300.png`. Замечание: замеры сделаны на загруженной машине (параллельно работали другие браузеры), абсолютные значения могут быть завышены, форма зависимости воспроизводится.

## BUG-03. Один повреждённый проект ломает страницу «Мои проекты» целиком

- Серьёзность: высокая. Срочность: в этом выпуске.
- Шаги: 1. Войти. 2. В консоли записать в `dslkit.projects.<id пользователя>` один из массивов: а) `[{"id":"x","title":"A","source":"a","updated":1}]` (нет `notation`); б) такой же проект с `"notation":5`; в) любой проект с `"trashedAt":"вчера"`. 3. Открыть `/app/dashboard.html`.
- Фактический результат: в консоли `DSLKit: component initDashboard failed` (для в) `RangeError: Invalid time value`; для а) и б) страница так же не инициализируется). Страница остаётся без работающего счётчика, фильтров и меню, показывает 33 статичные карточки общих примеров. Пользователь не может добраться ни к своим, ни к удалению повреждённой записи. Ту же причину имеет подпись корзины: `trashedAt` в будущем даёт «будет стёрт через 35 дн.».
- Ожидаемый результат: запись с неверными полями отбрасывается при чтении (как это уже делается для отсутствующих `title` и `source`), остальные проекты видны.
- Приложение: `screens/PRJ-09.png`, `screens/COR-01-5.png`, `screens/COR-01-10.png`. Источник: `site/js/storage/projects.js` (функция `valid`) и `site/js/components/dashboard.js` (`card`, подпись корзины).

## BUG-13. Пароль длиннее 128 символов обрезается молча

- Серьёзность: низкая. Срочность: позже.
- Шаги: ввести при регистрации пароль из 20000 символов.
- Фактический результат: поле `maxlength=128` обрезает ввод без предупреждения; вход возможен только по первым 128 символам (пользователь, вставивший длинную фразу из менеджера паролей, не заметит). Имя при длине более 60 символов обрезается так же.
- Ожидаемый результат: подсказка о максимуме длины рядом с полем.
- Приложение: скриншот не снят (дефект виден в атрибуте `maxlength` полей); строки AUTH-05 и AUTH-13 протокола.
