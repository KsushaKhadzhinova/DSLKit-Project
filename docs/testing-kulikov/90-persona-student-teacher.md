# 90. Проверка глазами двух персон: студентка и преподаватель

Дата прогона: 29-30.10.2026. Стенд: http://localhost:5190, Edge (Chromium 156), ноутбук 1366x768 и телефон 375x812 (касание, мобильный режим). Действия выполнены реальной мышью и клавиатурой через Playwright (page.mouse, page.keyboard) с таймаутами. Код сайта не менялся. Скриншоты: `docs/testing-kulikov/screens-persona/` (префикс S1 — студентка, S2 — преподаватель).

Ограничение: прогон выполнен одним проверяющим, роли сыграны по описанию; время указано по скрипту (с ожиданием загрузки), а не по секундомеру живого человека. Клики посчитаны по фактической последовательности действий.

## Что работает хорошо

- Понятные русские сообщения об ошибках формы регистрации и входа, не раскрывающие, что именно неверно (почта или пароль).
- Диагностика нотаций точна и ссылается на строку: IDEF0 (output, повтор id, неизвестный блок, 3-6 блоков, обратная связь), DFD («чудо», потоки между хранилищами и сущностями), UML (цикл наследования, кратность), ERD (нет первичного ключа). Для UML без вида показан список допустимых видов.
- Заголовок с HTML не исполняется, имя файла очищается.
- Экспорт PNG резкий, русский текст отображается правильно.
- От шаблона до работающей схемы — 2 клика.

## Пожелания

1. Ссылка на проект только для чтения («Поделиться» → адрес) или экспорт проекта одним файлом, который преподаватель открывает через «Импорт из файла».
2. Журнал правок с датами и счётчиком изменений, метка «пример/свой код» (доля изменённых строк относительно шаблона).
3. Чистый стартовый аккаунт: начальные примеры только во вкладке «Общие» и с понятной пометкой «пример», без фейковых дат.
4. Экспорт в PDF и на лист А4 с рамкой и штампом по ГОСТ; предупреждение при экспорте диаграммы с ошибками.
5. Телефонный вид редактора: крупные кнопки 44 px, без горизонтальной прокрутки, схема с автоподгонкой, режим «только просмотр».
6. Пустой лист для «Новая диаграмма» и кнопка «Начать с шаблона» отдельно; не тратить лимит, пока студент ничего не написал.
7. Индикатор «Сохранено» с точным временем и защита от потери правки при закрытии вкладки.
8. Превью диаграммы в карточке проекта.
9. Режим проверяющего: список проблем с отметкой ГОСТ/методички, сводка «ошибок / предупреждений» в одну строку для быстрого решения «принять/вернуть».
