# Применение техник тест-дизайна

Техники взяты из книги С. С. Куликова (раздел о тест-дизайне): эквивалентные классы, граничные значения, таблицы решений, диаграммы состояний и переходов, попарное тестирование, предугадывание ошибок, исследовательское тестирование. Правила пересказаны. Идентификаторы TC ведут в документ 13, требования REQ и сценарии UC и SC в документы 01–03 и 14.

Принцип граничных значений в книге: для упорядоченного класса берут последнее допустимое значение, первое недопустимое и значения рядом с границей. Для каждого поля ниже даны классы и границы; «в» означает значение внутри класса, «г» граничное.

## 3. Диаграмма состояний и переходов проекта

Состояния: **Нет** (проекта нет), **Активный** (виден в «Мои проекты»), **В корзине** (поле `trashedAt`), **Восстановлен** (после «Восстановить»: поле `trashedAt` удалено, ведёт себя как активный, выделен для проверки переходов), **Стёрт** (записи нет в хранилище).

```text
[Нет] --T1 создание/копия/импорт--> [Активный]
[Активный] --T2 изменение, сохранение, переименование--> [Активный]
[Активный] --T3 «В корзину» + подтверждение--> [В корзине]
[В корзине] --T4 «Восстановить»--> [Восстановлен]
[Восстановлен] --T5 изменение, сохранение, переименование--> [Активный]
[Восстановлен] --T6 «В корзину» + подтверждение--> [В корзине]
[В корзине] --T7 «Удалить навсегда» / «Очистить корзину» + подтверждение--> [Стёрт]
[В корзине] --T8 срок 30 суток, открытие панели--> [Стёрт]
[В корзине] --T9 срок меньше 30 суток, открытие панели--> [В корзине]
```

## 5. Предугадывание ошибок (список идей)

Составлен по опыту похожих систем и просмотру кода; каждая идея ведёт в кейсы.

| Идея | Почему может сломаться | Кейс |
|---|---|---|
| Двойной щелчок по любой кнопке отправки | Асинхронное хэширование: две записи или гонка | TC-015, TC-047, TC-099 |
| Назад после выхода | Страница из кэша показывает данные пользователя | TC-018, TC-156, TC-166 |
| Две вкладки | Состояние в `localStorage` меняется между чтениями | TC-046, TC-100, TC-167, TC-203 |
| Повреждённое хранилище | Нет защиты чтения JSON и типов | TC-076, TC-077, TC-162, TC-201, TC-202, TC-204 |
| XSS в названиях, имени, DSL, поиске | Вставка через `innerHTML` | TC-020, TC-032, TC-063, TC-083, TC-084, TC-152, TC-191 |
| Пробелы, юникод, эмодзи, невидимые символы | Нормализация и регулярные выражения | TC-030, TC-052, TC-085, TC-086, TC-192 |
| Очень длинные значения | Вёрстка, пределы хранилища | TC-026, TC-087, TC-150 |
| Время: смена суток, часы назад | Подсчёт квоты и срока корзины зависит от `Date` | TC-072, TC-098, TC-205 |
| Пустые значения и отмена диалогов | `null` из `prompt` | TC-081, TC-088 |
| Старые данные без новых полей | Нет `created`, нет `trashedAt` | TC-206 |
| Небезопасный контекст | Нет `crypto.subtle` по http с чужого хоста | TC-050 |
| Сброс хранилища во время работы | Данные исчезают под открытой страницей | TC-204 |
| Неверный метод и тип содержимого API | Ветки обработки запросов | TC-176, TC-184, TC-193 |
| Клавиатура вместо мыши | Недоступные элементы, ловушки фокуса | TC-016, TC-102, TC-130, TC-131 |
