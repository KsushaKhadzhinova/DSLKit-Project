# Тест-кейсы DSLKit

Всего тест-кейсов: **224** (High 95, Medium 99, Low 30). Формат кейса по книге С. С. Куликова (раздел о тест-кейсах): идентификатор, приоритет, предусловия, шаги, ожидаемый результат; добавлена трассировка на требования (`01-requirements.md`, REQ-xxx) и варианты использования (`02-use-cases.md`, UC-xx). Сценарии с нестандартными действиями пользователя из `03-user-scenarios.md` (SC-xx) покрыты кейсами, как показано в документе 14.

Правила: один кейс проверяет одну идею; шаги исполнимы без пояснений; ожидаемый результат наблюдаем; данные выбраны техниками документа 12. Если в ожидании стоит «записать в протокол» или «уточнить», требование не фиксирует поведение: итог записывается и передаётся владельцу продукта.

## Тестовые данные и окружение

- Адрес `http://localhost:5190`, сервер `npm start`.
- Пользователь A: Анна Петрова, anna@example.com, пароль Passw0rd!x. Пользователь B: Борис Иванов, boris@example.com, пароль Passw0rd!y. Значения только для тестов.
- Чистый профиль: в DevTools выполнить `localStorage.clear()` и перезагрузить страницу.
- Сдвиг времени: править поля `created`, `updated`, `trashedAt` (миллисекунды Unix) в ключе `projects.<id>` пользователя; сутки равны 86400000 мс.
- Ключи хранилища: `accounts`, `session`, `projects` (гость), `projects.<id>`, `seeded.<id>`, `likes-<id>`, `settings`, `theme`, `dashboard`, `dslkit.tour-done`.
- Защищена только страница «Мои проекты» (REQ-020); редактор, настройки и welcome открыты гостю (REQ-021, открытый вопрос владельцу).
