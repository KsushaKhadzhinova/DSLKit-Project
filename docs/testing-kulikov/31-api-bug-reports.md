Код не менялся, все дефекты воспроизводятся скриптами из `docs/testing-kulikov/scripts/`.

## BUG-01. Процесс сервера завершается при зависании тела ответа Kroki

- Серьёзность: Критическая. Приоритет: Высокий.
- Компонент: `tools/render-api.js`, функция `external`, обработка `/api/external/<язык>`; `tools/server.js` (вызов `handleApi`).
- Шаги:
  1. Запустить сервер с `KROKI_URL`, указывающим на сервис, который отвечает заголовками `200` и частью SVG, а затем не досылает тело (или обрывает соединение).
  2. Отправить `POST /api/external/graphviz` с `{"source":"x"}`.
  3. Подождать 10 секунд (`EXTERNAL_TIMEOUT_MS`).
- Ожидание: ответ 504 или 502, сервер продолжает работать.
- Факт: клиент получает обрыв соединения (ECONNRESET), процесс `node` завершается с кодом 1 и сообщением `DOMException [TimeoutError]: The operation was aborted due to timeout`. Статика и все остальные запросы перестают отвечать до ручного перезапуска.
- Причина: `await answer.text()` вне `try`, при этом вызов `return external(...)` в `handleApi` стоит без `await`, поэтому отклонённое обещание не попадает в `catch` функции `handleApi`; `server.js` не обрабатывает обещание, возвращённое `handleApi`. Необработанное отклонение завершает процесс Node. Тот же путь сработает при любом обрыве сети во время чтения тела.
- Проверки: K89b, K89. Скрипт: `run-external.mjs`.
- Предложение: `return await external(...)`, перенести чтение тела в `try`, в `server.js` добавить `.catch` с ответом 500.

## BUG-02. Запрос `/api/../index.html` не получает ответа

- Серьёзность: Высокая. Приоритет: Высокий.
- Компонент: `tools/server.js`, ветка `req.url.startsWith('/api/')`.
- Шаги: отправить сырой запрос `GET /api/../index.html HTTP/1.1` (или `/api/%2e%2e/index.html`) через `net.connect`.
- Ожидание: 200 (страница) или 404.
- Факт: ответа нет, соединение висит до таймаута клиента. `new URL` сворачивает путь в `/index.html`, `handleApi` возвращает `false`, `server.js` не проверяет результат и делает `return`, не отправив ответ. Каждый такой запрос занимает сокет на 5 минут (requestTimeout Node), что открывает путь к исчерпанию соединений.
- Проверки: I63, I63b.
- Предложение: если `handleApi` вернул `false`, продолжить обычную обработку статики.

## BUG-03. Анализ графа: время растёт как n^2.8, сервер блокируется

- Серьёзность: Высокая. Приоритет: Высокий.
- Компонент: анализ в `site/js/notations/graphs.js` (вызывается из `parseDiagram` для `/api/validate`, `/api/parse`, `/api/render`, `/api/generate`).
- Шаги: `POST /api/validate` с `diagram graph` и цепочкой из N вершин (`vertex nI`, `edge nI -> nI+1`).
- Замеры (без нагрузки): N=100: 0,08 с; 200: 0,3 с; 400: 2,5 с; 800: 18 с; 1000: 40-59 с; для `generate` и `parse` то же. Для сравнения DAG из 800 задач: 0,4-5 с. Полный граф из 60 вершин (3540 рёбер) рисуется 22-25 с. Источник на 100000 символов вмещает 5000 вершин, то есть один запрос занимает сервер на часы.
- Побочный эффект: Node однопоточный, пока идёт расчёт, не отвечает ни одна страница. В проверке G05 лёгкий запрос `GET /api/grammar` ждал 9-20 с при пяти запросах на 400 вершин, G04 (50 параллельных графов на 150 вершин) выполнился за 43-60 с, часть запросов клиента завершилась по таймауту.
- Ожидание: ответ за секунды либо отказ с 413/422 по лимиту узлов (например 300), расчёт вне основного потока.
- Проверки: D01, D02, D06, D11, D12, D12b, D12c, G04, G05.

## BUG-04. Отрисовка глубоких структур занимает секунды

- Серьёзность: Средняя. Приоритет: Средний.
- Шаги: `POST /api/render` с `diagram mindmap` из 2000 тем, соединённых цепочкой `branch`.
- Факт: 12-15 с, сервер блокирован (см. BUG-03). Для ориентировочного сравнения 300 узлов `graph` занимают 2-3 с.
- Ожидание: ограничение числа узлов или быстрый алгоритм раскладки.
- Проверка: D28.

## BUG-05. `diagram constructor` и `diagram __proto__` дают 500

- Серьёзность: Средняя. Приоритет: Средний.
- Компонент: `site/js/notations/index.js`, строки 120-121: проверка `key in NOTATIONS` находит свойства прототипа.
- Шаги: `POST /api/render` (и `validate`, `parse`, `generate`) с телом `{"source":"diagram constructor \"x\""}` или `diagram __proto__`.
- Ожидание: 422 `unknown-notation`, как для `diagram nothere`.
- Факт: 500 `internal`, «The source could not be processed»: у функции `Object` нет метода `parse`. Тот же вход в редакторе даёт исключение.
- Проверки: J05, J06 и их варианты на четырёх эндпоинтах (8 записей).
- Предложение: `Object.hasOwn(NOTATIONS, key)`.

## BUG-06. Ответы API без заголовков безопасности

- Серьёзность: Средняя. Приоритет: Высокий.
- Компонент: `tools/render-api.js`, функции `json` и ветка SVG в `handleApi`.
- Шаги: `GET /api/notations`, `GET /api/engines`, `POST /api/render` (любой код: 200, 400, 404, 405, 413, 422) и `POST /api/external/<язык>`; сравнить заголовки со статикой.
- Ожидание: те же `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`, что и у страниц (`SECURITY_HEADERS` в `server.js`).
- Факт: у всех ответов `/api/*` есть только `Content-Type` и `Cache-Control: no-store`. Особенно важен SVG при `Accept: image/svg+xml`: без CSP и `nosniff` документ, открытый напрямую во вкладке, исполняет скрипты на origin сайта (в наших проверках собственные отрисовщики экранируют ввод, F01 и F02 чисты, но защита держится на одном слое).
- Проверки: H05-H11, F03, F04, K06, K93.
- Предложение: добавить `SECURITY_HEADERS` в `json` и в SVG-ответы, для SVG `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox`.

## BUG-07. SVG внешнего сервиса передаётся без очистки и без CSP

- Серьёзность: Средняя. Приоритет: Высокий.
- Компонент: `external` в `tools/render-api.js`.
- Шаги: подставной Kroki отвечает `<svg><script>alert(1)</script><rect onload="alert(1)"/><a href="javascript:alert(1)">…</a></svg>`; `POST /api/external/graphviz`.
- Ожидание: сервер очищает ответ или помечает его так, чтобы скрипт не выполнился.
- Факт: 200 `image/svg+xml` с исходным содержимым, заголовков безопасности нет (BUG-06). Редактор очищает SVG на странице, прямой вызов API и открытие результата во вкладке нет. Пока upstream публичный `kroki.io`, это доверие к стороннему сервису.
- Проверка: K80.

## BUG-08. Размер ответа Kroki не ограничен

- Серьёзность: Средняя. Приоритет: Средний.
- Шаги: подставной Kroki отдаёт 100 МБ SVG; `POST /api/external/graphviz`.
- Факт: 200 и 100 МБ пересланы клиенту (за 7 с), сервер держит их целиком в памяти (`answer.text()`). Параллельные запросы исчерпают память.
- Ожидание: лимит (например 5 МБ) и 502.
- Проверка: K90.

## BUG-09. Content-Type определяется по подстроке

- Серьёзность: Низкая. Приоритет: Низкий.
- Компонент: `readInput`: `contentType.includes('application/json')`.
- Шаги: (а) `Content-Type: application/jsonx` с JSON в теле; (б) `Content-Type: text/plain; x=application/json` с обычным текстом диаграммы.
- Ожидание: (а) не JSON, 415 или текст; (б) текст, 200.
- Факт: (а) 200, тело разобрано как JSON; (б) 400 «not valid JSON».
- Проверки: B35, B36.

## BUG-10. Нет 415 для неподдерживаемых типов тела

- Серьёзность: Низкая. Приоритет: Низкий.
- Шаги: `POST /api/render` с `application/x-www-form-urlencoded`, `multipart/form-data` или `application/xml`.
- Ожидание: 415 Unsupported Media Type (или 400/422).
- Факт: 200, тело трактуется как исходный текст, ответ — пустая IDEF0 (см. BUG-11).
- Проверки: B31, B32, B33.

## BUG-11. Текст без заголовка `diagram` даёт 200 и рисует пустую IDEF0

- Серьёзность: Средняя. Приоритет: Средний.
- Шаги: `POST /api/render` с `{"source":"hello world"}`, `{"source":"a"}`, `{"source":"\u0000"}` или с JSON-текстом как `text/plain`.
- Ожидание: 422 `unknown-notation` (в коде есть такая ветка).
- Факт: 200, `notation:"idef0"`, `valid:false` с предупреждением `no-header` и ошибкой «Строка не распознана», `svg` содержит рисунок пустой диаграммы. Ветка 422 для отсутствующего заголовка недостижима (достижима только для `diagram nothere`). Клиент, смотрящий на код ответа, считает отрисовку удавшейся.
- Проверки: A13, B15, B30, C02, C20.

## BUG-12. Перевод строки CR не распознан

- Серьёзность: Низкая. Приоритет: Низкий.
- Компонент: `common.js`, `split(/\r?\n/)`.
- Шаги: шаблон `graph`, в котором `\n` заменён на `\r`.
- Ожидание: `valid:true` как для CRLF и LF.
- Факт: весь текст — одна строка, 200 с `valid:false`.
- Проверка: B42.

## BUG-13. HEAD на GET-эндпоинтах API даёт 405

- Серьёзность: Низкая. Приоритет: Низкий.
- Шаги: `HEAD /api/notations`, `HEAD /api/engines`.
- Ожидание: 200 без тела (HEAD обязан работать там, где работает GET).
- Факт: 405 `Allow: GET`.
- Проверки: A07-HEAD, K04-HEAD.

## BUG-14. Нет ограничения времени на медленного клиента

- Серьёзность: Низкая. Приоритет: Низкий.
- Шаги: (а) отправить заголовки `POST` с `Content-Length: 1000` и далее по одному байту в секунду; (б) отправить незавершённые заголовки и ждать.
- Факт: (а) сервер не закрывал соединение за 15 с наблюдения; (б) за 8 с ни 408, ни закрытия. Действуют значения Node по умолчанию (заголовки до 60 с, запрос до 300 с), поэтому небольшое число медленных соединений удерживает сокеты.
- Ожидание: `server.requestTimeout` и `headersTimeout` порядка 10-30 с.
- Проверки: G06, G07.

## BUG-15. Мелкие отклонения статического сервера от HTTP

- Серьёзность: Низкая. Приоритет: Низкий.
- Факты:
  - `GET /index.html/` отдаёт 200 (дубль страницы по другому адресу; `path.resolve` отбрасывает слэш) — I53.
  - `If-None-Match: *` и список ETag не дают 304 — I48, I49.
  - `OPTIONS` на статику даёт 405 вместо 204 с `Allow` — I38.
  - `Accept: image/svg+xml;q=0` не отключает SVG в `/api/render` (подстрока, q игнорируется) — I35.
- Ожидание: поведение по RFC 9110.

## BUG-16. `manifest.webmanifest` отдаётся как `application/octet-stream`

- Серьёзность: Низкая. Приоритет: Низкий.
- Компонент: таблица `TYPES` в `server.js` (нет `.webmanifest`, а также `.ico`, `.woff2`, `.webp`, `.jpg`, `.gif`).
- Шаги: `GET /manifest.webmanifest`.
- Ожидание: `application/manifest+json`.
- Проверка: I57b.

## Что проверено и дефектов не нашло

- Все 33 нотации: шаблон отрисовывается, `valid:true`, SVG сбалансирован, нет `<script>`, `on*`-атрибутов и `javascript:` в атрибутах, ответ быстрее 500 мс; все форматы `generate` и `parse` работают (261 проверка, ноль падений).
- XSS: 16 нагрузок в каждой строке каждого шаблона (528 запросов) и 165 запросов с нагрузками в идентификаторах — экранирование централизовано (`escapeXml`), нарушений нет. Текст `javascript:` встречается только как содержимое текста, не как атрибут.
- Обход путей: `..`, `%2e%2e`, двойное кодирование, `\`, `%00`, диски Windows, UNC, потоки NTFS, `.git`, `.env` — файлы вне `site/` не отдаются; битое процентное кодирование даёт 400.
- Коды 400, 404, 405, 413, 422 соответствуют ожиданиям; 500 только в BUG-05; пустое тело, битый JSON, `null`, массив, число, вложенный объект в `source`, дубли ключей, `__proto__` в теле — корректны.
- Граничные размеры тела по новому лимиту 6 x 100000 + 1024 байт: 100000 символов в JSON с экранированием по 6 байт проходит, 100001 и 601025 байт дают 413 (K50-K71, C04-C07, C21-C24 — все Pass).
- `/api/engines` и 33 языка `/api/external/<язык>`: маршрутизация, 404 для неизвестных (`__proto__`, `constructor`, `..`, кодированные варианты), 405 с `Allow: POST`, проверка `source`, лимит 100000, таймаут 504, 502/422 при ошибках upstream, 20 параллельных зависших запросов не блокируют сервер (K91).
- 50 параллельных запросов к разным нотациям — 200, ответы детерминированы; 100 бездействующих соединений не мешают; конвейер HTTP работает.
- CORS: заголовка `Access-Control-Allow-Origin` нет, чужие страницы не могут читать ответы; запрос `text/plain` с чужого origin выполняется (без cookies вреда нет, но это открытый прокси к Kroki, K94).

## Примечания

- Времена в BUG-03 и BUG-04 плавают (в 2 раза) из-за параллельной работы других процессов на машине; порядок роста стабилен.
- В сообщении 413 при превышении тела сказано «longer than 100000 characters», хотя предел теперь в байтах (601024); текст ошибки стоит уточнить.
- Публичный `kroki.io` по умолчанию получает текст диаграмм пользователя при вызовах `/api/external/*`; это сознательное решение, но его стоит отметить в политике конфиденциальности.
