# 01. Требования к DSLKit

Документ составлен по подходу С. Куликова («Тестирование программного обеспечения. Базовый курс», разделы о требованиях, их свойствах и видах документов). Требования восстановлены по коду и экранам сайта (`site/app/*.html`, `site/js/components/*`, `site/js/storage/*`, `tools/render-api.js`). Где формулировка в коде не заданы явно, это отмечено в колонке «Замечание».

## 1 Как читать таблицы

Приоритет: **В** высокий (без этого продукт не работает или теряются данные), **С** средний, **Н** низкий.

Проверка по свойствам качественного требования:

| Сокращение | Свойство                          | Вопрос проверки                                                                       |
| ---------- | --------------------------------- | ------------------------------------------------------------------------------------- |
| А          | Атомарность                       | Требование описывает одно проверяемое поведение, а не два сразу                       |
| Н          | Непротиворечивость                | Оно не спорит с другим требованием этого списка                                       |
| Д          | Недвусмысленность (однозначность) | Два человека поймут его одинаково, числа и границы названы                            |
| П          | Прослеживаемость                  | Есть ID и источник (экран, файл), к нему можно привязать вариант использования и тест |

Знак `+` свойство выполнено, `~` выполнено частично (см. замечание), `-` не выполнено.

Дополнительные свойства книги (завершённость, выполнимость, проверяемость, актуальность, модифицируемость, проранжированность) учтены так: завершённость и проверяемость описаны в разделе 5, проранжированность дана колонкой «Приоритет», модифицируемость обеспечена единой схемой ID.

Трассировка на варианты использования (UC) и сценарии (SC) дана в колонке «Связи».

## 5 Итоговая проверка набора

| Свойство           | Результат                                                                                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Завершённость      | Основные потоки описаны; нет требований к восстановлению пароля, смене пароля и удалению учётной записи (их в продукте нет — это сознательное ограничение беты, внести в «Вне рамок») |
| Атомарность        | Составные требования помечены `~`, при подготовке тест-кейсов разбираются на отдельные проверки                                                                                       |
| Непротиворечивость | Один конфликт (п. 1 таблицы выше)                                                                                                                                                     |
| Недвусмысленность  | Три требования с нечёткими словами (п. 3, 4, 7)                                                                                                                                       |
| Прослеживаемость   | У каждого требования есть ID, источник и связь с UC/SC                                                                                                                                |
| Проверяемость      | Все, кроме REQ-209 в текущей формулировке                                                                                                                                             |
| Приоритеты         | Расставлены; высокий приоритет у данных, доступа и безопасности                                                                                                                       |

Вне рамок беты: восстановление пароля, подтверждение почты, серверное хранение, совместная работа, публикация по ссылке.
