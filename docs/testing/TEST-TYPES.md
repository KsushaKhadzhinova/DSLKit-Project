# Виды тестирования в DSLKit: что сделано, где лежит, что нельзя автоматизировать

Дата: 24 октября 2026. Классификация взята из списков владелицы (уровни, характеристики, знание кода, автоматизация, этапы, специальные виды). Для каждого вида указано одно из состояний:

- **Сделано**: автоматический тест или скрипт есть, указано где.
- **Частично**: есть для части работ или с оговоркой.
- **Нужен человек**: проверка требует людей, устройств или аккаунтов, подготовлен чек-лист.
- **Не применимо**: у проекта нет предмета проверки, причина названа.

Тесты лежат в тех же ветках, что и работы. Запуск каждого набора: `npm test` в папке работы.

## 8 Что нельзя сделать без людей, и как это сделать

Приёмочное и бета-тестирование, удобство, совместимость:

1. Покажите работу преподавателю по сценарию: регистрация, вход, создание, правка, удаление, ошибка 404 и 500.
2. Попросите трёх знакомых пройти сценарий без подсказок. Записывайте, где они остановились, не объясняя интерфейс.
3. Откройте клиент в Firefox, Edge и на телефоне, сравните с Chrome.
4. Фиксируйте найденное в таблице: что делали, что ожидали, что получили, насколько важно.

## 9 Не применимо к проекту

Аппаратное, климатическое, механическое, IoT, HIL, безэховые камеры, радиация и космос, квантовые алгоритмы, нейроинтерфейсы, смарт-контракты, игры, связь (QoS), биометрия, медицинское ПО, большие данные, ИИ и LLM, монетизация, окончание эксплуатации, генетические вычисления, краудтестирование, социальная инженерия. У проекта нет такого предмета: это веб-редактор диаграмм и учебные серверы. Если появится ИИ-помощник в дипломном проекте, раздел о тестировании LLM (галлюцинации, утечка подсказок) потребуется.

### Найденные ошибки

1. **ЛР2 и ЛР3: поиск `?q=` с символом NUL или другим управляющим давал 500.** SQLite обрывал запрос, в который подставлен такой текст. Теперь 400 с понятным сообщением. Исправлено в `src/middleware/list-query.js` во всех копиях ЛР2 и ЛР3 (ветки `lab12`, `25`, `28`, `26`, `23`), для каждой есть повторный тест, отчёты пересобраны. Нашёл стресс-набор: обычные тесты эту ветку не проходили, а запрос без токена до неё не доходил.
2. **Часть 1: `setNodePosition` записывал в код `pos=NaNx1`** при нечисловых координатах. Теперь возвращает `null` и код не меняется. Исправлено в `site/js/utils/node-position.js`.
3. **ЛР1: мутационный прогон `validate.js`** показал 3 выживших изменения из 28 (проверка управляющих символов в названии и владельце не проверялась). Добавлен `tests/control-chars.test.js`, после него все 28 изменений обнаружены.
4. **ЛР8: Nginx не отдавал защитные заголовки для `/assets/`.** Блок `location` со своим `add_header` отменяет заголовки сервера: у файлов сборки пропадали `X-Frame-Options`, `Referrer-Policy` и `Content-Security-Policy`. Заголовки повторены в блоке, статическая проверка следит за этим для всех блоков.
5. **ЛР8: у контейнера клиента не были сброшены права.** Для API стояли `cap_drop: ALL` и `no-new-privileges`, для Nginx нет. Добавлено (образ `nginx-unprivileged` в них не нуждается). Режим `read_only` для Nginx не включался: без запущенного Docker проверить, что Nginx стартует, я не мог.
6. **ЛР5: страница 500 не проходила проверку доступности.** `main` с ролью `alert` недопустим, а внутри блока разбора заголовки шли от `h1` сразу к `h3`. Роль перенесена на вложенный блок, уровень заголовков передаётся параметром.

### Замечания без правок

- Пропускная способность ЛР3 на SQLite около 30 запросов в секунду: на каждый запрос пишутся две строки в журнал, а SQLite ждёт записи на диск. Для PostgreSQL это не проблема, SQLite в работе нужен только для тестов.
- Всплеск из 300 новых подключений за раз на Windows даёт отказы `ECONNREFUSED` у части клиентов (очередь подключений операционной системы). Стресс-набор ЛР1 держит 100 одновременных клиентов, пики из тысячи сырых сокетов проверены отдельно.
- Проверка `sanitizeSvg` на вложенности 20000 уровней в jsdom занимает около 25 секунд; в тесте оставлено 2000 уровней. В браузере разбор нативный.
- Мутационное тестирование ЛР3 запущено не до конца и прервано: один прогон набора ЛР3 длится минуту, на 30 изменений нужно полчаса на файл. Запуск: `node tools/mutate.cjs src/middleware/auth.js --cwd . --cmd "node --test tests/auth.test.js tests/security.test.js" --max 30`. Во время прерванного запуска в ЛР3 оставалась изменённая строка, она восстановлена и проверена по `git diff`.
- Docker во время прогона не был запущен, поэтому ЛР8 проверена статически. Не проверено на живых контейнерах: перезапуск после падения, остановка базы, убитый контейнер. Команды для этого есть в README ЛР8.
- Axe-core добавлен в `devDependencies` четырёх клиентских работ (версия 4.11).
