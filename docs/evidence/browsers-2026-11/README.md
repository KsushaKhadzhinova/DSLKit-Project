# Проверка клиентов лабораторных 5-8 в браузерах (14.11.2026)

English version: [README.en.md](README.en.md).

Цель: реальные подтверждения, что клиенты лабораторных 5, 6, 7 и 8 работают в Firefox и в Edge.

Среда: Windows 11, Playwright for Python 1.63.0, Firefox 155.0 (сборка Playwright), Microsoft Edge (`channel="msedge"`, установлен на машине), без окна. Каждый прогон идёт в новом контексте браузера, 1366x800 и 390x844. Код: дерево `main` (aac8566). Скрипты: [scripts/](scripts/). Сырые данные каждого прогона (шаги, ошибки консоли, неудачные запросы, ответы HTTP от 400): `lab-0N/result.json`. Снимки: `lab-0N/<браузер>-<ширина>.png` (`msedge` это Edge).

## Что не проверено или ограничено

- У ЛР6 нет клиентской страницы. Страница не может вызвать API лабораторной через `fetch()` (CSP `default-src 'none'`, заголовков CORS нет, так задумано), поэтому создание, правку, комментарий и удаление отправлял HTTP-клиент Playwright, а не браузер. В браузерах открыты только GET-адреса (`/health`, `/diagrams`, `/diagrams/:id`, `/count`, `/stats` и 400 на неверный id). Проверка шла на MongoDB в памяти, не на Atlas (`.env` лабораторной не читался).
- ЛР5 шла на SQLite (временный файл) с демо-данными, не на PostgreSQL. ЛР8 шла на PostgreSQL.
- Только режим без окна, по одной версии движка, без Safari и без настоящего телефона: 390 px это размер окна, не устройство. Edge это сборка Chromium, установленная на этой машине.
- Выполнены только сценарии из таблицы; страницы ошибок и тёмная тема не проверялись.
- Не проверено: Atlas, WebSocket через прокси, сенсорный ввод.

## Что ломалось при подготовке

1. Первый прогон ЛР8 в Edge при 1366 px: после «Сохранить» скрипт сразу перезагружал страницу, запрос сохранения прерывался, и возвращалось старое название. Страница обновляет список до ответа сервера. Теперь скрипт ждёт ответ PATCH (200) перед перезагрузкой, повторные прогоны проходят в обоих браузерах. Это гонка в проверке, но она же показывает, что перезагрузка сразу после сохранения может потерять правку в Edge.
2. Один из следующих прогонов упёрся в лимит регистраций API (10 в час на адрес, «Too many requests»): это работает ограничение ЛР3. Контейнер backend перезапущен, полный прогон повторён. В репозитории результаты этого чистого полного прогона.
3. Первая попытка запустить Firefox в оболочке с песочницей не удалась (`spawn UNKNOWN`), прогоны выполнены из PowerShell.

## Как запускались стенды

- ЛР3 + ЛР5: `SQLITE_STORAGE` на временный файл, `db:migrate`, `db:seed:all`, `CORS_ORIGIN=http://localhost:5178`, Vite на 5178, API на 3000. Случайные секрет JWT и пароли лежали в файле вне репозитория.
- ЛР6: `mongodb-memory-server` + `server.js` на порту 3006.
- ЛР7: `node server.js` на порту 3007 (история в памяти).
- ЛР8: `docker compose -p dslkit-evidence --env-file <вне репозитория> up --build --wait`, затем `down` без `-v`. Том `dslkit-evidence_pgdata` показан в списке и удалён через `docker volume rm`, также удалены два образа этого проекта. Другие тома, контейнеры и образы не затронуты.

Секретов в папке нет: скрипты берут тестовый пароль из переменной окружения.
