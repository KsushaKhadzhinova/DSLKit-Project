1. ЦЕЛЬ РАБОТЫ
Освоение концепции middleware в Express.js, разработка кастомных middleware для
логирования, аутентификации, обработки ошибок. Изучение работы шаблонизаторов
(EJS) для генерации динамических HTML-страниц на сервере.
2. НЕОБХОДИМЫЕ ЗНАНИЯ
Для успешного выполнения работы студент должен знать:
Понятие middleware (порядок выполнения, типы).
Встроенные middleware Express (express.json(), express.static()).
Кастомные middleware (функции с тремя параметрами (req, res, next)).
Шаблонизатор EJS: установка, настройка view engine, рендеринг страниц,
передача данных.

4. ПОРЯДОК ВЫПОЛНЕНИЯ (общий для всех вариантов)
Часть 1. Настройка проекта и EJS
1. Использовать существующий проект из лабораторной работы №9 (или создать
новый).
2. Установить EJS: npm install ejs.
3. В server.js добавить:
app.set('view engine', 'ejs');
app.set('views', './views');
Часть 2. Создание шаблонов EJS
Создать папку views/.
Создать файл layout.ejs (общий каркас с <%- body %>) или использовать
частичные шаблоны (partials).
Создать минимум три страницы:
index.ejs – главная страница (список элементов)
item.ejs – детальная страница элемента (по ID)
add.ejs – форма добавления нового элемента
Часть 3. Реализация middleware
Логирующее middleware: выводит в консоль метод, URL и время запроса.
Middleware для имитации авторизации: проверяет наличие query-параметра ?
auth=1. Если нет – редирект на /login (или устанавливает req.user = { name:
'Гость' }).
Часть 4. Маршруты и рендеринг
GET / → список элементов (массив данных).
GET /item/:id → детальная страница элемента.
GET /add → форма добавления.
POST /add → добавление элемента в массив (редирект на главную).
Данные хранятся в глобальном массиве (например, const items = [];).
Часть 5. Обработка ошибок
Middleware для 404 – рендерить страницу 404.ejs.
Middleware для 500 – рендерить страницу 500.ejs и логировать ошибку.
