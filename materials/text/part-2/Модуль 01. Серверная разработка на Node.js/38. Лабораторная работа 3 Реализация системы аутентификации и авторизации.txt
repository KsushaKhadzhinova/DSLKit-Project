1. ЦЕЛЬ РАБОТЫ
Освоение механизмов аутентификации и авторизации в веб-приложениях. Реализация
регистрации и входа пользователей с использованием JWT (JSON Web Tokens),
хеширование паролей с помощью bcrypt, защита маршрутов с помощью middleware для
продолжения разработки серверной части вашего курсового проекта.

Для успешного выполнения работы студент должен знать:
Понятия аутентификации и авторизации.

Хеширование паролей (bcrypt, соль).
Middleware в Express.js для проверки токена.
Безопасное хранение токенов на клиенте (localStorage / cookies).

4. ПОРЯДОК ВЫПОЛНЕНИЯ (общий для всех вариантов)
Часть 1. Установка зависимостей
npm install jsonwebtoken bcrypt
(При использовании переменных окружения установите также dotenv.)
Часть 2. Модель пользователя (Sequelize)
Создайте модель User:
npx sequelize-cli model:generate --name User --attributes email:string,passwordHash:string
Обязательные поля:
id (первичный ключ)
email (string, unique, allowNull: false)
passwordHash (string, allowNull: false)
При необходимости добавьте дополнительные поля в зависимости от выбранного
дополнительного механизма (например, role, refreshToken, failedLoginAttempts, lockUntil).
Выполните миграцию:
npx sequelize-cli db:migrate
Часть 3. Маршрут регистрации (POST /auth/register)
Создайте файл routes/auth.js. Реализуйте эндпоинт:
Принимает email и password.
Проверяет уникальность email.
Хеширует пароль: bcrypt.hash(password, 10).
Сохраняет пользователя.
Возвращает статус 201.
Часть 4. Маршрут входа (POST /auth/login)
Находит пользователя по email.
Сравнивает пароль с хешем.
Генерирует JWT: jwt.sign({ id, email }, process.env.JWT_SECRET, { expiresIn: '1h'
}).
Возвращает токен.
Часть 5. Middleware аутентификации
Создайте middleware/auth.js:
Извлекает токен из заголовка Authorization: Bearer <token>.
Верифицирует токен.
Прикрепляет req.user = decoded и вызывает next().
Часть 6. Защищённые маршруты
Защитите маршрут GET /profile (возвращает данные текущего пользователя).
По желанию добавьте другие защищённые маршруты (например, удаление
пользователя).
Часть 7. Реализация дополнительного механизма (по теме курсового проекта)
В зависимости от специфики вашего курсового проекта выберите один из предложенных
ниже механизмов или согласуйте с преподавателем свой.
Механизм
Краткое описание
Ролевая модель (RBAC)
Добавить поле role (user, admin). Создать
middleware isAdmin. Защитить маршруты, доступные только
администраторам.
Механизм
Краткое описание
Refresh-токены
Добавить поле refreshToken. Создать эндпоинт POST
/auth/refresh для выдачи новой пары токенов.
Блокировка после
неудачных попыток
входа
Поля failedLoginAttempts, lockUntil. После 5 неудачных
попыток блокировать учётную запись на 5 минут.
Смена пароля
Эндпоинт POST /auth/change-password с проверкой старого
пароля и хешированием нового.
Логирование входов
Модель LoginLog (userId, ip, userAgent, timestamp, success).
Эндпоинт для просмотра логов администратором.
Двухфакторная
аутентификация (email)
Генерация одноразового кода, отправка на email (имитация
– вывод в консоль), проверка на отдельном эндпоинте.
Проверка сложности
пароля
При регистрации и смене пароля проверять длину, наличие
заглавных букв, цифр, спецсимволов.
Подтверждение email
Генерация токена, отправка ссылки на email (имитация),
поле isVerified, запрет входа без подтверждения.
Ограничение активных
сессий
Модель Session с tokenVersion, запрет более 3
одновременных сессий.
Восстановление пароля
через email
Эндпоинты forgot-password (генерация токена) и reset-
password (смена пароля по токену).
«Запомнить меня»
Параметр rememberMe при логине, увеличение времени
жизни токена.
Блокировка
пользователей
администратором
Поля isBanned, banReason, middleware isNotBanned,
эндпоинты /ban и /unban.
Имитация OAuth (GitHub)
Создать заглушку входа через GitHub, возвращающую JWT.
Защита от CSRF
Генерация CSRF-токена, проверка в заголовке X-CSRF-
Token (кроме GET и auth-эндпоинтов).
Смена email
Эндпоинт POST /auth/change-email с проверкой пароля и
повторным подтверждением по email.
SMS-подтверждение
Генерация 6-значного кода, вывод в консоль, проверка на
отдельном эндпоинте.
Примечание: Выбор конкретного механизма может быть подсказан предметной
областью вашего курсового проекта (например, для интернет-магазина важны
роли, для системы задач – восстановление пароля). При необходимости
согласуйте выбор с преподавателем.
