2. НЕОБХОДИМЫЕ ЗНАНИЯ
Принципы REST (ресурсы, методы, идемпотентность, коды состояния).

3. ЗАДАЧИ РАБОТЫ (индивидуально)
Спроектировать REST API для заданной предметной области (минимум 3 ресурса).
Реализовать все необходимые эндпоинты (CRUD + дополнительные операции по
варианту).
Добавить валидацию входных данных.
Задокументировать API (описать эндпоинты, примеры запросов/ответов).
Документация может быть в виде отдельного файла (API.md) или через
Swagger/OpenAPI.
Протестировать API с помощью Postman или аналогичного инструмента.
4. ПОРЯДОК ВЫПОЛНЕНИЯ (общий для всех вариантов)
Часть 1. Проектирование API
Определите ресурсы (сущности) для вашей предметной области (минимум 3).
Для каждого ресурса определите операции:
GET /resource – список
GET /resource/:id – детали
POST /resource – создание
PUT /resource/:id – полное обновление
PATCH /resource/:id – частичное обновление
DELETE /resource/:id – удаление
Определите коды ответов и возможные ошибки.
Часть 2. Реализация (Node.js/Express)
Создайте роуты и контроллеры для каждого ресурса.
Для хранения данных используйте временное хранилище в массиве (в
реальном проекте позже замените на БД).
Реализуйте валидацию входных данных (проверка обязательных полей, типов).
Часть 3. Документирование API
Создайте файл API.md, в котором опишите все эндпоинты (метод, URL, параметры,
пример тела запроса, пример ответа, возможные ошибки).
(Опционально) Установите swagger-jsdoc и swagger-ui-express для
автоматической документации.
Часть 4. Тестирование
Запустите сервер (npm run dev).
Используйте Postman или Insomnia для проверки каждого эндпоинта.
