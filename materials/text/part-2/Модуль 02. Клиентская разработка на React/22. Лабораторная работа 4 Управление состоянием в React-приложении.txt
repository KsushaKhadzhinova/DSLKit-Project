Лабораторная работа №4. Управление состоянием в
React-приложении
Ветка репозитория: 24
1. ЦЕЛЬ РАБОТЫ
Освоение управления локальным состоянием в React с использованием
хуков useState и useEffect. Формирование навыков обработки побочных эффектов,
асинхронных операций и динамического обновления интерфейса для реализации
клиентской части вашего курсового проекта.
2. НЕОБХОДИМЫЕ ЗНАНИЯ
Для успешного выполнения работы студент должен знать:
Функциональные компоненты React, JSX.
Хук useState (инициализация, обновление состояния).
Хук useEffect (массив зависимостей, очистка эффекта).
Жизненный цикл функционального компонента.
Работа с формами и событиями в React.
Работа с localStorage (чтение, запись).
3. ЗАДАЧИ РАБОТЫ
Создать React-приложение (рекомендуется Vite).
Реализовать компонент управления списком элементов, соответствующим
предметной области вашего курсового проекта (например, список задач,
товаров, контактов, книг, фильмов и т.п.).
Использовать useState для хранения массива данных и значения поля ввода.
Использовать useEffect для сохранения списка в localStorage (при каждом
изменении) и загрузки при монтировании.
Реализовать фильтрацию или сортировку списка (в соответствии с логикой
вашего проекта).
Добавить дополнительные побочные эффекты (таймер автосохранения,
изменение заголовка страницы и т.п. – на выбор).
4. ПОРЯДОК ВЫПОЛНЕНИЯ (общий для всех вариантов)
Часть 1. Создание проекта
npm create vite@latest my-app -- --template react
cd my-app
npm install
Часть 2. Компонент управления списком
Создать компонент, соответствующий вашей предметной области
(например, TaskList.jsx, ProductList.jsx, ContactList.jsx и т.п.).
Использовать useState для:
массива элементов (начальные данные можно загрузить из localStorage или
задать моковыми).
значения поля ввода (для добавления/редактирования).
состояния фильтра/сортировки (если требуется).
Реализовать добавление, удаление элемента, редактирование (по
необходимости).
Часть 3. Хранение в localStorage
useEffect с зависимостью [items] — сохранять массив
в localStorage (использовать JSON.stringify).
useEffect с пустым массивом — при монтировании загружать данные
из localStorage (если есть) или инициализировать начальными данными.
Часть 4. Дополнительные эффекты (по выбору)
Изменение заголовка страницы document.title в зависимости от количества
элементов.
Таймер автосохранения с debounce (задержка 500 мс после последнего
изменения).
Имитация загрузки с сервера (задержка 1 секунда) при старте.
Подсчёт статистики (общее количество, выполненных/невыполненных, сумма и
т.п.).
Часть 5. Тестирование
Запустить приложение: npm run dev.
Проверить: добавление, удаление, редактирование, фильтрацию, сохранение
состояния после перезагрузки страницы.
Убедиться, что localStorage содержит корректные данные.

8. ПРИМЕЧАНИЯ
Работа выполняется индивидуально.
Данная лабораторная работа является клиентской и полностью
автономной (использует localStorage вместо серверного API). Однако в
следующей лабораторной работе (№5) вы замените localStorage на
взаимодействие с вашим REST API, добавив аутентификацию и CRUD-операции с
сервером.
Рекомендуется использовать компонентную архитектуру и выносить логику
работы с localStorage в отдельный пользовательский хук
(например, useLocalStorage). Это облегчит последующий рефакторинг.
Обязательно обработайте случаи отсутствия данных
в localStorage (инициализация начальными данными – например, парой
примеров, соответствующих вашей предметной области).
