Часть 2. Реализация API сервиса
1. В файле js/api/config.js определите базовый URL и, при необходимости, API-ключ (в учебных целях можно
хранить прямо в коде, но в реальном проекте используйте переменные окружения на сервере или ограничьте
ключ по домену):
export const API_CONFIG = {
    baseUrl: 'https://api.example.com',
    apiKey: 'your_key_here',   // для демонстрации; лучше использовать переменную окружения
};
2. В файле js/api/apiService.js реализуйте функции для отправки запросов:
fetchData(endpoint, params = {}) – универсальная GET-функция с использованием Fetch API.
Дополнительно можно реализовать postData при необходимости.
Пример для Fake Store API:
import { API_CONFIG } from './config.js';
export async function getProducts() {
    const response = await fetch(`${API_CONFIG.baseUrl}/products`);
    if (!response.ok) throw new Error(`HTTP error! status: ${response.status}`);
    return await response.json();
}
export async function getProductById(id) {
    const response = await fetch(`${API_CONFIG.baseUrl}/products/${id}`);
    if (!response.ok) throw new Error(`Product ${id} not found`);
    return await response.json();
}
3. Добавьте обработку ошибок (например, проверка статуса ответа, таймаут, отмена запроса
через AbortController). Обратите внимание на возможные коды ошибок (404, 500 и т.д.).
Часть 3. Работа с клиентским хранилищем (LocalStorage)
1. В файле js/storage/localStorage.js создайте обёртки для сохранения и извлечения данных:
export function saveToLocalStorage(key, data) {
    try {
        localStorage.setItem(key, JSON.stringify(data));
    } catch (e) {
        console.error('LocalStorage save error:', e);
    }
}
export function loadFromLocalStorage(key) {
    try {
        const data = localStorage.getItem(key);
        return data ? JSON.parse(data) : null;
    } catch (e) {
        console.error('LocalStorage load error:', e);
        return null;
    }
}
2. Определите список ключей для хранения:
'cached_products' – кэш списка товаров (для офлайн-доступа).
'favorites' – избранные элементы.
'cart' – корзина.
'search_history' – история поиска.
Часть 4. Утилиты для работы с данными

export function parseProducts(rawProducts) {
    return rawProducts.map(p => ({
        id: p.id,
        name: p.title,
        price: p.price,
        image: p.image,

Часть 5. Интеграция с UI и обработка состояний
1. В основном файле js/script.js реализуйте:
Загрузку данных из API при загрузке страницы (с индикатором загрузки).
Сохранение загруженных данных в LocalStorage.
Отображение данных (например, список товаров, новостей, рецептов) в HTML, созданном ранее.
Реализацию хотя бы одного интерактивного действия на основе API (например, поиск, фильтрация,
добавление в избранное).
2. Пример структуры script.js:
import { getProducts } from './api/apiService.js';
import { saveToLocalStorage, loadFromLocalStorage } from './storage/localStorage.js';
import { renderProductList } from './ui/render.js';   // функция отображения данных (создайте её сами)
document.addEventListener('DOMContentLoaded', async () => {
    let products = loadFromLocalStorage('cached_products');
    if (!products) {
        showLoader();
        try {
            products = await getProducts();
            saveToLocalStorage('cached_products', products);
        } catch (error) {
            showError('Не удалось загрузить данные. Проверьте соединение.');
            return;
        } finally {
            hideLoader();
        }
    }
    renderProductList(products);
});
3. Добавьте функциональность офлайн-доступа: если API недоступно, использовать данные из LocalStorage (с
пометкой «кэшированные данные»).

Часть 7. Обеспечение безопасности и обработка ошибок
Убедитесь, что API-ключ не загружается в репозиторий (не публикуйте его). В учебном проекте достаточно
хранить его в отдельном файле, который не коммитится (добавить в .gitignore), или использовать ограничение
по домену в настройках ключа.
Все сетевые запросы должны быть обёрнуты в try...catch.
Предусмотрите отображение сообщений об ошибке для пользователя (например, «Сервер временно
недоступен»).
Для запросов, требующих авторизации, добавьте заголовок Authorization: Bearer <token> или X-API-Key.

времени).

запроса).
