4. ПОРЯДОК ВЫПОЛНЕНИЯ РАБОТЫ (общий для всех вариантов)
Часть 1. Настройка окружения для тестирования
1. Перейдите в репозиторий вашего React-проекта (из лабораторной работы №7) и создайте новую ветку:
git checkout main
git pull origin main
git checkout -b feature/frontend-testing
2. Установите зависимости для тестирования (если не установлены):
cd my-react-app   # папка вашего React-проекта
npm install --save-dev jest @testing-library/react @testing-library/jest-dom jest-environment-jsdom @testing-library/us
3. Настройте скрипты в package.json:
"scripts": {
  "test": "jest",
  "test:watch": "jest --watch",
  "test:coverage": "jest --coverage"
}
4. Создайте конфигурационный файл jest.config.js (опционально, но рекомендуется):
export default {
  testEnvironment: 'jsdom',
  setupFilesAfterEnv: ['<rootDir>/src/setupTests.js'],
  moduleNameMapper: {
    '\\.(css|less|scss|sass)$': 'identity-obj-proxy',
    '\\.(jpg|jpeg|png|gif|svg)$': '<rootDir>/__mocks__/fileMock.js'
  },
  collectCoverageFrom: [
    'src/**/*.{js,jsx}',
    '!src/**/*.test.{js,jsx}',
    '!src/main.jsx',
    '!src/vite-env.d.js'
  ],
  coverageThreshold: {
    global: {
      statements: 70,
      branches: 60,
      functions: 70,
      lines: 70
    }
  }
};
5. Создайте файл src/setupTests.js:
import '@testing-library/jest-dom';
Часть 2. Тестирование чистых JavaScript функций (утилит)
Объяснение: Начните с тестирования чистых функций, которые не зависят от React. Например, функции
форматирования, валидации, преобразования данных.
Пример для утилит (создайте файл src/utils/helpers.js и src/utils/helpers.test.js):
// helpers.js
export function formatCurrency(amount, currency = 'RUB') {
    return new Intl.NumberFormat('ru-RU', { style: 'currency', currency }).format(amount);
}
export function truncateText(text, maxLength) {
    if (!text) return '';
    return text.length > maxLength ? text.slice(0, maxLength) + '...' : text;
}
// helpers.test.js
import { formatCurrency, truncateText } from './helpers';
describe('formatCurrency', () => {
    test('форматирует число в рубли', () => {
        expect(formatCurrency(1234.5)).toBe('1 234,50 ₽');
    });
    test('форматирует число в доллары', () => {
        expect(formatCurrency(99.99, 'USD')).toBe('99,99 $');
    });
});
describe('truncateText', () => {
    test('обрезает длинный текст', () => {
        expect(truncateText('Очень длинный текст для проверки', 10)).toBe('Очень длин...');
    });
    test('не обрезает короткий текст', () => {
        expect(truncateText('Короткий', 20)).toBe('Короткий');
    });
});
Задание для студента: Напишите unit-тесты для минимум трёх чистых функций, которые есть в вашем проекте (или
создайте их специально). Функции должны быть связаны с вашей предметной областью (форматирование дат, расчёт
скидки, фильтрация списка и т.п.).
Часть 3. Тестирование React компонентов
Объяснение: Используйте React Testing Library для тестирования компонентов, созданных в лабораторной работе №7.
Пример тестирования простого компонента (например, Button.jsx):
// Button.test.jsx
import { render, screen, fireEvent } from '@testing-library/react';
import Button from './Button';
describe('Button component', () => {
    test('рендерит кнопку с правильным текстом', () => {
        render(<Button>Нажми меня</Button>);
        expect(screen.getByText('Нажми меня')).toBeInTheDocument();
    });
    test('вызывает обработчик при клике', () => {
        const handleClick = jest.fn();
        render(<Button onClick={handleClick}>Клик</Button>);
        fireEvent.click(screen.getByText('Клик'));
        expect(handleClick).toHaveBeenCalledTimes(1);
    });
});
Задание для студента: Напишите тесты для минимум трёх ваших компонентов:
Один базовый UI-компонент (например, Button, Card).
Один компонент списка (например, ProductList, NewsList), проверяющий отображение данных из моковых
массивов.
Один компонент, содержащий обработчик событий (например, кнопка «добавить в корзину»), проверьте, что
заглушка вызывается.
Важно: Так как вы не используете состояние, тестируйте только то, что компонент получает через props и какие
функции-обработчики вызываются при взаимодействии.
Часть 4. Инструменты разработчика для отладки
Задание для студента: Выполните следующие шаги и задокументируйте их в отчёте.
1. Console Tab:
Добавьте в коде несколько console.log, console.table, console.group для отладки.
Сохраните скриншот вывода консоли.
2. Sources Tab:
Установите точку останова (breakpoint) в одном из ваших компонентов (например, в обработчике клика).
Выполните пошаговую отладку (Step Over, Step Into).
Наблюдайте за значениями переменных в панели Scope.
3. Network Tab:
Откройте вкладку Network, перезагрузите страницу.
Проанализируйте, какие ресурсы загружаются, найдите самые медленные запросы.
Сделайте скриншот.
4. React Developer Tools (расширение для браузера):
Установите расширение React DevTools.
Изучите вкладку Components – проверьте props ваших компонентов.
(Опционально) Вкладка Profiler – запишите профиль производительности.
Часть 5. Анализ производительности с Lighthouse
Задание для студента: Запустите аудит вашего React-приложения с помощью Lighthouse.
1. Откройте DevTools → вкладка Lighthouse.
2. Выберите категории: Performance, Accessibility, Best Practices, SEO.
3. Запустите генерацию отчёта.
4. Проанализируйте метрики:
First Contentful Paint (FCP) – время появления первого контента.
Largest Contentful Paint (LCP) – время загрузки самого большого элемента.
Cumulative Layout Shift (CLS) – стабильность макета.
5. Прочитайте рекомендации по улучшению (они появятся в отчёте).
6. Внесите хотя бы одно улучшение на основе рекомендаций (например, оптимизируйте изображение,
добавьте alt атрибуты) и повторно запустите Lighthouse, чтобы увидеть изменение.
Часть 6. Запуск тестов и анализ покрытия
1. Запустите тесты с отчётом о покрытии:
npm run test:coverage
2. Откройте отчёт: coverage/lcov-report/index.html в браузере.
3. Проанализируйте, какие строки кода остались непокрытыми.
4. Добавьте тесты, чтобы достичь минимум 70% покрытия для утилит и 60% для компонентов (или выше).
5. Сделайте скриншот итогового отчёта о покрытии.

9. ПРАКТИЧЕСКИЕ РЕКОМЕНДАЦИИ
Перед написанием тестов убедитесь, что ваш React-проект собирается и работает (npm run dev).
Для тестирования компонентов используйте screen для поиска элементов – это делает тесты читаемее.
Для асинхронных операций (если они появятся) используйте waitFor или findBy....
Не забывайте очищать моки после каждого теста: jest.clearAllMocks().
Для анализа покрытия полезно запускать npm run test:coverage и открывать HTML-отчёт.
