# ХОД РАБОТЫ

## Вариант использования

Проверки охватывают вариант использования UC-01, связанный с требованием R4 (проверки SM-07, CP-35, CP-36); тест-кейсы к нему описаны в лабораторной работе 2.

**Название.**

- **UC-01.** Подать заявку в лист ожидания

**Система и модуль.**

- **Система:** *DSLKit* — редактор диаграмм как кода (статический сайт, *site/*).
- **Модуль:** «Лист ожидания беты» — форма на главной странице.
- **Ссылка:** http://localhost:5173/#waitlist

**Основной актор.**

- Посетитель сайта (без регистрации и авторизации).

**Цель.**

- Оставить контакты, чтобы получить приглашение в бету DSLKit.

**Предусловия.**

- 1. Открыта главная страница (*/* или */en/*).
- 2. Форма пуста: нотация не выбрана, размер команды 0, согласие не отмечено.

**Основной поток.**

- 1. Посетитель нажимает **«В бету»** в шапке (или **«Записаться в бету»**) и попадает к форме *#waitlist*.
- 2. Вводит **«Имя\*»** и **«Электронная почта\*»**.
- 3. Выбирает **«Нотация\*»** (IDEF0, DFD, ERD, BPMN, UML, «Сети Петри»).
- 4. Вводит **«Размер команды\*»** (0–500) и при желании **«Комментарий»**.
- 5. Отмечает согласие\* и нажимает **«Отправить»**.
- 6. Система проверяет поля по таблице «Структура данных» (*validateWaitlist*).
- 7. Система сохраняет заявку в *LocalStorage* (ключ *dslkit.waitlist*).
- 8. Система открывает страницу благодарности *thanks.html*.
- \* — обязательное поле.

**Альтернативные потоки.**

- **A1.** Поле неверно (шаг 6): под полем красное сообщение, фокус на первом неверном поле, заявка не сохраняется; после исправления сообщение исчезает.
- **A2.** Повторная заявка с той же почтой: принимается как новая запись (дефект D-1).
- **A3.** Посетитель закрыл страницу до шага 5: данные не сохраняются.

**Постусловия.**

- Успех: в *LocalStorage* на одну запись больше, открыта *thanks.html*. Ошибка проверки: записей не добавилось, значения остаются в полях.

**Исключительные ситуации.**

- **E1.** Запись в *LocalStorage* не удалась: страница благодарности всё равно открывается, **заявка потеряна**, ошибки нет (дефект D-2).

**Другие точки входа.**

- Ссылки «Записаться в бету: UML / BPMN / …» в разделе нотаций, кнопка «В бету» на *privacy.html* и *thanks.html*, адрес */en/#waitlist*.

**Связанные задачи.**

- **R4** — Форма заявки и валидация
- **UC-00** — Прочитать политику конфиденциальности
- **UC-03** — Авторизация (в текущей версии не реализована)
- **UC-04** — Запись в бету из React-приложения
- **TC-WL-001…022** — Тест-кейсы формы (лаб. 2)
- **SM-07, CP-35, CP-36** — Проверки чек-листов (лаб. 3)

**Скриншоты.**

- **SCR-01** — Форма: ошибки при пустой отправке
- **SCR-02** — Форма: заполнена
- **SCR-03** — Страница благодарности

**Реализация.**

- *site/index.html* (форма *#waitlist-form*), *site/js/components/waitlist-form.js*, *site/js/utils/validation.js*, *site/js/utils/storage.js*, *site/thanks.html*

**Ссылки.**

- http://localhost:5173/#waitlist

Таблица: Структура данных заявки (сущность WaitlistEntry)

| Поле | Тип | Длина | Обязат. | Уник. | Маска | Связь |
|---|---|---|---|---|---|---|
| name\* (П1) | string | 2–60 | Да | Нет | буквы, пробел, апостроф, дефис; первая — буква | — |
| email\* (П2) | string | 6–120 | Да | Нет (дубликаты принимаются, D-1) | name@domain.zone | — |
| notation\* (П3) | enum | 3–5 | Да | Нет | idef0, dfd, erd, bpmn, uml, petri | → справочник Notation, N:1 |
| team\* (П4) | integer | 0–500 | Да | Нет | целое число; по умолчанию 0 | — |
| comment (П5) | string | 0–500 | Нет | Нет | без маски | — |
| consent\* (П6) | boolean | — | Да, только true | — | флажок; в запись не сохраняется | → политика (privacy.html) |
| createdAt | string ISO 8601 | 24 | Да, ставит система | Нет | ГГГГ-ММ-ДДTЧЧ:ММ:СС.сссZ | — |

Хранилище: массив JSON в LocalStorage, ключ dslkit.waitlist. Первичного ключа нет. Звёздочка означает обязательное поле.
