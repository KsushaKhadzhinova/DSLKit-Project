# Лабораторная работа №4. Адаптивный макет на CSS

Проект DSLKit (направление SaaS), ветка `feature/responsive-layout`. Условие: `materials/text/part-1/Модуль 04…/54. Лабораторная работа №4…`.

## 1 Цель и задание

Реализовать адаптивные стили для существующей семантической разметки ЛР3: Flexbox и Grid, медиазапросы по подходу mobile-first, переменные CSS, БЭМ, бургер-меню без JavaScript, проверка на трёх разрешениях.

## 2 Структура

| Путь                                                                                         | Назначение                                        |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `site/css/style.css`                                                                         | Подключает все файлы стилей                       |
| `site/css/variables.css`, `base.css`, `header.css`, `main.css`, `footer.css`, `adaptive.css` | Файлы, обязательные по условию                    |
| `site/css/components.css`, `pages.css`, `app.css`, `editor.css`                              | Компоненты, служебные страницы, экраны приложения |
| `labs/04-responsive-css/css-checks.js`                                                       | Функции проверок стилей                           |
| `labs/04-responsive-css/*.test.js`                                                           | Тесты проверок и тест по реальным стилям сайта    |
| `labs/04-responsive-css/figures/`                                                            | Скриншоты на 375, 768 и 1280 пикселей             |
| `labs/04-responsive-css/report*.tpl.md`, `report*.md`                                        | Шаблоны и собранные отчёты (RU и EN)              |

## 3 Запуск и проверка

```bash
npm start                 # сайт на http://localhost:5173
npm test                  # все тесты, порог покрытия 100 процентов
npm run lab4:report       # сборка отчётов из шаблонов
npm run format:check      # проверка форматирования
```

Валидаторы: W3C CSS (jigsaw.w3.org/css-validator) для каждого файла стилей, W3C Nu (validator.w3.org/nu) для страниц.

## 4 Архитектура CSS

```mermaid
flowchart LR
  style[style.css] --> variables[variables.css]
  style --> base[base.css]
  style --> components[components.css]
  style --> header[header.css]
  style --> main[main.css]
  style --> footer[footer.css]
  style --> pages[pages.css]
  style --> app[app.css]
  style --> editor[editor.css]
  style --> adaptive[adaptive.css]
```

Порядок подключения задаёт каскад: переменные, база, компоненты, части страницы, адаптив последним. Золотое сечение (`1.618`) лежит в основе шкалы шрифтов (шаги √φ и φ), отступов (числа Фибоначчи на 8 пикселей: 8, 16, 24, 40, 64, 104) и колонок (`1fr 1.618fr`).

## 5 Адаптивность

| Ширина     | Состояние                                                        |
| ---------- | ---------------------------------------------------------------- |
| меньше 576 | Телефон: базовые стили, бургер, одна колонка                     |
| от 576     | Две колонки карточек                                             |
| от 768     | Горизонтальное меню, три факта в ряд                             |
| от 1024    | Три колонки карточек, главный блок 1 : 1.618, переключатель темы |

Бургер работает на скрытом флажке `burger__input` и правиле `.burger__input:checked ~ .nav`. Тёмная тема включается правилом `:root:has(.theme__input:checked)`. Все медиазапросы используют `min-width`, это проверяет тест.

## 6 Тесты и проверки

- Каждый класс из HTML имеет правило в CSS.
- Токены: `--phi`, шкала шрифтов, отступы кратны 8 и образуют ряд Фибоначчи.
- Контраст WCAG AA для пар текста и фона в светлой и тёмной темах.
- Нет цветов в шестнадцатеричной записи вне `variables.css`, нет шрифтов меньше 12 пикселей.
- Только запросы `min-width` и точки 576, 768, 1024; у каждого `color-mix()` есть запасное значение.
- Имена переменных из условия присутствуют, бургер включается ниже 768 пикселей, карточки идут в 1, 2 и 3 колонки.

Дополнительно геометрия всех элементов сравнивалась до и после перехода на mobile-first при ширинах 500, 800 и 1440 пикселей, отличий нет.
