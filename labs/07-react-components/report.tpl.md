# Лабораторная работа №7. Создание компонентного интерфейса с использованием React

## 1 Цель работы

Освоить компонентный подход в React, JSX и передачу данных через `props` на примере проекта DSLKit, веб-редактора диаграмм как кода, тематика которого соответствует направлению SaaS и будущему курсовому проекту, и подготовить компонентную базу для следующих работ.

## 2 Краткие теоретические сведения

**Компонентный подход.** Интерфейс собирается из небольших независимых частей, у каждой из которых своя разметка, стили и логика. Компонент принимает данные через `props` и возвращает описание интерфейса, поэтому его можно переиспользовать и проверять отдельно.

**JSX.** Это расширение синтаксиса JavaScript, похожее на HTML. Отличия: вместо `class` пишется `className`, вместо `for` пишется `htmlFor`, атрибуты записываются в стиле camelCase, например `onClick`, любое выражение вставляется в фигурных скобках, а каждый тег должен быть закрыт.

**SPA и Virtual DOM.** Одностраничное приложение загружается один раз и меняет содержимое без перезагрузки страницы. React хранит в памяти лёгкую копию дерева интерфейса (Virtual DOM), при изменении сравнивает старую и новую копии и обновляет в настоящем DOM только отличающиеся узлы.

**React, Vue и Angular.** React предоставляет библиотеку для интерфейса и оставляет выбор остальных инструментов разработчику. Vue даёт прогрессивный фреймворк с шаблонами и более мягкой кривой обучения. Angular является полным фреймворком с TypeScript, внедрением зависимостей и жёсткой структурой.

## 3 Ход работы

### 3.2 Базовые компоненты и композиция

Базовые компоненты `Button`, `Card` и `Badge` ничего не знают о предметной области. `Button` принимает вариант, обработчик и остальные атрибуты через оператор `...props`. `Card` выводит необязательный заголовок и вставляет `children` внутрь блока. Предметные компоненты собираются из них: `NotationCard` состоит из `Card` и `Badge`, а `ProjectCard` добавляет к ним `Button`. Такая иерархия показана в приложениях А и Б.

### 3.3 Props, списки и условный рендеринг

Данные идут только сверху вниз. Корневой компонент передаёт `ProjectList` массив проектов, список нотаций и обработчики, а тот передаёт каждому `ProjectCard` один проект. Списки выводятся методом `map`, и у каждого элемента есть `key` с уникальным `id`. Условный рендеринг применён в `Card` (заголовок выводится только если он передан), в `ProjectCard` (метка «Общий доступ» только для общих проектов) и в списках (сообщение при пустом массиве). Вычисляемые значения вставляются выражениями в фигурных скобках, например `formatDate(project.updated)`.

### 3.4 Моковые данные и обработчики

В папке `data` лежат три массива: шесть нотаций, восемь проектов и три тарифа. Состояния в приложении нет, поэтому обработчики являются заглушками: нажатие кнопок и смена выбора нотации пишут сообщение в консоль через `console.log`. Выбор нотации в списке проектов только сообщает о значении родителю и не фильтрует список, потому что для этого нужно состояние, которое появится в следующей работе.

### 3.6 Тестирование

Автоматический тест читает исходные файлы и проверяет структуру папок, число компонентов, функциональную форму компонентов, размер моковых данных, наличие `key` в списках, заглушки обработчиков, CSS-модули и отсутствие `useState` и `useEffect`. Работа приложения дополнительно проверена в Chrome: консоль не содержит ошибок, четыре заглушки пишут сообщения в консоль. Снимок вкладки Components инструмента React DevTools и проверка в Firefox и Edge остаются задачей на этап приёмки.

## 4 Ответы на контрольные вопросы

{{answers}}
1. **JSX и HTML.** JSX записывается внутри JavaScript и превращается в вызовы функций. Три отличия: `className` вместо `class`, `htmlFor` вместо `for` и выражения в фигурных скобках, например `{project.name}`.
2. **Передача через props.** Родитель передаёт данные атрибутами, а дочерний компонент получает их объектом. В проекте `ProjectList` передаёт `ProjectCard` проект и обработчик: `<ProjectCard project={project} onOpen={onOpen} />`.
3. **Преимущества компонентов.** Повторное использование, изоляция стилей и логики, простое тестирование и понятная иерархия. В чистом JavaScript разметка, обработчики и состояние переплетаются, и их труднее менять.
4. **Virtual DOM.** React строит лёгкое дерево в памяти, сравнивает его с предыдущим и вносит в настоящий DOM только отличающиеся изменения. Это сокращает число дорогих операций с DOM.
5. **React, Vue и Angular.** По кривой обучения проще всего Vue, затем React, а Angular сложнее из-за TypeScript и множества понятий. По производительности все три применяют эффективные обновления, а различия заметны только на больших интерфейсах. По экосистеме самая широкая у React, у Angular много встроенного, а Vue занимает середину.
6. **Чистые компоненты.** Компонент как чистая функция всегда возвращает одинаковый результат для одинаковых `props` и не меняет внешние данные. Это позволяет React безопасно пропускать лишние перерисовки и упрощает тесты.
7. **JavaScript в JSX.** Выражение пишется в фигурных скобках: `Обновлён {formatDate(project.updated)}`. Внутри допустимы вызовы функций, условия через `&&` и тернарный оператор, но не операторы `if` и `for`.
8. **Props и state.** Props приходят от родителя и не меняются внутри компонента, state принадлежит компоненту и меняет интерфейс. В этой работе все данные статические, а условие запрещает `useState`, поэтому состояния нет.
9. **Условный рендеринг.** Применяются `&&` и тернарный оператор: `{title && <h3>{title}</h3>}` в `Card` и `{visible.length === 0 ? <p>…</p> : <ul>…</ul>}` в `ProjectList`.
10. **Списки и key.** Массив превращается в элементы методом `map`. Атрибут `key` с уникальным `id` помогает React сопоставлять элементы между перерисовками и не пересоздавать лишнее.
11. **Подъём состояния.** Когда несколько компонентов должны делиться данными, состояние переносят к ближайшему общему родителю и передают вниз через `props`. В проекте фильтр нотации появится в `App` и будет управлять `ProjectList`.
12. **Типы props.** Можно передавать строки, числа, булевы значения, объекты, массивы и функции. В проекте это строка `title`, число `year`, объект `project`, массив `notations` и функция `onOpen`.
13. **Композиция и children.** Компонент выводит `{children}` там, где должно быть вложенное содержимое. `Card` оборачивает любое содержимое, и `NotationCard` вкладывает в него `Badge`, абзац и код.
14. **Фрагменты.** Запись `<>…</>` группирует несколько элементов без лишнего узла в DOM. В `App` фрагмент объединяет шапку, основное содержимое и подвал.
15. **События без состояния.** Обработчик передаётся через `onClick` или `onChange` и вызывает функцию-заглушку, например `console.log`. В `App` такие заглушки передаются вниз как `props`.
16. **CSS-модули в Vite.** Достаточно назвать файл `Name.module.css` и импортировать его: `import styles from './Button.module.css'`. Vite сделает имена классов уникальными, а настройка не нужна.
17. **Vite и Create React App.** Vite запускает сервер разработки почти мгновенно за счёт нативных модулей браузера, быстро обновляет страницу и собирает проект современным сборщиком, а Create React App больше не развивается.
18. **Моковые данные.** Массивы импортируются в корневой `App` из папки `data` и передаются дочерним компонентам через `props`, поэтому компоненты не зависят от источника данных.
19. **UI и предметные компоненты.** `Button`, `Card` и `Badge` не знают о предметной области и подходят для любого проекта. `NotationCard`, `ProjectCard` и `PlanCard` знают о данных DSLKit, поэтому лежат в `features`.
20. **Развитие проекта.** В следующих работах появятся состояние через `useState` и `useEffect`, маршрутизация через React Router, загрузка данных из API, как в лабораторной работе 6, и тесты компонентов.
{{/answers}}

## Заключение

Для проекта DSLKit создано приложение на Vite и React с десятью компонентами: базовыми, макета и предметными.
