# Лабораторная работа №6. Работа с API браузера и асинхронными операциями

## 1 Цель работы

Освоить асинхронное программирование в JavaScript, работу с Fetch API, форматом JSON и клиентским хранением данных на примере интеграции внешнего API в проект DSLKit, веб-редактор диаграмм как кода, тематика которого соответствует направлению SaaS и будущему курсовому проекту.

## 2 Краткие теоретические сведения

**Асинхронность.** JavaScript выполняется в одном потоке, а долгие операции (сеть, таймеры) передаются браузеру. Когда операция завершается, цикл событий ставит её обработчик в очередь и вызывает его, когда стек вызовов пуст.

**Promise и async/await.** Promise представляет результат, который появится позже, и находится в одном из состояний: ожидание, выполнен или отклонён. Запись `async/await` позволяет писать асинхронный код как последовательный, а ошибки ловить блоком `try/catch`.

**Fetch API.** Функция `fetch` отправляет HTTP-запрос и возвращает Promise с объектом `Response`. Она отклоняется только при сетевой ошибке, поэтому статус ответа нужно проверять через `response.ok`. Тело читается методами `json()` и `text()`, отмена запроса выполняется через `AbortController`.

**JSON и LocalStorage.** Объекты превращаются в строки методом `JSON.stringify` и восстанавливаются методом `JSON.parse`. LocalStorage хранит строки по ключам, работает синхронно и вмещает несколько мегабайт, поэтому для кэша нужны срок жизни и ограничение размера.

**Безопасность.** Ключи в клиентском коде видны всем, поэтому секреты не хранят в репозитории, а чужой ответ считают недоверенным. Браузер разрешает запрос к другому домену только тогда, когда сервер отвечает заголовками CORS.

## 3 Ход работы

### 3.1 Выбор API и структура файлов

Работа выполнена в ветке `feature/async-api-storage`. Для проекта выбрано открытое API Kroki (`https://kroki.io`): оно по тексту рисует диаграммы, то есть решает ту же задачу, что и DSLKit, поэтому его можно использовать и в курсовом проекте. Ключ и регистрация не нужны. Применяются два запроса: `GET /health` проверяет доступность сервиса, а `POST /graphviz/svg` принимает текст Graphviz DOT и возвращает изображение SVG. ### 3.2 Сервис запросов

Функция `createApi` принимает конфигурацию, функцию `fetch` и функцию паузы, поэтому в тестах сеть заменяется подставными ответами. Каждая попытка запроса получает свой `AbortController`: он срабатывает по таймауту в десять секунд или по сигналу вызывающего кода. Ошибки приводятся к классу `ApiError` с видом `network`, `timeout`, `aborted`, `http` или `invalid`, и по виду код выбирает сообщение для пользователя.

Сетевые ошибки, таймауты, код 429 и коды 5xx повторяются до трёх раз с паузой, которая растёт вдвое после каждой попытки, а при коде 429 учитывается заголовок `Retry-After`. Ошибки клиента, например 400 и 404, не повторяются. Одинаковые параллельные запросы без сигнала отмены используют один общий Promise. Функция `renderDiagram` дополнительно проверяет, что в ответе есть разметка `svg`, иначе возвращает ошибку вида `invalid`.

### 3.3 Хранилище

Кэш диаграмм хранит вместе с данными момент сохранения, поэтому срок жизни в 24 часа проверяется при чтении, а при переполнении удаляются самые старые записи. История запусков хранит последние пять результатов без повторов. Оба модуля работают через общий слой `storage.js` из лабораторной работы 5, который оборачивает запись и чтение в `try/catch` и возвращает запасное значение при повреждённых данных. Ключи называются `diagram_cache`, `run_history` и `favorites`.

### 3.4 Преобразование данных

Модуль `dataParser.js` читает код из редактора: заголовок `diagram`, блоки `box` с портами `input`, `control`, `output`, `mechanism` и стрелки `arrow`. Незнакомые строки не останавливают запуск, а попадают в список пропущенных. Из модели строится текст Graphviz DOT с экранированием кавычек, обратных косых черт и переводов строк. Ответ сервера считается недоверенным, поэтому перед показом из SVG удаляются теги `script` и `foreignObject`, атрибуты `on*` и ссылки `javascript:`.

### 3.5 Интеграция с интерфейсом

На холсте редактора добавлены кнопки «Нарисовать через Kroki» и «Обновить с сервера», строка состояния с `aria-live`, строка о доступности сервиса и список последних запусков. Пока идёт запрос, кнопки отключены, на холсте стоит `aria-busy`, а в строке состояния показан текст загрузки. Успешный результат показан на рисунке 1.

### 3.6 Безопасность и ошибки

Ключ для Kroki не нужен, поэтому в репозитории нет секретов. Для будущих API в `.gitignore` добавлены файлы `.env.local` и `site/js/api/config.local.js`. Все запросы обёрнуты в обработку ошибок, подробности попадают в консоль, а пользователь получает короткое сообщение. Браузерный запрос к Kroki разрешён политикой CORS самого сервиса, на странице работает проверка доступности через `GET /health`.

### 3.7 Тестирование

Для сервиса запросов, хранилища, разбора данных и компонента написаны автоматические тесты. Сеть заменяется подставным `fetch`, поэтому тесты проверяют успех, коды 404, 429 и 503, повторы с паузами, таймаут, отмену, объединение одинаковых запросов, неверный ответ и повреждённое хранилище. Покрытие всех файлов JavaScript равно 100 процентов по строкам, ветвлениям и функциям. Интеграция дополнительно проверена в браузере Chrome с настоящим сервисом Kroki: диаграмма получена, запись попала в LocalStorage, офлайн-режим показал сохранённую копию. Снимки вкладок Network и Application и проверка в Firefox и Edge остаются задачей на этап приёмки.

## 4 Ответы на контрольные вопросы

{{answers}}
1. **LocalStorage и SessionStorage.** LocalStorage переживает закрытие вкладки и общий для всех вкладок одного сайта, SessionStorage живёт до закрытия вкладки. В проекте кэш диаграмм и история лежат в LocalStorage, а временное состояние одной сессии при необходимости можно держать в SessionStorage.
2. **Promise и колбэки.** Promise убирает вложенные колбэки и даёт единый путь для ошибок. В проекте `fetch` возвращает Promise, а `renderDiagram` строится из него цепочкой без вложенности.
3. **async/await и then/catch.** Код читается сверху вниз, а ошибки ловит обычный `try/catch`. Цикл повторов в `apiService.js` с `await` внутри `try` на цепочках `then` был бы заметно сложнее.
4. **Стратегии ошибок.** Статус проверяется через `response.ok`, ошибки приводятся к `ApiError` с видом, сетевые сбои повторяются, а при неудаче показывается сохранённая копия или понятное сообщение.
5. **Кэширование.** Применён кэш в LocalStorage с ключом по хешу исходного текста и сроком жизни 24 часа. Актуальность поддерживает проверка срока при чтении, а принудительное обновление кнопкой игнорирует кэш.
6. **Офлайн-режим.** Проверяется `navigator.onLine`, а при отсутствии сети или ошибке показывается сохранённая копия с пометкой. Для редактора критичны последние отрисованные диаграммы и код.
7. **CORS.** Браузер запрещает чтение ответа другого домена, если сервер не разрешил его заголовком `Access-Control-Allow-Origin`. Обходят это прокси на своём сервере или настройкой сервера API, а Kroki разрешает запросы из браузера.
8. **Ключи на клиенте.** Ключ в браузере виден всем, поэтому его ограничивают по домену и правам и не коммитят. Для Kroki ключ не нужен, а локальные файлы настроек внесены в `.gitignore`.
9. **Пагинация.** Запрос получает параметры `page` и `limit`, а кнопка «Ещё» увеличивает номер страницы и добавляет результат к списку, например `fetchData('/items', { params: { page: 2, limit: 20 } })`.
10. **HTTP-статусы.** Важны 200 и 201 для успеха, 400 для неверного запроса, 401 и 403 для доступа, 404 для отсутствия, 429 для лимита и 5xx для ошибок сервера. В проекте 4xx не повторяются, а 429 и 5xx повторяются.
11. **Частые запросы.** Помогают отмена предыдущих запросов, задержка ввода и кэш. В проекте новый запуск отменяет старый запрос, а кэш избавляет от повторных обращений.
12. **AbortController.** Объект создаёт сигнал, который передаётся в `fetch`, а вызов `abort()` отклоняет запрос. В `diagram-runner.js` перед новым запуском вызывается `controller.abort()`.
13. **Повтор запроса.** В `apiService.js` рекурсивная функция повторяет попытку до трёх раз: `await sleep(delay * 2 ** attempt)`. Повторяются только сетевые ошибки, таймауты, 429 и 5xx.
14. **Заголовки.** Для `POST` передаётся `Content-Type: text/plain`, чтобы сервис понял тип тела. Для API с авторизацией добавляется `Authorization: Bearer <token>` или `X-API-Key`.
15. **GET, POST, PUT, DELETE.** GET читает данные, POST создаёт или отправляет данные на обработку, PUT заменяет ресурс, DELETE удаляет. В проекте GET проверяет доступность, а POST отправляет код диаграммы.
16. **Проверка ответа.** Проверяются статус, возможность прочитать тело и наличие разметки `svg`, а полученный SVG разбирается как XML и очищается. Любой сбой превращается в ошибку вида `invalid`.
17. **Офлайн в DevTools.** В Chrome открывают вкладку Network и включают режим Offline или Slow 3G, после чего перезагружают страницу и проверяют сообщения.
18. **Ограничения LocalStorage.** Объём около 5 мегабайт, только строки, операции синхронные и блокируют поток. Поэтому кэш ограничен 20 записями, а большие объёмы лучше хранить в IndexedDB.
19. **TTL.** Вместе с данными сохраняется время записи: `{ data, savedAt }`. При чтении сравнивается `now() - savedAt` со сроком жизни.
20. **JSON, даты и функции.** `JSON.stringify` превращает дату в строку, а функции пропускает, поэтому даты хранят числом `Date.now()` или строкой ISO и восстанавливают вручную.
21. **Бесконечная прокрутка.** `IntersectionObserver` следит за последним элементом списка и при его появлении запрашивает следующую страницу, пока сервер не вернёт пустой ответ.
22. **Оптимистичное обновление.** Интерфейс меняется сразу, а запрос уходит в фоне. При ошибке изменение откатывается, например комментарий появляется в списке до ответа сервера.
23. **Инструменты тестирования API.** Запросы к Kroki проверялись командой `curl` и вкладкой Network браузера, для сложных сценариев подходят Postman и Insomnia.
24. **Ошибка 429.** Нужно подождать и повторить запрос. В проекте учитывается заголовок `Retry-After`, а при его отсутствии пауза растёт вдвое после каждой попытки.
25. **Rate limiting.** Это ограничение числа запросов в единицу времени на стороне сервера. Клиент учитывает его кэшем, отменой лишних запросов, повтором с паузой и показом сообщения при коде 429.
26. **Защита от дублирования.** Активные запросы хранятся в `Map` по ключу из метода, адреса и тела, и повторный вызов получает тот же Promise. После завершения запись удаляется, а запросы с сигналом отмены не объединяются.
27. **Параметры в строке запроса.** Параметры собирает `URLSearchParams`, например `/items?q=order&sort=name&page=2&limit=20`. В `fetchData` они передаются объектом `params` и кодируются автоматически.
28. **Индикатор загрузки.** Пользователь видит, что запрос идёт, и не нажимает кнопку повторно. В проекте кнопки отключаются, на холсте ставится `aria-busy`, а строка состояния объявляет загрузку.
29. **Promise.all.** Метод ждёт выполнения всех запросов сразу и возвращает массив результатов, например загрузку нескольких диаграмм параллельно. При ошибке одного отклоняется весь результат, поэтому для независимых запросов подходит `Promise.allSettled`.
30. **Журнал ошибок клиента.** Ошибки выводятся в `console.error` с видом и кодом, а персональные данные в журнал не попадают. При необходимости последние ошибки можно складывать в LocalStorage.
{{/answers}}

## Заключение

Для проекта DSLKit подключено открытое API Kroki: код диаграммы из редактора превращается в Graphviz DOT, отправляется запросом `POST`, а полученный SVG очищается и рисуется на холсте.
