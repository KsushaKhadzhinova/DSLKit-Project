## Что осталось владелице (1 файл-заглушка)

| Файл | Рисунок | Программа | Действие | Что должно быть видно |
|---|---|---|---|---|
| `owner-tests.png` | 21 | PowerShell | `npm test` в `part-2/pz-02-rest-api` | конец вывода: `tests`, `pass`, `fail 0`, таблица покрытия 100 % |

Файл сейчас **заглушка**: оранжевая карточка с меткой `dslkit-placeholder` внутри PNG, не снимок. Почему не снят автоматически: в окне Windows Terminal (PowerShell 5.1 и 7) покрытие `server.js` каждый раз выходит 84,62 процента (8 запусков из 8), `npm test` там не проходит порог 100 %, а текст отчёта (3.10) говорит о 100 %. Снимок с неверным числом в отчёт не попал, поэтому `"final": true` пока не включён. Проверьте `npm test` в своём окне: если там то же, это дефект теста запуска сервера (см. ниже). После замены добавьте в `report.meta.json` строку `"final": true`, затем `node tools/docx-cli.js part-2/pz-02-rest-api` из корня репозитория (нужен Word для номеров страниц). Число тестов в окне должно быть 176, если оно другое, поправьте число в 3.10 обоих шаблонов и пересоберите отчёт: `node tools/build.js part-2/pz-02-rest-api`.

## Находка для исполнителя кода ПЗ2: покрытие неустойчиво

Команда `npm test` порог 100 процентов ветвей иногда не проходит (99,75 процента в 3 из 9 запусков). В окне Windows Terminal `server.js` каждый раз даёт 84,62 процента (строки 20–23, обработчики сигналов), в оболочке инструмента без консоли 100. Вероятная причина: тест `server.js starts on the given port` запускает сервер дочерним процессом и завершает его принудительно, поэтому покрытие дочернего процесса не всегда записывается. Код ПЗ2 в этой задаче не менялся.

## Как воспроизвести сбой журнала вручную (рисунок 4)

```powershell
cd part-2/pz-02-rest-api
$env:JOURNAL_FILE='demo.sqlite'; $env:PORT=4210; node src/server.js
# в другом окне:
node tools/break-journal.mjs demo.sqlite
# открыть http://localhost:4210/api/users, затем вернуть таблицу:
node tools/break-journal.mjs demo.sqlite --restore
Remove-Item Env:JOURNAL_FILE
```

## Открытые вопросы, которые не закрывает отчёт

1. Тексты страниц ошибок на рисунках английские (каталог `src/error-catalog.js`), в отчёте это сказано в 3.6. Русские страницы потребуют правки кода.
2. Номера рисунков сквозные («Рисунок N»), в образцах по разделам. Правило 06 требует «Рисунок N», уточнить у преподавателя.
3. Ветка `pz22` и ссылка на репозиторий взяты из `report.meta.json`, ветку создаёт владелица.
4. Swagger UI в приложении нет, рисунок 6 показывает сам документ OpenAPI.
