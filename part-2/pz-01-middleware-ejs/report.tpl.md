# Практическое занятие №1. Middleware и шаблонизаторы

## 1 Цель работы

Освоить концепцию middleware в Express.js, разработать собственные middleware для журнала запросов, имитации авторизации и обработки ошибок и изучить шаблонизатор EJS для генерации динамических страниц на сервере на примере проекта DSLKit, веб-редактора диаграмм как кода, тематика которого соответствует направлению SaaS и будущему курсовому проекту.

## 2 Краткие теоретические сведения

**Middleware.** Это функция с параметрами `req`, `res` и `next`, которая видит запрос и ответ и либо завершает ответ, либо передаёт управление дальше вызовом `next()`. Функции выполняются в том порядке, в котором подключены, поэтому порядок подключения определяет поведение приложения. Обработчик ошибок отличается четырьмя параметрами и подключается последним.

**Шаблонизатор EJS.** Шаблон содержит HTML и вставки на JavaScript. Запись `<%= value %>` выводит значение с экранированием, запись `<% code %>` выполняет код, запись `<%- include() %>` подключает частичный шаблон. Данные передаются вторым аргументом `res.render()`.

**Хранение данных.** По условию занятия данные лежат в массиве в памяти процесса и пропадают при перезапуске сервера.

### 3.2 Журнал запросов

Middleware журнала подключается первым после статических файлов. Когда ответ завершён, оно пишет в консоль метод, адрес, статус и время обработки, и добавляет такую же строку в таблицу в памяти. Эта таблица выводится на странице `/log`. Условие занятия запрещает базу данных, поэтому журнал хранится в массиве за функцией `createRequestLog`, а размер ограничен сотней строк. Листинг приведён в приложении А.

### 3.3 Имитация авторизации

Middleware `fakeAuth` проверяет параметр `?auth=1`. Если он есть, в `req.user` попадает владелец, иначе гость, а в шаблоны передаются имя пользователя и хвост адреса для ссылок. Маршруты `/add` защищены функцией `requireAuth`: гость перенаправляется на страницу `/login`, где объяснено, как «войти». Листинг приведён в приложении Б.

### 3.4 Маршруты и страницы

Реализованы четыре маршрута из условия и три служебных, они сведены в таблице 2.

Таблица 2 – Маршруты приложения

| Маршрут         | Результат                                                                                                      |
| --------------- | -------------------------------------------------------------------------------------------------------------- |
| `GET /`         | Список диаграмм из массива                                                                                     |
| `GET /item/:id` | Детальная страница, неизвестный номер ведёт на страницу 404                                                    |
| `GET /add`      | Форма добавления, доступна с `?auth=1`                                                                         |
| `POST /add`     | Проверка полей, добавление в массив и переход на главную, при ошибке код 400 и форма с сохранёнными значениями |
| `GET /login`    | Страница-подсказка                                                                                             |
| `GET /log`      | Таблица журнала запросов                                                                                       |
| `GET /boom`     | Намеренная ошибка для страницы 500                                                                             |

Шаблоны выводят все значения с экранированием, поэтому введённая в форме разметка показывается как текст. Шаблон списка приведён в приложении Г.

### 3.5 Обработка ошибок

После всех маршрутов подключены два обработчика. Первый рендерит `404.ejs` для любого адреса без совпадения. Второй имеет четыре параметра, записывает ошибку в журнал ошибок и рендерит `500.ejs`; если заголовки уже отправлены, он просто закрывает ответ. Листинг приведён в приложении В.

### 3.6 Проверка

Автоматические тесты на встроенном `node:test` запускают сервер на свободном порту и проверяют страницы, перенаправление гостя, добавление записи, проверку полей, экранирование, журнал и обе страницы ошибок. Покрытие строк, ветвей и функций равно 100 процентам. Команда запуска: `npm test` в каталоге проекта.

## Заключение

Для проекта DSLKit собрано приложение на Express с шаблонами EJS: список диаграмм, детальная страница и форма добавления получают данные из массива в памяти. Журнал запросов пишет в консоль и в таблицу в памяти, имитация авторизации по параметру `?auth=1` закрывает форму от гостей, а отдельные страницы 404 и 500 обрабатывают ошибки. Автоматические тесты покрывают весь код. Остаётся приложить снимки страниц, сделанные в браузере.
