# Аудит ЛР5 (клиент React и CORS/поиск сервера)

Каждый пункт подтверждён кодом или запуском. Статус: «исправлено» (с тестом) или причина, почему не сделано.

| Проблема | Риск | Что сделано |
| --- | --- | --- |
| `remove` и `update` брали список из замыкания, быстрый двойной щелчок по «Удалить» отправлял два DELETE, второй ответ 404 вставлял `undefined` в список | падение страницы, дубль запроса | исправлено: актуальный список через ref, множество занятых id, второй вызов игнорируется (тест «одна DELETE при двойном щелчке») |
| Удаление или правка записи с временным id `temp-N` (до ответа POST) | запрос к несуществующему адресу, рассинхрон | исправлено: хук игнорирует такие вызовы, кнопки отключены (тест) |
| Ответ 404 на DELETE возвращал запись в список | «воскресшая» запись, ложное уведомление | исправлено: 404 значит «уже удалена», откат не нужен (тест) |
| Откат правки и удаления через `items` из старого рендера | потеря чужих изменений списка | исправлено: откат функциональным обновлением состояния |
| Ответ уже отменённого запроса мог записаться в список | устаревшие данные поверх свежих | исправлено: проверка `signal.aborted` до `setItems` и `setError` |
| Клиент считал пароль в символах, сервер в байтах (72), адрес почты без предела | кириллический пароль от 37 символов отклонялся сервером с непонятной ошибкой | исправлено: проверка в байтах и 254 символа почты, предел в `limits.json` (тест) |
| При коде 401 форма входа появлялась без объяснения | пользователь не понимает, почему его «выбросило» | исправлено: сообщение «Сессия истекла. Войдите снова.» (тест) |
| `errorMessage` предполагал объект в `response.data`, прокси может вернуть HTML-строку | текст «undefined» или разметка в сообщении | исправлено: строка и не объект дают «Ошибка сервера (код)» (тест), React выводит текст без разметки (тест с `<img onerror>`) |
| Доступ к `localStorage` без защиты | исключение при заблокированном хранилище (приватный режим) роняет приложение | исправлено: `getToken`, `saveToken`, `clearToken` с `try/catch` (тест) |
| Двойная отправка формы входа клавишей Enter | два запроса входа | исправлено: `if (busy) return` |
| Правка названия показывала старый черновик после отката | в поле старый текст | исправлено: черновик берётся при входе в режим правки |
| CORS ставил `Access-Control-Allow-Origin` на любой запрос, не сверяя `Origin` | заголовки уходят и чужим адресам, смысл «одного адреса» теряется | исправлено в `lab-03-auth/src/middleware/cors.js`: разрешающие заголовки только при равном `Origin`, `Vary: Origin` всегда, `*` запрещён при создании (5 тестов в `cors-search.test.js`) |
| Токен JWT в `localStorage` | кража токена при XSS | не изменено: так требует условие. Смягчение: нет `innerHTML`, срок токена один час, 401 удаляет токен. Надёжнее cookie `HttpOnly`, это выходит за рамки ЛР5 |
| Нет заголовка Content-Security-Policy у клиента | слабее защита от XSS | не сделано: заголовок задаёт сервер статики, а `<meta>` ломает инлайн-скрипт dev-сервера Vite. Нужно выставить при публикации |
| Поиск `?search=` передаёт `%` и `_` в `LIKE` как шаблон | пользователь видит больше записей, чем ввёл, вреда и инъекции нет | не сделано: Sequelize не даёт `ESCAPE` без `literal`, значение остаётся параметром запроса (тест на кавычки есть) |
| Мутации (POST, PUT, DELETE) нельзя отменить | после выхода ответ дойдёт в уже размонтированный хук | не сделано: React 19 это допускает, состояние не используется после выхода |
| Добавление во время смены поискового текста | запись, созданная до перезагрузки списка, может пропасть из представления до обновления | не сделано: данные на сервере целы, список всегда берётся с сервера заново |
| Страницы 404 нет | в одностраничном клиенте нет маршрутов | не требуется: маршрутизатор в работе не используется, страница 500 есть (`ErrorBoundary`) |
