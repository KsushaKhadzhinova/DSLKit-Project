# Практическое занятие №3. Маршрутизация в React-приложениях

## 1 Цель работы

Освоить маршрутизацию в React-приложении: настроить маршруты, создать одностраничное приложение с несколькими страницами, использовать динамические маршруты и защищённые маршруты на примере проекта DSLKit, веб-редактора диаграмм как кода (направление SaaS).

## 2 Выбор версии React Router

Условие называет React Router v6 с пометкой «v6?». Использована библиотека `react-router-dom` версии 7.18.4. Весь API из условия (`BrowserRouter`, `Routes`, `Route`, `Link`, `NavLink`, `Outlet`, `Navigate`, `useParams`, `useNavigate`, `useLocation`) в версии 7 в режиме библиотеки работает так же, как в v6. Версия 7 поддерживается, совместима с React 19 и уже используется в приложении из первой части курса. При необходимости код переносится на v6 командой `npm i react-router-dom@6` без правок.

## 3 Ход работы

### 3.1 Карта маршрутов

Приложение состоит из страниц, показанных в таблице 1. Все страницы, включая вход и выход, находятся внутри общего маршрута-обёртки `Layout`, который рисует меню и через `Outlet` подставляет содержимое страницы.

| Путь           | Страница               | Доступ                             |
| -------------- | ---------------------- | ---------------------------------- |

| `/catalog`     | Каталог шаблонов       | открыт                             |
| `/catalog/:id` | Карточка шаблона       | открыт, неверный `id` ведёт на 404 |

### 3.2 Меню и динамический маршрут

Меню построено на `NavLink`, функция в `className` получает флаг `isActive` и добавляет класс активного пункта. Для главной страницы указан `end`, чтобы пункт не оставался активным на всех путях. Страница `/catalog/:id` читает параметр через `useParams`, ищет шаблон в данных и при неудаче показывает страницу 404 на месте компонентом `NotFound`, адрес не меняется. Кнопка «Назад» вызывает `navigate(-1)`. Над содержимым стоят хлебные крошки: компонент `Breadcrumbs` разбивает `pathname` на части и строит цепочку «Главная / Каталог / название шаблона», последний элемент отмечен `aria-current`. Для неизвестного адреса и неизвестного `id` цепочка не показывается. Страницы каталога, кабинета и администратора загружаются лениво через `lazy`, а `Layout` оборачивает `Outlet` в `Suspense` с сообщением «Загрузка страницы…», поэтому меню остаётся на экране, пока код страницы скачивается. Каталог читает фильтр из адреса хуком `useSearchParams`: ссылка `/catalog?q=UML&sort=title` сразу показывает отфильтрованный и отсортированный список. Запрос обрезается до предела из `limits.json`, запрос из одних пробелов и неизвестная сортировка игнорируются, а текст запроса выводится как текст. Код приведён в приложении А.

### 3.3 Защищённый маршрут и имитация входа

Компонент `PrivateRoute` работает как маршрут-обёртка: для вошедшего пользователя он рисует `Outlet`, иначе перенаправляет на `/login` и передаёт в `state` запрошенный адрес целиком, с параметрами запроса и якорем, не показывая его в адресной строке. Форма входа спрашивает имя пользователя. Пустое имя и имя из одних пробелов отклоняются, предел длины взят из файла `src/limits.json`. Сессия хранится в состоянии `AuthProvider` и в `localStorage`, а запись без допустимого имени не считается входом. После входа `Login` возвращает на запрошенную страницу или на `/dashboard`. Адрес возврата проверяется функцией `safeReturnPath`: чужие адреса, начинающиеся с `//` или с имени протокола, игнорируются. Выход сделан отдельным маршрутом `/logout`, он очищает сессию и возвращает на главную декларативно. Вход в другой вкладке и выход из неё подхватываются событием `storage`. Роль выводится из имени: имя `admin` в любом регистре даёт роль администратора, остальные имена дают роль пользователя. Компонент `RoleRoute` вложен в `PrivateRoute` и пропускает на `/admin` только роль admin, а другим ролям показывает страницу 403 в стиле сайта. Гость на `/admin` сначала попадает на вход и после входа под именем admin возвращается на `/admin`.

Проверка на сервере в этой работе невозможна, поэтому защита скрывает страницы в интерфейсе и не защищает данные. В реальном проекте доступ проверяет сервер по токену.

### 3.4 Доступность и страницы ошибок

После смены маршрута страница не перезагружается, поэтому фокус остаётся на нажатой ссылке. Компонент `Layout` переносит фокус на основное содержимое и обновляет заголовок вкладки, чтобы программа чтения с экрана объявила новую страницу. Есть ссылка пропуска меню и один заголовок первого уровня на странице. Страница 404 оформлена карточкой ошибки сайта первой части и показывается для любого неизвестного пути и для неизвестного `id`. Идентификатор из адреса никогда не вставляется в страницу как разметка. Страница 500 появляется через `ErrorBoundary`, когда отрисовка завершилась сбоем.

### 3.5 Внешний вид

Приложение использует стили и разметку сайта первой части: закреплённую шапку с логотипом, меню с подсветкой активного пункта через `aria-current`, кнопку меню для телефона, переключатель темы в виде луны и солнца, карточки, поля форм и подвал. На каждом экране только одна главная кнопка.

### 3.7 Тестирование

Шестьдесят один автоматический тест на `MemoryRouter` проверяет все страницы, фильтр каталога в адресе (огромный и пробельный запрос, подделанную сортировку, разметку в запросе), ленивую загрузку с запасным сообщением, хлебные крошки, маршрут только для роли admin (гость, пользователь, администратор, выход в другой вкладке), двойной щелчок по кнопке входа, подсветку `NavLink`, динамический маршрут, страницу 404, редирект гостя, возврат с параметрами запроса, проверку имени, подделанный адрес возврата, выход в другой вкладке, перенос фокуса, вывод разметки как текста и страницу 500. Ручная проверка описана в `README.md`.

### 3.8 Адреса и размещение

Приложение можно разместить не в корне сервера. Сборка с переменной `VITE_BASE=/dslkit/` кладёт файлы в подпапку, а компонент `AppRouter` берёт её как `basename`. Сборка с переменной `VITE_ROUTER=hash` переключает приложение на `HashRouter`: адреса получают вид `/#/catalog`, и статическому хостингу не нужны правила перенаправления на `index.html`. По умолчанию работает обычный `BrowserRouter`.

Приложение на Vite содержит восемь маршрутов, меню с подсветкой активного пункта, динамический маршрут с обработкой неизвестного параметра, страницу 404 защищённый кабинет с имитацией входа и программной навигацией, фильтр каталога через `useSearchParams`, ленивую загрузку страниц, хлебные крошки и раздел только для роли admin. ## Ответы на контрольные вопросы

25. **Чем `BrowserRouter` отличается от `HashRouter`?** Первый использует обычные адреса и требует настройки сервера на возврат `index.html`, второй хранит путь после `#` и работает на статическом хостинге без настройки.
26. **Как сделать модальное окно с отдельным маршрутом?** Вложить маршрут модального окна в страницу галереи и показывать его через `Outlet` поверх содержимого, закрытие это `navigate(-1)`.
27. **Как протестировать маршрутизацию?** Обернуть компонент в `MemoryRouter initialEntries={['/catalog/2']}` и проверять отрисовку и переходы. Так написаны тесты проекта.

```jsx
// App.jsx: карта маршрутов, Layout даёт меню и Outlet
<Routes>
  <Route element={<Layout />}>
    <Route index element={<Home />} />
    <Route path="catalog/:id" element={<CatalogItem />} />
    <Route path="logout" element={<Logout />} />
    <Route element={<PrivateRoute />}>
      <Route path="dashboard" element={<Dashboard />} />
      <Route element={<RoleRoute role="admin" />}>
        <Route path="admin" element={<Admin />} />
      </Route>
    </Route>
    <Route path="*" element={<NotFound />} />
  </Route>
</Routes>
```
