# Практическое занятие №3. Маршрутизация в React-приложениях

## 1 Цель работы

Освоить маршрутизацию в React-приложении: настроить маршруты, создать одностраничное приложение с несколькими страницами, использовать динамические маршруты и защищённые маршруты на примере проекта DSLKit, веб-редактора диаграмм как кода (направление SaaS).

## 2 Выбор версии React Router

Условие называет React Router v6 с пометкой «v6?». Использована библиотека `react-router-dom` версии 7.18.4. Весь API из условия (`BrowserRouter`, `Routes`, `Route`, `Link`, `NavLink`, `Outlet`, `Navigate`, `useParams`, `useNavigate`, `useLocation`) в версии 7 в режиме библиотеки работает так же, как в v6. Версия 7 поддерживается, совместима с React 19 и уже используется в приложении из первой части курса. При необходимости код переносится на v6 командой `npm i react-router-dom@6` без правок.

## 3 Ход работы

### 3.1 Карта маршрутов

Приложение состоит из страниц, показанных в таблице 1. Все страницы, включая вход и выход, находятся внутри общего маршрута-обёртки `Layout`, который рисует меню и через `Outlet` подставляет содержимое страницы.

Таблица 1 – Маршруты приложения

| Путь           | Страница               | Доступ                             |
| -------------- | ---------------------- | ---------------------------------- |
| `/`            | Главная                | открыт                             |
| `/catalog`     | Каталог шаблонов       | открыт                             |
| `/catalog/:id` | Карточка шаблона       | открыт, неверный `id` ведёт на 404 |
| `/about`       | О проекте              | открыт                             |
| `/login`       | Вход (имитация)        | открыт                             |
| `/logout`      | Выход, редирект на `/` | открыт                             |
| `/dashboard`   | Личный кабинет         | только после входа                 |
| `*`            | 404                    | открыт                             |

### 3.2 Меню и динамический маршрут

Меню построено на `NavLink`, функция в `className` получает флаг `isActive` и добавляет класс активного пункта. Для главной страницы указан `end`, чтобы пункт не оставался активным на всех путях. Страница `/catalog/:id` читает параметр через `useParams`, ищет шаблон в данных и при неудаче показывает страницу 404 на месте компонентом `NotFound`, адрес не меняется. Кнопка «Назад» вызывает `navigate(-1)`. Код приведён в приложении А.

### 3.3 Защищённый маршрут и имитация входа

Компонент `PrivateRoute` работает как маршрут-обёртка: для вошедшего пользователя он рисует `Outlet`, иначе перенаправляет на `/login` и передаёт в `state` запрошенный адрес целиком, с параметрами запроса и якорем, не показывая его в адресной строке. Форма входа спрашивает имя пользователя. Пустое имя и имя из одних пробелов отклоняются, предел длины взят из файла `src/limits.json`. Сессия хранится в состоянии `AuthProvider` и в `localStorage`, а запись без допустимого имени не считается входом. После входа `Login` возвращает на запрошенную страницу или на `/dashboard`. Адрес возврата проверяется функцией `safeReturnPath`: чужие адреса, начинающиеся с `//` или с имени протокола, игнорируются. Выход сделан отдельным маршрутом `/logout`, он очищает сессию и возвращает на главную декларативно. Вход в другой вкладке и выход из неё подхватываются событием `storage`.

Проверка на сервере в этой работе невозможна, поэтому защита скрывает страницы в интерфейсе и не защищает данные. В реальном проекте доступ проверяет сервер по токену.

### 3.4 Доступность и страницы ошибок

После смены маршрута страница не перезагружается, поэтому фокус остаётся на нажатой ссылке. Компонент `Layout` переносит фокус на основное содержимое и обновляет заголовок вкладки, чтобы программа чтения с экрана объявила новую страницу. Есть ссылка пропуска меню и один заголовок первого уровня на странице. Страница 404 оформлена карточкой ошибки сайта первой части и показывается для любого неизвестного пути и для неизвестного `id`. Идентификатор из адреса никогда не вставляется в страницу как разметка. Страница 500 появляется через `ErrorBoundary`, когда отрисовка завершилась сбоем.

### 3.5 Внешний вид

Приложение использует стили и разметку сайта первой части: закреплённую шапку с логотипом, меню с подсветкой активного пункта через `aria-current`, кнопку меню для телефона, переключатель темы в виде луны и солнца, карточки, поля форм и подвал. На каждом экране только одна главная кнопка.

## Ответы на контрольные вопросы

{{answers}}
1. **Как передать параметр через URL?** Объявить сегмент `path="catalog/:id"` и прочитать `const { id } = useParams()`.
2. **Что такое `Outlet`?** Место во вложенном маршруте-обёртке, куда подставляется дочерняя страница. В проекте так устроен `Layout`.
3. **Как выполнить программную навигацию?** Вызвать функцию из `useNavigate()`, например `navigate('/dashboard')`.
4. **Как защитить маршрут?** Написать компонент, который при отсутствии входа возвращает `<Navigate to="/login" replace />`, иначе `<Outlet />`. В проекте это `PrivateRoute`.
5. **Чем `Link` отличается от `NavLink`?** `NavLink` знает, активна ли ссылка, и ставит `aria-current` и класс. Его используют в меню, а `Link` во всех остальных местах.
6. **Как создать вложенные маршруты?** Вложить `<Route>` в родительский, а в элементе родителя поставить `<Outlet />`.
7. **Как передать `state`, не показывая его в URL?** Через `navigate(path, { state })` или `<Navigate state>`, читать через `useLocation().state`.
8. **Что такое `useNavigate`?** Хук, возвращающий функцию перехода. Переход назад это `navigate(-1)`.
9. **Как обработать неизвестный параметр?** Найти данные по `id`, и если их нет, показать страницу 404 на месте или перенаправить на `*`. В проекте показывается `NotFound`.
10. **Как получить текущий путь?** `useLocation().pathname`.
11. **Как сделать активную ссылку?** `NavLink` с функцией в `className`: `({ isActive }) => (isActive ? 'on' : 'off')`.
12. **Как сделать редирект?** Отрисовать `<Navigate to="/" replace />`.
13. **Как проверить роль пользователя?** В компоненте-обёртке сравнить `user.role` с требуемой и при несовпадении показать 403 или перенаправить.
14. **Как прочитать строку запроса?** `const [params, setParams] = useSearchParams()` и `params.get('sort')`.
15. **Как задать необязательный параметр?** Записать два маршрута или использовать `path="catalog/:id?"`, где знак вопроса делает сегмент необязательным.
16. **Как обработать все несуществующие маршруты?** Добавить `<Route path="*" element={<NotFound />} />` последним.
17. **Как использовать `useLocation`?** Он возвращает объект с `pathname`, `search`, `hash` и `state`, а параметры запроса удобнее разбирать через `URLSearchParams`.
18. **Как вложить один `Routes` в другой?** Родительский маршрут заканчивается на `/*`, а внутри компонента объявляется свой `<Routes>` с относительными путями.
19. **Как заменить запись в истории?** `navigate(path, { replace: true })` или атрибут `replace` у `Link` и `Navigate`.
20. **Как разместить приложение не в корне сервера?** Передать `basename="/app"` в `BrowserRouter` и настроить `base` у сборщика.
21. **Как загружать страницы лениво?** Объявить `const Page = lazy(() => import('./Page'))` и обернуть `Routes` в `<Suspense fallback=...>`.
22. **Как защитить маршрут хуком `useAuth`?** Хук возвращает `isAuth` из контекста, и `PrivateRoute` решает по нему. В проекте хук есть в `auth.jsx`.
23. **Как сделать хлебные крошки?** Разбить `pathname` по слэшам и построить цепочку ссылок накопленных путей.
24. **Как передать параметры в компонент через `element`?** Записать `element={<Page title="Каталог" />}`.
25. **Чем `BrowserRouter` отличается от `HashRouter`?** Первый использует обычные адреса и требует настройки сервера на возврат `index.html`, второй хранит путь после `#` и работает на статическом хостинге без настройки.
26. **Как сделать модальное окно с отдельным маршрутом?** Вложить маршрут модального окна в страницу галереи и показывать его через `Outlet` поверх содержимого, закрытие это `navigate(-1)`.
27. **Как протестировать маршрутизацию?** Обернуть компонент в `MemoryRouter initialEntries={['/catalog/2']}` и проверять отрисовку и переходы. Так написаны тесты проекта.
28. **Как задать стиль активного маршрута?** Через функцию `className` или `style` у `NavLink`, получающую `isActive`.
29. **Как предупредить о несохранённых данных при уходе?** Использовать `useBlocker` в маршрутизаторе данных или событие `beforeunload` для закрытия вкладки.
30. **Можно ли использовать несколько `Routes`?** Да, каждый `Routes` сопоставляет путь независимо, поэтому их используют для модульной маршрутизации и боковых панелей.

## Приложение А (обязательное) Ключевые части кода

```jsx
// App.jsx: карта маршрутов, Layout даёт меню и Outlet
<Routes>
  <Route element={<Layout />}>
    <Route index element={<Home />} />
    <Route path="catalog/:id" element={<CatalogItem />} />
    <Route path="logout" element={<Logout />} />
    <Route element={<PrivateRoute />}>
      <Route path="dashboard" element={<Dashboard />} />
    </Route>
    <Route path="*" element={<NotFound />} />
  </Route>
</Routes>
```

```jsx
// CatalogItem: параметр из URL и страница 404 на месте
const { id } = useParams();
const template = findTemplate(id);
if (!template) return <NotFound />;
```

```jsx
// PrivateRoute: защита и запоминание запрошенного пути
const from = `${location.pathname}${location.search}${location.hash}`;
return isAuth ? <Outlet /> : <Navigate to="/login" replace state={{ from }} />;
```

```jsx
// Login: программная навигация после имитации входа
login(name);
navigate(safeReturnPath(location.state?.from), { replace: true });
```
