# Практическое занятие №4. Управление состоянием приложения

## 1 Цель работы

Освоить глобальное управление состоянием в React с помощью Context API и хука `useReducer`: показать проблему prop drilling, решить её контекстами и реализовать бизнес-логику проекта DSLKit, веб-редактора диаграмм как кода (направление SaaS), в виде редьюсера и провайдера.

## 2 Ход работы

### 2.1 Проблема prop drilling

Иерархия `PropDrilling` → `DrillingHeader` → `Navigation` → `UserMenu` → `UserAvatar` передаёт имя пользователя через все уровни, хотя использует его только `UserAvatar`. Три промежуточных компонента получают `userName` лишь ради передачи дальше, поэтому любое изменение данных требует правок во всей цепочке. Код приведён в приложении А.

Решение показано рядом, в том же разделе страницы. Имя пользователя лежит в `UserContext`, а `ContextHeader`, `ContextNavigation` и `ContextMenu` не получают props: `ContextAvatar` читает имя хуком `useUser`. Глубина вложенности та же, но передача данных вниз по цепочке исчезает, и добавление нового уровня не требует правок.

### 2.2 Контексты темы и языка

`ThemeProvider` хранит тему в `useState`, переключает её функцией `toggleTheme` и записывает в атрибут `data-theme` корневого элемента, а CSS-переменные меняют цвета всей страницы. `LanguageProvider` хранит язык и словарь на русском и английском, компоненты получают функцию `t(key)` и не принимают тексты через props. Значения контекстов обёрнуты в `useMemo`, чтобы потребители не перерисовывались без изменения данных.

### 2.3 Избранное на useReducer и Context

Предметная область: избранные шаблоны диаграмм. Состояние это массив объектов `{ id, qty }`. Редьюсер обрабатывает действия `ADD` (без дублей), `REMOVE`, `TOGGLE`, `INCREMENT`, `DECREMENT`, `SET_QTY` и `CLEAR`, возвращает новый массив и не изменяет прежний, неизвестное действие оставляет состояние без изменений. Количество всегда целое число от 1 до предела `maxQty` из `limits.json`, значение вне диапазона, дробное или нечисловое приводится к ближайшему допустимому. `FavoritesProvider` разделён на два контекста: данные (`useFavorites`) меняются при каждом действии, а `dispatch` (`useFavoritesDispatch`) не меняется никогда, поэтому компонент, который только отправляет действия, не перерисовывается при изменении данных. Карточка шаблона и панель «Избранное» работают с одним состоянием без передачи через props, в панели есть кнопки «минус» и «плюс» и текущее количество. Список сохраняется в `localStorage` эффектом и читается ленивым инициализатором `useReducer`.

### 2.4 Устойчивость к чужим данным

Содержимое `localStorage` может быть изменено вручную. Функция `sanitizeFavorites` оставляет только известные идентификаторы шаблонов, по одному разу, исправляет повреждённое количество и принимает прежний формат со списком идентификаторов как количество 1. Тема и язык принимаются из хранилища только при допустимых значениях, иначе тема берётся из настройки системы, а язык русский. Недоступное хранилище и неверный JSON не ломают приложение. Тексты выводятся как текст, поэтому разметка в имени пользователя не выполняется, а пустое имя в цепочке prop drilling заменяется знаком вопроса. Страница 500 показывается через `ErrorBoundary`, если отрисовка завершилась сбоем.

### 2.5 Внешний вид

Приложение использует стили и разметку сайта первой части: закреплённую шапку с логотипом и меню по разделам страницы, кнопку языка, переключатель темы в виде луны и солнца с подсказкой, карточки и подвал. Переключатель темы и кнопка языка читают те же контексты, что остальные компоненты, а подписи шапки меняются вместе с языком.

### 2.7 Тестирование

Тридцать восемь автоматических тестов проверяют редьюсер как чистую функцию, изменение количества с пределами, разделение контекстов (число перерисовок), проблему и решение prop drilling, двойной щелчок по кнопкам, переключение темы и языка, сохранение выбора, добавление, удаление и очистку избранного, восстановление после перезагрузки, повреждённые данные, ошибку записи в хранилище, демонстрацию prop drilling, вывод разметки как текста и страницу 500.

## Заключение

Prop drilling показан на цепочке из пяти компонентов и устранён контекстами темы, языка и избранного, а блок решения стоит рядом с проблемой. Бизнес-логика вынесена в чистый редьюсер, состояние и `dispatch` доступны в любом компоненте через хуки `useTheme`, `useLanguage`, `useFavorites` и `useFavoritesDispatch`, избранное сохраняется между сессиями.

## Ответы на контрольные вопросы

{{answers}}
1. **Что такое prop drilling?** Передача данных через цепочку компонентов, которым они не нужны. Любое изменение данных требует правок всей цепочки.
2. **Как создать и использовать Context API?** Создать `createContext`, обернуть дерево в `Provider` со значением и читать значение через `useContext` в любом потомке.
3. **В чём преимущество `useReducer`?** Логика переходов собрана в одной чистой функции, её легко тестировать, а обновления описываются действиями.
4. **Как комбинировать Context и `useReducer`?** Создать `[state, dispatch] = useReducer(...)` в провайдере и отдать их в `value`. В проекте так работает `FavoritesProvider`.
5. **Как предотвратить лишние перерисовки?** Мемоизировать значение через `useMemo`, делить контексты по назначению и использовать `React.memo`.
6. **Для каких данных подходит Context?** Для редко меняющихся глобальных данных: тема, язык, пользователь.
7. **Как разделить Context на несколько?** Создать отдельные контексты и вложить их провайдеры друг в друга, как `ThemeProvider`, `LanguageProvider` и `FavoritesProvider`.
8. **Что такое `useMemo` и как он помогает?** Он запоминает вычисленное значение до смены зависимостей, поэтому объект в `value` не создаётся заново и потребители не перерисовываются зря.
9. **Как в редьюсере обработать действие, зависящее от состояния?** Прочитать `state` внутри `case`, как в `ADD`: если идентификатор уже есть, вернуть прежнее состояние.
10. **Как сохранить корзину в `localStorage`?** Записывать состояние эффектом на каждое изменение и читать ленивым инициализатором `useReducer`, проверяя формат данных.
11. **В чём разница между `useState` и `useReducer`?** `useState` подходит для простых независимых значений, `useReducer` для связанных полей и сложных переходов.
12. **Как передать `dispatch` через Context?** Положить его в отдельный контекст и получить в потомке: `const dispatch = useFavoritesDispatch()`.
13. **Что такое действия?** Простые объекты с полем `type` и данными: `{ type: 'INCREMENT', id: 2 }`. Тип записывают константой или строкой в верхнем регистре.
14. **Как обработать несколько полей состояния?** Хранить объект и возвращать копию с изменённым полем `{ ...state, cart: ... }` или разбить на несколько редьюсеров.
15. **Как избежать мутации?** Возвращать новые массивы и объекты: `[...state, item]` и `filter`, а не `push` и присваивание полей.
16. **Как подписаться на часть состояния?** Разделить контекст на несколько или вычислять производное значение в компоненте. Для точных селекторов нужна внешняя библиотека.
17. **Как использовать несколько `useReducer`?** Вызвать хук несколько раз с разными редьюсерами, у каждого свои состояние и `dispatch`.
18. **Как реализовать сброс?** Добавить действие `RESET`, которое возвращает начальное состояние. В проекте это `CLEAR`.
19. **Как отладить `dispatch`?** Вывести `action` и состояние в консоль внутри редьюсера или обернуть `dispatch` логирующей функцией, а также использовать инструменты разработчика React.
20. **Как передать начальное состояние функцией?** Третьим аргументом `useReducer(reducer, arg, init)`. В проекте `useReducer(favoritesReducer, undefined, loadFavorites)`.
21. **Как мемоизировать значение провайдера?** `const value = useMemo(() => ({ favorites, dispatch }), [favorites])`. В проекте данные и `dispatch` лежат в двух контекстах, а `dispatch` не меняется никогда, поэтому новое значение нужно только контексту данных.
22. **Что такое action creator?** Функция, которая возвращает объект действия: `const increment = (id) => ({ type: 'INCREMENT', id })`.
23. **Как организовать аутентификацию?** Состояние `{ user, status }` и действия `LOGIN` и `LOGOUT` в редьюсере, а токен хранить вне состояния или в защищённом хранилище.
24. **Как реализовать отмену действия?** Хранить историю `{ past, present, future }`, а действие `UNDO` перемещает последнее состояние из `past` в `present`.
25. **Можно ли использовать `useReducer` без Context?** Да, для локального состояния одного компонента, например формы или счётчика: `const [n, dispatch] = useReducer(r, 0)`.
26. **Чем Context плюс `useReducer` отличается от Redux?** Для малых проектов проще и без зависимостей, но нет инструментов отладки, промежуточных слоёв и точных подписок, как в Redux.
27. **Как получить только `dispatch`?** Вынести `dispatch` в отдельный контекст, тогда компонент не перерисовывается при смене состояния. Так сделано в проекте через `useFavoritesDispatch`.
28. **Что такое thunk и как имитировать асинхронные действия?** Это функция вместо объекта действия. В `useReducer` асинхронный код выполняют в обработчике и вызывают `dispatch` с результатом.
29. **Как исправить лишние перерисовки?** Разделить контекст на два, для данных и для `dispatch`, и мемоизировать значения. В проекте есть два контекста, `useFavorites` и `useFavoritesDispatch`, а тест считает число отрисовок.
30. **Как протестировать редьюсер?** Вызвать функцию напрямую: `expect(reducer([], { type: 'ADD', id: 1 })).toEqual([{ id: 1, qty: 1 }])`. Так написаны тесты проекта.

```jsx
// FavoritesContext.jsx: редьюсер и провайдер
export function favoritesReducer(state, action) {
  switch (action.type) {
    case 'ADD':
      return state.some((item) => item.id === action.id) ? state : [...state, { id: action.id, qty: 1 }];
    case 'REMOVE':
      return state.filter((item) => item.id !== action.id);
    case 'INCREMENT':
      return changeQty(state, action.id, (qty) => qty + 1);
    case 'DECREMENT':
      return changeQty(state, action.id, (qty) => qty - 1);
    case 'SET_QTY':
      return changeQty(state, action.id, () => action.qty);
    case 'CLEAR':
      return [];
    default:
      return state;
  }
}

const [favorites, dispatch] = useReducer(favoritesReducer, undefined, loadFavorites);
```
