# Практическое занятие №4. Управление состоянием приложения

## 1 Цель работы

Освоить глобальное управление состоянием в React с помощью Context API и хука `useReducer`: показать проблему prop drilling, решить её контекстами и реализовать бизнес-логику проекта DSLKit, веб-редактора диаграмм как кода (направление SaaS), в виде редьюсера и провайдера. Работа выполнена в ветке `pz24`, код лежит в папке `part-2/pz-04-context-reducer`.

## 2 Ход работы

### 2.1 Проблема prop drilling

Иерархия `PropDrilling`, `DrillingHeader`, `Navigation`, `UserMenu` и `UserAvatar` передаёт имя пользователя через все уровни, хотя использует его только `UserAvatar`. Три промежуточных компонента получают `userName` лишь ради передачи дальше, поэтому любое изменение данных требует правок во всей цепочке. Код цепочки приведён в приложении А.

### 2.2 Контексты темы и языка

`ThemeProvider` хранит тему в `useState`, переключает её функцией `toggleTheme` и записывает в атрибут `data-theme` корневого элемента, а CSS-переменные меняют цвета всей страницы. `LanguageProvider` хранит язык и словарь на русском и английском, компоненты получают функцию `t(key)` и не принимают тексты через props. Значения контекстов обёрнуты в `useMemo`, чтобы потребители не перерисовывались без изменения данных.

### 2.3 Избранное на useReducer и Context

Предметная область: избранные шаблоны диаграмм. Состояние это массив записей `{ id, addedAt }`. Редьюсер обрабатывает действия `ADD` без дублей, `REMOVE`, `TOGGLE` и `CLEAR`, возвращает новый массив и не изменяет прежний, а неизвестное действие оставляет состояние без изменений. Время добавления приходит в действии, поэтому редьюсер остаётся чистой функцией. Провайдер отдаёт состояние и `dispatch` двумя разными контекстами: компоненты, которые только отправляют действия, не перерисовываются при изменении списка. Список сохраняется в `localStorage` эффектом и читается ленивым инициализатором `useReducer`. Данные неверного формата и недоступное хранилище не ломают приложение.

### 2.4 Время создания и страница ошибки

У каждого шаблона в списке показано время создания, у каждой записи избранного время добавления в формате «2026-10-16 12:30:05», поэтому записи визуально различаются. Компонент `ErrorBoundary` показывает оформленную страницу 500 с кнопкой обновления вместо пустого экрана, если отрисовка падает с ошибкой.

### 2.5 Проверка введённых значений

В работе нет полей ввода, поэтому проверки длины, пустых и пробельных значений и файла `limits.json` здесь не требуется. Проверяется единственный внешний источник данных, содержимое `localStorage`: значение должно быть массивом записей с числовым `id` и строковым `addedAt`, иначе берётся пустой список.

### 2.6 Тестирование

Тринадцать автоматических тестов проверяют редьюсер как чистую функцию, переключение темы и языка, добавление, удаление и очистку избранного, время создания и добавления, восстановление после перезагрузки, повреждённые данные и данные старого формата, ошибку записи в хранилище, страницу ошибки и демонстрацию prop drilling. Запуск описан в `README.md`.

## 3 Ответы на контрольные вопросы

Ответы даны на вопросы 25, 26 и 27, которые соответствуют варианту 26.

25. Да. `useReducer` не зависит от Context: компонент может держать `const [state, dispatch] = useReducer(reducer, initial)` и использовать их локально, например для формы с несколькими связанными полями или счётчика с действиями `inc`, `dec` и `reset`. Context нужен только тогда, когда состояние должны читать компоненты на разных уровнях дерева.
26. Context вместе с `useReducer` встроен в React, не требует зависимостей и подходит для небольшого проекта вроде DSLKit с темой, языком и избранным. Redux добавляет промежуточные слои, селекторы с точечной подпиской, `Redux DevTools` с историей действий и строгую структуру, поэтому лучше масштабируется на большое число сущностей, но требует больше кода и пакетов. Недостаток Context: все потребители перерисовываются при смене значения, готовых селекторов и средств отладки нет.
27. Нужно разделить Context на два: один хранит состояние, второй только `dispatch`. Функция `dispatch` из `useReducer` не меняется между рендерами, поэтому компоненты, которые лишь отправляют действия, подписываются на контекст с `dispatch` и не перерисовываются при изменении списка. В работе это сделано в `FavoritesContext.jsx`: хуки `useFavorites` и `useFavoritesDispatch`.

## Заключение

Prop drilling показан на цепочке из пяти компонентов и устранён контекстами темы, языка и избранного. Бизнес-логика вынесена в чистый редьюсер, состояние и `dispatch` доступны в любом компоненте через хуки `useTheme`, `useLanguage`, `useFavorites` и `useFavoritesDispatch`, избранное сохраняется между сессиями, а записи различаются временем создания.

## Приложение В – Редьюсер и провайдер избранного

```jsx
export function favoritesReducer(state, action) {
  const has = state.some((item) => item.id === action.id);
  switch (action.type) {
    case 'ADD':
      return has ? state : [...state, { id: action.id, addedAt: action.addedAt }];
    case 'REMOVE':
      return state.filter((item) => item.id !== action.id);
    case 'TOGGLE':
      return has ? state.filter((item) => item.id !== action.id) : [...state, { id: action.id, addedAt: action.addedAt }];
    case 'CLEAR':
      return [];
    default:
      return state;
  }
}

const [favorites, dispatch] = useReducer(favoritesReducer, undefined, loadFavorites);
```
