# Лабораторная работа №4. Управление состоянием в React-приложении

## 1 Цель работы

Освоить управление локальным состоянием в React с помощью хуков `useState` и `useEffect`, обработку побочных эффектов и динамическое обновление интерфейса на примере списка диаграмм проекта DSLKit, веб-редактора диаграмм как кода (направление SaaS).

## 2 Краткое описание приложения

Приложение показывает список диаграмм пользователя. У диаграммы есть название, нотация (UML, BPMN, ERD, DFD, IDEF0, сети Петри), статус «Черновик» или «Опубликована» и дата изменения. Пользователь добавляет диаграмму через форму, переименовывает её, меняет статус, удаляет, ищет по названию, фильтрует по статусу и сортирует по дате или названию. Список переживает перезагрузку страницы, потому что хранится в `localStorage`.

Проект создан на Vite командой `npm create vite@latest` с шаблоном React, тесты написаны на Vitest и React Testing Library. Запуск описан в `README.md` работы.

## 3 Ход работы

### 3.1 Состояние компонента

Массив диаграмм, поле ввода названия, выбранная нотация, строка поиска, фильтр статуса и режим сортировки хранятся через `useState`. Изменения массива записаны функциональными обновлениями вида `setDiagrams((prev) => ...)`, поэтому быстрые подряд идущие действия не теряют друг друга. Поле ввода сделано контролируемым, форма отправляется и кнопкой, и клавишей Enter. Ключевые части кода приведены в приложении А.

### 3.2 Хранение в localStorage

Логика хранения вынесена в хук `useLocalStorage`. Начальное значение читается из `localStorage` функцией-инициализатором `useState`, поэтому при первом рендере уже видны сохранённые данные. Эффект `useEffect` с зависимостью от значения записывает массив через `JSON.stringify` при каждом изменении. Если ключа нет или JSON повреждён, берётся начальный набор из трёх диаграмм.

### 3.3 Фильтрация, сортировка и статистика

Функции `filterDiagrams`, `sortDiagrams` и `getStats` чистые и лежат в `utils/diagrams.js`, поэтому проверяются без отрисовки. Сортировка работает с копией массива и не изменяет состояние.

### 3.4 Дополнительные эффекты

Заголовок вкладки обновляется эффектом и показывает число диаграмм. Хук `useAutosaveStatus` показывает «Сохранение…» после изменения и «Сохранено» через 500 мс тишины. Это debounce: каждое новое изменение очищает прежний таймер функцией очистки эффекта.

### 3.5 Проверка вводимых значений

Форма и режим редактирования проверяют название диаграммы до сохранения. Значение из одних пробелов считается пустым и отклоняется сообщением «Введите название диаграммы». Название длиннее предела отклоняется сообщением с числом допустимых символов. Пределы длины названия и числа записей лежат в отдельном файле `src/limits.json`, а не в коде компонентов. Список ограничен 200 записями, поэтому бесконечные добавления не заполнят `localStorage`. Поле «Создана» у каждой записи показывает время создания с секундами. Если запись создана в ту же секунду, что и предыдущая, время сдвигается на секунду вперёд, поэтому у записей нет одинакового времени.

### 3.6 Устойчивость к чужим данным

Содержимое `localStorage` может быть изменено вручную или остаться от прежней версии. Функция `isDiagramList` принимает только список, где у каждой записи есть допустимое название, известная нотация, логический статус и корректные даты, а идентификаторы не повторяются. При любом отклонении берётся начальный набор. Названия выводятся как текст, поэтому разметка внутри названия не выполняется. Идентификатор создаётся через `crypto.randomUUID`, а на адресе без защищённого контекста подставляется запасной способ. Компонент `ErrorBoundary` показывает страницу 500 в стиле сайта вместо пустого экрана при сбое отрисовки.

### 3.7 Внешний вид

Приложение использует те же стили и разметку, что сайт первой части: закреплённую шапку с логотипом, меню с кнопкой для телефона, переключатель темы в виде луны и солнца с подсказкой, карточки, поля форм и подвал. Светлая тема включена первой, тёмная выбирается по настройке системы или переключателем. Одна главная кнопка на экране это «Добавить».

Пятьдесят пять автоматических тестов проверяют чистые функции, оба хука и поведение приложения: добавление, удаление, редактирование с Enter и Esc, переключение статуса, фильтры, сортировку, восстановление списка, проверку пробельных и огромных значений, уникальное время создания, повреждённые данные хранилища, вывод разметки как текста, переключатель темы и страницу 500. ## Заключение

Приложение на Vite реализует добавление, удаление и редактирование диаграмм, фильтрацию и сортировку, сохранение в `localStorage` и два дополнительных эффекта, заголовок страницы и автосохранение с debounce. Логика хранения вынесена в пользовательский хук, что упростит замену `localStorage` на REST API в лабораторной работе №5.

1. **Для чего нужен хук `useState`?** Он хранит значение между отрисовками. Для обновления по прежнему значению передают функцию: `setCount((prev) => prev + 1)`.
2. **Что такое побочный эффект?** Это действие вне отрисовки: запись в `localStorage`, таймер, смена `document.title`. В проекте так работают `useLocalStorage` и `useAutosaveStatus`.
3. **Как работает массив зависимостей?** Эффект запускается после отрисовки, если изменилось любое значение из массива. Пустой массив означает один запуск после монтирования.
4. **Как загрузить данные из `localStorage` при монтировании?** Прочитать значение функцией-инициализатором `useState` или в эффекте с пустым массивом зависимостей.
5. **Почему нельзя вызывать хуки в условиях?** React сопоставляет хуки по порядку вызова, и другой порядок на следующей отрисовке сломает состояние.
6. **Чем `localStorage` отличается от `sessionStorage`?** Первый живёт между сессиями, второй очищается при закрытии вкладки.
7. **Как сделать ленивую загрузку состояния?** Передать в `useState` функцию: `useState(() => readStorage(key))`. Она вызывается один раз при первой отрисовке.
8. **Как отладить бесконечный цикл перерисовок?** Проверить массив зависимостей, не создаются ли в нём новые объекты на каждой отрисовке, и не меняет ли эффект своё же значение без условия.
9. **Как сохранить объект или массив в `localStorage`?** Сериализовать через `JSON.stringify`, а прочитать через `JSON.parse` с `try/catch` и проверкой формы данных.
10. **Что будет, если изменить состояние сразу после `setState`?** Значение в текущем вызове не изменится, потому что обновления группируются и применяются на следующей отрисовке. Для цепочки используют функциональную форму.
11. **Как имитировать загрузку с сервера?** В `useEffect` запустить `setTimeout`, который через секунду записывает данные в состояние, а в очистке вызвать `clearTimeout`.
12. **Какую функцию очистки можно вернуть из эффекта?** Ту, что снимает подписку или таймер. В проекте `return () => clearTimeout(timer)` в `useAutosaveStatus`.
13. **Как работать с формами?** Контролируемый компонент хранит значение в состоянии и задаёт его через `value` и `onChange`, неконтролируемый читает значение из DOM через `ref`. В проекте формы контролируемые.
14. **Как реализовать горячую клавишу Enter?** Обернуть поля в `<form onSubmit>`, тогда Enter отправляет форму, либо обработать `onKeyDown` и проверить `event.key`.
15. **Как оптимизировать большой список?** Виртуализировать список, мемоизировать вычисления через `useMemo`, а компоненты строк обернуть в `React.memo`.
16. **Как реализовать debounce для автосохранения?** В эффекте поставить `setTimeout` на 500 мс и очистить его при следующем изменении: `const t = setTimeout(save, 500); return () => clearTimeout(t);`.

## Приложение А (обязательное) Ключевые части кода

```jsx
// hooks/useLocalStorage.js: загрузка через инициализатор, запись эффектом
export function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => readStorage(key, initialValue));
  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);
  return [value, setValue];
}
```

```jsx
// hooks/useAutosaveStatus.js: debounce 500 мс с очисткой таймера
useEffect(() => {
  setStatus('saving');
  const timer = setTimeout(() => setStatus('saved'), AUTOSAVE_DELAY);
  return () => clearTimeout(timer);
}, [value]);
```
