# Часть 2. Лабораторная работа 6. MongoDB и Mongoose

Проект DSLKit (диаграммы как код, SaaS). Условие: `materials/text/part-2/Модуль 03…/11. Лабораторная работа №6…`. Работа сдаётся из ветки `26`. Это копия сервера из [лабораторной работы 2](../lab-02-sequelize), в которой Sequelize заменён на Mongoose: те же маршруты `/diagrams`, но диаграмма хранится одним документом MongoDB, а теги и комментарии лежат внутри него. Отчёты: [`report.md`](report.md) на русском, [`report.en.md`](report.en.md) на английском (шаблоны `report.tpl.md`, `report.en.tpl.md`; сборка `node tools/build.js part-2/lab-06-mongodb` из корня репозитория).

## 1 Подключение к MongoDB

Адрес базы читается из переменной `MONGODB_URI` в файле `.env` (образец в `.env.example`, сам `.env` в репозиторий не попадает).

| Вариант                      | Значение `MONGODB_URI`                                                       |
| ---------------------------- | ---------------------------------------------------------------------------- |
| Локальный MongoDB Community  | `mongodb://127.0.0.1:27017/dslkit`                                           |
| MongoDB Atlas (кластер M0)   | `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/dslkit?retryWrites=true&w=majority` |

Атлас: создайте бесплатный кластер M0, пользователя базы данных, в разделе Network Access разрешите свой IP, затем скопируйте строку из Connect, Drivers. Подключение к Атласу в этой сессии **не проверялось**: код одинаков для обоих вариантов, меняется только строка подключения. Проверен запуск сервера и сида на локальном `mongod` 8.2.

## 2 Запуск

Нужен Node.js 22 или новее и запущенный MongoDB.

```bash
cd part-2/lab-06-mongodb
npm install
cp .env.example .env     # затем впишите свой MONGODB_URI
npm run seed             # три демонстрационные диаграммы (можно запускать повторно)
npm run dev              # nodemon; npm start для обычного запуска
npm test                 # тесты
```

Запросы для проверки лежат в `requests.http` (расширение VS Code REST Client) и открываются так же в Postman. Данные видно в MongoDB Compass: база `dslkit`, коллекция `diagrams`.

## 3 Что изменилось по сравнению с ЛР 2

| Путь                                     | Назначение                                                                                                         |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `src/db.js`, `server.js`                 | `mongoose.connect(process.env.MONGODB_URI)`; при ошибке подключения сервер завершается с понятным сообщением       |
| `src/models/diagram.js`                  | Схема `Diagram` с массивом `tags`, вложенными документами `comments`, enum, индексами по `owner` и `tags`         |
| `src/controllers/diagrams.controller.js` | Методы `find`, `findById`, `create`, `findByIdAndUpdate`, `findByIdAndDelete` и операторы `$push`, `$set` с `$`, `$pull` |
| `src/middleware/validate.js`             | Проверка ObjectId (24 hex-символа), тела диаграммы и комментария                                                  |
| `scripts/seed.js`                        | Сид вместо миграций: в MongoDB схема задаётся кодом, таблиц и миграций нет                                         |
| `tests/`                                 | Тесты на временной базе MongoDB                                                                                   |

Маршруты, формат ошибок и коды ответов остались как в ЛР 2, идентификатор теперь строка ObjectId, а не число.

| Маршрут                                | Действие                                                                 |
| -------------------------------------- | ------------------------------------------------------------------------ |
| `GET /diagrams?tag=&owner=`            | Список, фильтр «массив тегов содержит значение» и по владельцу           |
| `GET /diagrams/:id`                    | Одна диаграмма                                                           |
| `POST /diagrams`                       | Создание, 201 и `Location`                                               |
| `PUT /diagrams/:id`                    | Замена полей диаграммы, комментарии сохраняются                          |
| `DELETE /diagrams/:id`                 | Удаление вместе с комментариями, 204                                     |
| `POST /diagrams/:id/comments`          | Добавить комментарий в массив (`$push`), 201                             |
| `PUT /diagrams/:id/comments/:commentId` | Изменить текст одного комментария внутри массива (`$set` и `comments.$`) |
| `DELETE /diagrams/:id/comments/:commentId` | Удалить один комментарий (`$pull`)                                    |

## 4 Проверка

`npm test` запускает 30 тестов и проверку сборки и оформления отчётов (`report.test.mjs`). Тесты поднимают временный `mongod` через `mongodb-memory-server` на случайном порту и во временной папке, поэтому рабочие базы не затрагиваются.

- По умолчанию библиотека один раз скачивает бинарник `mongod` (около 100 МБ) в свой кэш.
- Чтобы не скачивать, укажите уже установленный `mongod`: `MONGODB_URI` для тестов не нужен, нужна только переменная `MONGOMS_SYSTEM_BINARY` (например, `E:\MongoDB\Server\8.2\bin\mongod.exe`).
- MongoDB 8 отказывается работать при свободном месте на диске меньше 500 МБ. Если временная папка системы лежит на почти полном диске, задайте `TEMP` и `TMP` на другой диск.
