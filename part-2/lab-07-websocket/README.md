# Часть 2. Лабораторная работа 7. Реальное время с WebSocket

Проект DSLKit (диаграммы как код, SaaS). Условие: `materials/text/part-2/Модуль 03…/12. Лабораторная работа №7…`. Ветка сдачи по условию называется `27`. Отчёты: [`report.md`](report.md) на русском, [`report.en.md`](report.en.md) на английском (шаблоны `report.tpl.md` и `report.en.tpl.md`, сборка `node tools/build.js part-2/lab-07-websocket` из корня репозитория).

## 1 Что сделано

Сервер на Express и Socket.IO 4 и простой клиент на чистом HTML и JavaScript. Идея для DSLKit: у каждой диаграммы своя комната, в ней идёт чат и виден список тех, кто сейчас открыл диаграмму и кто её редактирует.

| Событие клиент → сервер | Данные              | Что делает сервер                                             |
| ----------------------- | ------------------- | ------------------------------------------------------------- |
| `room:join`             | `{ room }`          | Входит в комнату, отвечает историей и списком людей           |
| `room:leave`            | `{ room }`          | Выходит из комнаты                                            |
| `chat:message`          | `{ room, text }`    | Рассылает сообщение всем в комнате и сохраняет в историю      |
| `private:message`       | `{ to, text }`      | Шлёт сообщение одному пользователю по `socket.id`             |
| `typing`                | `{ room, typing }`  | Сообщает остальным в комнате, что человек печатает            |
| `editing`               | `{ room, editing }` | Отмечает, что человек редактирует диаграмму, обновляет список |

| Событие сервер → клиент | Когда приходит               | Кому и что                                                     |
| ----------------------- | ---------------------------- | -------------------------------------------------------------- |
| `welcome`               | сразу после подключения      | Ваш `id`, имя и список подключённых                            |
| `user:online`           | кто-то подключился           | Всем, кроме него (`socket.broadcast`)                          |
| `user:offline`          | кто-то отключился            | Всем остальным                                                 |
| `room:joined`           | кто-то вошёл в комнату       | Остальным в комнате                                            |
| `room:left`             | кто-то вышел или отключился  | Всем в комнате                                                 |
| `presence:update`       | состав или editing изменился | Всем в комнате: `{ room, users: [{ id, username, editing }] }` |
| `chat:message`          | сообщение в комнате          | Всем в комнате, включая автора                                 |
| `private:message`       | личное сообщение             | Только адресату                                                |
| `typing`                | кто-то печатает              | Остальным в комнате                                            |

Имя пользователя передаётся при подключении в `auth: { username }`. Сервер отклоняет пустое, неверное или занятое имя. На события с подтверждением (`ack`) сервер отвечает `{ ok: true, ... }` или `{ ok: false, error }`. Все ограничения (длина имени, комнаты и текста, размер истории, частота сообщений) лежат в [`limits.json`](limits.json) и отдаются клиенту по `/limits.json`. Пустой текст и текст из одних пробелов отклоняются и на клиенте, и на сервере. У каждого сообщения есть время (поле `at`), клиент показывает дату и время с секундами.

История по умолчанию лежит в памяти (по 50 последних сообщений на комнату). Если задана переменная `MONGODB_URI`, сообщения пишутся в коллекцию `messages` MongoDB и переживают перезапуск (`createMongoHistory` в `src/history.js`); обработчики используют только `add` и `list` и подставляют любое хранилище. Тесты работают на подставной коллекции без базы, запуск с настоящей MongoDB не проверялся.

Вход по токену: `POST /login` с `{ "username": "..." }` возвращает подписанный токен (HMAC-SHA256, один час), сокет подключается с `auth: { token }`. Секрет берётся из `TOKEN_SECRET` (для локального запуска есть значение по умолчанию), `REQUIRE_TOKEN=1` запрещает вход без токена. Английское описание: [`README.en.md`](README.en.md).

## 2 Почему клиент на чистом HTML и JS

Условие разрешает React или отдельный HTML/JS. Выбран HTML/JS: для одной страницы с чатом сборщик не нужен, клиент раздаётся самим Express из `public/` с того же адреса, поэтому нет настройки CORS и второго dev-сервера, а скрипт `socket.io.js` отдаёт сам сервер. Проверка в двух окнах сводится к открытию одного адреса. React-клиент для DSLKit появится в основном проекте, протокол событий для него уже готов.

## 3 Запуск

Нужен Node.js 22 или новее.

```bash
cd part-2/lab-07-websocket
npm install
npm start       # или npm run dev (nodemon)
npm test        # тесты, покрытие, проверка отчётов
```

Откройте `http://localhost:3000` в двух окнах (лучше одно обычное, одно приватное), введите разные имена, войдите в комнату `diagram-1`. Порт меняется через `PORT` в `.env` (образец `.env.example`, сам `.env` в репозиторий не попадает). Если клиент открывается с другого сайта, его адрес перечисляется в `ALLOWED_ORIGINS` через запятую, иначе сервер отклоняет подключение по заголовку `Origin`.

Интерфейс собран из стилей и разметки Части 1 (`site/css`): закреплённая шапка с логотипом и переключателем темы «луна/солнце», кнопки, поля, подвал, ссылка «Skip to the main content». Файл `public/dslkit.css` получен командой `node docs/design-contest/bundle-css.mjs public/dslkit.css`, собственные правила лежат в `public/style.css`. Страницы 404 и 500 оформлены так же.

Что проверить руками:

1. Второе окно подключилось: в первом появилась строка «bob connected».
2. Сообщение из одного окна появляется в другом; в третьем окне в другой комнате его нет.
3. Новое окно при входе в комнату получает последние сообщения.
4. Пока печатаете, у собеседника видно «is typing...»; флажок «I am editing» добавляет «(editing)» в списке людей.
5. Личное сообщение: нажмите значок конверта рядом с именем собеседника в списке «Online», над полем ввода появится «Private to …», отправьте текст. Отменить можно крестиком.
6. Закрытие окна даёт «disconnected» и «left» у остальных.

## 4 Структура

| Путь                | Назначение                                                        |
| ------------------- | ----------------------------------------------------------------- |
| `server.js`         | Точка входа: читает `.env`, слушает порт                          |
| `src/app.js`        | `createServer(options)`: Express, статика, Socket.IO, без запуска |
| `src/socket.js`     | Все обработчики событий                                           |
| `src/validate.js`   | Проверка имени, комнаты и текста                                  |
| `src/history.js`    | История сообщений: память или MongoDB                                        |
| `limits.json`       | Все числовые ограничения в одном месте                            |
| `src/rate-limit.js` | Ограничение частоты сообщений                                     |
| `src/origin.js`     | Проверка `Origin` при подключении                                 |
| `public/`           | Клиент: `index.html`, `client.js`, `theme.js`, `dslkit.css`, `style.css`, `404.html`, `500.html` |
| `tests/`            | 69 тестов на `socket.io-client` (`socket.test.js`, `audit.test.js`) |
| `AUDIT.md`          | Результаты аудита: проблема, риск, что сделано                    |

## 5 Проверка

`npm test` поднимает настоящий сервер на свободном порту и подключает к нему несколько клиентов `socket.io-client` по WebSocket. Покрыты подключение и отказы, уведомления online/offline, комнаты и изоляция, история, typing, editing, личные сообщения, лимиты и раздача клиента. В тот же запуск входит проверка сборки и оформления отчётов. Скриншоты двух окон в отчёт не вставлены. Отчёт содержит ответы на контрольные вопросы 9, 10, 11 (вариант 26, блок `{{answers}}`).

`npm audit` может показывать замечание по `braces` в цепочке `nodemon` (инструмент разработки, в рабочий запуск не входит).
