## Исправления по red-team аудиту ПЗ3

- **F1 (/__proto__ → 500).** `src/components/Breadcrumbs.jsx`: `LABELS[parts[i]]` — обычный объект, поэтому сегмент `__proto__` возвращал `Object.prototype`, а `constructor`/`toString`/`valueOf`/`hasOwnProperty` — функции; React бросал «Objects are not valid as a React child», и страницу ловил `ErrorBoundary` (500 вместо 404). Исправлено через `Object.hasOwn(LABELS, parts[i])` и проверку `typeof label === 'string'` (как уже было сделано в `Catalog.jsx` для `?sort=`). Тест в `features.test.jsx`.
- **F2 (skip-link в hash-режиме).** `src/components/Layout.jsx`: ссылка «Перейти к основному содержимому» переводила адрес на `#main`; в режиме `VITE_ROUTER=hash` `HashRouter` читает это как маршрут `main` и показывает 404. Исправлено: клик по ссылке переводит фокус на `<main>` через `ref` и `preventDefault()`, не меняя адрес, — работает одинаково в обычном и hash-режиме. Тест в `features.test.jsx` (рендер под `AppRouter` с `VITE_ROUTER=hash`).
- **F3 (ErrorBoundary ведёт на жёсткий `/`).** `src/shell/ErrorBoundary.jsx`: ссылка на логотип использовала `href="/"`, что ломается при `VITE_BASE` (сервер в подпапке) и при hash-режиме (адрес без `#/` не открывает приложение). Исправлено: `href` строится из `import.meta.env.BASE_URL`, а в hash-режиме к нему добавляется `#/`. Тест в `features.test.jsx`.
- **F4 (`npm audit`: 2 moderate только здесь).** `react-router`/`react-router-dom` 6.0.0–7.17.0: GHSA-wrjc-x8rr-h8h6 (открытое перенаправление через обратную косую в `<Link>`/`useNavigate`) и GHSA-337j-9hxr-rhxg (`deserializeErrors` при SSR-гидратации). Патча внутри линии 6.x нет — `npm view react-router-dom versions` показывает, что после `6.30.6` следующая версия сразу `7.0.0`; `npm audit fix --force` сам предлагает поставить `7.18.5`, то есть сломать требуемую «v6» задания. Риск принят и не достижим в этом приложении: все `<Link>`/`<NavLink>`/`<Navigate>` используют только константные адреса, единственный динамический переход (`navigate(target)` после входа) проходит через `safeReturnPath`, которая уже отрезает обратную косую черту и любые управляющие символы (см. `negative.test.jsx`, `redirect.test.jsx`); SSR в проекте не используется (чисто клиентский `createRoot`). Если потребуется закрыть и формальную запись аудита, а не только риск — единственный вариант, не ломающий v6, это `overrides`/`resolutions` на патч-версию, которой для 6.x не существует, либо переход на `react-router-dom@7`, что меняет версию библиотеки из условия задания; оставлено как решение преподавателя.
- **F6 (logout по обычному GET, logout-CSRF).** `src/pages/pages.jsx`: компонент `Logout` выполнял `logout()` в `useEffect` сразу при монтировании — значит, выйти из сессии мог любой переход на `/logout`, в том числе чужая `<a href="https://site/logout">` или `<img src=".../logout">`, без подтверждения пользователя. Исправлено: `logout()` вызывается автоматически только при навигации типа `PUSH` (клик по ссылке «Выйти» внутри приложения, `useNavigationType()` из `react-router-dom`); при прямом открытии адреса, перезагрузке страницы или переходе назад/вперёд (`POP`/`REPLACE`) показывается страница подтверждения с кнопкой «Подтвердить выход» — само действие происходит только по явному клику. Тест в `negative.test.jsx`.
- **F7 (невидимые и bidi-символы в имени).** `src/auth.jsx`: `validateUserName` проверял только длину после `trim()`, поэтому имя из `​` (пробел нулевой ширины), `ㅤ` (хангыльский филлер, не видимый, но Unicode-категория `\p{L}` — «буква») или `‮` (управление RLO, переворачивает видимый текст) проходило как обычное. Добавлена проверка `/[\p{Cc}\p{Cf}ᅟᅠㅤﾠ]/u` внутри (не только по краям) значения. Тест в `negative.test.jsx`.
- **F5 (безопасный возврат пропускает `/logout` с хвостом) — не исправлялось, известное ограничение.** `safeReturnPath` сравнивает только точные `/logout` и префиксы `/login?`/`/login#`; `/logout?x=1`, `/LOGOUT`, `/login/` формально проходят. Недостижимо: единственный источник `state.from` — `PrivateRoute` на собственных защищённых страницах, внешняя страница `history.state` задать не может, поэтому эксплуатации нет (это защита вглубь, а не реальная дыра). Чинить сейчас не стали, чтобы не трогать и без того покрытый тестами `safeReturnPath` без конкретного эксплойта.
- **F8 (фальшивая роль через `localStorage`) — не исправлялось, ожидаемое поведение демо.** Задание требует клиентской имитации входа без сервера; флаг `dslkit.isAuth`/имя `dslkit.userName` в `localStorage` неотличимы от настоящей защиты без бэкенда и могут быть подменены в консоли — это прямо описано в `README.md`, `src/pages/Admin.jsx` и в самом `auth.jsx`. Повышение роли по `storage`-событию из другой вкладки — то же самое ожидаемое поведение (синхронизация вкладок, а не отдельная дыра).
